## 1. 適應控制收尾

[▶ 00:05](https://youtu.be/7YdOx-ih0II?t=5) 超快速回顧：

- **系統辨識**：收集軌跡資料 → 寫成迴歸問題 → 近似動態。
- **MRAC**：考慮「控制器 + 適應機制 + 系統動態」的耦合系統，用 Lyapunov 分析穩定性。**直接**法：適應機制直接改進控制器；「參考」指的是要追蹤一個參考訊號。

### 1.1 MRAC 的補充：參考訊號與可辨識性

[▶ 02:38](https://youtu.be/7YdOx-ih0II?t=158)

- 上次的例子有點「做作」：假設有人給我們控制律 $u$、Lyapunov 函數 $V$、適應律。實際上要自己想出來，再做穩定分析。上次推薦的第一本參考書適合看「往前推導」的方向。

**參考訊號太簡單或太複雜** [▶ 03:40](https://youtu.be/7YdOx-ih0II?t=220)：

| 參考訊號 | 後果 |
|---|---|
| **很簡單**（0 或常數） | 很多不同的參數值都能完美追蹤 → **可辨識性**（identifiability）問題。MRAC 只在乎追蹤表現，不一定在乎參數估得準 |
| **夠複雜**（只有估到真參數才追得上） | 迫使你在乎參數估計 → 回到**持續激勵**：想估到真參數，就要用有意義的方式刺激系統 |

### 1.2 MIAC：確定性等價 vs 謹慎

[▶ 05:46](https://youtu.be/7YdOx-ih0II?t=346) **MIAC**（模型辨識適應控制）很依案例而定：

- 把**系統辨識**當成控制的**內迴圈**：一邊估模型，一邊用一個控制器**把估出的模型當成真的**來用。
- 非常可客製：模型和控制器可以各自選，兩者相當獨立。

**兩種處理參數不確定性的方式** [▶ 06:18](https://youtu.be/7YdOx-ih0II?t=378)：

| 方式 | 意思 |
|---|---|
| **確定性等價**（certainty equivalence） | $\hat\theta$ 是一個**點估計**，完全相信它 |
| **謹慎**（cautious） | 估計參數的**分布**，用分布表達對估計的不確定性；控制時也可能用到這個不確定性 |

### 1.3 MRAC vs MIAC

[▶ 07:21](https://youtu.be/7YdOx-ih0II?t=441)

| | MRAC | MIAC |
|---|---|---|
| 參數怎麼更新 | 直接最小化**追蹤誤差**（對參考訊號） | 最小化**資料擬合誤差**（中間目標：參數估計） |
| 彈性 | 較低 | **較高**：模型和控制器容易搭配 |
| 依賴參數估計 | 不太依賴 | **依賴**好的參數估計 |
| 保證 | 穩定和收斂通常**由設計得到** | 證明表現和穩定**較難** |

## 2. 為什麼 IL 和 RL 現在很重要

[▶ 08:55](https://youtu.be/7YdOx-ih0II?t=535) 課程地圖：從左上（古典學習型控制）移到**右上**——講者說這大概是目前控制和自主系統**最活躍的研究領域**之一。

- 機器人有很大進展，原因之一是**基礎模型**（LLM、VLM 用於控制）。
- 但這三四年來的**端到端**（end-to-end）流程，最終都是用**模仿學習**或**強化學習**訓練的——它們是這些架構背後真正的學習訊號。
- **自駕車** [▶ 10:31](https://youtu.be/7YdOx-ih0II?t=631)：例如 NVIDIA 最近的自駕堆疊 **Alpamayo**，同時用模仿學習（監督式學習）和強化學習訓練一部分。
- **大型語言模型的對齊**：把 LLM、VLM 微調成有用的助理，主要工作通常靠 RL。

## 3. 從狀態到動作的三種方式

[▶ 11:34](https://youtu.be/7YdOx-ih0II?t=694) 整門課的方法都在做同一件事：從某種狀態表示（結構化程度不一）得到**最佳控制**。

| 方式 | 想法 | 本課 |
|---|---|---|
| **1. 深入理解問題** | 先取得對問題的深刻理解（例如動態方程），再設計利用它的解 | 前半學期全部；最極端的例子：間接法（用動態推最佳性條件） |
| **2. 從示範學**（模仿學習） | 收集「狀態 + 在那個狀態做的決定」的資料，近似這個映射 | 第 14–15 集 |
| **3. 從試誤學**（強化學習） | 資料把狀態配上一個**分數**：在那個狀態做某動作有多好 | 第 14、16–19 集 |

**哲學上的差別** [▶ 13:40](https://youtu.be/7YdOx-ih0II?t=820)：

- IL：有一個**老師**告訴你好的動作是什麼。
- RL：沒有人告訴你該怎麼做，只有一個**衡量**告訴你某個動作多好。目標是嘗試不同策略，找出最有回報的。

【Q&A】[▶ 14:44](https://youtu.be/7YdOx-ih0II?t=884) 學生問：資料一定被當成完美的嗎？能不能告訴演算法「這是好例子，但還能更好」？答：這觸及 IL 的主要限制之一。表面上 IL 假設資料代表好的解，所以**被資料裡行為的表現限制住**——通常受限於老師的表現。（有星號：有些表述能偏好資料中表現較好的行為。）

【Q&A】[▶ 15:45](https://youtu.be/7YdOx-ih0II?t=945) 學生問：是不是先用監督式學習學基礎，再用 RL 微調？答：對，第 7 節會講。現在的自主堆疊是**分層訓練**的（從 LLM／NLP 社群繼承來的）：大規模預訓練學世界的一般規則，再逐步用越來越高品質的資料蒸餾。監督式學習／IL 給好起點，RL 微調。

**參考資料** [▶ 17:46](https://youtu.be/7YdOx-ih0II?t=1066)：除了課本，Sutton & Barto 的 RL 教科書；Stanford 的 Deep RL 課、Berkeley 的對應課。

## 4. 監督式學習複習

[▶ 18:16](https://youtu.be/7YdOx-ih0II?t=1096) **監督式學習**：學一個映射 $f:\mathcal X\to\mathcal Y$。大部分迴歸和分類都能這樣理解。

- 例：影像分類器，輸入 RGB 影像 $x$，輸出物件類別 $y$。
- 資料是輸入輸出配對 $(x,y)$，通常用類似**最大概似估計**的方法近似映射。

**例子** [▶ 19:18](https://youtu.be/7YdOx-ih0II?t=1158)：用拋物線擬合資料點。參數化函數 $f_\theta$，學 $\theta$ 最小化誤差：

$$\hat\theta=\arg\min_\theta\sum_i\left(y_i-f_\theta(x_i)\right)^2$$

**機率觀點** [▶ 20:51](https://youtu.be/7YdOx-ih0II?t=1251)：假設資料照某分布產生，例如 $p(y\mid x)=\mathcal N\left(f_\theta(x),\sigma^2\right)$（$f_\theta$ 是高斯的均值，變異數已知）。圖像：每個點上放一個小高斯；學習 = 最大化所有點的聯合機率：

$$\hat\theta=\arg\max_\theta\prod_ip\left(y_i\mid f_\theta(x_i)\right)$$

**取 log** [▶ 21:53](https://youtu.be/7YdOx-ih0II?t=1313)：一堆 0 到 1 之間的數相乘，數學上不好處理。實務上改成**最小化負對數概似**（negative log-likelihood）：

$$\hat\theta=\arg\min_\theta-\sum_i\log p\left(y_i\mid f_\theta(x_i)\right)$$

log 是**單調**轉換，保持極值點不變；而且會把很尖的目標函數「抹平」，同時保持同一個最佳點。

> 以下**不是逐字稿內容**：高斯假設下，負對數概似 = 平方誤差 /（$2\sigma^2$）+ 常數，所以最大概似和最小平方給出同一個 $\hat\theta$。

## 5. 模仿學習

[▶ 23:02](https://youtu.be/7YdOx-ih0II?t=1382) 監督式學習是**模仿學習的基石**。

**模仿學習**（imitation learning，IL）：把技能從**專家**轉移到**學習者**。機器人裡專家通常是人類操作員或既有的控制策略。

例 [▶ 23:33](https://youtu.be/7YdOx-ih0II?t=1413)：雙臂操作機器人，人類遙控操作（teleoperation）。人記錄下的動作 = 老師；學習問題 = 從機器人狀態映射到控制，最小化跟人類動作的誤差。

**資料**：專家行為的 $(x,u)$ 配對。

**IL 是總稱，包含兩類** [▶ 24:38](https://youtu.be/7YdOx-ih0II?t=1478)：

| 類型 | 學什麼 |
|---|---|
| **行為複製**（behavior cloning，BC） | 直接學**策略** $\pi_\theta:x\mapsto u$，最小化跟資料中 $(x,u)$ 的誤差 |
| **逆強化學習**（inverse reinforcement learning，IRL），也叫**逆最佳控制**（inverse optimal control） | 近似專家在最佳化的**獎勵／目標** $r(x,u)$，再用它來控制 |

> ⚠️ 逐字稿缺字 [▶ 25:38](https://youtu.be/7YdOx-ih0II?t=1538)：字幕寫「known as **reinforcement learning** or also often known as inverse optimal control」，依上下文應為「**inverse** reinforcement learning」。

兩者很互補：一個直接近似「狀態 → 控制」；一個近似「專家心中的目標」，再拿來控制。

【Q&A】[▶ 26:42](https://youtu.be/7YdOx-ih0II?t=1602) 學生問：IRL 是不是反推專家在想的策略？答：例如導航任務（起點到終點）。BC：收集怎麼到終點的軌跡，模仿它們。IRL：學一種**向量場**——終點成本低、離終點越遠越高——告訴你該怎麼走。

【Q&A】[▶ 27:44](https://youtu.be/7YdOx-ih0II?t=1664) 學生問：IRL 之後還要做最佳化找最佳控制？答：對，它不直接給行為規則，還要額外一步：求最佳化這個目標的策略——但我們有很多工具做這件事。

**IRL 什麼時候有用** [▶ 28:15](https://youtu.be/7YdOx-ih0II?t=1695)：自駕車。很難用數字說清楚「好的駕駛」是什麼——而且每個人的理解都不同。但讓人開車、收集例子很容易。從例子推出「這些人認為好駕駛是什麼」的式子，再最佳化它。

### 5.1 行為複製

[▶ 28:45](https://youtu.be/7YdOx-ih0II?t=1725) 主要想法很簡單：**用監督式學習訓練策略**。

```
1. 收集專家示範資料集 D = {(x_i, u_i)}（例如人遙控機器人）
2. 用任何監督式學習方法訓練 π_θ 模仿專家（例如在 D 上做最大概似估計）
```

**最早的成功例子之一** [▶ 29:15](https://youtu.be/7YdOx-ih0II?t=1755)：1980 年代末 CMU 的研究，從人類駕駛的例子學開車。一台軍用車，把**前方攝影機影像**映射到**方向盤角度**，用一個小神經網路學。在簡單的道路、受控環境中成功——以當時來說很驚人。

【口頭】[▶ 30:47](https://youtu.be/7YdOx-ih0II?t=1847) 這其實勾勒出很多最新方法的骨架：從高維輸入（例如影像）映射到我們關心的控制。

> 這項研究講者沒說名字，一般認為是 **ALVINN**（Pomerleau, 1989），待確認。

### 5.2 為什麼模仿學習不只是監督式學習

[▶ 30:47](https://youtu.be/7YdOx-ih0II?t=1847) 1980 年代就有了，那就這樣嗎？這個簡單食譜保證有效嗎？——**不**。

| 差異 | 說明 |
|---|---|
| **1. 誤差會累積** [▶ 31:48](https://youtu.be/7YdOx-ih0II?t=1908) | 資料是 $x_0,u_0,x_1,u_1,\dots$。部署時從同一個 $x_0$ 出發，模型再好也有一點預測誤差 → $\hat u_0$ 跟 $u_0$ 稍微不同 → 到了稍微不同的 $\hat x_1$ → 現在可能**稍微超出資料分布**的支撐範圍 → 下一個預測更偏 → ……越來越糟。因為你是環境中的**主動 agent**，你的誤差會**改變你看到的狀態分布**。普通監督式學習沒有這件事 |
| **2. 物理約束** [▶ 33:51](https://youtu.be/7YdOx-ih0II?t=2031) | 影像分類可以輸出詞彙表裡任何類別；預測機械手臂關節角度就有限制，不能輸出任意值 |
| **3. 領域不同** [▶ 34:22](https://youtu.be/7YdOx-ih0II?t=2062) | 例：看人類影片學控制人形機器人 → **具身落差**（embodiment gap） |
| **4. 資料貴** [▶ 35:23](https://youtu.be/7YdOx-ih0II?t=2123) | 影像可以從網路爬；有用的機器人示範要實際開車、操作，貴很多 |

**共變量偏移**（covariate shift）[▶ 34:53](https://youtu.be/7YdOx-ih0II?t=2093)：大部分問題都歸結到這裡——看專家行為時觀察到的狀態分布，跟**我們自己做決定時**觀察到的狀態分布**不同**。下週一詳細講。

### 5.3 逆強化學習

[▶ 35:54](https://youtu.be/7YdOx-ih0II?t=2154) 跟行為複製「正交」：從示範中**恢復獎勵函數**。

**例子** [▶ 36:27](https://youtu.be/7YdOx-ih0II?t=2187)：倉庫機器人從起點導航到終點。

- **BC**：收集 A 到 B 的示範，訓練模仿策略。在相似場景（同樣的起點終點組合）很有效；但倉庫**重新配置**後可能就有限制。
- **IRL**：理解專家的**整體目標**，例如「靠近目標好、靠近障礙壞」——像路徑空間裡的向量場，**可能更能泛化**。

【口頭】這不是說 IRL 一般比較好，只是凸顯兩者的不同。之後會看具體的 IRL 方法。

## 6. 強化學習

### 6.1 基本迴圈

[▶ 38:10](https://youtu.be/7YdOx-ih0II?t=2290) **強化學習**（reinforcement learning，RL）：學習型決策的形式化框架——**從經驗學怎麼做決定**。

兩個角色互動：

```
         動作 u_t
  Agent ─────────→ 環境
   (策略)  ←─────────
         狀態 x_{t+1}、獎勵 r_t
```

1. agent 觀察狀態 $x_t$。
2. 根據狀態算出動作 $u_t$。
3. 環境回傳新狀態 $x_{t+1}$ 和一個純量**獎勵** $r_t$。

展開成**軌跡** $\tau=(x_0,u_0,r_0,x_1,u_1,r_1,\dots)$ [▶ 39:12](https://youtu.be/7YdOx-ih0II?t=2352)。所有 RL 演算法都是用這些軌跡**改進策略**——這就是「試誤學習」：agent 主動嘗試不同策略，用探索產生的軌跡最大化某種分數。

### 6.2 術語

[▶ 40:12](https://youtu.be/7YdOx-ih0II?t=2412) RL 文獻來自電腦科學，有一套術語：

| 術語 | 數學 | 意思 |
|---|---|---|
| **策略**（policy） | $\pi(u\mid x)$ | 定義 agent 的行為。RL 裡通常是**給定狀態的動作分布**（以前我們多半用確定性策略） |
| **環境**（environment） | $p(x'\mid x,u)$ | agent 互動的系統；下一狀態的條件分布 |
| **獎勵**（reward） | $R(x,u)$ | **立即**成功的純量衡量 |
| **值函數**（value function） | $V^\pi(x)$ | **長期**表現：agent 預期未來能拿到多少 |
| **模型**（model，可選） | $\hat p(x'\mid x,u)$ | agent 對環境的**理解**（近似的動態）；用不用它區分**基於模型**和**無模型** RL |

**策略分布的例子** [▶ 41:16](https://youtu.be/7YdOx-ih0II?t=2476)：

- 格子世界導航，動作是四個方向（離散）→ 策略是四個方向上的分布。
- 連續動作空間 → 例如用高斯分布。

**值函數的直覺** [▶ 42:55](https://youtu.be/7YdOx-ih0II?t=2575)：獎勵只看一步轉移；但從一個狀態出發，策略和轉移都可能隨機，會有一整片可能的演化。值函數是「在某策略下，預期的獎勵總和」。

【口頭】[▶ 43:57](https://youtu.be/7YdOx-ih0II?t=2637) 為什麼幾乎所有 RL 演算法都很注重估計值函數？因為那是做決定的黃金標準：你在乎的通常不是立即的成功，而是**整個任務**的成功。

【課本補充】課本 §18.1.1 列出同樣五個元素（策略、環境、獎勵、值函數、可選的模型），並舉例：一個狀態可能立即獎勵很低、但值很高（因為它通常通往高獎勵的狀態），反之亦然。課本也提到「行為策略」（實際用來互動的策略）不一定等於正在學的策略。

### 6.3 RL 的長處

[▶ 45:42](https://youtu.be/7YdOx-ih0II?t=2742)

**1. 能發現新的、意想不到的解**

- IL 原則上被示範品質限制；RL 最大化表現，**沒有老師**所以不受老師限制。
- **Atari Pong**（2010 年代中期的遊戲成功）[▶ 46:44](https://youtu.be/7YdOx-ih0II?t=2804)：一開始很爛，試了各種策略後越來越像職業玩家；最後發現一個有趣的策略——在畫面側邊**挖一條隧道**，很容易得很多分。

  > 「挖隧道」的描述比較像 Atari **Breakout**（打磚塊）的著名例子，而不是 Pong；字幕寫 Pong，待確認。
- **AlphaGo** [▶ 47:48](https://youtu.be/7YdOx-ih0II?t=2868)：擊敗世界冠軍**李世乭**。**第 37 手**連專家都震驚、絕對想不到。講者推薦那部紀錄片。

**2. 擅長最佳化複雜的目標** [▶ 48:49](https://youtu.be/7YdOx-ih0II?t=2929)

- 例：四足機器人在崎嶇地形上行走——用解析或最佳化型控制工具極難。
- RL 現在是**機器人行走的事實標準**：利用高度可平行化的模擬環境，讓機器人在裡面學，不需要對接觸動力學做假設、估計系統模型。

【Q&A】[▶ 49:54](https://youtu.be/7YdOx-ih0II?t=2994) 學生問：模擬器裡還是要接觸動力學模型吧？答：模擬器內部是物理模擬器，至少有很準的物理模型，但可能很貴。這裡是把物理知識**蒸餾**進策略：策略只是一個從輸入到輸出的神經網路，沒有明確考慮物理，而是透過模擬器**隱含地**學到。

### 6.4 RL 跟其他機器學習的差別

[▶ 50:56](https://youtu.be/7YdOx-ih0II?t=3056)

| 差別 | 說明 |
|---|---|
| **沒有監督訊號** | 只有獎勵函數，沒人教你好的動作是什麼 |
| **回饋可能延遲** [▶ 51:26](https://youtu.be/7YdOx-ih0II?t=3086) | 下西洋棋：直到最後才知道輸贏，很難把功勞歸給某一步 → **功勞分配**（credit assignment）問題，RL 的基本問題之一；不同演算法多半用值函數處理 |
| **資料不是 i.i.d.** [▶ 52:27](https://youtu.be/7YdOx-ih0II?t=3147) | 統計學習理論幾乎所有定理都假設資料**獨立同分布**。RL 裡現在的動作影響未來看到的狀態 → 資料不獨立 → 學習通常更不穩定。很多演算法都有某種機制來**正則化**學習問題 |

【課本補充】課本 §18.1 還列了第四個 RL 獨有的挑戰：**探索 vs 利用**（exploration vs exploitation）——要探索以發現可能有回報的動作，也要利用已知去最大化累積獎勵；只探索就無法兌現所學，只利用則可能收斂到次佳策略。

### 6.5 MDP 與 RL 目標

[▶ 53:27](https://youtu.be/7YdOx-ih0II?t=3207) RL 建立在第 9 集的 **MDP** 上。

【口頭】要培養對不同記號的「可塑性」：RL 文獻（電腦科學）用 $s$、$a$；本課為了一致，繼續用控制界的 $x$、$u$。

**MDP** [▶ 54:31](https://youtu.be/7YdOx-ih0II?t=3271)：

$$\mathcal M=\left(\mathcal X,\ \mathcal U,\ p,\ R,\ \gamma\right)$$

| 元素 | 意思 |
|---|---|
| $\mathcal X$ | 狀態空間（例：導航時所有可能的格子） |
| $\mathcal U$ | 動作空間 |
| $p(x_{t+1}\mid x_t,u_t)$ | 轉移（動態），RL 裡通常寫成條件分布 |
| $R(x,u)$ | 獎勵函數 |
| $\gamma$ | 折扣因子：多在乎立即 vs 長期獎勵（數學技巧） |

**軌跡分布** [▶ 55:33](https://youtu.be/7YdOx-ih0II?t=3333)：對所有可能軌跡給機率。由條件獨立性：

$$p_\pi(\tau)=p(x_0)\prod_{t}\pi(u_t\mid x_t)\,p(x_{t+1}\mid x_t,u_t)$$

兩個隨機來源：下一狀態的隨機性、策略的隨機性。

**RL 目標** [▶ 56:35](https://youtu.be/7YdOx-ih0II?t=3395)：

$$\max_\pi\ J(\pi)=\mathbb E_{\tau\sim p_\pi(\tau)}\left[\sum_{t=0}^{\infty}\gamma^tR(x_t,u_t)\right]$$

折扣讓你調整立即和未來獎勵的權重；數學上讓無限時域可處理（「無限和的話，祝你好運最佳化它」）。

> ⚠️ 逐字稿缺字 [▶ 55:03](https://youtu.be/7YdOx-ih0II?t=3303)：字幕寫「expected reward, future reward」反覆改口，最後說的是「**期望的折扣未來獎勵**」。

**定義 MDP 是第一步** [▶ 57:40](https://youtu.be/7YdOx-ih0II?t=3460)（作業設定 RL 問題時也一樣）：

| | 西洋棋 | 四足機器人 |
|---|---|---|
| 狀態 | 棋盤上所有棋子的位置 | 機器人姿態 |
| 動作 | 所有合法的下一步 | 每條腿的關節力矩指令 |
| 動態 | **確定性**：棋盤 + 動作 → 下一個棋盤 | 給定力矩後機器人會到哪 |
| 獎勵 | 輸 −1、贏 +1 | 往前走一步 +、跌倒 −、站著 0（想讓它走快） |

### 6.6 值函數與 Q 函數

[▶ 59:16](https://youtu.be/7YdOx-ih0II?t=3556)

**狀態值函數**（state value function）：

$$V^\pi(x)=\mathbb E_\pi\left[\sum_{t=0}^\infty\gamma^tR(x_t,u_t)\ \Big|\ x_0=x\right]$$

從 $x$ 出發、照 $\pi$ 行動的預期總獎勵。**值函數依賴策略**——未來能拿多少取決於你打算怎麼做。期望涵蓋環境的不確定性和策略的不確定性。

**動作值函數**（action-value function），即 **Q 函數** [▶ 60:46](https://youtu.be/7YdOx-ih0II?t=3646)：

$$Q^\pi(x,u)=\mathbb E_\pi\left[\sum_{t=0}^\infty\gamma^tR(x_t,u_t)\ \Big|\ x_0=x,\ u_0=u\right]$$

從 $x$ 出發、**先做 $u$**、之後照 $\pi$ 行動的預期總獎勵。

**為什麼 Q 函數對控制更實用？** 【課堂討論】[▶ 61:16](https://youtu.be/7YdOx-ih0II?t=3676)

- 學生 1：可以探索現有策略以外的動作？講者：某種意義上對——下週三講**離策略**（off-policy）演算法時，這就是嘗試不依賴策略的動作的機制。但不是這裡要的答案。
- 學生 2：它能幫你預測下一步？例如西洋棋把騎士走到這裡會怎樣？講者：對！最終要的是**選下一個動作**的機制。有了最佳 Q 函數，就有一個容易最佳化的函數：
$$\pi^*(x)=\arg\max_uQ^*(x,u)$$
想像 Q 是一張查表：每個狀態、每個動作給一個未來獎勵的估計；在狀態 $x$ 把所有動作掃一遍，挑最大的就好。

（呼應第 9 集：用 $V^*$ 求動作需要知道轉移 $p$；用 $Q^*$ 不需要。）

**最佳值函數** [▶ 63:59](https://youtu.be/7YdOx-ih0II?t=3839)：值函數依策略好壞有**偏序**關係。定義

$$V^*(x)=\max_\pi V^\pi(x),\qquad Q^*(x,u)=\max_\pi Q^\pi(x,u)$$

這是大部分演算法想收斂到的黃金標準；有了 $Q^*$，最佳動作就是對 $Q^*$ 取 argmax。

【口頭】[▶ 65:01](https://youtu.be/7YdOx-ih0II?t=3901) 一定要把這些概念記牢，它們是大部分 RL 演算法的基礎。

### 6.7 RL 演算法分類與取捨

[▶ 65:32](https://youtu.be/7YdOx-ih0II?t=3932)

```
RL 演算法
├─ 無模型（model-free）：不學動態
│   ├─ 策略最佳化（policy optimization）：直接最佳化 RL 目標 J(π)
│   └─ 基於值（value-based）：估計最佳值函數，π = argmax Q*（隱含地最佳化目標）
└─ 基於模型（model-based）
    ├─ 學模型：估計動態（類似系統辨識），再用它改進策略
    └─ 模型已知：回到前半學期的工具
```

> ⚠️ 逐字稿缺字 [▶ 65:32](https://youtu.be/7YdOx-ih0II?t=3932)：字幕多次把「model-free」寫成「model **3**」。

【課本補充】課本 §18.4 有同樣的 RL 演算法分類。

**為什麼有這麼多演算法？取捨** [▶ 67:37](https://youtu.be/7YdOx-ih0II?t=4057)：

| 考量 | 說明 |
|---|---|
| **樣本效率**（sample efficiency） | 要跟環境互動多少次才收斂到有用的東西 |
| **穩定性** | 估最佳值函數比較容易，還是直接最佳化 RL 目標比較容易？ |
| **環境假設** | 回合制（能輕易重開一局棋）還是無限時域、沒有重置？ |
| **狀態／動作空間** | 連續還是離散？ |
| **策略好表示還是模型好表示？** [▶ 68:37](https://youtu.be/7YdOx-ih0II?t=4117) | 見下 |

**倒單擺（cart-pole）的例子**：要估近似動態模型，依桿子位置可能非常非線性、很難；但**行為規則**不難——桿子往左倒，車也往左補償。就像洗澡：你不會去建熱傳導和水流的模型，只是覺得燙就轉旋鈕。控制比估完整模型容易。

**樣本效率 vs 牆鐘時間** [▶ 70:13](https://youtu.be/7YdOx-ih0II?t=4213)：

- 會看到**離策略**和**同策略**（on-policy）演算法，從最不有效率到最有效率的光譜。
- 為什麼要用比較沒效率的？因為**牆鐘時間**（wall clock time）≠ 樣本效率。比較沒效率的演算法通常比較**穩定**。如果能輕易平行化或便宜地模擬，經驗很便宜，就不需要為了效率去用複雜又不穩定的演算法。

## 7. 不是二選一：分層訓練流程

[▶ 71:17](https://youtu.be/7YdOx-ih0II?t=4277) 講者希望大家帶走的重點：**不要把不同類別的演算法當成替代品**，尤其 IL 和 RL 不是二選一。

前沿的自主系統越來越依賴端到端框架，有大量學習；但學習**不是**只用 IL 或只用 RL，而是**分層的訓練流程**，不同技術在不同階段扮演不同角色。

**例：NVIDIA Alpamayo R1**（自駕的推理型 VLA 模型，用視覺語言模型計算車輛動作）[▶ 72:19](https://youtu.be/7YdOx-ih0II?t=4339)：

| 階段 | 方法 |
|---|---|
| 1. 一般預訓練 | 網路規模的**監督式學習** |
| 2. 監督式微調（SFT） | 基本上就是**模仿學習** |
| 3. 最後階段 | **強化學習**：對齊人類理解和價值，並擠出最後一點表現 |

## 8. 一頁速查表

### 適應控制

| | MRAC | MIAC |
|---|---|---|
| 更新依據 | 追蹤誤差 | 資料擬合誤差 |
| 彈性 | 低 | 高 |
| 保證 | 由設計得到 | 較難 |
| 參數不確定性 | — | 確定性等價（點估計） / 謹慎（分布） |

參考訊號太簡單 → 可辨識性問題；夠複雜 → 需要持續激勵。

### IL vs RL

| | 模仿學習 | 強化學習 |
|---|---|---|
| 資料 | 專家的 $(x,u)$ | 自己互動得到的 $(x,u,r,x')$ |
| 訊號 | 老師告訴你做什麼 | 分數告訴你多好 |
| 上限 | 受老師表現限制 | 可能超越人類（Pong／Breakout、AlphaGo 第 37 手） |
| 子類 | 行為複製（學 $\pi$）、逆 RL（學 $r$） | 無模型（策略最佳化、基於值）、基於模型 |

### 行為複製的陷阱

誤差累積 → 共變量偏移（專家看到的狀態分布 ≠ 自己看到的）；物理約束；具身落差；示範很貴。

### 監督式學習

$\hat\theta=\arg\min_\theta-\sum_i\log p(y_i\mid f_\theta(x_i))$；高斯時 ⟺ 最小平方。

### RL 形式化

| 項目 | 式子 |
|---|---|
| MDP | $(\mathcal X,\mathcal U,p,R,\gamma)$ |
| 軌跡分布 | $p_\pi(\tau)=p(x_0)\prod_t\pi(u_t\mid x_t)p(x_{t+1}\mid x_t,u_t)$ |
| 目標 | $\max_\pi\mathbb E_{\tau\sim p_\pi}\left[\sum_t\gamma^tR(x_t,u_t)\right]$ |
| $V^\pi(x)$ | 從 $x$ 照 $\pi$ 的預期折扣總獎勵 |
| $Q^\pi(x,u)$ | 從 $x$ 先做 $u$ 再照 $\pi$ |
| 最佳 | $V^*=\max_\pi V^\pi$，$Q^*=\max_\pi Q^\pi$，$\pi^*=\arg\max_uQ^*$ |
| RL 挑戰 | 無老師、延遲獎勵（功勞分配）、非 i.i.d.、探索 vs 利用 |

### 訓練流程

預訓練（監督式）→ SFT（模仿學習）→ RL（對齊、擠表現）。
