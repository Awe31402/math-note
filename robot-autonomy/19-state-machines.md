## 1. 什麼是狀態機

### 1.1 函數 vs 狀態機

[▶ 02:11](https://youtu.be/l5kwVWOe0OM?t=131)

- **函數**：輸入 → 輸出的映射（可能很非線性），**沒有歷史**的概念。
- **狀態機**：一種建模方法，描述**輸出取決於整段輸入歷史**的系統。「輸入的歷史」就是它的定義性概念。

【口頭】[▶ 02:51](https://youtu.be/l5kwVWOe0OM?t=171) 狀態機本身**不是演算法**，只是**建模框架**——就像用機率密度描述濾波問題、用 Markov 決策過程描述決策問題（下一堂）一樣，之後還得設計演算法來操作它。

### 1.2 三種用途

[▶ 03:33](https://youtu.be/l5kwVWOe0OM?t=213)

1. **合成**（synthesis）：為機器人**指定程式**。最基本的用途。例：提款機（ATM）背後就是一個狀態機——插卡 → 吃卡 → 讀卡號 → ……
2. **分析**（analysis）：建模自主代理和環境中其他代理的互動（例如自駕車和行人），找出控制演算法可能的失效模式。
3. **預測**（prediction）：預測其他代理的行為，用來模擬。例：模擬中常用有限狀態機建模**行人**，再測試自駕車和這個行人互動時是否安全、有效率。

【口頭】「只要你待在機器人領域，你這輩子都會和狀態機打交道——除非深度學習接管一切，讓狀態機過時。」

【口頭】[▶ 05:36](https://youtu.be/l5kwVWOe0OM?t=336) 研究上仍活躍：證明正確性、從資料學出狀態機等。例：Stanford 資工系 Chris Manning 2019 年結合學習與狀態機的論文。「這可能是機器人學最古老的主題之一，但仍是活躍的研究領域。」

### 1.3 數學定義

[▶ 06:26](https://youtu.be/l5kwVWOe0OM?t=386)

**為什麼需要「狀態」**：原則上可以寫一個超複雜的函數，把每一段可能的輸入歷史對到一個輸出。但可能的歷史數量**指數成長**，根本無法指定。

狀態機的做法（也是這學期一直在用的做法）：引入**狀態**，用精簡的方式記住「預測輸出所需要的歷史資訊」。

一個狀態機由以下組成：

| 元素 | 意思 |
|---|---|
| 狀態集合 $S$ | |
| 輸入詞彙（input vocabulary）$I$ | 所有可能的輸入 |
| 輸出詞彙（output vocabulary）$O$ | 所有可能的輸出 |
| 狀態轉移函數 $n: S \times I \to S$ | $s_{t+1} = n(s_t, i_t)$；概念上和機器人的狀態轉移模型一樣 |
| 輸出函數 $o: S \times I \to O$ | $o_t = o(s_t, i_t)$ |
| 初始狀態 $s_0 \in S$ | |

注意轉移和輸出都**不直接依賴整段輸入歷史**——那些依賴全被封裝在狀態 $s_t$ 裡。

【口頭】[▶ 08:24](https://youtu.be/l5kwVWOe0OM?t=504) 這是建模與控制的共同主題：一種是純**輸入－輸出**方法；另一種是**狀態空間**方法，引入狀態來簡化輸入到輸出的映射。

**圖形表示** [▶ 08:52](https://youtu.be/l5kwVWOe0OM?t=532)：節點是狀態；有向邊（弧）是轉移，標上「觸發的輸入 / 產生的輸出」。例如在 $s_0$ 收到 $i_1$ → 轉到 $s_1$、輸出 $o_1$；收到 $i_0$ → 轉到 $s_2$。

【課本補充】§16.1 區分兩種慣例：
- **Mealy 機**：輸出取決於目前狀態**和**目前輸入，$o_t = o(s_t, i_t)$——課堂和課本都用這種。
- **Moore 機**：輸出只取決於目前狀態，$o_t = \tilde o(s_t)$；圖上輸出標在節點上，邊只標輸入。
- **確定性**（deterministic）狀態機：每個狀態對每個輸入只有一條轉移。

## 2. 例子：停車場柵欄

[▶ 10:27](https://youtu.be/l5kwVWOe0OM?t=627)

**情境**：門口一根柵欄，可以在頂端（升起）、底端、或中間（正在升或降）。感測器告訴我們：車是否在柵欄前、車是否剛通過。柵欄能做的動作：升、降、什麼都不做。（假設免費停車，只是要控制進場速率。）

**想要的行為**：

1. 有車要進 → 柵欄升起。
2. 車通過前保持升起。
3. 車通過後放下。

**建模**（有自由度，「設計好的狀態機是一門藝術」；狀態越少越好——省記憶體，更重要的是**容易理解、容易驗證正確性**）：

| | 內容 |
|---|---|
| 狀態 | 等待（waiting）、升起中（raising）、已升起（raised）、放下中（lowering） |
| 輸入 | 有車／沒車在門口；柵欄到頂／沒到頂；柵欄到底／沒到底；車剛離開／沒有 |
| 輸出 | 升（raise）、降（lower）、無動作（nop）——想成給駕駛看的顯示 |

**轉移** [▶ 15:02](https://youtu.be/l5kwVWOe0OM?t=902)：

1. **等待**：一直輪詢感測器。沒車 → 留在等待，輸出 nop；有車 → 輸出 raise，進入**升起中**。
2. **升起中**：輪詢柵欄角度。沒到頂 → 繼續升；到頂 → 進入**已升起**（例如每秒輪詢一次）。
3. **已升起**：等車通過；車通過 → 進入**放下中**。
4. **放下中**：放到底 → 回到**等待**。

【Q&A】[▶ 13:33](https://youtu.be/l5kwVWOe0OM?t=813) 學生問：每個時間步只收到一個輸入，還是好幾個？
Pavone：在某個狀態下，只有一個輸入決定往哪個狀態走。

【Q&A】[▶ 13:45](https://youtu.be/l5kwVWOe0OM?t=825) 學生指出：柵欄到頂時車應該還在，否則就是出了問題？
Pavone：很好的觀點。分析狀態機時通常還要加**異常狀態**：例如感測器沒有回傳值怎麼辦？觀測到的狀態互相矛盾怎麼辦？這裡為了簡單沒放。

**會出什麼問題** [▶ 16:00](https://youtu.be/l5kwVWOe0OM?t=960)：例如有車**緊跟**前車，感測器沒偵測到，柵欄放下時正好有車通過——狀態機沒有處理這種情況。

【口頭】所以設計狀態機是**反覆迭代**的過程：設計 → 測試 → 發現漏掉的失效模式 → 加新狀態、新輸入、新輸出 → 再測。開源專案裡很多抱怨和未解決的 issue 都和底層狀態機的行為有關。

【課本補充】例 16.1.1 用同樣的例子，狀態命名為 Down、Raising、Up、Lowering，另加一個週期性的 TICK 輸入，讓狀態機在端點事件之間持續下達運動指令。例如 $n(\text{Down}, \text{CAR\_DETECTED}) = \text{Raising}$、$o(\text{Down}, \text{CAR\_DETECTED}) = \text{RAISE}$；$n(\text{Raising}, \text{TICK}) = \text{Raising}$、輸出 RAISE。

## 3. 狀態機的極限

[▶ 17:09](https://youtu.be/l5kwVWOe0OM?t=1029)

**例子**：判斷任意長度的字串中，括號是否**配對平衡**（左右括號數量相等）。看似簡單，但字串可以任意長，用狀態機做需要**無限多個狀態**——和「有限」狀態機的假設矛盾。

> 以下**不是逐字稿內容**，是依「狀態要記住什麼」推論的：要判斷平衡，必須記住「目前還有幾個左括號沒配對」。這個數可以是 $0, 1, 2, \dots$ 任意大，每個值都需要一個不同的狀態（因為之後要看到不同數量的右括號才算平衡），所以狀態數無上限。

在**建模的計算能力**上，有限狀態機在階梯的**底部**，**Turing 機**在頂端。儘管如此，狀態機仍然非常有用、被廣泛使用。

## 4. 怎麼有原則地設計狀態機

[▶ 18:52](https://youtu.be/l5kwVWOe0OM?t=1132)

兩個關鍵挑戰：(1) 不要過度複雜；(2) 要正確。三種有原則的做法：

1. **狀態最小化**：輸入一個狀態機，輸出一個行為相同但狀態數最少的狀態機——移除多餘狀態。
2. **階層式分解**：把一些狀態聚成**超狀態**（super state），更容易理解整體行為，又不丟資訊。
3. **常見設計模式**：盡量模組化——為了可解釋性，也為了以後能抽換部分模組。

### 4.1 狀態最小化

[▶ 20:43](https://youtu.be/l5kwVWOe0OM?t=1243)

**想法**：找出行為**等價**的狀態並合併。狀態機一複雜，很容易不小心出現重複狀態。

**等價狀態**（大致上）：產生相同輸出，而且對所有輸入都轉移到相同（或等價）的狀態。

**在解什麼**：給一個狀態機，找出輸入－輸出行為相同、狀態數最少的版本。

**步驟**（分割細化，partition refinement）：

1. 把**所有**狀態放進同一個等價類。（等於假設「只用一個狀態就夠」，通常太粗。）
2. **依輸出分割**：輸出不同的狀態不可能是重複的，分到不同類。
3. **依下一個狀態分割**：同一類裡，若某些狀態在某個輸入下會轉到**不同類**，就再分開。
4. 重複步驟 3，直到不能再分（固定點）。
5. 每一類合併成一個狀態。

【口頭】好消息：這類演算法相對快。

**什麼時候會失敗**：只能合併「完全等價」的狀態；行為相近但不完全相同的狀態合併不了（這時要靠階層式分解）。

### 4.2 例子：偵測 010 或 110

[▶ 22:28](https://youtu.be/l5kwVWOe0OM?t=1348)

**任務**：輸入一串 0、1。每看完 3 個數字，若剛好是 **010** 或 **110** 就輸出 1（true），否則輸出 0（false），然後重新開始。

**最直接的設計：樹狀結構** [▶ 23:22](https://youtu.be/l5kwVWOe0OM?t=1402)

- $S_0$：初始狀態。
- 第 1 個數字：0 → $S_1$，1 → $S_2$。
- 第 2 個數字：$S_1$ 收 0 → $S_3$（看過 00）、收 1 → $S_4$（01）；$S_2$ 收 0 → $S_5$（10）、收 1 → $S_6$（11）。
- 第 3 個數字：全部回到 $S_0$（重設）。只有「$S_4$ 收 0」（010）和「$S_6$ 收 0」（110）輸出 1，其餘輸出 0。

驗證：輸入 000 → $S_0 \to S_1 \to S_3 \to S_0$，輸出 0，沒辨識到。✓

| 狀態（看過的前綴） | 收 0 → | 收 1 → | 收 0 輸出 | 收 1 輸出 |
|---|---|---|---|---|
| $S_0$（重設） | $S_1$ | $S_2$ | 0 | 0 |
| $S_1$（0） | $S_3$ | $S_4$ | 0 | 0 |
| $S_2$（1） | $S_5$ | $S_6$ | 0 | 0 |
| $S_3$（00） | $S_0$ | $S_0$ | 0 | 0 |
| $S_4$（01） | $S_0$ | $S_0$ | **1** | 0 |
| $S_5$（10） | $S_0$ | $S_0$ | 0 | 0 |
| $S_6$（11） | $S_0$ | $S_0$ | **1** | 0 |

【Q&A】[▶ 26:18](https://youtu.be/l5kwVWOe0OM?t=1578) 學生問：$S_1$ 和 $S_2$ 不就一樣嗎？第一個數字是什麼都沒差。
Pavone：完全正確，這就是這個例子的重點。樹狀設計最直觀，但狀態數不是最少；$S_1$、$S_2$ 代表同一件事，可以合併。

**套用分割細化** [▶ 27:06](https://youtu.be/l5kwVWOe0OM?t=1626)（逐步寫完整）：

1. 全部一類：$\{S_0, \dots, S_6\}$。
2. 依輸出：$S_4$、$S_6$ 在收到 0 時會輸出 1，和其他不同 →
   $\{S_0, S_1, S_2, S_3, S_5\}$、$\{S_4, S_6\}$。
3. 依下一個狀態檢查第一類：
   - $S_0$ → $S_1, S_2$（都在第一類）✓
   - $S_3$、$S_5$ → $S_0$（第一類）✓
   - $S_1$ → $S_3$（第一類）或 $S_4$（**第二類**）✗；$S_2$ 同理會到 $S_6$。
   → 分出 $\{S_1, S_2\}$：$\{S_0, S_3, S_5\}$、$\{S_1, S_2\}$、$\{S_4, S_6\}$。
4. 再檢查 $\{S_0, S_3, S_5\}$：$S_0$ → $\{S_1, S_2\}$；$S_3$、$S_5$ → $S_0$（在 $\{S_0, S_3, S_5\}$）。轉到不同類 → 分開：$\{S_0\}$、$\{S_3, S_5\}$。
   （步驟 4 是依課本例 16.2.1 補完的；課堂上講到步驟 3 就說「繼續做下去」。）
5. 不能再分，得到 **4 個狀態**：
   $S_0$、$S_1' = \{S_1, S_2\}$、$S_3' = \{S_3, S_5\}$、$S_4' = \{S_4, S_6\}$。

**簡化後的狀態機** [▶ 29:03](https://youtu.be/l5kwVWOe0OM?t=1743)：

| 狀態 | 收 0 → | 收 1 → | 收 0 輸出 | 收 1 輸出 |
|---|---|---|---|---|
| $S_0$ | $S_1'$ | $S_1'$ | 0 | 0 |
| $S_1'$（看過 1 個數字） | $S_3'$ | $S_4'$ | 0 | 0 |
| $S_3'$（第 2 個是 0） | $S_0$ | $S_0$ | 0 | 0 |
| $S_4'$（第 2 個是 1） | $S_0$ | $S_0$ | **1** | 0 |

意思：第一個數字無所謂（記作 $x$）；只要第二個是 1、第三個是 0，就是 010 或 110。

驗證：010 → $S_0 \xrightarrow{0} S_1' \xrightarrow{1} S_4' \xrightarrow{0} S_0$，輸出 1 ✓；110 同理 ✓；其他序列輸出 0。

【Q&A】[▶ 31:03](https://youtu.be/l5kwVWOe0OM?t=1863) 學生問：投影片說這個演算法是多項式時間，可是要先生成整棵樹再分割，這還算多項式嗎？
Pavone：多項式是指相對於**狀態數**（分割的次數）。生成樹是你自己做的設計，不是演算法的一部分。這個演算法可以證明是正確的，也有現成工具能把狀態機最小化。

### 4.3 階層式分解

[▶ 31:46](https://youtu.be/l5kwVWOe0OM?t=1906)

把狀態聚成**超狀態**，在超狀態之間轉移。主要為了**可解釋性**。（課堂只簡短帶過，說有現成工具。）

【課本補充】§16.2.2：**階層式有限狀態機**（hierarchical FSM, HFSM），又稱 **Statecharts**（Harel, 1987）。超狀態（composite state）把相關狀態包起來，加上能進出超狀態的泛化轉移，減少圖的雜亂、緩解**狀態爆炸**，讓共用的轉移可以在高層重用。適用於「不完全等價但行為相近」的狀態。

### 4.4 組合

[▶ 32:21](https://youtu.be/l5kwVWOe0OM?t=1941)

把大狀態機**模組化**：用小狀態機各管一個行為，再用三種基本運算組起來。「沒什麼魔法，就是設計模式；以模組化的方式思考，方便驗證和認證。」

1. **串接**（cascade／sequential）：前一個的輸出當後一個的輸入。前提：前一個的輸出詞彙對得上後一個的輸入詞彙。
2. **並聯**（parallel）：兩個狀態機的輸入詞彙相同，同時吃同一個輸入；輸出是兩個輸出**接在一起**。
3. **回授**（feedback）：輸出接回輸入。例如用來做**計數器**。

【課本補充】§16.2.3 的正式定義（$M_1$、$M_2$，連線映射 $\rho: O_1 \to I_2$）：

- 串接 $M = M_2 \circ_\rho M_1$：
$$
S = S_1 \times S_2,\quad I = I_1,\quad O = O_2,\quad
n\left( (s_1, s_2), i \right) = \left( n_1(s_1, i),\ n_2\left( s_2, \rho(o_1(s_1, i)) \right) \right),\quad
o\left( (s_1, s_2), i \right) = o_2\left( s_2, \rho(o_1(s_1, i)) \right)
$$
- 並聯 $M = M_1 \parallel M_2$：
$$
S = S_1 \times S_2,\quad O = O_1 \times O_2,\quad
n\left( (s_1, s_2), i \right) = \left( n_1(s_1, i),\ n_2(s_2, i) \right),\quad
o\left( (s_1, s_2), i \right) = \left( o_1(s_1, i),\ o_2(s_2, i) \right)
$$
- 回授：輸出（的一部分）接回輸入；若「由輸出決定輸入」的方程有唯一解才良定義，否則稱為 ill-formed。

注意組合後的狀態集合是**笛卡兒積**，狀態數會相乘。

## 5. 實作：常見模式

[▶ 33:40](https://youtu.be/l5kwVWOe0OM?t=2020)

【口頭】Pavone：「狀態機容易懂，但設計好的狀態機非常難。」接著由他的博士生示範。

【口頭】博士生先強調：這裡介紹的工具都是**選用**的，不一定要用現成工具；但要熟悉**常見的實作方式**。如果你進了 Zoox 或 Waymo，第一件事大概就是在超大的程式碼庫裡找出他們的狀態機在哪。

### 5.1 物件導向＋固定頻率迴圈

[▶ 35:58](https://youtu.be/l5kwVWOe0OM?t=2158)

最常見的模式：

1. 寫一個**類別**把狀態機抽象出來。
2. 類別裡用一個變數記住目前狀態。
3. 有一個方法以**固定頻率**執行：讀輸入 → 依目前狀態和輸入決定轉移 → 更新狀態 → 執行對應動作。

### 5.2 PX4 的飛行模式狀態機

[▶ 36:40](https://youtu.be/l5kwVWOe0OM?t=2200)

PX4：最受歡迎的開源無人機飛控軟體（四旋翼、固定翼都能用）。它的文件裡就有飛行模式的轉移圖，例如 RTL（return to land，返航降落）、已降落、降落中、盤旋（loiter，停在空中）。很多心力花在讓圖保持簡單，並確保程式碼和圖一致。

【口頭】[▶ 38:03](https://youtu.be/l5kwVWOe0OM?t=2283) 在 PX4 的程式碼中，`commander.cpp` 裡有一個主迴圈（無人機的主迴圈），以固定頻率執行，在裡面處理各種狀態轉移。狀態機的抽象對上百個開發者很有用，所以他們還寫了專門的輔助函式：例如在某狀態下收到「切換到 acro 模式」的輸入，就把飛行器狀態更新為 acro 模式。（acro 模式是用來翻跟斗的，「你不會想不小心觸發它」。）

【口頭】[▶ 39:31](https://youtu.be/l5kwVWOe0OM?t=2371) 他去看了 PX4 狀態機相關的 issue：還有 14–15 個沒解決，有的討論有 24 則留言，「大家互相吼叫該怎麼做才對」——呼應 Pavone 說的，狀態機真的難。

【課本補充】§16.2 也用 PX4 的圖說明：即使狀態不多，完整描述系統行為的 FSM 也可能很複雜。

### 5.3 作業裡的 navigator.py

[▶ 40:11](https://youtu.be/l5kwVWOe0OM?t=2411)

作業中的 `navigator.py` 就是一個狀態機——大概是「能做點有趣事情的機器人」最簡單的狀態機。

結構：一個 `run` 函式，裡面一串 if/elif：依目前的**模式**（mode，對應狀態機的狀態）檢查條件（例如是否已對準、是否接近目標），再切換到正確的模式。

## 6. ROS 的 SMACH

[▶ 40:58](https://youtu.be/l5kwVWOe0OM?t=2458)

ROS 附帶了狀態機工具 **SMACH**（state machine）。

【口頭】這也是教狀態機觀念的原因：ROS 有很多「神奇」工具可用，但前提是你能把問題**轉成工具要的格式**。如果你能把問題想成一個正式的狀態機，就能用 SMACH——它讓實作乾淨、抽象，還附**視覺化**工具，可以監看狀態機、和隊友分享，甚至放進期末報告。

### 6.1 狀態與容器

[▶ 42:18](https://youtu.be/l5kwVWOe0OM?t=2538)

兩個主要元件：

- **狀態**（state）：和前面講的狀態一一對應。實作時繼承 SMACH 的 State 類別，需要寫兩個函式：
  1. **建構子**：任意初始化；重要的是**宣告這個狀態可能的結果**（outcome），例如成功、失敗。
  2. **execute**：做這個狀態該做的事（例如翻個跟斗），然後**回傳一個結果**。
- **容器**（container）：例如一個有限狀態機。（SMACH 的容器比狀態機更一般化一點，但可以先把它當狀態機。）建立容器 → 加入狀態 → 指定轉移。

**結果和輸入的對應**：可以把「結果」想成前面形式化裡的「輸入」——它決定要轉到哪個狀態。有些結果是**容器本身**的結果（整個狀態機結束），而不是轉到另一個狀態。

**組合也有對應的容器** [▶ 45:41](https://youtu.be/l5kwVWOe0OM?t=2741)：串接、並聯、回授在 SMACH 裡都有對應的容器（例如 sequence 容器把兩個狀態機串起來）。能把狀態機拆成這些模式，用 SMACH 設計整體就很容易。

### 6.2 簡單例子：foo 與 bar

[▶ 46:46](https://youtu.be/l5kwVWOe0OM?t=2806)

程式結構（文字描述，不抄程式碼）：

1. 初始化 ROS 節點。
2. 建立一個狀態機容器，指定整個狀態機的可能結果。
3. 在 Python 的 `with` 區塊中，把兩個狀態 foo、bar 加進去，並指定轉移：foo 的「結果 1」→ 轉到 bar；其他結果 → 別的轉移或結束。
4. 執行狀態機：從第一個加入的狀態開始，依結果轉移，直到沒有轉移可做為止。

【口頭】[▶ 47:25](https://youtu.be/l5kwVWOe0OM?t=2845) `with` 語法：建立一個「情境」（context）。Python 會呼叫該類別的設定函式，區塊結束時（即使中間出錯）也會收尾。經典例子是開檔：寫入失敗時仍確保檔案被關掉，不會讓當掉的程式佔著資源。在 SMACH 裡，它表示「這些狀態都加到這個狀態機上」；不用懂細節也能用。

執行後終端機會印出：正在執行 foo → foo 回傳結果 1 → 狀態機知道要轉到 bar → 執行 bar。

### 6.3 用 SMACH 重寫 navigator

[▶ 49:45](https://youtu.be/l5kwVWOe0OM?t=2985)

【口頭】這和期末專題直接相關。往年常見的問題：機器人卡在角落，狀態機就一直卡在那，完全沒有偵測到 EKF 已經亂掉或感測器全壞了。其實只要有一個**失效保護**（failsafe）狀態：重設定位、可能稍微倒退、再繼續——這種狀態能讓期末專題走很遠，SMACH 能幫你更有效地做到。

示範的三個狀態（只放了部分）：

| 狀態 | 做什麼 | 可能的結果 |
|---|---|---|
| **等待**（waiting） | 送零速度給致動器，等指令 | 沒事 → 留在等待；收到新指令 → 規劃 |
| **規劃**（planning） | 計算路徑（相當於 navigator 的 replan） | 成功；失敗；收到新指令（新目標）；收到新地圖（應重新規劃）；錯誤 |
| **追蹤**（tracking） | 跟隨現有路徑直到終點 | 到達；路徑過期（離起點太遠或計時器到期）…… |

**轉移**（寫好狀態之後，轉移只剩幾行，非常乾淨、好改）[▶ 52:31](https://youtu.be/l5kwVWOe0OM?t=3151)：

- 等待 ＋ 沒事 → 等待
- 等待 ＋ 新指令（例如從 RViz 下的目標）→ 規劃
- 規劃 ＋ 成功 → 追蹤
- 規劃 ＋ 失敗 → 等待（沒有好計畫，先停著）
- 追蹤 ＋ 路徑過期 → 由設計狀態機的人決定：重新規劃，或停下等待

【口頭】好處：狀態本身只負責偵測並回報「路徑過期了」，至於要怎麼反應，由定義狀態機的人決定——和前面理論的框架完全一致。

### 6.4 smach_viewer

[▶ 54:42](https://youtu.be/l5kwVWOe0OM?t=3282)

安裝 `smach_viewer` 後執行，**不用額外工作**（因為你用了正確的形式化和工具）就能得到狀態機的視覺化：

- 可以檢查設計，和隊友爭論幾小時「等待之後出錯應該轉到追蹤還是規劃」。
- 執行時能**即時看到**目前在哪個狀態：給機器人新目標 → 很快進入規劃 → 很簡單的計畫，幾乎馬上進入追蹤 → 完成後回到等待。
- 與其坐在那裡納悶「我的 TurtleBot 在幹嘛，為什麼要撞柵欄」，不如看 viewer：「你在這個狀態，這個轉移好像沒被觸發」——省下大量時間。
- 也是給隊友的好文件。

【口頭】SMACH 是開源軟體，難免有些小怪癖，但大致可用；助教可以幫忙設定。

【課本補充】§16.3 歸納狀態機的四個根本限制，正好引出下一章：
1. **難以擴展**：狀態數隨影響決策的因素**組合爆炸**。
2. **脆弱**：只能對設計者預先想到的輸入做出有意義的反應，遇到新情況無法推理或泛化。
3. **沒有最佳性**：只描述哪些行為被允許，無法依成本或報酬比較不同動作。
4. **確定性**：無法有原則地處理雜訊、隨機結果和信念更新。

## 8. 一頁速查表

### 定義（Mealy）

$$
M = (S, I, O, n, o, s_0),\qquad s_{t+1} = n(s_t, i_t),\qquad o_t = o(s_t, i_t)
$$

- **關鍵想法**：狀態把整段輸入歷史壓縮成預測輸出所需的資訊；否則要為指數多種歷史各指定一個輸出。
- Moore：$o_t = \tilde o(s_t)$。

### 狀態最小化（分割細化）

1. 全部一類 → 2. 依輸出分 → 3. 同類中轉移到不同類的再分 → 4. 重複到固定點 → 5. 每類合併。

- **關鍵一步**：兩個狀態等價 ⟺ 每個輸入下輸出相同且轉到等價狀態。
- 010/110 偵測器：7 個狀態 → 4 個（第一個數字無關，只看「第 2 個是 1、第 3 個是 0」）。

### 組合

| 組合 | 狀態 | 輸入 | 輸出 |
|---|---|---|---|
| 串接 $M_2 \circ M_1$ | $S_1 \times S_2$ | $I_1$ | $O_2$ |
| 並聯 $M_1 \parallel M_2$ | $S_1 \times S_2$ | 共同的 $I$ | $O_1 \times O_2$ |
| 回授 | — | 輸出接回輸入 | 解唯一才良定義 |

### 限制

- 計算能力最弱（平衡括號就需要無限狀態；Turing 機在頂端）。
- 難擴展、脆弱、無最佳性、無法處理不確定性 → 下一集 MDP。

### 實作

- 類別 ＋ 狀態變數 ＋ 固定頻率迴圈（PX4 `commander.cpp`、作業 `navigator.py`）。
- SMACH：狀態（建構子宣告結果、execute 回傳結果）＋ 容器（加狀態、指定「結果 → 下個狀態」）；`smach_viewer` 即時視覺化。
- 期末專題：加**失效保護**狀態（重設定位、倒退）。
