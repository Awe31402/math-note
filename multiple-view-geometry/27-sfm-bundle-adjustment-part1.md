## 1. 問題：從一堆照片重建 3D

[▶ 02:13](https://youtu.be/MUadR35FFqk?t=133)

給一組照片 $I_1,\dots,I_N$：

1. 求拍攝它們的**相機運動**：在世界座標系 $F_W$ 下的投影矩陣 $P_1,\dots,P_N$。用前幾講的**相對位姿估計**（$F$、$E$）和**絕對位姿估計**（PnP）。
2. 有了相機，從影像對應點**三角化**出 3D 結構。

- 只要重建**對應點**的 3D 位置 → **structure from motion（SfM）**：先求相機運動（motion），再求結構（structure）。
- 每個**像素**都要 3D 位置 → **稠密立體（dense stereo）**，下一講。

## 2. 流程三部分

[▶ 05:01](https://youtu.be/MUadR35FFqk?t=301)

| 步驟 | 做什麼 | 輸出 |
|---|---|---|
| **1. 資料關聯（data association）** | 照片沒有順序。任兩張 $I_i,I_j$：找對應點，用 RANSAC 估 $F$／$E$；內點數超過門檻 → 兩張看到同一個場景 | **場景圖（scene graph）**：節點 = 照片，邊 = 有重疊視野 |
| **2. SfM** | 前兩張用 $F$／$E$ 分解得相機（相對位姿）→ 三角化 → 之後每加一張用 2D–3D 對應做 PnP（絕對位姿）→ 再三角化新點；最後 **bundle adjustment** 最佳化所有相機和 3D 點，讓重投影誤差最小 | **稀疏 3D 模型** + 所有相機位姿 |
| **3. 稠密建模** | 已知相機位姿，求每張圖每個像素的深度（多視角稠密立體、平面掃描） | **稠密 3D 模型** |

- 「稀疏」：只用抽出來的特徵點三角化，不是每個像素。
- 所有相機和 3D 點都在**同一個**世界座標系 $F_W$ 裡。

**例子** [▶ 14:28](https://youtu.be/MUadR35FFqk?t=868)【口頭】：

- 開源 SfM 系統 **COLMAP**：輸入照片，輸出相機位姿（紅點）和彩色點雲。
- 舊金山市政廳（講者參與的 CVPR 2016 論文）。
- Agarwal、Snavely 等人重建羅馬競技場。

⚠️ 逐字稿缺字：Whisper 把 COLMAP 寫成 “COMAT”、Sameer Agarwal 寫成 “Samir Aragao”。

## 3. 資料關聯：建場景圖

[▶ 15:51](https://youtu.be/MUadR35FFqk?t=951)

- 目標：從一堆無序照片得到場景圖。
- **連通分量（connected component）**：彼此有重疊視野、連在一起的一群照片。
- 用雙視角幾何來判斷兩張圖要不要連一條邊。

### 3.1 特徵點與描述子

[▶ 17:33](https://youtu.be/MUadR35FFqk?t=1053)

三步驟的第一、二步：

1. **抽特徵點和描述子**：例如 SIFT、ORB（講者不細講，給參考文獻）。
   - 特徵點：影像上一個位置（像素）。
   - 描述子：那個位置的「簽名／指紋」，SIFT 是 **128 維**向量。
2. **配對**：比較兩張圖的描述子（例如內積），相似的就配成一對 → **初步對應（putative correspondences）**。
   - 只靠**外觀**，沒用任何幾何資訊 → 一定會有**錯誤對應**。

⚠️ 逐字稿缺字：Whisper 把 ORB 寫成 “op”、putative 寫成 “punitive”。

### 3.2 幾何驗證

[▶ 20:45](https://youtu.be/MUadR35FFqk?t=1245)

3. **幾何驗證（geometric verification）**：
   - 對初步對應跑 **RANSAC** 估 $F$（未校正）或 $E$（已校正）（第 09、18 集）。
   - 分出內點（綠線）和錯誤對應（紅線）。
   - **內點數超過門檻** → 有很多正確對應支持這個 $F$／$E$ → 兩張圖看到同一個場景 → 在場景圖上加一條邊。

- 意義：在外觀配對之外，用**幾何**再篩一次。

### 3.3 窮舉太慢

[▶ 24:06](https://youtu.be/MUadR35FFqk?t=1446)

- 窮舉所有照片對做幾何驗證，$N$ 大時算不完。
- **一張查詢影像**的複雜度：$O(NK^2)$——和 $N$ 張比，每對要比 $K\times K$ 個特徵。

**例子** [▶ 25:39](https://youtu.be/MUadR35FFqk?t=1539)：

- 每張 $K=1000$ 個 SIFT 特徵；資料庫 1 億張照片；每次特徵比較 0.1 ms。
- 一張查詢影像要 **317 年**。

> 以下**不是逐字稿內容**，是驗算：$N=10^8$，比較次數 $NK^2=10^8\times10^6=10^{14}$，乘 $10^{-4}$ 秒 $=10^{10}$ 秒 $\approx317$ 年。講者口述時把 $N$ 說成「100,000」、比較次數說成「100,000 million」，數字前後不一；317 年對應的是 $N=10^8$。

## 4. 詞袋影像檢索

[▶ 27:21](https://youtu.be/MUadR35FFqk?t=1641)

**想法**：不要兩兩暴力比特徵（$K^2$），改建一棵**樹**，讓查詢影像的特徵能快速找到資料庫中相似的影像。

### 4.1 用訓練資料建階層 k-means 樹

[▶ 28:01](https://youtu.be/MUadR35FFqk?t=1681)

1. **訓練資料**：任何一組照片都可以（例如網路上隨便抓的）。
2. 每張抽特徵點和描述子，全部收集起來。
   - 為了畫圖用 2 維示意；實際 SIFT 在 128 維空間。
3. **階層 k-means（hierarchical k-means）**：
   - 根節點：所有描述子的重心。
   - 第二層：對全部描述子做 k-means（例如 $k=3$），得到 3 個群的中心。
   - 第三層：每個群再各自做 k-means 分成 3 個……
   - 最底層的節點叫**葉節點**——每個葉節點代表描述子空間中的一塊區域，叫一個**視覺單字（visual word）**。
4. 建好樹之後**訓練資料就丟掉**；樹本身代表「所有可能的描述子長什麼樣」。

### 4.2 建倒排索引

[▶ 34:46](https://youtu.be/MUadR35FFqk?t=2086)

對**資料庫**（要被查詢的那些照片）的每一張：

1. 抽特徵點和描述子。
2. 每個描述子**沿樹往下走**：每一層選最近的子節點，其他分支直接忽略，直到葉節點。
3. 在葉節點記下：**影像 ID** 和**次數**（這張圖有幾個特徵落在這個葉節點）。

- 例 [▶ 38:45](https://youtu.be/MUadR35FFqk?t=2325)：影像 1 有兩個特徵（可能都來自眼睛，長得像）落在同一個葉節點 → 記「ID 1，次數 2」。
- 全部做完，每個葉節點有一串「(影像 ID, 次數)」——這就是**倒排索引（inverted file index）**。

### 4.3 查詢

[▶ 41:41](https://youtu.be/MUadR35FFqk?t=2501)

1. 查詢影像抽特徵點。
2. 每個特徵沿樹走到最近的葉節點。
3. 讀出那個葉節點的影像 ID 清單，**每個 ID 的計數器加一**。
4. 所有特徵都查完，**計數最高**的資料庫影像就是外觀最相似的。

**正規化** [▶ 46:54](https://youtu.be/MUadR35FFqk?t=2814)：某張資料庫影像在某個葉節點的次數是 2（這個特徵在那張圖裡很常見），就只加 $1/2$。理由：太常出現的特徵不夠**有辨別力**，不該重複算。

> 以下**不是逐字稿內容**，是補充：實務上常用的是 TF-IDF 加權（一個視覺單字在越多張影像出現，權重越低），講者講的「除以次數」是其中一種簡化。

### 4.4 快多少

[▶ 48:22](https://youtu.be/MUadR35FFqk?t=2902)

同樣 1 億張資料庫、每張 1000 個特徵、每次比較 0.1 ms：

- 樹：分支 $b=10$、深度 $L=6$ → $10^6$ = **100 萬個視覺單字**。
- 一張查詢影像的比較次數：$K\times b\times L=1000\times10\times6=60{,}000$。
  - 每個特徵走 $L$ 層，每層和 $b$ 個子節點比。
- 時間：$60{,}000\times0.1\text{ ms}=$ **6 秒**（對比 317 年）。

**複雜度** [▶ 50:49](https://youtu.be/MUadR35FFqk?t=3049)：一張查詢從 $O(NK^2)$ 降到 $O(KbL)$——和資料庫大小 $N$ 無關（不算讀清單）。

### 4.5 和幾何驗證合用

[▶ 51:13](https://youtu.be/MUadR35FFqk?t=3073)

1. 先用影像檢索**刪掉不可能的邊**：分數很低的影像對直接不連 → 得到候選場景圖。
2. 影像檢索還是只看外觀 → 對候選邊再做**幾何驗證**（RANSAC 數內點），超過門檻才留下。

## 5. 一頁速查表

### 大規模 3D 重建

1. 資料關聯 → 場景圖（節點 = 照片，邊 = RANSAC 內點夠多）。
2. SfM → 相機位姿 + 稀疏點雲（相對位姿 → 三角化 → PnP 加新相機 → 三角化 → BA）。
3. 稠密立體 → 稠密模型（Lecture 11）。

### 資料關聯

| 步驟 | 內容 |
|---|---|
| 特徵 | SIFT（128 維）、ORB；外觀配對 → 初步對應 |
| 幾何驗證 | RANSAC 估 $F$／$E$；內點數 > 門檻 → 加邊 |
| 窮舉 | 每張查詢 $O(NK^2)$；$N=10^8$、$K=1000$ → 317 年 |

### 詞袋影像檢索

| 步驟 | 內容 |
|---|---|
| 建樹 | 訓練描述子做階層 k-means（$b$ 分支、$L$ 層）；葉節點 = 視覺單字 |
| 倒排索引 | 資料庫每個特徵走到葉節點，記 (影像 ID, 次數) |
| 查詢 | 每個特徵走到葉節點，清單中每個 ID 計數加 1（除以次數正規化）；最高分 = 最相似 |
| 複雜度 | $O(KbL)$；$b=10$、$L=6$、$K=1000$ → 6 萬次比較 → 6 秒 |

## 附：本集一句話總結

> **大規模 3D 重建分三步：先做資料關聯（特徵配對 + RANSAC 幾何驗證，內點夠多就在場景圖上連邊），再做 SfM（相對位姿、三角化、PnP 加相機、bundle adjustment）得到相機和稀疏點雲，最後做稠密立體；窮舉配對一張要 317 年，所以先用詞袋影像檢索——階層 k-means 樹加倒排索引，把一張查詢降到 $O(KbL)$、約 6 秒——篩出候選邊，再做幾何驗證。**
