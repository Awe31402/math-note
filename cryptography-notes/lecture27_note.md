## 1. 用公鑰建立金鑰：兩種方法

`[00:03]` 目標：在**不安全通道**上分配金鑰，不能親手送。

**方法一：金鑰協議** —— 例如 **Diffie-Hellman**（今天的主角）。

**方法二：金鑰傳送**（`[00:05]`）—— 用**公鑰加密**（RSA 或 Elgamal）：

```
   Alice                              Bob
                                      產生 (k_pr, k_pub)
          ←────── k_pub ──────
   隨機選 k（例如 128 bit）
   y = e_{k_pub}(k)
          ─────── y ─────────→
                                      k = d_{k_pr}(y)
   之後雙方用 k 做 AES 加解密
```

- Bob 是**唯一**能解密的人 —— 這就是公鑰密碼的意義。
- 【口頭】「某種程度上**比 Diffie-Hellman 簡單**，也許更自然。」

【口頭】`[00:07]` 例：**SSL / TLS**（瀏覽器的**小鎖頭**）。你和 Amazon.de 的伺服器協商協定時，**兩種都允許**：Diffie-Hellman 和 RSA。「兩者都**極廣泛使用**，不能說哪個比較重要。」

【口頭】`[00:06]` 今天要講的問題，**所有公鑰方案都有**，不只金鑰協議，**數位簽章也有**。只是用 Diffie-Hellman 當例子。

## 2. 中間人攻擊

`[00:09]` **Man-in-the-middle attack**，通常寫成帶連字號（Bindestrich）的形式，縮寫 **MIM**（教授口頭唸「MITM」/「mittem」）。

【口頭】`[00:10]`「順便說：講**多重加密**（例如雙重 DES）時，我們講過 **meet-in-the-middle attack**，聽起來很像。**完全不同的電影，跟今天毫無關係。**」

【口頭】`[00:11]`「這**超級重要**。大概有 8 到 10 個人在**教學評鑑**上寫：『Paar 教授提醒我們什麼時候要醒著，很好。』**就是現在。**」

### 2.1 先看正常的 Diffie-Hellman

`[00:12]`（教授在中間留了空間，「因為等一下要把 Oscar 放在中間」。）

```
   Alice                                  Bob
   a = k_pr,A                             b = k_pr,B
   A = α^a                                B = α^b
          ─────────── A ──────────→
          ←────────── B ───────────
   k_AB = B^a                             k_AB = A^b
```

【口頭】`[00:13]`「今天我**不寫 mod p**，黑板上的資訊已經夠多，不想讓你們更混亂。當然**所有運算都是 mod p**，p 是大質數，等等等等。」

【口頭】`[00:14]`
- 這個方案**不是可證明安全**，但**計算上安全** → 實務上安全。
- 特別是數字夠大：$p$ 是 **2048 bit** 而且仔細挑選，還要注意一些數論上的小細節，「但那也**不難**」。
- 「**據我們所知，這是安全的。**」

### 2.2 被動 vs 主動攻擊者

`[00:14]`【課堂討論】被動攻擊者能做什麼？→ **只能聽**（竊聽 eavesdropping，德文 lauschen）。

只要 Oscar **只能聽**，上面的協定就完全沒問題。

**主動攻擊者**呢？（`[00:15]`）
- 【口頭】「我們**絕對要**考慮主動攻擊。透過網路通訊，我們**對通道的控制非常少**。我寄 email 給比利時的人，**完全不知道訊息被怎麼路由**。」
- 「假設攻擊者**只能聽、不能改我的 IP 封包**，那是**非常天真的**。」
- 「在**大部分實務情況**下，都要考慮主動攻擊者。」

### 2.3 攻擊步驟

`[00:16]` Oscar 站在**中間**，攔截並**替換**雙方的公鑰。

**步驟 1：Oscar 造自己的公鑰**
- 選私鑰 $o_1$（小寫 o，「Kleines o」）算出 $\alpha^{o_1}$。
- 【口頭】`[00:17]`「Oscar 很**狡猾**。他**不會**把它叫做『Oscar 的公鑰』，他說：**『嘿，我是 Alice 的金鑰。』**」→ 記作 $\tilde{A}$（「A tilde，A 蛇」）。
- 對稱地在另一邊也做一次：選**另一個**私鑰 $o_2$，造出 $\tilde{B}$。

```
   Alice                       Oscar                         Bob
   a,  A = α^a                                               b,  B = α^b
          ──── A ────→   攔截
                         Ã = α^{o₁}    ──────── Ã ───────→
                         B̃ = α^{o₂}    ←─────── B ────────   攔截
          ←─── B̃ ────
   k_AO = B̃^a                k_AO = A^{o₂}
                              k_BO = B^{o₁}                  k_BO = Ã^b
```

**步驟 2：Alice 算出的金鑰**（`[00:18]`）
- 【口頭】「**很不愉快的事**發生了。Alice **不再算 $k_{AB}$** 了。」
- 問題是 **Alice 看不到那個 tilde**：「$B$ 只是 **2048 個無辜的 bit**，**聞起來也沒有 Bob 的香水味**。」Alice 沒辦法知道它是不是真的來自 Bob，所以假設它是 Bob 的。
- 她照協定做：

$$\tilde{B}^{a} = (\alpha^{o_2})^a = \alpha^{o_2 a}$$

- 【口頭】`[00:19]`「她**確實**算出了一個 Diffie-Hellman 金鑰。**數學上這仍然是 Diffie-Hellman**，只是有點可疑。」
- 【課堂討論】這把金鑰該叫什麼比較好？→ **Alice 和 Oscar 之間的金鑰**：$k_{AO}$。
- Alice 很天真，以為那是 $k_{AB}$。

**步驟 3：Oscar 也算出同一把**（`[00:20]`）

$$A^{o_2} = (\alpha^a)^{o_2} = \alpha^{a\,o_2} = k_{AO}$$

【口頭】「Alice 和 Oscar 做了一次**很好的私人 Diffie-Hellman 金鑰交換**，沒什麼不對 —— **只是 Oscar 知道他在跟 Alice 講話，Alice 不知道她在跟 Oscar 講話。**」

⚠️ `[00:21]` 教授一開始寫成 $A^{o_1}$，經學生提醒改正：「對、對、對，**因為這裡是 $o_2$**。很好，謝謝。」

**步驟 4：Bob 那邊同理**（`[00:21]`）

$$\text{Bob：}\tilde{A}^{b} = \alpha^{o_1 b} = k_{BO}, \qquad \text{Oscar：}B^{o_1} = \alpha^{b\,o_1} = k_{BO}$$

**結果**（`[00:23]`）：

> **Oscar 跟 Alice 有一把金鑰 $k_{AO}$，跟 Bob 有一把 $k_{BO}$。但 Alice 和 Bob 仍以為他們在跟彼此講話。**

【課本補充】
- 實際上是**同時跑了兩次 Diffie-Hellman**：Alice–Oscar 一次，Bob–Oscar 一次。
- 課本裡 Oscar 用**同一個**私鑰 $o$，所以 $\tilde{A}$ 和 $\tilde{B}$ 其實是**同一個值**，只是取不同名字，強調 Alice 和 Bob 以為收到的是對方的公鑰。課堂上教授用兩個不同私鑰 $o_1, o_2$，兩種都可以。

### 2.4 攻擊之後 Oscar 能做什麼

`[00:24]`【口頭】後果：「**可怕**。Oscar 現在**完全控制**了 Alice 和 Bob 的通訊。」

`[00:25]`「『完全控制』聽起來有點模糊，我們看具體的意思。**目前只做了金鑰交換，還沒造成真正的損害。**真正的損害從他們開始用會期金鑰時開始。」

`[00:26]` Alice 用 **AES-256** 加密秘密 email：「**超級安全，NSA 認證，破不了**，等等等等。」

$$y = \text{AES}_{k_{AO}}(x)$$

（Alice 以為她用的是 $k_{AB}$。）

【口頭】`[00:27]` Oscar 得**很警覺（aufmerksam）**：如果直接把 $y$ 轉給 Bob，Bob 用 $k_{BO}$ 解密會得到亂碼，就會發現有問題。

**Oscar 先解密**（`[00:28]`）：$x = \text{AES}^{-1}_{k_{AO}}(y)$ → **他能讀**，這是第一個問題。

然後他有三種選擇：

| 選項 | 做法 | 說明 |
|---|---|---|
| **1. 攔下** | 不轉送 | 【口頭】`[00:29]`「想像**軍事情境**：某個命令**永遠沒送到**。Bob 也許根本沒在等訊息。」【口頭】`[00:31]`「這其實不難，**連中間人都不用做**，不轉送就好。」 |
| **2. 重新加密轉送** | $y' = \text{AES}_{k_{BO}}(x)$，送給 Bob | 【課堂討論】要怎樣轉送才不會被發現？→ 學生答（德文）：「**要再用這把金鑰加密一次。**」<br>【口頭】`[00:30]`「這裡**不能叫 $y$**，因為兩個密文是**不同的 bit 圖樣**，叫 $y'$。」<br>Bob 用 $k_{BO}$ 解密得到 $x$，**一切看起來正常** |
| **3. 竄改** | 改掉 $x$ 再加密 | 【口頭】`[00:31]`「這是我**特別喜歡**的，因為它**更顯示這有多糟**。」<br>Bob 是**銀行**，Alice 做網路銀行：「請轉 **10 歐元**到 Oscar 的帳戶。」Oscar 改成 **10,000 歐元**，重新加密，銀行收到**假的轉帳（Überweisung）** |

```
   Alice                     Oscar                              Bob
   y = AES_{k_AO}(x)
          ──── y ────→   x = AES⁻¹_{k_AO}(y)    ← 能讀
                         （可以改 x）
                         y' = AES_{k_BO}(x)
                                    ──── y' ────→   x = AES⁻¹_{k_BO}(y')
```

【口頭】`[00:32]`「從攻擊的角度看，**這很漂亮**。」

### 2.5 為什麼對所有公鑰方案都有效

`[00:33]`【口頭】「現在我要**用紅筆**寫一句話。**就算你從這個資安學士學程退學了**，也請記住：」

> 🔴 **中間人攻擊對所有公鑰方案都有效。**

【口頭】`[00:34]`「用那種**有毒墨水的黃色螢光筆**標起來，或者**掛在床頭**。這是**人生教訓**。會有一題作業。」

#### 為什麼這是**通用**攻擊？

`[00:35]`【口頭】「如果你聽得很仔細，你可能會想：這是個很酷的攻擊，但**看起來是針對 Diffie-Hellman 的，不是普遍問題**。所以你應該**還不理解**為什麼紅字這麼寫。」

**根本原因**（`[00:36]`）：
- 【課堂討論】更根本地，到底發生了什麼？→ 公鑰**沒有被鑑別（not authenticated）**。
- 【口頭】`[00:37]` 回想數位簽章那講的**安全服務插曲**：大家記得**買福斯汽車**和**不可否認性**的例子；另一個安全服務**我們沒那麼認真看待**的，就是**訊息鑑別**。**這裡就違反了鑑別。**

**實務上公鑰長這樣**：
- 【口頭】「只送 2048 個 bit、沒有任何附加資訊**很蠢**。至少要說明『**接下來這 2048 bit 是 Alice 的公鑰**』。」
- 所以實務上一定會附一個**標頭（header）**，叫 **ID（Identität）**：email 地址、名字、員工編號（Mitarbeiternummer）、學號（Immatrikulationsnummer）……

$$k_A = (k_{pub,A},\; ID_A)$$

**Oscar 做的事**（`[00:38]`）：
- 他**不笨**，不會寫成 $(k_{pub,O}, ID_O)$，那就全露餡了。
- 他寫成：

$$(k_{pub,O},\; ID_A)$$

- 【口頭】`[00:39]`「**他在說謊、他在作弊。**這違反了**鑑別**，也違反了**訊息完整性**，因為你在亂動訊息。」

**為什麼對所有公鑰方案都成立**（`[00:40]`）：
- 只要公鑰從通道傳過來、說「我是 Alice 的公鑰」，Oscar 就**換成自己的公鑰，但保留 ID 不變**。**這個原理永遠成立。**
- **數位簽章也一樣**：【課堂討論】數位簽章裡公鑰用來做什麼？（Wofür braucht man den?）→ **驗證**。Oscar 就把**驗證金鑰**換掉。
- 【口頭】`[00:42]`「過去三個月我們學了很多公鑰方案。給你們**任何一個**、給 10 分鐘，**這間教室每個人**都能想出類似的攻擊：**Elgamal 加密、RSA 加密、橢圓曲線 Diffie-Hellman**，甚至新的**無線協定**（可能有兩頁的來回交換）。」

【課本補充】
- 中間人攻擊**不要跟** meet-in-the-middle 搞混（課本 §5.3.1）。
- 課本的關鍵結論：

> **雖然公鑰方案不需要安全通道，但它們需要「經過鑑別的通道（authenticated channel）」來分配公鑰。**

| 通道 | 要求 | 誰需要 |
|---|---|---|
| **安全通道** | 保密 + 鑑別 | 對稱金鑰 |
| **經過鑑別的通道** | 只要鑑別（可以被看到，但不能被改） | 公鑰 |

## 3. 憑證

`[00:43]` 問題是：公鑰**沒被鑑別**。它說「我來自 Alice」，但其實不是。

【口頭】「Paar 教授大概 **5 週前**介紹了數位簽章，一個**提供鑑別**的密碼學工具。」

### 3.1 用什麼來鑑別公鑰：簽章還是 MAC？

`[00:44]`【課堂討論】有哪些密碼學工具提供鑑別？
1. **數位簽章**（之前已經有學生提議：「為什麼不簽這則訊息？」）
2. 【課堂討論】另一個？→ **MAC**。「很好。」

【課堂討論】`[00:45]` 為什麼用 MAC **大概是個蠢主意**？MAC 基於什麼？→ **對稱**。
- 【口頭】「MAC 很好用，但它是**對稱密碼**。用 MAC 等於**回到老路**：用對稱密碼保護非對稱方案，那些金鑰交換的問題全回來了。**能用，但會重新引入我們想擺脫的所有問題。**」
- → **用數位簽章**。

#### 看起來有個邏輯漏洞

`[00:45]`【口頭】「我先**洩漏**一件通常 15 分鐘後才講的事，**看起來像論證鏈的缺陷（Fehler in der Argumentationskette）**：」
- 【課堂討論】`[00:46]` 用數位簽章修補這個攻擊，問題在哪？→ 學生答：**數位簽章也是公鑰**！
- 【口頭】「看紅框：我說這攻擊**對所有公鑰方案**都有效，現在我卻提議**用另一個公鑰方案去修補公鑰方案**？看起來有矛盾。」
- 「**某種程度上有道理，但其實不完全是**，課堂最後你會看到為什麼。**真正專心的人應該看到這個矛盾**，而實務上**可以化解**。」（→ 3.5 節）

### 3.2 憑證機構（CA）與憑證

`[00:47]` 需要一個**可信任機構**。
- 對稱的情況，可信任機構的例子是 **KDC**。
- 「不知道為什麼，這裡用**不同的名字**」：**憑證機構（Certification Authority, CA）**。
- 【口頭】`[00:48]`「這是**很常見**的詞。我準備講義時 Google 了一下，大概**一百萬筆**結果。」

【口頭】`[00:48]`「這是我喜歡這一講的原因之一：講 CA、**根憑證（root certificate）**、**信任鏈（chain of trust）**的文獻，有 **380 頁的書**，但**全都可以歸結到這件很簡單的事**。」

#### 憑證到底是什麼

【口頭】`[00:49]`
> **「憑證就只是一把公鑰。」**
> 「瀏覽器跳出『**憑證無效**』的警告，真正的意思是：**這不是一把我們能檢查、確定有效的公鑰**。」
> 「從現在起，Alice 不用她**赤裸的公鑰**，而是用**憑證**。但請把憑證想成**一把公鑰**。」

$$\boxed{\text{Cert}_A = \Big[\,(k_{pub,A},\; ID_A),\;\; \text{sig}_{k_{pr,CA}}(k_{pub,A},\; ID_A)\,\Big]}$$

- 前半：就是剛才的 $(k_{pub,A}, ID_A)$。
- 後半：**用 CA 的私鑰**對它簽章。
- 【課堂討論】`[00:50]` 誰能算這個簽章？→ **CA**，用 $k_{pr,CA}$。

【課本補充】憑證**把使用者的身分和他的公鑰綁在一起**。如果 Oscar 想把 $k_{pub,A}$ 換成 $k_{pub,O}$，會被偵測到（簽章保護了被簽的訊息不被竄改）。

#### 怎麼產生憑證

`[00:51]`（課本 p.345–346，「當然是簡化過的，但實務上大致就這樣」）

```
   Alice                                    CA
   產生 k_pr,A, k_pub,A
          ── RQST(k_pub,A, ID_A) ──→
                                            驗證 ID_A
                                            s_A = sig_{k_pr,CA}(k_pub,A, ID_A)
                                            Cert_A = [(k_pub,A, ID_A), s_A]
          ←──────── Cert_A ─────────
```

【口頭】`[00:52]`
- CA 有時是**商業公司**，有時是**政府**。
- CA 首先要**驗證身分**：「這是**不屬於密碼學**的事之一，而且**不容易**。」
- 「誰用網路銀行？他們有同樣的問題：開新帳戶時，怎麼確定在跟對的人講話？**特別是網路上**，這不容易。理想上你要**親自出現**，出示**身分證、護照或出生證明**。**這些我們在這門課不討論。**」

【課本補充】
- 第一次傳送**很關鍵**：$(k_{pub,A}, ID_A)$ 必須經過**鑑別的通道**送出，否則 Oscar 可以**冒 Alice 的名**申請憑證。
- 另一種做法：**CA 幫使用者產生金鑰對**：

```
   Alice                                    CA
          ──────── RQST(ID_A) ──────→
                                            驗證 ID_A
                                            產生 k_pr,A, k_pub,A
                                            s_A = sig_{k_pr,CA}(k_pub,A, ID_A)
                                            Cert_A = [(k_pub,A, ID_A), s_A]
          ←───── Cert_A, k_pr,A ─────
```

  第二次傳送裡有**私鑰**，所以不只要鑑別、還要**安全通道**。實務上可能是**郵寄光碟**。
- 註：MAC 原則上也能鑑別公鑰，但 MAC 金鑰又需要安全通道分配。

### 3.3 帶憑證的 Diffie-Hellman

`[00:54]`

```
   Alice                                       Bob
   a = k_pr,A,  A = α^a                        b = k_pr,B,  B = α^b
   Cert_A = [(A, ID_A), s_A]                   Cert_B = [(B, ID_B), s_B]
          ──────────── Cert_A ────────────→
          ←─────────── Cert_B ─────────────
   驗證憑證：                                   驗證憑證：
   ver_{k_pub,CA}(Cert_B)                      ver_{k_pub,CA}(Cert_A)
   算會期金鑰：                                 算會期金鑰：
   k_AB = B^a                                  k_AB = A^b
```

【課堂討論】`[00:56]` Bob 收到 Alice 的憑證，做 Diffie-Hellman 之前**第一件事**是什麼？「**一個動詞**，我在等。」「憑證就只是**公鑰加上數位簽章**，收到數位簽章要做什麼？」→ **驗證**。

【口頭】`[00:57]`「這**只是數位簽章的一個應用**。驗證得到**真或假**。如果是假，**就有問題，也許 Oscar 在中間**。」

【課堂討論】驗證需要金鑰，公鑰還是私鑰？→ **公鑰**，「這是簡單的部分」。
**難的部分：誰的公鑰？** → **CA 的**。「很好。」因為簽章是 CA 算的。

`[00:58]` 如果驗證通過，Bob **確定**這真的是 Alice 的金鑰 → 計算 $k_{AB} = A^b = \alpha^{ab}$。
Alice 也一樣：用 **CA 的公鑰**驗證 $\text{Cert}_B$，再算 $k_{AB} = B^a = \alpha^{ab}$。

**所以 Alice 和 Bob 都要有 CA 的公鑰 $k_{pub,CA}$。**

### 3.4 Oscar 還能攻擊嗎？

`[00:59]`【口頭】「最後 5 分鐘我要講兩件事。**很重要。**平常最後幾分鐘是補充資訊，想睡或要趕下一堂課沒關係，但**今天最後 5 分鐘不是最重要的，但相當重要**。」

**Oscar 再試一次同樣的把戲**（`[01:00]`）：把 Alice 的憑證裡的 $A$ 換成 $\tilde{A}$。
- 【課堂討論】在哪裡會失敗？→ **驗證會失敗**。CA 簽的是 Alice 的公鑰，不是 $\tilde{A}$。

**那 Oscar 自己做一張假憑證？**（`[01:01]`）
- 他想算 $\text{sig}_{k_{pr,CA}}(\tilde{A}, ID_A)$。
- 【口頭】「他**先買我的書，看影片**（影片免費），所以他知道數位簽章怎麼運作，用 RSA-2048，**知道需要私鑰** —— 但他需要的是 **CA 的私鑰**，希望他沒有。」

#### 【口頭】根金鑰的保護

`[01:03]`【口頭】
- 「你聽過**根憑證**或**根金鑰（root key）**嗎？」
- 如果攻擊者拿到像 **VeriSign**（靠賣憑證賺錢的大公司之一）的 CA 金鑰，或 **Microsoft 的根金鑰**：「根金鑰也就只是一把 RSA、橢圓曲線或離散對數的金鑰。**拿到了，就天下大亂（hell is loose）**，因為你可以開始**發假憑證**。**後果極其嚴重。**」
- `[01:04]`「看人們怎麼保護 CA 金鑰**很有趣**。**我不是開玩笑，聽起來像天方夜譚**：瑞士跟大多數國家不一樣的地方是有很多**大山**。**冷戰時期**他們在山裡挖了**核子掩體**。現在有人**出租阿爾卑斯山裡的核子掩體**，放超級安全的伺服器，CA 就在裡面，有大量**實體安全**。」
- 「如果能拿到，**整個系統就在全網際網路範圍崩潰**。」

#### 【Q&A】Oscar 用自己的假 CA 金鑰呢？

`[01:02]`【Q&A】學生問：Oscar 不能用**自己假造的 CA 金鑰**簽，像 $k_{pr,CA/O}$ 之類？
- 教授：「好、好、好。對。**這是第二點，非常非常好。**60 秒後回來講。」
- `[01:05]`「同學**搶先了一步**，很聰明的想法。」
  - Oscar 隨便拿一把簽章金鑰（例如 RSA）簽假憑證。單這樣**會在驗證時失敗**（因為 Bob 用真的 CA 公鑰驗證）。
  - **但**：CA 也只是一個**公鑰來源**，本質上**也是個公鑰演算法**。那就**用紅框那句話**：**對 CA 公鑰的傳送做中間人攻擊！**
  - `[01:06]`「如果 Oscar 在 CA 公鑰送給 Bob 時做中間人攻擊，把 CA 公鑰換成自己的，他就能發假憑證，**整件事就崩潰了**。」
  - 「這就是我 20–30 分鐘前開始講憑證時說的**缺失環節**：我用公鑰保護公鑰，但有個**永遠有效的通用攻擊**。**你注意得非常非常好。**」

### 3.5 CA 的公鑰怎麼送？

`[01:06]`【口頭】「**這是真實世界的問題，跟這個協定無關，走出黑板、走出這門課。**實務上，人類（die Menschheit）能做什麼讓這個攻擊變得很難？」

【Q&A】`[01:07]` 學生提議：CA 金鑰是**靜態的**，可以事先**同步/核對**。
- 教授：「對，就是**檢查**它。」
- 【口頭】例：**紐約時報**在 1990 年代的**週日版**（Sonntagsausgabe）**印了一大把公鑰**。你可以**手動核對十六進位字元**，看你拿到的是原版還是假的。「不知道現在還有沒有這樣做。」

**更好的解法**（`[01:08]`）：
- 【課堂討論】CA 公鑰要交換幾次？→ 理想上**只要一次**。
- 【口頭】「有人用 **Microsoft Windows** 嗎？如果你有**正版** Windows 和瀏覽器（教授說 Thunderbird，⚠️ 那其實是郵件程式），**瀏覽器裡已經預先安裝了這些金鑰**。」
- 「歸結起來：你當然需要一條**經過鑑別的連結**，確保傳送正確，但**只要一次，在設定時**。」
- `[01:09]`「除非有人動了手腳，在你安裝用的**光碟**裡放了別的金鑰 —— 只要你買的是**沒被竄改的原版光碟**，你就有那把公鑰。**有了這一把，基本上就搞定了。**」

> **憑證原則上仍然會被針對 CA 公鑰的中間人攻擊打到；但只要在設定時小心一次，把真的 CA 公鑰裝好，你就贏了。**

【口頭】「我們大概可以——**我只是半誇張**——再花**一整個學期**，至少**半學期**、7 週，講真實世界的影響。但就停在這裡。」

【課本補充】
- 看起來好像沒賺到什麼，因為又需要一條鑑別通道。**差別是：只在設定時需要一次。**
- 這是**信任的轉移（transfer of trust）**：沒有憑證時，Alice 和 Bob 要**直接**信任彼此的公鑰；有了憑證，他們**只需要信任 CA 的公鑰**。CA 簽了的其他公鑰，他們也能信任 → **信任鏈（chain of trust）**。

## 4. 【課本補充】PKI 的實務問題

課堂沒講，依課本 §13.3.3、§13.4 整理。

**PKI（Public-Key Infrastructure，公鑰基礎建設）**：CA 加上所有必要的支援機制組成的整個系統。實際建置很複雜：要處理使用者身分識別、CA 金鑰的可信分配、**多個 CA**、**撤銷憑證**等。

### 4.1 X.509 憑證

實務憑證欄位很多。**X.509** 是重要標準，用在 **S/MIME、IPsec、SSL/TLS**。主要欄位：

| 欄位 | 內容 |
|---|---|
| **憑證演算法** | 用哪個簽章演算法和參數，例如 RSA + SHA-1、ECDSA + SHA-2 |
| **發行者（Issuer）** | 哪個 CA 發的 |
| **有效期間** | 通常 1–2 年。私鑰可能外洩，限制期限能控制損害；公司也可能不存在了 |
| **主體（Subject）** | 就是 $ID_A$：人名或組織名（公司也能有憑證） |
| **主體公鑰** | 公鑰本身，加上演算法（例如 DH）和參數（例如 $p$、$\alpha$） |
| **簽章** | 對以上所有欄位的簽章 |

注意：每張憑證涉及**兩個**公鑰演算法 —— 被保護的公鑰用的那個，和簽憑證用的那個，**可以完全不同**。例：用 RSA-2048 簽，裡面的公鑰屬於 160 bit 的橢圓曲線方案。

### 4.2 CA 鏈

現實中不只一個 CA：各國政府的官方 CA、50 多家（多半是商業的）網站憑證 CA（瀏覽器預裝它們的公鑰）、企業自己的 CA……

**做法：CA 互相認證。**
例：Alice 的憑證由 CA1 發、Bob 的由 CA2 發。Alice 只有 $k_{pub,CA1}$。

```
   Alice                                   CA2
          ────── RQST(Cert_CA2) ─────→
          ←──────── Cert_CA2 ────────
   ver_{k_pub,CA1}(Cert_CA2)  ⇒  k_pub,CA2 有效
   ver_{k_pub,CA2}(Cert_B)    ⇒  k_pub,B 有效
```

$$\text{Cert}_{CA2} = \big[(k_{pub,CA2}, ID_{CA2}),\; \text{sig}_{k_{pr,CA1}}(k_{pub,CA2}, ID_{CA2})\big]$$

- 這建立了**憑證鏈**：CA1 信任 CA2（簽了它的公鑰）→ Alice 能信任 Bob 的公鑰。叫做**信任的委派**。
- CA 可以**階層式**排列（每層簽下一層），或互相**交叉認證**。

### 4.3 憑證撤銷清單（CRL）

需要撤銷憑證的情況：存憑證的**智慧卡遺失**、某人**離開組織**。
- 解法：公布目前無效憑證的清單 → **CRL（Certificate Revocation List）**，通常用憑證**序號**識別，而且 **CRL 必須由 CA 簽章**。

**問題：怎麼送給使用者？**

| 做法 | 問題 |
|---|---|
| 每次收到憑證就問 CA | CA 參與**每個會期**的建立 —— 這正是 KDC 的主要缺點；憑證本來的承諾是**不需要線上聯絡中央機構** |
| 定期廣播 CRL | 總有一段時間憑證已無效但使用者還不知道。例：每天**凌晨 3 點**送，不誠實的人可能有**將近一整天**能用已撤銷的憑證。改成每小時送 → 網路頻寬負擔很大。**成本與安全的取捨** |
| **Delta CRL** | 只送跟上次相比的變動，讓 CRL 小一點 |

### 4.4 其他

- 實務上的協定大多以 **Diffie-Hellman** 或**金鑰傳送**為基礎，例：**MTI** 協定（1986）、**STS（station-to-station）**、**MQV**（常配橢圓曲線）、**IKE**（IPsec 用：DH 金鑰協議 + 鑑別，鑑別用憑證或預先共享金鑰）。
- 1990 年代後期大家以為**每個網路使用者都需要憑證**，「PKI」成了流行語。結果現在是**伺服器有憑證、多數個人使用者沒有**。這種不對稱可以接受，因為通常是使用者提供信用卡號之類的重要資訊。
- 另一種概念：**信任網（web of trust）**，如果 Alice 信任 Bob，也就信任 Bob 信任的人。例：**PGP、GPG**（email 簽章與加密）。

## 5. 一頁速查表

### 5.1 中間人攻擊（對 DHKE）

| | Alice | Oscar | Bob |
|---|---|---|---|
| 送出/收到 | 送 $A$，收到 $\tilde{B} = \alpha^{o_2}$ | 攔截，換掉 | 送 $B$，收到 $\tilde{A} = \alpha^{o_1}$ |
| 算出的金鑰 | $k_{AO} = \tilde{B}^a$ | $k_{AO} = A^{o_2}$，$k_{BO} = B^{o_1}$ | $k_{BO} = \tilde{A}^b$ |
| 以為 | 跟 Bob 共享 $k_{AB}$ | 知道一切 | 跟 Alice 共享 $k_{AB}$ |

Oscar 之後可以：**讀**、**攔下**、**重新加密轉送**、**竄改**（10 € → 10,000 €）。

### 5.2 核心觀念

| 觀念 | 內容 |
|---|---|
| 🔴 **人生教訓** | **中間人攻擊對所有公鑰方案都有效** |
| 根本原因 | 公鑰**沒被鑑別**：Oscar 送 $(k_{pub,O}, ID_A)$ |
| 公鑰需要 | **經過鑑別的通道**（不必保密） |
| 對策 | **憑證** = 公鑰 + ID + **CA 的簽章** |
| 為什麼不用 MAC | MAC 是對稱的，又回到金鑰分配問題 |
| 驗證憑證用 | **CA 的公鑰** |
| 剩下的漏洞 | 對 **CA 公鑰**做中間人攻擊 |
| 實務解法 | CA 公鑰**只需在設定時傳一次**（預裝在瀏覽器/作業系統） |
| 信任的轉移 | 只需信任 CA 的公鑰 → 信任鏈 |

### 5.3 憑證公式

$$\text{Cert}_A = \big[(k_{pub,A}, ID_A),\; \text{sig}_{k_{pr,CA}}(k_{pub,A}, ID_A)\big]$$

### 5.4 對稱 vs 非對稱金鑰建立

| | 對稱（KDC，第 26 講） | 非對稱（今天） |
|---|---|---|
| 可信任第三方 | **KDC** | **CA** |
| 需要的通道 | **安全通道**（設定時） | **經過鑑別的通道**（設定時，傳 CA 公鑰） |
| 第三方是否要線上參與每個會期 | 是 | 否（除非查 CRL） |
| 主要攻擊 | 單點失效、無 PFS | **中間人攻擊** |

> **公鑰密碼不需要保密的通道，但需要「經過鑑別」的通道：只要公鑰沒被鑑別，Oscar 就能站在中間把雙方的公鑰換成自己的，跟兩邊各建一把金鑰，之後讀、擋、改所有訊息 —— 這對所有公鑰方案都成立；對策是憑證，也就是由大家信任的 CA 對「公鑰 + 身分」做數位簽章，而剩下的 CA 公鑰問題，靠在設定時用一次可信的管道（例如預裝在瀏覽器裡）解決。**
