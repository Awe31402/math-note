## 0. 這堂課要做什麼

上一講（教授的說法）：很高層次地討論雜湊函數的**安全需求**，「我們平常不這樣做，通常直接跳進演算法」。

**回顧**：
- 成功攻擊雜湊函數 = 找到 $x_1, x_2$，使 $h(x_1) = h(x_2)$。
- 例子：「轉 **10 歐元**到 Oscar 的帳戶」vs「轉 **10,000 歐元**」—— 我們簽的是**雜湊值**，兩者雜湊一樣就糟了。
- 結論：密碼學上強的雜湊函數，找碰撞大約要 $2^{n/2}$ 步（$\sqrt{2^n}$）。160 bit 輸出 → 約 $2^{80}$ 步。

今天：

| # | 主題 |
|---|---|
| 1 | **SHA-3 簡介**：歷史、競賽、需求 |
| 2 | **Keccak 高階描述**：海綿結構 |
| 3 | **f 函數**：θ、ρ、π、χ、ι |

【口頭】
- 「今天是課程**非常現代**的部分。SHA-3 是**很新**標準化的演算法，大概**去年**左右，**全新的**。」
- 「這兩學期裡最老的大概是 **DES**，大約 **40 歲**。SHA-3 才**一歲**左右。」
- **SHA** 原本代表 **Secure Hash Algorithm**（安全雜湊演算法）。

## 1. SHA-3 簡介

### 1.1 歷史：MD4 家族的興衰

【口頭】「就像有很多很多區塊密碼被提出，雜湊函數也有**一整個動物園**。區塊密碼大家多半用 3DES 或 AES；雜湊函數也一樣，**絕大多數人用 MD4 家族**的演算法。」

| 演算法 | 年代 | 狀況（依教授所述） |
|---|---|---|
| **MD4** | 1980 年代（「我沒有確切日期」，**待補**） | **被破**（找到碰撞），死了 |
| **MD5** | **1991** | 被廣泛使用，**也被破了** |
| **SHA-1** | **1995**，NIST 提出 | 超廣泛使用，「**地球上幾乎每個瀏覽器**」。**2004** 年提出攻擊原理（理論上被破）；**今年**真的做出碰撞 |
| **SHA-2** | **2001** | ✔ 目前安全。「**打了類固醇的 SHA-1**」、「SHA-1 的**渦輪版**」 |

#### 【口頭】MD5 與 Dobbertin

「**跟你我很近**：MD5 是被 **Dobbertin 教授**破的，他是這裡（波鴻）**第一位密碼學教授**，跟我一起。他是這個攻擊的**主要人物**，我想大約 **1995 年**左右。」
⚠️ 語音辨識在「他 2001 年……」那句不清楚（可能是他來波鴻的年份），**待補**。

#### 【口頭】SHA-1 被真正攻破

- 「這**真的是個震撼**，因為 SHA-1 **理論上被破**了。攻擊原理 **2004** 年提出，但至少在**情報圈以外**，沒人能真的做出來。」
- 「然後**今年稍早**真的做出來了，**很新**，大概**五個月前**。」
- 他們做了什麼？**用 PDF 檔做出碰撞**：「有點像那個 10 歐元 / 10,000 歐元的**蠢例子**」—— 兩個**意思不同**的 PDF 檔，雜湊值一樣，「而且**你可以完全選擇**檔案的內容。**這很戲劇性。**」

#### 【口頭】但沒那麼絕望

- 「幸好事情**沒有看起來那麼糟**（verzweifelt）」：SHA-2 早在 **2001** 年就提出了，比攻擊早好幾年。
- 「但**世界很有惰性**，很慢，人們不喜歡改變，很多系統沒更新，很多瀏覽器還在用 SHA-1 —— **這很糟**。」
- SHA-2 跟 SHA-1 **關係很密切**。雖然 SHA-2 目前看起來完全沒問題，**大家還是有點不安**：「SHA-2 **真的會一直安全**嗎？」
- → 2004 年攻擊公布後，NIST 開始找**另一個雜湊函數**。

⚠️ 教授這裡把 NIST 說成「National Institute of **Science** and Technology」，後面才說對：**National Institute of Standards and Technology**（美國國家標準與技術研究院）。
【口頭】「有點像**德國的 DIN**（德國標準化學會），但在**密碼學**上很活躍。整體來說他們**做得很好**。」

### 1.2 SHA-3 競賽

| 時間 | 事件 |
|---|---|
| **2007 年 11 月** | **公開徵求演算法**（SHA-1 攻擊理論提出約三年後）。「**任何資安系學生**，像你們，都可以坐下來發明自己的雜湊函數送給 NIST，希望它成為**世界標準**。」 |
| **2008 年 10 月** | 截止，收到 **64 個**提案（「這個數字我不完全確定，有幾個好像被排除了，但大概是這樣」） |
| **2010 年 12 月** | 剩下 **5 個**，叫**第三輪演算法**（前兩輪淘汰，原因可能是安全性，也常常是**效率**） |
| **2012 年 10 月 2 日** | 選出 **Keccak** 成為 SHA-3 |

【課堂討論】**AES 競賽**一開始有幾個提案？「**這是我們有時會出的選擇題**。」
- 學生猜 7 → 「不，比 7 多。」學生猜 16 → 「**很接近，是 15**。」
- 【口頭】「我覺得很有趣：**十年前**區塊密碼只有 15 個提案，這顯示這十年來**密碼學社群多了多少人**。」

【口頭】
- 「**有趣的是**：10 月 2 日也是 NIST 在 **2000 年**宣布 **Rijndael** 贏得 AES 的日子，**同一天**。」
- 「也是**我兒子的生日**，所以我記得。」
- 「誰看過電影**《飢餓遊戲》**？……還沒看的，**下週前看完，這是作業**。64 個參賽者**互相殘殺**，一個人贏了。」
- 「**SHA-3 那段既迷人又無聊的歷史**。」

【課本補充】課本（2010 年）寫的狀況：2008 年秋天收到 64 個提案；寫書時還有 33 個留在競賽中；預計 **2012** 年做最後決定；這段期間 **SHA-2** 似乎是最安全的選擇。跟 AES 的選拔過程**很像**。

### 1.3 NIST 的需求：四種輸出長度

- 輸入：**任意長度**（「64 bit 或 64 GB」）。
- 輸出長度 $n$ 是**關鍵**。NIST 要求**四種**：**224、256、384、512 bit**。

【口頭】「這些數字看起來**怪怪的**，特別是 224 和 384。」

【課堂討論】224 bit 輸出，攻擊者要多少步才能找到碰撞？
- 「不是 224，那太大了。」→ **生日悖論**：大約**位元長度的一半** → $2^{112}$。「這是今天的作業。」
- 【課堂討論】哪個演算法的安全等級也是 **112**？→ **3DES**。「**完全正確。**三把金鑰是 3 × 56 = 168 bit，但有 **meet-in-the-middle 攻擊**。」

| SHA-3 輸出 | 抗碰撞強度 | 對應的對稱密碼 |
|---|---|---|
| 224 | $2^{112}$ | **3DES**（還有很多系統在跑） |
| 256 | $2^{128}$ | **AES-128**（「地球上最流行的演算法」） |
| 384 | $2^{192}$ | AES-192（「實務上沒那麼常用」） |
| 512 | $2^{256}$ | **AES-256**（最長的 AES 金鑰） |

> **四種安全等級，剛好對應同樣由 NIST 標準化的常用演算法。**

## 2. Keccak 的高階描述

【口頭】「現在進入 Keccak 的**殘酷細節**。」

**最大特色**：內部結構**非常新、非常創新** —— **跟 MD4、MD5、SHA-1、SHA-2 完全不同**。「**這是 Keccak 被選中的原因之一：它很不一樣。**」

### 2.1 海綿結構

基於**海綿結構（sponge construction）**，德文 **Schwammkonstruktion**（「很美的德文字」）。

| 階段 | 做什麼 | 比喻 |
|---|---|---|
| **吸收（absorbing）** | 讀入輸入 $x_i$ 並處理（eingelesen, verarbeitet） | 打開海綿，**吸水** |
| **擠壓（squeezing，quetschen）** | 產生輸出 | **擠海綿，放出水** |

### 2.2 參數

**狀態寬度 $b$**（狀態 = Zustand）：
- 像**內部匯流排寬度**（Busweite）。【口頭】類比 **AES** 的狀態是 128 bit，演算法內部一直在操作一個 128 bit 的大字。
- $$b = 25 \cdot 2^{\ell}$$
- 可能值：25、50、100、200、400、800、**1600**（每次加倍）。
- ⚠️ 教授說「$\ell$ 可以是 1、2…6」，但列出的值從 25 開始，25 對應 $\ell = 0$，所以應是 $\ell = 0, 1, \ldots, 6$。

【口頭】「**拿紅筆**。」
- Keccak 很通用，能做很多事。**Keccak 和 SHA-3 不完全一樣**。
- **只有 $b = 1600$ 才是 SHA-3**。用 800 之類的也能跑，可能也很安全，但**不屬於 SHA-3 標準**。

**輪數 $n_r$**：
- 【課堂討論】AES 有幾輪？→ **10、12、14**，看金鑰長度。
- $$n_r = 12 + 2\ell$$
- SHA-3：$\ell = 6$ → $n_r = 12 + 12 = \mathbf{24}$。
- 【口頭】「你接下來 40 年當成功的資安專家，**大概只會碰到 24 輪**。你不用再管這個公式，**重要的是紅色的部分**。」

**SHA-3 的參數表**（$b$ 都是 1600）：

| 輸出 $n$ | 區塊大小 $r$（bit rate） | 容量 $c$（capacity） | $r + c$ |
|---|---|---|---|
| 224 | **1152** | 448 | 1600 |
| 256 | **1088** | 512 | 1600 |
| 384 | **832** | 768 | 1600 |
| 512 | **576** | 1024 | 1600 |

- **$r$** = 區塊大小（輸入/輸出區塊）。「像 AES 區塊永遠 128，但這裡**隨輸出長度變**。」「**有點奇怪的數字**。」
- **$c$** = **容量** = $b - r$。
- 【口頭】「（心算）1152 + 448 = 1600，**永遠成立**。」
- ⚠️ 語音辨識把 448 辨識成「488」，依 $1152 + 448 = 1600$ 應為 448。
- 【Q&A】有學生指出教授把 832 寫成 **833**：「**謝謝，抓得好（gut aufgepasst）**，是 832。」

### 2.3 整體方塊圖

【口頭】「**現在是這堂課最重要的部分**。如果你在看 YouTube，**醒來**。」「**把紙轉成橫的**，每平方毫米都會用到。」

```
           ┌────────────────────── Keccak / SHA-3 ──────────────────────┐
   M ──→ [前處理（填充）] ──→ x₀, x₁, …, x_{t-1} ──→ [ 內部 Keccak ] ──→ y₀ (, y₁, y₂, …)
           └────────────────────────────────────────────────────────────┘
```

- 輸入這次叫 **$M$**（message），「因為 $x$ 在演算法別處要用」。
- **前處理**：主要是**填充**，讓輸入變成 $r$ 的倍數（例如 1152 的倍數）。【口頭】「有一些**怪規則**，我們不講，在網路上的講義裡。」「密碼學上**相對不重要**。」（填充規則**待補**。）
- **內部 Keccak（inner Keccak）**：真正的重點。

#### 吸收階段

```
          ┌──── r bits ────┬── c bits ──┐
  0 ───→  │       0        │     0      │   （初始狀態，b = 1600 bit）
          └───────┬────────┴─────┬──────┘
          x₀ ──→ ⊕               │
                  │              │
          ┌───────┴──────────────┴──────┐
          │            f               │
          └───────┬──────────────┬──────┘
          x₁ ──→ ⊕               │
                  │              │
          ┌───────┴──────────────┴──────┐
          │            f               │
          └───────┬──────────────┬──────┘
                  ⋮              ⋮
        x_{t-1} ─→ ⊕             │
          ┌───────┴──────────────┴──────┐
          │            f               │
          └───────┬──────────────┬──────┘
                  │  ← 吸收結束、擠壓開始
                  ↓
           前 r bit → y₀ → 取前 n bit = SHA-3(M)
```

步驟：
1. 狀態 $b$ bit 分成兩部分：**$r$ bit** 和 **$c$ bit**（例如 1152 + 448）。
2. 第一個輸入區塊 $x_0$（$r$ bit）跟狀態的 **$r$ 部分做 XOR**。
3. 送進 **$f$ 函數** —— 「**真正的密碼學發生的地方**，資料被攪亂的地方」。
4. 輸出是**下一個狀態**。「這些只是**暫存器**，裡面沒有數學。」
5. 下一個區塊 $x_1$ 再 XOR 進來，再跑 $f$……一直到最後一塊 $x_{t-1}$（假設共 $t$ 塊）。

⚠️ **教授當場更正**：他一開始說「$f$ 函數要跑 24 次」，接著說：「**對不起，我完全錯了，忽略我剛說的**。**24 輪是在 $f$ 函數裡面**。」每多一個輸入區塊才多跑一次 $f$。

【口頭】
- 1152 bit「大概 100 多、120 byte 左右」（⚠️ 實際是 144 byte）。所以一個大 PDF 檔要做「**一千萬次**」之類的。
- **狀態很大**（1600 bit），比區塊密碼大得多，但跟**公鑰演算法**比（RSA、Diffie-Hellman 標準 2048 bit）**其實也沒那麼大**。
- 「海綿**吸水**，Keccak 函數**吸進 bit 並處理**。」（例：「**10 GB 非法下載的電影**，不知為何你想雜湊它」。）

### 2.4 輸出：截斷，或繼續擠

**擠壓階段**：最常見的情況，吸收完就**幾乎做完了**。
- 拿出來的是狀態的 **$r$ bit**，至少 576、可能 1088 bit。
- 但 SHA-3 要的是 224/256/384/512 → **總是太多 bit**。

【課堂討論】拿到 1088 bit，只要 256 bit，**最簡單、最笨**的方法？→ 學生答：**取前面的 bit**。
- 「對。取**最高位（MSB）**那幾個，**其他丟掉**。」
- 【口頭】「如果這聽起來很怪：這裡做的事**有點像亂數產生器**，做了很多很好的攪亂，產生一大塊代表訊息的隨機 bit（訊息的**指紋**）。太長？**沒問題，取前幾個就好**。」

**繼續擠**（「**不是 SHA-3**，比較少見、比較特殊的 Keccak 用法」）：
- 想要 $y_1, y_2, y_3, \ldots$（例如**一百萬個隨機 bit**）：**再跑 $f$、再跑、再跑……**，每次拿出 $r$ 個**新鮮、密碼學上強的偽隨機 bit**。
- 用途：**偽亂數產生**，甚至當**串流密碼**的**金鑰串流產生器**。
- 【口頭】「瀏覽器呼叫 SHA-3 時，**停在 $y_0$**，取前面的 bit 就好。但如果你**第一份工作**在嵌入式裝置上需要一百萬個隨機 bit，可以用**同一個演算法**一直跑。」
- 【口頭】「**文獻裡這部分常常有點混亂**，我不覺得都解釋得很好。」

## 3. f 函數

【課堂討論】「這像只看 DES 的 Feistel 結構、或 AES 的各層怎麼接。要用 C++ 實作，**還缺什麼關鍵細節**？」→ **$f$ 函數**。

### 3.1 輪與五個步驟

```
   b bit ──→ [第 1 輪] ──→ [第 2 輪] ──→ … ──→ [第 n_r 輪] ──→ b bit
                                               （SHA-3：n_r = 24）
```

【口頭】「我今天大概第 **500 次**說了：**實作 SHA-3 時 $n_r = 24$**。」
「不意外：所有**類區塊密碼**的構造都是**迭代**的。**DES 16 輪**，**AES 10 輪**，**Serpent**（我們沒講過）**48 輪**。」
（⚠️ Serpent 的輪數是教授口述，課本沒有寫，**待查**。）

**每一輪 = 五個基本（原子）運算**，每個都是 $b$ bit 進、$b$ bit 出：

```
   → [ θ ] → [ ρ ] → [ π ] → [ χ ] → [ ι ] →
```

【口頭】
- 設計團隊是**歐洲團隊**（「我想是比利時、法國、義大利」，⚠️ 教授自己不確定）。
- 「他們做了一個**不幸的選擇**：用**怪怪的希臘字母**命名。叫 A、B、C、D、E 多好。」
- **π**：「有些**其實有道理**」，叫 π 是因為它是**排列（permutation）**，所以用 p。
- **χ**：「數學裡不常用的字母。」
- **ι**：「像小寫的 i，**像個帶點的逗號**。」
- 「他們只是**想耍帥**。**沒有任何密碼學上的意義**。不是講希臘語的人會很困惑。」

【口頭】「**我喜歡教 SHA-3 到這裡為止。下一章我不喜歡，會變得很亂**，很多 byte 和 bit 搬來搬去，**不漂亮**。先警告你們。」
「沒辦法寫成同餘運算之類的漂亮公式。」

### 3.2 把狀態看成三維陣列

$b = 1600$ bit 的狀態可以看成**三維陣列**：

```
          z（深度，0…63）
         ╱
        ┌─┬─┬─┬─┬─┐
   y 4  │ │ │ │ │ │ ╲
   y 3  ├─┼─┼─┼─┼─┤  ╲  64 層
   y 2  ├─┼─┼─┼─┼─┤   ╲
   y 1  ├─┼─┼─┼─┼─┤
   y 0  └─┴─┴─┴─┴─┘
        x0 x1 x2 x3 x4
```

- 每個小方格 = **1 bit**。一層是 **5 × 5 = 25 bit**（「今天在哪裡看過 25？$25 \cdot 2^\ell$」）。
- SHA-3 有 **64 層**（$2^6 = 64$）。$64 \times 25 = 1600$ ✔
- 【口頭】「你們有**方格紙**（Kästchenpapier）真好……沒有？**下次帶方格紙。**」「我比較喜歡電腦硬體的想法，把 1600 bit 畫成一長條，像 AES 的 128 bit 匯流排。」
- **為什麼要三維**？因為這些函數**作用在三維陣列的某些部分**上，比較好解釋。

**座標系**：
| 座標 | 方向 | 範圍 |
|---|---|---|
| $x$ | 橫 | 0–4 |
| $y$ | 直 | 0–4 |
| $z$ | 深入黑板/紙裡 | 0–63 |

**軟體上怎麼存**：
- 【口頭】「照我剛才的解釋，你可能會想把 25 bit 存在一個暫存器、存 64 個 —— **很怪**。」
- 實際做法：沿著 $z$ 方向的 64 bit 存成**一個字**。整個狀態 = **25 個 64 bit 的字**。
- Keccak 文件裡叫這種 64 bit 的「條」為 **lane（車道）**。
- 「現代 **Intel CPU** 有 64 bit 暫存器，剛好放一個。**Android 手機的 ARM CPU** 要用兩個 32 bit 暫存器。」
- 好處：每個字有座標 $(x, y)$，$x, y \in \{0, \ldots, 4\}$ → **25 個變數的陣列**。

### 3.3 θ（Theta）步驟

【口頭】教授說用**講義**（網路上免費的**課本延伸章節**，「你不用買書」）第 14 頁的圖和公式；講義的具體公式**待補**。

**做法**：**1600 個狀態 bit 每一個都被更新**，換成 **11 個 bit 的 XOR 和**：

$$\text{新 bit} = \text{原本的 bit} \;\oplus\; (\text{「左邊」那一欄的 5 個 bit}) \;\oplus\; (\text{「右邊」且「往前一格」那一欄的 5 個 bit})$$

（1 + 5 + 5 = 11 個 bit。「欄（column）」= 同一個 $x$、同一個 $z$ 的 5 個 bit。）

**邊界怎麼辦？**
- 【課堂討論】如果在最左邊，左邊沒有欄了怎麼辦？→ 學生答：**繞回去** —— **mod 5**。「所以我給『左邊』加引號。」
- 右邊同理，mod 5。
- 【Q&A】學生問：「往前一格」如果已經在最前面一層怎麼辦？方向怎麼走？
  教授：「**很好的問題**。同樣**繞回去，mod 64**，拿**最後一層**。你不是掉到地上，而是回到最後一層。」

【口頭】
- 「為什麼這樣做？因為**密碼學上很強**，設計者是這樣定義的。」
- 「看起來像一堆**醜陋的位元操作**，但用軟體做**比圖上看起來簡單**。」
- 「**對硬體非常友善**，軟體上也相當快。」
- 「**這是特別難解釋的一個**，後面的會好一點。」

### 3.4 ρ（Rho）與 π（Pi）步驟

【口頭】「如果這完全看不出道理，想想**八個月前**介紹 DES 時的 **S-box**：那張怪表格『**沒有道理也沒有理由**』（ohne Sinn und Verstand）。這裡也一樣，選這些函數有**密碼學上的理由**。」

輸入：陣列 $A[x, y]$（25 個 64 bit 字），輸出：陣列 $B[x, y]$。
（【口頭】教授一度把 A、B 搞反：「我錯了、我錯了……我看錯講義頁了。**壞教授**。」）

**ρ 步驟：每個字循環移位固定的位數**

$$\text{temp}[x, y] = \text{ROT}\big(A[x, y],\; r[x, y]\big)$$

$r[x, y]$ 是查表得到的旋轉量（講義表 1.3 / 1.4，完整表格**待補**）。課堂上提到的例子：

| $(x, y)$ | 旋轉位數 $r[x,y]$ |
|---|---|
| (0, 0) | 0（「爛例子，不用轉」） |
| (1, 0) | 1 |
| (2, 0) | 62 |
| (3, 1) | 55 |

「為什麼是 62？**因為密碼學上安全**。我們只做功能描述。」

**π 步驟：把轉好的字換位置**

$$B[y,\; 2x + 3y] = \text{temp}[x, y], \qquad x, y \in \{0, \ldots, 4\}$$

**例子**：輸入 lane $(3, 1)$
1. **ρ**：查表 $r[3,1] = 55$ → 把那 64 bit 循環移 55 位 → $\text{temp}[3,1]$。
2. **π**：新位置 $= (y,\; 2x + 3y) = (1,\; 2\cdot 3 + 3\cdot 1) = (1, 9)$。
3. 【課堂討論】沒有座標 9，只到 4，怎麼辦？→ **mod 5**。「**很好的答案。所有座標永遠 mod 5。**」
4. $9 \bmod 5 = 4$ → $B[1, 4] = \text{temp}[3, 1]$。

> 原本在 $(3,1)$ 的字，轉 55 位後放到 $(1,4)$。

### 3.5 χ（Chi）步驟

【口頭】「最後兩個**還好不太痛**。」

輸入 $B$（上一步的輸出），輸出 $A$（「不完全一致，但講義裡我就是這樣寫的」）：

$$A[x, y] = B[x, y] \;\oplus\; \big(\overline{B[x+1, y]} \;\wedge\; B[x+2, y]\big)$$

- $\overline{\phantom{B}}$ = **反相**（bit 翻轉：1 變 0、0 變 1）
- $\wedge$ = **AND**
- 座標同樣 **mod 5**
- 白話：每個 bit = 原本的 bit XOR（右邊一格的反相 AND 右邊兩格）。

（課堂上教授還用逐 bit 的電路來說明：一個**反相器**、一個 **AND 閘**，最後 XOR。對照講義圖 1.6。）

### 3.6 ι（Iota）步驟

**最簡單的一步**：從常數表拿一個常數，加到**一個字** $A[0, 0]$（左下角那個 lane）：

$$A[0, 0] = A[0, 0] \oplus RC[i]$$

- $i$ = **輪數**，從 0 到 **23**。
- 常數表 $RC$（講義表 1.5，「講義裡標成 1.4 是我的錯，要修 LaTeX」）**待補**。
- 【口頭】作用：**防止某種特定的雜湊函數攻擊**（哪一種沒說，**待補**）。
- ⚠️ 教授說「加上（add）」常數；在 bit 的世界裡，加法就是 XOR，這裡寫成 $\oplus$。

【口頭】「謝謝大家，**很棒的一堂課**。」

## 4. 一頁速查表

### 4.1 歷史

| 年 | 事件 |
|---|---|
| 1980 年代 | MD4（被破） |
| 1991 | MD5（被破，Dobbertin） |
| 1995 | SHA-1（NIST） |
| 2001 | SHA-2 |
| 2004 | SHA-1 理論攻擊 |
| 2007.11 | SHA-3 徵件 |
| 2008.10 | 64 個提案 |
| 2010.12 | 剩 5 個（第三輪） |
| 2012.10.02 | **Keccak** 獲選 |
| 錄影當年 | SHA-1 實際碰撞（兩個不同的 PDF） |

### 4.2 輸出長度與安全等級

| 輸出 | 強度 | 對應 | $r$ | $c$ |
|---|---|---|---|---|
| 224 | 112 | 3DES | 1152 | 448 |
| 256 | 128 | AES-128 | 1088 | 512 |
| 384 | 192 | AES-192 | 832 | 768 |
| 512 | 256 | AES-256 | 576 | 1024 |

### 4.3 Keccak 參數

| 參數 | 公式 | SHA-3 |
|---|---|---|
| 狀態 $b$ | $25 \cdot 2^\ell$ | **1600**（$\ell = 6$） |
| 輪數 $n_r$ | $12 + 2\ell$ | **24** |
| $r + c$ | $= b$ | 1600 |
| 狀態看成 | $5 \times 5 \times 64$ | 25 個 64 bit lane |

### 4.4 海綿結構

| 階段 | 做法 |
|---|---|
| 吸收 | 每個 $r$ bit 區塊 XOR 進狀態的 $r$ 部分，再跑一次 $f$ |
| 擠壓 | 取狀態的前 $r$ bit；SHA-3 只取前 $n$ bit。要更多 bit → 再跑 $f$（PRNG、串流密碼） |

### 4.5 一輪的五個步驟

| 步驟 | 做什麼 |
|---|---|
| **θ** | 每個 bit ⊕ 左邊那欄 5 bit ⊕ 右前那欄 5 bit（共 11 bit） |
| **ρ** | 每個 lane 循環移 $r[x,y]$ 位 |
| **π** | $B[y, 2x+3y] = \text{temp}[x,y]$（mod 5） |
| **χ** | $A[x,y] = B[x,y] \oplus (\overline{B[x+1,y]} \wedge B[x+2,y])$ |
| **ι** | $A[0,0] \oplus= RC[i]$，$i = 0 \ldots 23$ |

### 4.6 SHA-2 vs SHA-3

| | SHA-1 / SHA-2 | **SHA-3（Keccak）** |
|---|---|---|
| 結構 | **Merkle–Damgård** | **海綿結構** |
| 家族 | MD4 家族 | 完全不同的新設計 |
| 輸出可變長度 | 否 | 可以一直擠（PRNG、串流密碼） |

> **因為 SHA-1 被攻破、大家擔心同家族的 SHA-2，NIST 辦了公開競賽，2012 年選出完全不同於 MD4 家族的 Keccak 當 SHA-3：它用「海綿結構」先把訊息一塊塊 XOR 進 1600 bit 的狀態並用 24 輪的 f 函數攪拌（吸收），再從狀態擠出需要長度的輸出（擠壓）；每一輪由 θ、ρ、π、χ、ι 五個位元層級的步驟組成，把狀態看成 5×5×64 的立方體最好理解。**
