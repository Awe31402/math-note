## 1. 區塊密碼還能做什麼

`[00:02]` 到目前為止，我們對區塊密碼的用法很簡單：

```
x₁ → [E] → y₁
x₂ → [E] → y₂
x₃ → [E] → y₃     ← 一塊接一塊，各自加密
```

【口頭】「我沒明說，但隱含的就是這樣。**這是個好方法嗎？**」AES 一塊只有 128 bit = 16 個字元，連很短的 email 都要好幾塊。

`[00:05]`【口頭】「這可能讓你們很驚訝：**區塊密碼可以用來做很多其他事情**。」

| 用途 | 什麼時候講 |
|---|---|
| **各種加密方式**（不同的操作模式） | **今天** |
| **當成串流密碼**（!）| **今天** |
| 偽亂數產生器（PRNG） | — |
| **雜湊函數** | 第 20–22 講（教授說「2011 年 5 月」） |
| **MAC**（訊息鑑別碼，「跟漢堡無關」） | 第 25 講 |
| 金鑰建立協定 | 第 26 講【課本補充】 |

【口頭】
- 之前我們把「區塊密碼」和「串流密碼」嚴格分開。**這不完全對**：區塊密碼**可以變成**串流密碼。反過來就沒那麼容易。
- 「區塊密碼非常重要，不只是用來**笨笨地**加密資料。」

## 2. 什麼是操作模式

`[00:09]` **操作模式（mode of operation，德文 Betriebsmodus）**：用區塊密碼加密**比一個區塊長**的資料的方法。

【口頭】「我給你一個 AES 函式庫，請你在筆電上加密一個 PDF 檔。大家都知道**一種**做法 —— 就是第一個模式。它**不是最好的**。課本有 6、7 種模式，我們講 3 種。」

### 分類（`[00:11]`，課本沒有這張圖）

```
                      操作模式
          ┌──────────────┴──────────────┐
     確定性                          機率性
   (deterministic)               (probabilistic)
          │                    ┌────────┴─────────┐
        ECB             當區塊密碼用          當串流密碼用
                             CBC          OFB、CFB、CTR
```

【課堂討論】「probabilistic」的德文？→ wahrscheinlich、zufällig、stochastisch。「有人想講得很炫的話就說 stochastisch。」

| 名稱 | 全名 | 今天講 |
|---|---|---|
| ECB | Electronic Codebook | ✔ |
| CBC | Cipher Block Chaining | ✔ |
| OFB | Output Feedback | ✔ |
| CFB | Cipher Feedback | 課本 |
| CTR | Counter | 課本 |
| GCM | Galois Counter Mode | 課本 |

【口頭】`[00:15]`「如果你現在不知道我在講什麼，**完全沒關係**。我只是丟了一堆術語。接下來 60 分鐘會解釋。」

## 3. ECB 模式（Electronic Codebook）

### 3.1 做法

`[00:16]` 最直接的做法：**每一塊各自用同一把金鑰加密**。

$$y_i = e_k(x_i), \qquad x_i = e_k^{-1}(y_i)$$

```
Alice:  x₁ → [e_k] → y₁      x₂ → [e_k] → y₂      x₃ → [e_k] → y₃  …
                       ↓                    ↓                    ↓
Bob:    y₁ → [e_k⁻¹] → x₁    y₂ → [e_k⁻¹] → x₂    y₃ → [e_k⁻¹] → x₃ …
```

【口頭】「直覺上這不只是自然的做法，好像**是唯一的做法**。但不是。這是**最簡單**的方法，結果也**不是最好的**。」

### 3.2 攻擊：銀行轉帳的替換攻擊

`[00:18]`【口頭】「這堂課很少見的做法：我**示範一個攻擊**。在密碼學裡『不是好主意』通常就是『**可以被攻擊**』。」

> 【口頭】「這不是我的例子。我大約 15 年前剛開始學、教密碼學時，在某本書（可能是 Schneier 的書）讀到的。我很喜歡，一直記得。」

#### 情境

`[00:19]` **電子轉帳**：Bochum 市儲蓄銀行（Bank A）→ 郵政銀行（Bank B），透過銀行網路。

- 【口頭】銀行不笨，當然會加密。「這正是 1970 年代初開發 DES 的主要動機之一：**銀行業**是大客戶。」
- 假設它們用 **ECB 模式**（「它們沒來上這堂課，也沒買我的書」）。

**轉帳格式**（5 個欄位）：

| 區塊 | 內容 |
|---|---|
| **BL1** | 轉出銀行代碼（德國的 **Bankleitzahl**, BLZ） |
| **BL2** | 轉出帳號 |
| **BL3** | 轉入銀行代碼 |
| **BL4** | 轉入帳號 |
| **BL5** | 金額（歐元、美元、日圓、茲羅提……） |

**兩個假設**（`[00:24]`）：
1. **每個欄位剛好是一個區塊寬**（AES 是 128 bit；是區塊寬的倍數也行）。【口頭】「有點不切實際，但不算太離譜。」
2. **銀行 A、B 之間的金鑰 $k_{AB}$ 會固定一段時間**（可能一小時、幾分鐘）。**不是每筆轉帳都換金鑰。**「這很實際。」

#### 攻擊者 Oscar

`[00:26]` Oscar 是**主動攻擊者（active attacker）**：不只能偷聽，還能**竄改**訊息。（相對的是**被動攻擊者（passive attacker）**，只能聽。）

【口頭】「就算用 AES-256，密碼學上超安全，**還是有弱點**。」

#### 攻擊步驟

| 步驟 | 做法 |
|---|---|
| 1 | Oscar 在**銀行 A** 開戶（【口頭】實務上要出示身分證，所以需要假證件），**也在銀行 B** 開戶 |
| 2 | 從 A 帳戶轉 **1 歐元**到 B 帳戶，**重複很多次**。「花 100 次損失 100 歐元，但都進了自己的另一個帳戶，**零成本**。」 |
| 3 | 同時在銀行網路上**竊聽（wiretap）** |
| 4 | 認出自己的轉帳，**存下 BL1、BL3、BL4** |
| 5 | 之後監看所有轉帳：只要 **BL1 和 BL3 跟存下來的一樣**，就是「A 銀行某帳戶 → B 銀行某帳戶」 |
| 6 | 把那筆轉帳的 **BL4 換成自己存下來的 BL4**（= 自己的帳號，加密後） |
| 7 | 【課本補充】趕快從 B 銀行把錢領走，飛到一個不太會引渡白領罪犯的國家 |

#### 【課堂討論】Oscar 怎麼認出自己的轉帳？

`[00:29]` 他看得到金額嗎？**不行**，是 AES-256 加密的。銀行代碼、帳號也看不到。

那怎麼知道？→ **每次的密文都一模一樣！** 銀行、帳號、金額都不變，ECB 又是確定性的。
在網路上幾百家銀行的隨機位元流中，他看到一串 5 × 128 bit **一直重複出現** → 「這一定是我的轉帳」。

這叫**流量分析（traffic analysis）**：【口頭】「這其實是軍事術語。只看密文、試著從密文**學到些什麼**，跟破解 AES 完全不同 —— 祝你好運，破不了。」

#### 結果

`[00:37]`【口頭】「Bochum 市儲蓄銀行一天可能有幾百、幾千筆轉帳到郵政銀行。**這些全都會進 Oscar 的帳戶。**很酷。違法，但如果你沒有道德，很酷。」

#### 【Q&A】他不需要知道那些帳號嗎？

`[00:38]`

**學生問**：（大意）Oscar 不需要知道其他人的帳號或明文嗎？

**教授答**：**對，他不需要知道。**這就是重點。

> ⚠️ 逐字稿缺字：學生問題的完整內容沒被字幕抓到，上面是依教授回答推斷的大意。

#### 重點

`[00:39]`

> **Oscar 沒有破解區塊密碼。**AES 破不了。攻擊之所以成功，**只是把密文區塊重新排列、替換**，完全在密文層級進行。

【課本補充】
- 就算用 AES-256、每塊加密 1000 次，**都擋不住**這個攻擊。
- 但它也**不算破解**區塊密碼：Oscar 不知道的訊息仍然保密。他做的是破壞**訊息完整性（integrity）**。
- 防禦方法：**MAC**（第 25 講）、**數位簽章**（第 18 講），或內建完整性檢查的 **GCM 模式**。
- 金鑰換得越頻繁，這個攻擊越難 → 又一個**常換金鑰（key freshness）** 的理由。

### 3.3 為什麼叫「電子密碼本」

`[00:40]`【口頭】**類似對替換密碼的頻率攻擊**（第 1 講、第一次作業）：

| | 替換密碼 | ECB |
|---|---|---|
| 對應 | 字母 → 字母（固定） | 區塊 → 區塊（固定） |
| 字母表大小 | 26 | $2^{128}$ |

> 【口頭】「金鑰固定時，區塊密碼就只是一張**查找表**、一本**密碼本（code book）**。只是這本書要有 $2^{128}$ 頁 —— 地球上的原子都不夠。但它**運作起來就像一本密碼本**。」

`[00:43]`【口頭】
- ECB 是**不好的模式**，所以實務上不常用。「有些情況**必須**用它，它有存在的理由（Berechtigung）。」
- **我們真正想要的**（「有點違反直覺」）：**同一段明文加密兩次，要得到不同的密文。**

### 3.4 【課本補充】ECB 加密圖片

課本 Example 5.2：用 AES-256 的 ECB 模式加密一張**簡單的點陣圖**（有文字的圖）。
- 背景只有少數幾種明文區塊 → 密文背景也**很一致**。
- 有字的區塊 → 密文看起來很隨機。
- 結果：**加密後的圖還是看得出文字**。

## 4. 確定性 vs 機率性加密

`[00:44]` ECB 的兩個問題：
1. **同樣的明文 → 同樣的密文**
2. **每塊各自獨立加密**，彼此毫無關聯。我們希望**把整則訊息當成一個整體**。

`[00:47]`（非正式定義）

> **確定性加密（deterministic）**：特定的明文**永遠**對到同一個密文（金鑰固定時）。
>
> **機率性加密（probabilistic）**：在產生密文時**使用隨機性（randomness, Zufall）**。

【口頭】「這不算嚴格的定義。三年後碩士班你會上另一門也叫密碼學的課，做的是**基於證明的現代密碼學**，那時確定性 vs 機率性會變成**非常重要**的概念。今天先嚐一點。」

### 機率性加密的架構

`[00:52]`【口頭】「這張圖**不在課本裡**，我想也不在任何入門書裡。我以前也沒這樣教過，舊的德文影片裡也沒有。但**它真的很有幫助**，一分鐘後你就會知道為什麼 —— 它能幫你理解所有的操作模式。」

```
        x                                          y, r
        ↓                                           ↓
  ┌──────────┐                              ┌──────────┐
  │    e     │ ──→ y ────── 通道 ──────→    │    d     │ ──→ x
  └──────────┘ ──→ r ────── 通道 ──────→    └──────────┘
   ↑       ↑                                   ↑
   k       r（隨機）                            k
```

- 加密除了 $x$、$k$，**多一個輸入 $r$**（跟隨機有關）。
- 同一個 $x$，不同的 $r$ → **不同的 $y$**。
- 【口頭】`[00:53]`「**醒來，這很重要**：$r$ **跟密文一起送過去**。$r$ **不是**金鑰（金鑰不能明文傳送），$r$ **不是秘密**。」
- Bob 解密時用 $y$、$r$、$k$。

## 5. CBC 模式（Cipher Block Chaining）

`[00:44]`【口頭】「它**曾經**是最流行的模式，至少以前是。」

### 5.1 兩個要解決的問題

| 問題 | CBC 的解法 |
|---|---|
| 確定性 | 加入 **IV**（扮演上面 $r$ 的角色）→ 機率性 |
| 各塊獨立 | 把**前一塊的密文**接進來 → **鏈接（chaining, Verkettung）** |

### 5.2 加密

`[00:55]`【口頭】「先別抄，我會改這張圖。」

**想法**：
1. 第一塊：$x_1$ 先 XOR 一個 **IV（Initialization Vector，初始向量）** 再加密。
2. 如果第二塊也用同一個 IV，雖然也是機率性的，但**各塊還是獨立**。
3. 所以：從第二塊開始，**改 XOR 前一塊的密文 $y_{i-1}$**。教授用一個「開關」表示：$t = 1$ 時接 IV，$t \ge 2$ 時切到存起來的 $y_{i-1}$。

```
        IV            y₁             y₂
         ↓             ↓              ↓
 x₁ →  ⊕  → [e_k] → y₁   x₂ → ⊕ → [e_k] → y₂   x₃ → ⊕ → [e_k] → y₃
                     └──────────↑              └──────────↑
```

$$\boxed{y_1 = e_k(x_1 \oplus IV), \qquad y_i = e_k(x_i \oplus y_{i-1}), \quad i \ge 2}$$

#### 鏈接效果

`[00:59]`
- $y_2$ 依賴 $x_2$ 和 $y_1$；$y_1$ 又依賴 $x_1$。
- $y_3$ 依賴 $x_3$、$y_2$ → 也就依賴 $x_2$、$x_1$。
- 【口頭】「這就是為什麼叫 **chaining**。腳踏車鏈條德文叫 Kette。」

### 5.3 解密

`[01:00]` 把加密看成**兩步**：(1) 很弱的 XOR 加密，(2) 真正的區塊密碼加密。倒回去：

1. 先做**區塊密碼解密** $e_k^{-1}$
2. 【課堂討論】XOR 的反運算是什麼？→ **再 XOR 一次**（「非常非常好」）。XOR **同一個值**：第一塊是 IV，之後是前一塊密文。

$$\boxed{x_1 = e_k^{-1}(y_1) \oplus IV, \qquad x_i = e_k^{-1}(y_i) \oplus y_{i-1}, \quad i \ge 2}$$

### 5.4 初始向量 IV

`[01:04]`【口頭】「第一次看到的人常有種感覺：『IV 好像金鑰，我可以把它當金鑰用』。**我們不把它當金鑰。**」

| 性質 | 說明 |
|---|---|
| **不需要保密** | 可以明文傳送，透過網路或無線電 |
| **應該是 nonce** | **n**umber used **once**，只用一次的數 |

【課堂討論】nonce 是什麼的縮寫？→ number used once。

**為什麼要 nonce**（`[01:06]`）：回到銀行例子。Oscar 每次轉 1 歐元，5 個欄位的明文**完全一樣**。但如果**每則訊息的 IV 都不同**，每次的密文 $y_1 \ldots y_5$ 就**完全不同** → 流量分析失效。

#### 怎麼產生 IV

`[01:07]`【口頭】「沒有唯一的做法，很大程度取決於你的應用和協定。」

| 方法 | 說明 |
|---|---|
| **真亂數** | AES 的話用 TRNG 產生 128 bit。⚠️ 要小心：**可能產生兩次一樣的亂數**（生日悖論，第 20 講雜湊函數會講）。可以存下所有用過的 IV 檢查，但不一定容易 |
| **計數器** | 【課堂討論】最簡單的方法？→ **往上數（hochzählen）**。兩家銀行第一次通訊設 0，之後 1、2、3……要 $2^{128}$ 次才會重複，「宇宙的壽命都不夠」 |
| **身分 + 時間** | 例如 Alice 的 ID（網路位址、IP 位址，可能 32 bit）**串接（concatenate, ‖）** 當下時間（精確到秒甚至微秒）。不是真亂數，而是**偽隨機、且對 Alice 和 Bob 是專屬的** → 網路上其他人不會用到同一個 |

【口頭】`[01:11]`「還有很多其他方式。」

## 6. OFB 模式（Output Feedback）：把區塊密碼當串流密碼

`[01:12]`【口頭】「現在我想示範怎麼**把區塊密碼當串流密碼用**，這看起來可能很奇怪、很意外。結果它**超級簡單**，至少跟 CBC 一樣簡單。」

### 6.1 教授的抱怨

`[01:13]`【口頭】
- 「課本通常不從這個角度開始。它們直接給你**方塊圖和公式**，還有那個奇怪的 IV 和開關，你不知道在幹嘛。」
- 「它們常常**不告訴你：這是一個串流密碼**。我覺得這**超級重要**，所以今天第一件事就是畫那張分類圖說『現在講的是串流密碼模式』。」

### 6.2 想法

`[01:14]` 回想串流密碼（第 3–4 講）：

```
金鑰 → [ 金鑰串流產生器 ] → s_i → ⊕ → y_i
                               ↑
                              x_i
```

第 4 講試過放 LFSR（單一 LFSR 不行）。**現在放 AES 進去！**

> **把區塊密碼當作金鑰串流產生器。**

【口頭】`[01:16]`「真正的加密是**XOR**，不是區塊密碼。**資料不會進區塊密碼**，資料只進 XOR。區塊密碼的輸出提供**隨機性質很好的遮罩**。」

### 6.3 做法

**第一塊**（`[01:17]`）：
- 區塊密碼需要輸入 → 用 **IV**。
- IV 可以很確定性，例如**全零**或計數器。【口頭】「看起來不太隨機？但記得這是**密碼學上很強的區塊密碼**。用 AES 加密 128 個零，輸出對攻擊者來說**看起來非常隨機**，他算不出來。」
- 輸出 128 bit $s_1$，**一次 XOR 128 個明文 bit**（128 個 bit 的 XOR 平行做）。

#### 【Q&A】這還算串流密碼嗎？（德文問答）

`[01:19]`

**學生問**：一次處理 128 bit，這還是串流密碼嗎？

**教授答**：是。因為**這些 bit 彼此不連動**：第 2 個 bit 只跟第 2 個 bit XOR，跟第 1、第 3 個 bit 無關 —— 就像一般的串流密碼，只是那裡在時間上一個一個慢慢來。

**第二塊**（`[01:20]`）：
- 【課堂討論】$x_2$ 能再用同一個 IV 嗎？→ **超蠢**，會得到同樣的 128 bit 遮罩（金鑰串流重複使用，回想 OTP 的教訓）。
- 需要**新的遮罩** → 給區塊密碼**新的輸入**。
  - 一種做法：用計數器 → 那就是 **CTR 模式**。
  - **OFB 的做法**：把**上一次的輸出 $s_{i-1}$ 回授**當作這次的輸入。（又是一個開關：$t = 1$ 接 IV，$t \ge 2$ 接 $s_{i-1}$。）

```
    IV → [e_k] → s₁ → [e_k] → s₂ → [e_k] → s₃ → …
                  ↓             ↓             ↓
          x₁ →   ⊕ → y₁   x₂ → ⊕ → y₂   x₃ → ⊕ → y₃
```

$$\boxed{s_1 = e_k(IV), \quad s_i = e_k(s_{i-1}), \qquad y_i = s_i \oplus x_i}$$

### 6.4 解密

`[01:21]`【課堂討論】XOR 的反運算？→ **另一個 XOR**。接收端的金鑰串流產生器是什麼？→ **一模一樣的**。

$$x_i = s_i \oplus y_i$$

#### 【口頭】口試的經典問題

`[01:23]`
> 「如果你以後當教授或老師要考學生，就問：**畫出 OFB 模式。**他們努力背了，大概畫得出來。然後問：**為什麼解密端不用 $e^{-1}$**（像 CBC 那樣）？」

**答案**：

> **這不是在把區塊密碼當區塊密碼用，而是當串流密碼用。**我們「濫用（missbrauchen）」區塊密碼來產生偽亂數 bit。兩端要產生**一樣的** bit，所以兩端都用 **$e_k$（加密方向）**。

【口頭】「它看起來跟 CBC 有點像，軟硬體實作上也沒差很多。但**在密碼學上是完全不同的故事**。」

### 6.5 OFB 的性質【課本補充】

- **同步串流密碼**：金鑰串流只跟 IV 和金鑰有關，**跟明文、密文都無關**。
- 只要 IV 換了，同樣的明文就會有不同的密文 → **機率性**。
- 金鑰串流可以**預先算好**（因為不依賴資料）。

## 7. 【課本補充】CFB、CTR、GCM

這三個模式課堂沒講，依課本 §5.1.4–5.1.6 整理。

### 7.1 CFB（Cipher Feedback）

也是**把區塊密碼當串流密碼**，但回授的是**密文**（不是區塊密碼的輸出）：

$$y_1 = e_k(IV) \oplus x_1, \qquad y_i = e_k(y_{i-1}) \oplus x_i$$

$$x_1 = e_k(IV) \oplus y_1, \qquad x_i = e_k(y_{i-1}) \oplus y_i$$

- 因為金鑰串流**依賴密文** → **非同步**串流密碼（第 3 講提過的例子就是它）。
- 解密也只用 $e_k$，理由跟 OFB 一樣。

### 7.2 CTR（Counter Mode）

區塊密碼的輸入是一個**計數器**，每塊不同：

$$y_i = e_k(IV \,\|\, CTR_i) \oplus x_i, \qquad x_i = e_k(IV \,\|\, CTR_i) \oplus y_i$$

- 例：AES 的 128 bit 輸入 = **96 bit 的 IV（nonce）** ‖ **32 bit 的計數器**（從 0 開始，每塊 +1）。
- 這樣一個 IV 最多加密 $2^{32}$ 塊 = $2^{35}$ byte ≈ **32 GB**，之後就要換 IV。
- **最大優點：可以平行化。** 不像 OFB、CFB 要等上一塊算完，CTR 可以多個區塊密碼**同時**算不同的計數器值。高速應用很需要這個。

### 7.3 GCM（Galois Counter Mode）

**同時提供加密和鑑別**（authenticated encryption）：
- **加密**：就是 CTR 模式。
- **鑑別**：產生一個 **MAC**（訊息鑑別碼）作為「密碼學檢查碼」，用來確認訊息**沒被竄改**（完整性）、**來源正確**（鑑別）。
- 還可以保護一段**不加密、但要鑑別**的額外資料 **AAD**（Additional Authenticated Data），例如封包標頭。

做法概要：
1. 鑑別子金鑰 $H = e_k(0)$
2. $g_0 = AAD \times H$
3. $g_i = (g_{i-1} \oplus y_i) \times H$（**$GF(2^{128})$ 乘法**）
4. 鑑別標籤 $T = (g_n \times H) \oplus e_k(CTR_0)$

$GF(2^{128})$ 用的不可約多項式是 $x^{128} + x^7 + x^2 + x + 1$ —— 第 7 講的 Galois Field 又出場了。

**回扣 §3.2**：GCM 這種內建完整性檢查的模式，**就能擋住**銀行轉帳的替換攻擊。

## 8. 一頁速查表

### 8.1 模式總表

| 模式 | 加密 | 解密 | 類型 | 用到 $e_k^{-1}$ |
|---|---|---|---|---|
| **ECB** | $y_i = e_k(x_i)$ | $x_i = e_k^{-1}(y_i)$ | 確定性、區塊 | ✔ |
| **CBC** | $y_i = e_k(x_i \oplus y_{i-1})$，$y_0 = IV$ | $x_i = e_k^{-1}(y_i) \oplus y_{i-1}$ | 機率性、區塊 | ✔ |
| **OFB** | $s_i = e_k(s_{i-1})$，$s_0 = IV$；$y_i = s_i \oplus x_i$ | $x_i = s_i \oplus y_i$ | 同步串流 | ✘ |
| **CFB** | $y_i = e_k(y_{i-1}) \oplus x_i$，$y_0 = IV$ | $x_i = e_k(y_{i-1}) \oplus y_i$ | 非同步串流 | ✘ |
| **CTR** | $y_i = e_k(IV \| CTR_i) \oplus x_i$ | $x_i = e_k(IV \| CTR_i) \oplus y_i$ | 串流、**可平行** | ✘ |
| **GCM** | CTR + $GF(2^{128})$ 鑑別 | 同左 + 驗證標籤 | 加密 + 鑑別 | ✘ |

### 8.2 ECB 的問題

| 問題 | 後果 |
|---|---|
| 確定性：同明文 → 同密文 | **流量分析**、圖片加密後仍看得出輪廓 |
| 各塊獨立 | **區塊替換攻擊**（銀行轉帳例子） |
| 本質 | 金鑰固定時就是一本 $2^{128}$ 頁的**密碼本** |

### 8.3 IV / nonce

| 項目 | 內容 |
|---|---|
| 要保密嗎 | **不用**，跟密文一起送 |
| 要求 | **nonce**：不能重複 |
| 產生方式 | 真亂數（注意生日悖論）、計數器、身分 ‖ 時間 |

### 8.4 三個關鍵觀念

1. **攻擊不一定要破解演算法**：ECB 的攻擊只是重排密文區塊。
2. **機率性加密**：同一明文要能產生不同密文 → 靠 IV。
3. **區塊密碼可以當串流密碼用**（OFB、CFB、CTR）：這時兩端都只用**加密方向** $e_k$。

## 附：本講一句話總結

> **ECB 把區塊密碼當成一本固定的密碼本，同樣的明文永遠得到同樣的密文 —— 攻擊者不必破解 AES，只要替換密文區塊就能把別人的轉帳導到自己帳戶；CBC 用 IV 和密文鏈接讓加密變成機率性的，而 OFB 則把區塊密碼「濫用」成金鑰串流產生器，所以解密端也只需要加密函數。**
