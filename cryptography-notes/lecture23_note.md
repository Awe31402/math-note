## 1. 量子電腦與密碼學

`[00:01]`【口頭】「這不是量子技術的課。我們只關心**量子電腦（QC）和密碼學**的關係。」
「**如果你今晚要退出 IT 安全學程，記住我在這塊黑板上寫的就好。**這在 IT 安全之外也很有意思。」

### 1.1 大型量子電腦目前不存在

`[00:02]`

> **大型（large-scale）量子電腦目前不存在。**

- 「大型」= 夠大，能做有用的事。
- 「你不能去 eBay 或 Media Markt 花 1 萬美元買一台，**花 1000 萬也買不到**。」

> **但它們可能在 10～20 年內出現。**

- 【口頭】「這兩個都有問號：『可能』是多可能？『10～20 年』是多準？**兩個都很模糊**。如果我知道，大概就能賺大錢了。」
- 有一個很大的國際社群（實驗物理學家、量子演算法學者）在努力，Bochum 也有，例如 **Walter 教授**也開課。
- 「每年在建造大型量子電腦上**輕易就花了幾十億歐元**。我們不知道會不會成功。很多比我懂得多的聰明人說，**10～20 年是不錯的猜測**。」
- 「也就是說，**它們很有可能在我們有生之年出現**。」

`[00:04]`【口頭】「接下來的**零數學**，但這些事實**很酷、很重要**。」

**重點**：量子電腦對兩大家族的影響**差異極大**。

### 1.2 對對稱密碼：Grover 演算法

`[00:05]`【課堂討論】最流行的對稱演算法？→ **AES**。

| | 傳統攻擊（暴力搜尋） | 量子攻擊（**Grover 演算法**） |
|---|---|---|
| $n$ bit 金鑰 | $2^n$ 步 | $\sqrt{2^n} = 2^{n/2}$ 步 |
| AES-128 | $2^{128}$ | 【課堂討論】$2^{64}$（「可以用 iPhone 驗算 128 ÷ 2 = 64，開玩笑的」） |

【口頭】「如果你不知道 $n$ bit 區塊密碼的暴力搜尋是 $2^n$，你就得退出這個學程了，**這很重要**。」

> **量子電腦把 AES 的有效金鑰長度砍半。**

**怎麼修？**（`[00:08]`）
- 【課堂討論】→ **金鑰至少要 256 bit**。
- AES 有問題嗎？**沒有**，因為**有 AES-256**。
- 【口頭】「記得吧？**為什麼有 AES-256？就是因為這個。**這不是巧合。AES 競賽大約 1997 年開始，**大概 28 年前**，那時 Grover 攻擊才剛出現，NIST 就已經知道了，所以要求 256 bit。如果只考慮傳統暴力攻擊，128 bit 就夠了；**擔心 10～20 年後的攻擊，才需要 256。**」

> 【口頭】「如果這是量子電腦和密碼學的全部，**這堂課就結束了**，我們可以去學生餐廳吃午餐。可惜……」

【課本補充】課本 §5.4 也提到：Grover 演算法讓 $2^n$ 的金鑰搜尋只需約 $2^{n/2}$ 步；**可以證明沒有比 Grover 更有效的量子金鑰搜尋演算法**；這也是 AES 要求 192、256 bit 的動機。

### 1.3 對公鑰密碼：Shor 演算法

`[00:09]`【口頭】實際使用中（瀏覽器、WhatsApp、Signal）的公鑰密碼只有**三大家族**：

| 家族 | 量子攻擊 |
|---|---|
| RSA | **Shor 演算法** → **完全破解** |
| 離散對數 | **Shor 演算法** → **完全破解** |
| 橢圓曲線（ECC） | **Shor 演算法** → **完全破解** |

【口頭】「我要換我**第二喜歡的顏色：紅色**。」
- 「如果有量子電腦，**破解我們端對端加密的 WhatsApp 很容易**，因為它用橢圓曲線做金鑰交換。**這很戲劇性，所以我用紅色。**」
- 「**如果**量子電腦現在存在 —— 它們不存在。一旦存在，**我們全都慘了**。」

**跟對稱密碼的差別**（`[00:11]`）：
- 對稱：金鑰**適度**加長就好（128 → 256，「誰在乎」）。
- 公鑰：**加長金鑰也沒用**。「就算 RSA 用 10,000 bit，**還是能被破**。背後是**找循環（cycle finding）**的攻擊，**威力強得不可思議**。」

> 【口頭】「**我們輸了。**所以我們需要**新的演算法**。」

### 1.4 後量子密碼學

`[00:12]`

> 需要**不屬於** RSA、離散對數、ECC 家族、而且**不怕量子攻擊**的公鑰演算法。
> 它們有一個很炫的名字：**後量子密碼學（Post-Quantum Cryptography, PQC）**。

【口頭】`[00:18]`「（謝謝 Julian 提醒）**這很重要**：」
- 這個名字據說是**著名密碼學家 Dan Bernstein** 取的。
- 「**名字很美，但很誤導人。**我第一次聽到時以為這是量子的東西，像《星艦迷航記》的企業號。」
- **後量子密碼學並不利用量子效應來計算。**
- 「它們基本上是**普通、無聊的演算法**，只是**剛好能抵抗量子電腦**。」
- 「我沒有數據，但我猜**超多人誤解這一點**。」

【課本補充】課本 §6.4（2010 年）：
- 有四類不同的單向函數特別有意思：**以雜湊、以編碼（code）、以格（lattice）、以多變數二次方程（MQ）為基礎**。
- 它們沒被廣泛使用的原因：實務缺點（例如**金鑰很長，有時好幾 MB**），或密碼強度還沒被充分理解。
- 約 2005 年起學界興趣增加，部分原因是**目前沒有已知對這四類的量子攻擊**。
- 「雖然不清楚量子電腦會不會存在（最樂觀的估計也還要幾十年）」—— 這是 2010 年的說法。

### 1.5 【Q&A】怎麼確定情報單位沒有攻擊？

`[00:13]`

**學生問**：我們需要後量子密碼學來解決非對稱演算法的問題。但我們怎麼確定，情報單位**沒有**（或還不會有）類似的攻擊方法對付這些新演算法？

**教授答**：「**非常好的問題。基本上，我們不確定。**」
- 【課堂討論】要破 RSA 要做什麼？→ **整數分解**。「從 1977 年開始，**快 50 年**，大家一直在擔心：有沒有更好的分解演算法？**我們不知道，沒有保證。**」
- 現在有一個**全世界的社群**在找對這些新演算法的攻擊（就像今天要做的），**目前還沒找到**。
- 「量子電腦（我懂得很少）很特別，比較像**專用電腦**，**不是通用可程式化**的。你不能用它寫你最愛的 TikTok App。」
- 「我們剛好想出新的後量子公鑰演算法，**又剛好**能用量子電腦攻擊它 —— 這會是**很大的巧合**。（RSA、DL、ECC 其實只算兩族，因為 ECC 也是離散對數，某種程度上是巧合。）」

#### 【Q&A】對稱密碼呢？

**學生問**：（大意）對稱密碼的量子攻擊有沒有可能更好？

**教授答**：「我懂得很少，但**據說甚至有證明**：至少就**金鑰搜尋**而言，**不可能比平方根更好**。」

### 1.6 後量子演算法的四大家族

`[00:15]`【口頭】「這是今天我**唯一**用投影片的地方，我討厭用投影片。」
- 很多人在做，**包括 Bochum**：「這是全世界做公鑰密碼學的**領先地點之一**。不是我，是我兩位最喜歡的同事：**RUB 的 Eike Kiltz** 和 **Max Planck 研究所的 Peter Schwabe**。」

**公鑰密碼學做兩件事**（第一學期末就開始學了）：
- **數位簽章**
- **加密** → 這裡叫 **KEM（Key Encapsulation Mechanism，金鑰封裝機制）**，就是第一學期講的**金鑰傳輸（key transport）**的炫版本。

`[00:17]`【口頭】全世界的社群（科學家、政府機構、標準化機構）**正在收斂到三四種演算法**：

| 家族 | 數位簽章 | KEM | 說明 |
|---|---|---|---|
| **以格為基礎（lattice-based）** | ✔ | ✔ | **唯一例外**：兩件事都能做 |
| **以編碼為基礎（code-based）** | | ✔ | **最老的** |
| **以雜湊為基礎（hash-based）** | ✔ | | **今天講的** |
| 多變數（multivariate） | | | 「比較不流行，但看起來也合理」 |

【口頭】
- 「通常每個家族**只能做一件事**。」
- 「（順便幫我的書打個廣告，**新版書**裡都有。）」
- **為什麼講雜湊式**？「因為**好玩**。雜湊式很好玩，就只是雜湊。」
- 「**明年**很有可能加上以格或以編碼為基礎的。我們從簡單的開始。」
- 「如果你今晚要退學，**你需要知道的就這些**。」

## 2. 簡單的雜湊簽章

`[00:19]` 目標：一步步走向雜湊式簽章。

### 2.1 回顧：一般的數位簽章

`[00:20]` 例如 **RSA** 或 **ECDSA**（「ECDSA 我們沒講，但課本有」）。三四週前講過：

```
   Alice                                    Bob
   k_pr（私鑰）、k_pub（公鑰）
              ─────── k_pub ───────→
   s = sig(k_pr, m)
              ─────── (m, s) ──────→
                                    ver(k_pub, m, s) = true / false
```

- 「這是公鑰密碼學的**典範**。只有一個人知道超級秘密的私鑰（例如 2048 bit 的 RSA 私鑰，可能在智慧卡或手機裡），用它簽，例如一份**買機車的數位合約 PDF**。」
- 簽章演算法需要**兩個輸入：私鑰和訊息** —— 「**10 分鐘後這會很重要**」。
- 【課堂討論】驗證有幾種結果？→ **true / false，1 個 bit**。「可能算出 2048 bit 的數，但我們要的是真或假。」

**安全服務**（`[00:24]`，回顧第 18 講）：

| 服務 | 意思 |
|---|---|
| **真實性（authenticity）** | 發送者鑑別：Bob 能確定訊息來自 Alice。（「也能用對稱密碼做，幾週後講」） |
| **完整性（integrity）** | 【課堂討論】Oscar 把 $m$ 換成 $m'$，Bob 察覺得到嗎？→ 當然，$s$ 對不上 $m'$ |
| **不可否認性（non-repudiation）** | 「記得那個**車商**的例子嗎？」Alice 之後不能說「這不是我發的，是 Bob 產生的」—— 因為只有私鑰能簽，公鑰只能驗 |

【口頭】`[00:26]`「**這是基準線。目標是：能不能用後量子密碼學做到這些？**因為 RSA 20 年後可能被破：去 eBay 花 100 萬甚至 1 萬美元買台量子電腦，就沒了。」

### 2.2 為什麼用雜湊函數

`[00:28]`【口頭】
- 雜湊函數**本質上是對稱的演算法**。
- 攻擊雜湊函數（例如上週的 **SHA-3**）最好的量子方法**還是只有 Grover**，只能開平方根。
- 「所以我們**多少有保證**：雜湊函數本身**不能被量子電腦攻破**。」
- 「在格、編碼、雜湊三族裡，**雜湊式可能是最保守的**，因為有人能破 SHA-3 或 SHA-2 的機率**極小**。」

`[00:29]`【口頭】「**醒來**。我們要做**極度簡單**的事。這不是橢圓曲線群運算那種瘋狂的東西，**數學極簡單**。我們做的事看起來很怪、**簡單到不像真的**。」

### 2.3 一個天真的雜湊簽章

`[00:29]`

**金鑰產生**：
- **私鑰**：Alice 隨便選一個隨機數 $r$，例如 **512 bit**。
- **公鑰**：$P = f(r)$，$f$ 是**雜湊函數**（實務上例如 **SHA-3**，「你們昨晚或今早寫的作業」）。

【口頭】「私鑰是隨機數不奇怪；通常要花不少力氣算公鑰。這裡也算，但**方法極其簡單**。」

> 這裡用到雜湊函數的性質：**原像抵抗（單向性）**。「接下來 60 分鐘會一再出現。」

【課堂討論】`[00:31]` Oscar 最想知道哪個值？→ **私鑰 $r$**，「他大概就能簽了，例如『Alice 轉 1000 歐元到 Oscar 的帳戶』」。
【課堂討論】從 $f(r)$ 拿到 $r$ 要做什麼？
- 有人回答了真實世界的攻擊 →「**你太進階了**，要更簡單的答案。」
- →「**反轉（invert）**。」能做到嗎？→ **不能**，這就是**單向函數**的意思。「上週的 SHA-3：就算輸入只有 30 bit，給你 512 bit 的輸出，你**回不去**。」

**簽章**（`[00:33]`）：
> 【口頭】「**抓穩了。現在要做一件很蠢的事**，它行不通，但它有**一個很好的性質**。」
> 「**我們不管 $m$。Alice 直接說：私鑰 $r$ 就是簽章。**」

$$s = r$$

【口頭】「你會想：Christof 在說什麼？這很蠢。**它很蠢，但不是完全蠢。**」
- 今天講的全部都是**一次性簽章（one-time signature）** —— **全新的概念**：這個 $r$ **只能用一次**。
- 所以 Oscar 知道 $r$ 也不太要緊，因為只用一次。
- 「如果我每天做一次銀行轉帳，就先產生 365 個，可以用一年。所以也許沒那麼可怕。」
- 「**它還是很怪。請不要離開，這方案不是我想出來的。**」

**驗證**（`[00:35]`）：
- Bob 拿到 $(r, m)$。$f$ 是公開的（在書裡、在維基百科）。
- Bob 雜湊 $r$，檢查 $f(r) \stackrel{?}{=} P$。

```
   Alice                                    Bob
   r（隨機）
   P = f(r)
              ─────── P ───────→
   s = r
              ────── (m, r) ────→
                                    f(r) =? P
```

### 2.4 它提供了什麼

`[00:36]`【課堂討論】「這看起來不可能行得通。你們說得對，它不行。但還有一點點希望。**有人能做出這個智力上的跳躍嗎？如果檢查通過，Bob 知道什麼？**」
→ 學生答：**一定是 Alice 送的**。「**沒有別人**，就算我這個『有名的應用密碼學家』也送不出 $r$。」

| 服務 | 有嗎 | 理由 |
|---|---|---|
| **真實性** | ✔ | Oscar 想送 $(r, m')$，但他**不知道 $r$**，要反轉 SHA-3，「祝好運」 |
| **完整性** | ✘ | 【口頭】「Oscar 能把『轉 10 歐元』換成『轉 10,000 歐元』嗎？**當然**。驗證式裡**根本沒有 $m$**！這就是它看起來很蠢的原因。」 |
| **不可否認性** | ✘（大致上沒有） | Bob 也能把 $m$ 換成 $m'$，驗證照樣通過，法官無法分辨 $m$ 和 $m'$ |

【口頭】`[00:39]`「大家有沒有稍微鬆一口氣？沒有？一點點？」

#### 【Q&A】如果 Bob 拿到錯的公鑰呢？

`[00:40]`

**學生**指出：這假設 Bob 拿到的是**正確的**公鑰。

**教授答**：「**你 100% 對，是我教得不好。**」
- 隱含的假設是：Bob 拿到的 $P$ 寫著「我是 Alice 的公鑰」，而且是對的。
- 「**這一講沒寫下來，太馬虎了。**」需要**憑證**這種特別的機制來保證，「這門課最後一講（第 25 講左右）會講，你們 IT 安全學程之後還有網路安全的課大量談數位憑證。」
- 「就像對稱密碼我們**一直假設** Alice 和 Bob 有正確的共享金鑰一樣。」
- 【課堂討論】誰聽過瀏覽器的憑證？→ 大家都聽過。

#### 【Q&A】簽章跟訊息完全無關？

`[00:42]`

**學生**指出：Alice 簽章時**根本沒用到 $m$**。

**教授答**：「**很棒的問題。**對，不管 $m$ 是一個 bit 還是 1 GB、是 PDF 合約、email 還是電子投票，**簽章永遠是 $r$**。超蠢，**我們現在就來修**。」

> 「我們要用它保護**核彈發射指令**嗎？當然不。但有一點希望：**能做到真實性**不錯。」

## 3. Winternitz 一次性簽章（WOTS）

`[00:43]` OTS = **One-Time Signature**（一次性簽章）。

### 3.1 想法：每個訊息值一個不同的簽章

`[00:45]` 先看**很小的訊息**：**3 bit**（「不是大的 PDF，是 3 bit。懂了 3 bit，也許就能做 100 萬 bit」）。

3 bit 能表示 0～7 共 8 個值。**每個訊息值都要有不同的簽章**（上一節的問題就是不管 $m$ 都輸出同一個 $r$）。

| 訊息 $m$（二進位） | 十進位 | 簽章 |
|---|---|---|
| 000 | 0 | $r$ |
| 001 | 1 | $f(r)$ |
| 010 | 2 | $f(f(r)) = f^2(r)$ |
| 011 | 3 | $f^3(r)$ |
| 100 | 4 | $f^4(r)$ |
| **101** | **5** | $f^5(r)$ |
| 110 | 6 | $f^6(r)$ |
| 111 | 7 | $f^7(r)$ ← 這也是**公鑰** |

【口頭】
- 「**$f^2(r)$ 不是**學校學的代數平方（不是 $5^2 = 25$）。它是**記號**：**把 $f$ 連續套用兩次**。」
- 「$m = 5$ 時：把 $r$ 丟進 SHA-3 得到輸出，**再把輸出丟進 SHA-3**，再一次……共 **5 次**。」
- 「（有錯隨時糾正我，我很會犯錯。）」

#### 【Q&A】訊息越大跑越久？

`[00:50]`

**學生問**：訊息越大，執行時間不就越長？

**教授答**：
- 「每一列的輸出多長？→ 取決於**雜湊函數**，例如 512 bit。」
- 「（訊息額外負擔 message overhead）**不太好看**。**但另一個選擇是 NSA 或俄羅斯情報單位 10 年後破解你的訊息。**」
- 「這些下週都會改，我們會做更酷的事。」

> ⚠️ 學生的問題在字幕中不太清楚，上面依教授回答推斷。

### 3.2 雜湊鏈的圖像

`[00:53]`【口頭】「另一種表示法，**我比較喜歡**（不是我發明的，這很自然）。很多人看著那張表還是不太相信我在做什麼。」

```
  r ──f──→ f(r) ──f──→ f²(r) ──f──→ f³(r) ──f──→ f⁴(r) ──f──→ f⁵(r) ──f──→ f⁶(r) ──f──→ f⁷(r)
  ↑                                                           ↑                         ↑
私鑰                                                      簽章（m=5）                   公鑰
```

這叫**雜湊鏈（hash chain）**。

【口頭】「我剛剛有點偷偷摸摸：從私鑰開始做了一堆蠢步驟，最後說『這是公鑰』，把你們搞混了。**真實世界中，Alice 一開始就要從 $r$ 雜湊 7 次，算出公鑰。**」

#### 【Q&A】也需要公鑰吧？

`[00:55]`

**學生問**：（大意）還需要一把公鑰吧？

**教授答**：「**完美的問題。**陪我兩分鐘。」

### 3.3 三個階段：金鑰產生、簽章、驗證

`[00:57]`【口頭】「這是**三階段的協定**：」

**1. 金鑰產生**：
- 私鑰 $r$（隨機）
- 公鑰 $P = f^7(r)$（雜湊 7 次）

**2. 簽章**（$m = 5$）：
- Alice 在算公鑰的路上，**第 5 次雜湊後的中間值**就是簽章：
$$s = f^5(r)$$

**3. 驗證**（`[00:58]`）：

【課堂討論】還缺哪一步？→ **驗證**。「**你們不知道我在說什麼，對吧？沒人知道。別擔心，抓穩。**」

- Bob 拿到 $s$，還知道什麼？→「不是私鑰，但很接近」→ **公鑰** $P$。
- 【口頭】「答對的人**期末考加一分**。Bob 要怎麼從 $s$ 走到 $P$？」
- 【課堂討論】最後一排答：**再雜湊兩次**。「再一分！……開玩笑的，沒人有加分，別相信我。」

$$f^2(s) \stackrel{?}{=} P$$

**為什麼對**（`[01:00]`）：

$$f^2(s) = f^2(f^5(r)) = f^7(r) = P \;✔$$

【口頭】「（跟指數律一樣。）$r$ 跳了 1、2、3、4、5 次就是 $s$，**Bob 再幫它跳 6、7 兩次**，就到了終點。**我喜歡這張圖。**」

### 3.4 一般化

`[01:01]` 訊息每段有 **$w$ bit**（$w$ 是 **Winternitz 參數**；「$w$ 可以代表 window，也可以代表 Winternitz，你自己選」）。

| 階段 | 公式 |
|---|---|
| 公鑰 | $P = f^{2^w - 1}(r)$ |
| 簽章 | $s = f^m(r)$ |
| 驗證 | $v = f^{2^w - 1 - m}(s) \stackrel{?}{=} P$ |

$w = 3$ 時：$2^3 - 1 = 7$，所以公鑰 $f^7(r)$，驗證 $f^{7-5}(s) = f^2(s)$。

【口頭】`[01:04]`「我應該先說：從 $r$ 走到公鑰要 **$2^w - 1$ 步**。（第一次教這個，明年會更好。）」

#### 【Q&A】$w$ 能不能選大一點，例如 1024？

`[01:02]`

**學生問**：選一個好數字，例如 $w = 1024$ 會怎樣？

**教授答**：「我正要問這個。」
- 如果 $w = 1024$，最大的訊息值是 $2^{1024} - 1$，公鑰要雜湊 $2^{1024} - 1$ 次 → 「**宇宙的壽命**」。
- 「所以實務上 **$w$ 很適中，例如 8**。」

#### 完整協定（$w = 3$）

`[01:05]`

```
   Alice                         Oscar                         Bob
   k_pr = r
   k_pub = P = f⁷(r)
              ─────────────── k_pub ──────────────────→
   m = 5
   s = f⁵(r)
              ──── (m, s) ────→（放左邊，等一下要攻擊）
                                                          v = f^{7−m}(s) = f²(s)
                                                          v =? P
```

【口頭】「這跟剛剛的資訊**完全一樣**，只是另一種寫法 —— 不是為了搞混你們，是要讓你們看**一般密碼學怎麼寫**。」

### 3.5 安全服務

`[01:10]`（假設**公鑰正確分發**；「如果公鑰來自 Oscar，一切都完了」）

| 服務 | 有嗎 | 理由 |
|---|---|---|
| **真實性** | ✔ | Oscar 要產生簽章需要 $r$；從公鑰**不能往回走** |
| **完整性** | ✔（但見下節） | 【課堂討論】Oscar 把 $m = 5$ 換成 $m = 4$？→「它不會回到公鑰」。Bob 會雜湊 $7 - 4 = 3$ 次，對不上 |
| **不可否認性** | ✔ | Bob 只能**往前**走（從 $s$ 跳一下、兩下到公鑰），**自己產生不了 $s$**。「跟 RSA 一樣」 |

【口頭】「全部打勾，太棒了，它能用！**但剛剛有人提了一個很好的攻擊。**」

### 3.6 攻擊：訊息遞增攻擊

`[01:13]`【口頭】「我很狡猾：我問『Oscar 把 5 換成 4 會怎樣』，那不行。**但反過來可以！**」

教授叫它**訊息遞增攻擊（message incrementation attack）**（「文獻可能有這個名字，我不確定」）：

- Oscar 攔截 $(m, s) = (5, f^5(r))$。
- 他把訊息改成 $m' = 6$（或 7）。
- 【課堂討論】從 $s = f^5(r)$ 要怎麼得到 $m' = 7$ 的簽章？→「**再雜湊兩次**」（$f(f(s))$）。
- **只能往前走、不能往回走** —— 但**往前走正好就是把數字變大**！
- Oscar 送出 $(m', s')$，**驗證照樣通過**。

$$s' = f^{m' - m}(s) = f^{m'}(r)$$

【口頭】「這很糟。**而且很方便**：等你當上教授教密碼學，這是個好例子 —— 用電子轉帳，**把金額加大**，很酷吧。」

#### 【Q&A】學生的對策想法

`[01:17]`

**學生**：問題是我們不能確定收到的訊息和簽章是對的。可以送一個比較精巧的「**濃縮值**」來確保嗎？

**教授答**：「**正是我們要做的。**我們要做一個**精巧版的同位元檢查（parity bits）**。你甚至可能想到用雜湊檢查碼，他們做的有點不一樣。」

### 3.7 對策：檢查碼

`[01:18]`【口頭】密碼學裡這叫**對策（countermeasure）**。

**三件事**：
1. 對要送的訊息**算一個檢查碼（checksum）**（「其實計算很簡單」）。
2. **簽「訊息 + 檢查碼」**。
3. 但要小心：**檢查碼本身也不能被遞增**。

#### 步驟 a：把長訊息切成 $w$ bit 的「數字」

`[01:19]`【口頭】「我先跳一下，抱歉。上面我們只做了 3 bit 的玩具。實際上要簽的是**幾 MB 的 PDF**（幾百萬 bit）。」

$$M = (m_0, m_1, \ldots, m_{L-1}), \quad \text{每個 } m_i \text{ 有 } w \text{ bit}$$

- 實務上 **$w = 8$**，每段就是**一個 byte**。「很多訊息類型（email、PDF）本來就是以 byte 表示。」
- 例：$n = 800$ bit、$w = 8$ → $L = 100$ 段。
- $L = \lceil n / w \rceil$（800 能整除，803 就要無條件進位）。
- 【課堂討論】每段可能的值？→ $0, 1, \ldots, 2^w - 1$。$w = 8$ 時最大是？→ **255**。

#### 步驟 b：算檢查碼

`[01:22]`

> $$\boxed{C = \sum_{i=0}^{L-1} \left( (2^w - 1) - m_i \right)}$$

【口頭】「**小心，別抄錯，會死的**（開玩笑）。」
- 「簡單的做法是直接加總 $m_i$，**但那行不通**：遞增任何 $m_i$，$C$ 也會跟著變大，攻擊者剛好可以利用。」
- 「所以我們用一個小技巧：**用最大值 $2^w - 1$ 減掉 $m_i$** —— 某種意義上取它的『反向』。」

> ⚠️ 學生問「為什麼要取負的」，教授問助教習題課會不會講，答案不清楚（「也許講一點點」）。
>
> **筆者補充（推理，非課堂原話）**：這樣設計之後，攻擊者如果把某個 $m_i$ **變大**（他唯一做得到的方向），$C$ 就會**變小**；而 $C$ 也被同一套雜湊鏈簽了，要讓 $C$ 的某些數字**變小**就得在雜湊鏈上**往回走** —— 也就是反轉雜湊函數，做不到。所以「遞增訊息」和「遞增檢查碼」**不可能同時成立**。

**$C$ 有多長**（`[01:24]`、`[01:26]`）：
- 加總很多個 $w$ bit 的值，會得到比 $w$ 多一些的 bit。
- 【課堂討論】什麼情況 $C$ 最大？→ 每個 $m_i = 0$ → $C_{\max} = L \cdot (2^w - 1)$。
- 「看起來很糟，其實**不糟**：$C$ 的位數只跟 $L$ 成**對數**關係。例如 1024 段，大約只多 $\log_2 1024 = 10$ 個 bit。」
- 把 $C$ 也切成 $w$ bit 的數字：$C = (c_0, \ldots, c_{K-1})$。$K$ **很小**。

#### 步驟 c：準備要簽的輸入

$$M \,\|\, C = (m_0, \ldots, m_{L-1}, c_0, \ldots, c_{K-1})$$

【口頭】（$\|$ 是「接在一起」的符號，「沒什麼神奇的」。）之後不區分訊息和檢查碼，統一叫 **$MC_0, \ldots, MC_{J-1}$**，$J = L + K$。（「這個記號有點蠢，我從某本書抄來的，抱歉。」）

### 3.8 完整的 WOTS

`[01:30]`【口頭】「這是我們**第一次**談**怎麼簽長訊息**。之前的玩具只簽 3 bit；**現在要簽 100 萬 bit 左右**。」

**每個 $w$ bit 的數字，都配一條自己的雜湊鏈、一個自己的隨機數。**

| 階段 | 做法 |
|---|---|
| **金鑰產生** | 私鑰：$J$ 個隨機數 $r_0, \ldots, r_{J-1}$<br>公鑰：$p_i = f^{2^w - 1}(r_i)$，$i = 0, \ldots, J-1$<br>（$w = 8$：每個 $r_i$ 雜湊 **255 次**） |
| **簽章** | $s_i = f^{MC_i}(r_i)$<br>例：$MC_0 = 113$ → 把 $r_0$ 雜湊 113 次 |
| **送出** | $(M \| C, \; s_0, \ldots, s_{J-1})$ |
| **驗證** | 對每個 $i$：$f^{(2^w - 1) - MC_i}(s_i) \stackrel{?}{=} p_i$ |

【口頭】`[01:33]`「講了 90 分鐘很累，大家都累了。$w = 8$ 時每個 $MC_i$ 的範圍？→ 0、1、2……最大 255。」

#### 【Q&A】跟傳統簽章比，效率怎樣？

`[01:36]`

**學生問**：（大意）這跟傳統簽章比效率如何？

**教授答**：
- 「很難說。首先它**不算太糟**：$w$ 例如 8 的話，就是一堆**雜湊運算**。」
- 「**完全沒有指數運算**，只有雜湊。你付出的代價是**雜湊次數**，但**雜湊通常很快**。」

#### 【Q&A】$J$、$K$、$L$ 是什麼？

**學生問**：$J$、$K$、$i$ 只是索引嗎？

**教授答**：「**好問題。$J = L + K$**，我應該說的。」
「**第一次教，歡迎批評我。**你們平常看的影片是我教了大約 15 年後錄的（我 1995 年開始教，『那時用泥板』，開玩笑的），在美國有時一年教兩次。**這次是第一次。**」

## 4. 對 WOTS 的攻擊（簡述）

`[01:38]`【口頭】「我們完全沒空間了，很簡短，**只是兩個關鍵字**，連一章都不算。」

| 攻擊 | 說明 |
|---|---|
| **反轉 $f$** | 「這很糟，相當於**破解 AES**：用數學方法算出金鑰。」 |
| **重複使用** | **非常不簡單**：一旦用某組隨機數簽了一則訊息，**它們就必須丟掉**。「習題課會講。**這在實務上是很大的問題。**」 |

**一次性的根本問題**（`[01:40]`）：
- 公鑰是從這些隨機數算出來的，**只能簽一次**，「就像 One-Time Pad」。
- **每簽一次，就要送一把新的公鑰** → 「**這不太好。**」

> 【口頭】「下一講（其實是兩週後）會解決：**怎麼從一次性雜湊簽章變成多次簽章**。基於 **Merkle 樹（雜湊樹）**，跟**加密貨幣**有點關係。**真的很酷。**謝謝大家。」

## 5. 一頁速查表

### 5.1 量子電腦的影響

| | 對稱（AES） | 公鑰（RSA、DL、ECC） |
|---|---|---|
| 量子演算法 | **Grover** | **Shor** |
| 效果 | $2^n \to 2^{n/2}$（有效長度砍半） | **完全破解**，加長金鑰沒用 |
| 對策 | **用 256 bit**（AES-256 就是為此存在） | **換演算法 → 後量子密碼學** |

大型量子電腦：**目前不存在**，可能 10～20 年內出現。

### 5.2 後量子密碼學

| 項目 | 內容 |
|---|---|
| 意思 | 能抵抗量子電腦的**普通**演算法（**不**用量子效應） |
| 命名 | 據說由 Dan Bernstein 提出 |
| 家族 | **格**（簽章 + KEM）、**編碼**（KEM，最老）、**雜湊**（簽章，最保守）、多變數 |
| KEM | Key Encapsulation Mechanism ≈ 金鑰傳輸 |

### 5.3 天真雜湊簽章

| | |
|---|---|
| 私鑰 / 公鑰 | $r$ / $P = f(r)$ |
| 簽章 | $s = r$（跟 $m$ 無關！） |
| 驗證 | $f(s) \stackrel{?}{=} P$ |
| 提供 | ✔ 真實性；✘ 完整性；✘ 不可否認性 |

### 5.4 WOTS（一段 $w$ bit）

```
r ─f→ f(r) ─f→ … ─f→ f^m(r) ─f→ … ─f→ f^{2^w−1}(r)
私鑰                  簽章 s                公鑰 P
```

| 階段 | 公式 |
|---|---|
| 公鑰 | $P = f^{2^w-1}(r)$ |
| 簽章 | $s = f^m(r)$ |
| 驗證 | $f^{2^w-1-m}(s) \stackrel{?}{=} P$ |
| 例（$w=3, m=5$） | $s = f^5(r)$，驗證 $f^2(s) = f^7(r)$ |
| 實務 | $w = 8$（一個 byte） |

### 5.5 遞增攻擊與檢查碼

| 項目 | 內容 |
|---|---|
| 攻擊 | 雜湊鏈**只能往前走** → Oscar 能把 $m$ **變大**：$s' = f^{m'-m}(s)$ |
| 對策 | 檢查碼 $C = \sum_i \left((2^w - 1) - m_i\right)$ |
| 原理 | $m_i$ 變大 → $C$ 變小 → 要往回走 → 做不到 |
| $C$ 的長度 | 跟 $L$ 成對數關係（很短） |

### 5.6 完整 WOTS

訊息切成 $L$ 段 + 檢查碼 $K$ 段 = $J$ 段，每段一條雜湊鏈：
- 私鑰 $r_0, \ldots, r_{J-1}$；公鑰 $p_i = f^{2^w - 1}(r_i)$
- 簽章 $s_i = f^{MC_i}(r_i)$；驗證 $f^{2^w - 1 - MC_i}(s_i) = p_i$
- **只有雜湊，沒有指數運算**
- **只能用一次**

## 附：本講一句話總結

> **量子電腦的 Grover 演算法只會把對稱金鑰長度砍半（所以用 AES-256 就好），但 Shor 演算法會徹底打垮 RSA、離散對數和橢圓曲線，所以需要「後量子」公鑰演算法；其中最保守的是只靠雜湊函數的簽章 —— Winternitz 一次性簽章把訊息值編碼成「在雜湊鏈上走幾步」，再用一個反向的檢查碼擋住「只能往前走」帶來的遞增攻擊，代價是每把金鑰只能用一次。**
