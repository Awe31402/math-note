## 2. 密碼學的分類

### 2.1 Cryptology = Cryptography + Cryptanalysis

`[00:10]` **最上層的詞不是 cryptography，是 cryptology（密碼學 / 密碼科學）。** 它分成兩支：

```
              Cryptology（密碼學）
              ├── Cryptography（密碼編碼學）
              │     ├── Symmetric Ciphers（對稱式）
              │     ├── Asymmetric Ciphers（非對稱式 = 公鑰）
              │     └── Protocols（協定）
              └── Cryptanalysis（密碼分析學）
```

| 分支 | 意思 | 白話 |
|---|---|---|
| **Cryptography** | 秘密書寫的科學，目的是**隱藏訊息的意思** | 好人：想辦法加密 |
| **Cryptanalysis** | **破解**密碼系統的科學（有時是藝術） | 想辦法破解加密 |

#### 為什麼「破解」也算一門正經學問？

【口頭】教授故意問：破解不就是駭客、俄羅斯黑手黨、情報單位在做的事嗎？為什麼要寫在科學分類的黑板上？
（他說等一下再解釋 → 答案在 [§4 Kerckhoffs 原則](#4-加密方法要公開嗎kerckhoffs-原則)。）

課本給的答案：
- 現在大部分密碼分析是**學術界正派的研究者**在做。
- **沒有人試著去破解，我們就永遠不知道一個加密方法到底安不安全。**
- 所以 cryptanalysis 是唯一能確認密碼系統安全的方法，是 cryptology 不可缺的一部分。

這門課**主要講 cryptography**，但會一直提到 cryptanalysis。

### 2.2 Cryptography 的三個分支

| 分支 | 說明 |
|---|---|
| **Symmetric（對稱式）** | 兩方共用**同一把秘密金鑰**來加密、解密。**1976 年以前所有密碼學都是對稱式的**。現在仍大量用於資料加密與完整性檢查 |
| **Asymmetric（非對稱式）** | 1976 年由 Diffie、Hellman、Merkle 提出。每個人有一把**秘密金鑰**和一把**公開金鑰**。可用於數位簽章、金鑰建立，也可用於加密 |
| **Protocols（協定）** | 把演算法**當積木**組成應用。例如瀏覽器用的 **TLS** |

> **Asymmetric cryptography = Public-key cryptography，兩個詞完全一樣。**【口頭】「沒有任何差別。」

【課本補充】
- **Hash function（雜湊函數）** 嚴格說是第三類演算法，但跟對稱式密碼有些共同特性（第 20–22 講）。
- 實際系統裡，對稱、非對稱、雜湊通常**一起用**，叫 **hybrid scheme（混合架構）**，因為每一類都有自己的強項和弱點。

#### 【口頭】兩學期課程的時間分配

`[00:13]` 這門課是 Intro to Cryptography 1 + 2，共兩學期（冬季 + 夏季）。

| 部分 | 比例 |
|---|---|
| 對稱式演算法 | 約 35–40% |
| 非對稱式演算法 | 約 35–40% |
| 協定（數位簽章、雜湊函數、真實協定） | 約 20–30% |

### 2.3 密碼學 vs 資訊安全

`[00:14]`【口頭】教授提醒：你的學位叫 **IT Security（資訊安全）**，不叫 Cryptography。

```
  ┌─────────── Security（資訊安全）────────────┐
  │  安全軟體   安全作業系統   安全硬體   ...   │
  │            ┌──────────────┐                │
  │            │ Cryptography │ ← 核心元件      │
  │            └──────────────┘                │
  └────────────────────────────────────────────┘
```

兩句話記住這個關係：

1. **只有密碼學，不夠。** 如果光靠密碼學就能安全，你修完這兩學期就可以畢業「發財出名」了。還需要安全的軟體、作業系統、硬體等。
2. **沒有密碼學，不行。** 幾乎沒有任何安全應用是不用密碼學的。只有周邊、沒有密碼學，**什麼安全的東西都做不出來**。

> 【口頭】「密碼學是現代安全設計、安全工程的**基礎**，所以第一學期就教它。」

## 3. 對稱加密的基本架構

### 3.1 Alice、Bob、Oscar 與不安全的通道

`[00:18]` 最簡單的問題：**兩個人想透過不安全的通道（insecure channel）溝通。**

| 角色 | 身分 |
|---|---|
| **Alice** | 好人，傳送方 |
| **Bob** | 好人，接收方 |
| **Oscar** | 壞人，攻擊者（名字取自 **o**pponent，「對手」） |

**Channel（通道）** 就是傳輸媒介，例如：網際網路、GSM 的空中無線電、Wi-Fi。

【口頭】為什麼通道不安全：
- 70 年代可以向德國郵政**租一條點對點專線**，那大致是封閉的。
- 但網際網路成功的原因正是它**開放**。
- 你從 Bochum 寄 email 到隔壁的 Cologne，封包可能被繞到德國外、甚至歐洲外。**我們根本不知道通道上發生什麼事、有沒有人竊聽。**

**竊聽（eavesdropping）**：Oscar 偷聽通道上的訊息。

【口頭】另一個解法是不走網路，派**專人送信** —— 可以，但「你得買火車票，什麼都很慢」。我們還是想用 email。

### 3.2 加密與解密

`[00:22]` 解法：Alice 先**加密**，Bob 收到再**解密**。

```
                       Oscar（壞人）
                          ↑ 只看到 y
                          │
Alice ──x──→ [ e() ] ──y──→ 不安全通道 ──y──→ [ d() ] ──x──→ Bob
```

- **加密（encryption）** $e$：某種數學函數，把 **plaintext（明文）** $x$ 變成 **ciphertext（密文）** $y$。
- **解密（decryption）** $d$：反過來，把 $y$ 變回 $x$。解密就是加密的反函數。
- 好的密碼學：**對 Oscar 來說，$y$ 看起來就像隨機位元**，裡面沒有任何對他有用的資訊。

### 3.3 加入金鑰 k

`[00:33]` 問題來了：如果 $e$、$d$ 都公開（見 §4），Oscar 拿 $d$ 一樣能解開 $y$。

**缺的那一塊是金鑰（key）$k$**：

$$y = e_k(x) \qquad\qquad x = d_k(y)$$

- 加密不只看明文 $x$，也看金鑰 $k$。
- **Bob 必須有一模一樣的金鑰，才能解密。**

```
Alice ──x──→ [ e() ] ──y──→ 不安全通道 ──y──→ [ d() ] ──x──→ Bob
               ↑                                ↑
               k ←────── 安全通道 ──────→ k
```

### 3.4 五個基本符號

【口頭】「這五個基本參數，從今天起**每一週**都會用到。」

| 符號 | 名稱 | 說明 |
|---|---|---|
| $x$ | **Plaintext / Cleartext** 明文 | 原本的訊息 |
| $y$ | **Ciphertext** 密文 | 加密後的訊息 |
| $k$ | **Key** 金鑰 | 只有 Alice 和 Bob 知道 |
| $e()$, $d()$ | **Encryption / Decryption** 加密 / 解密函數 | 公開的演算法 |
| $\mathcal{K}$ | **Key space** 金鑰空間 | **所有可能金鑰的集合**。它的大小 $\lvert\mathcal{K}\rvert$ 就是「金鑰有幾種」 |

【課堂討論】`[00:36]` 教授問：最簡單的破解方法是什麼？學生答：**暴力法（brute force）** —— 把所有金鑰都試一遍。這就是為什麼 key space 的大小很重要（細節見 [§6](#6-攻擊-1暴力搜尋brute-force)）。

### 3.5 金鑰怎麼送過去？

【課堂討論】`[00:38]` 開始加密前，Alice 和 Bob 要先**共享金鑰**。
- 最簡單：Alice 直接把金鑰從不安全通道傳過去。
- 為什麼很蠢：**Oscar 也會拿到金鑰。**

所以需要另一條**安全通道（secure channel）**。它聽起來很高級，其實可以是：

| 安全通道 | 例子 |
|---|---|
| 郵寄信件 | 網路銀行的一次性密碼（TAN）用郵寄 |
| 電話 | 在電話上約定秘密金鑰 |
| 專人遞送 | 有人帶著金鑰在 Alice、Bob 之間跑 |

【課本補充】
- Wi-Fi WPA 的 **pre-shared key（預先共享金鑰）** 就是這種方式的好例子。
- 金鑰只需要安全傳一次，之後可以用很多次。
- 課本之後會教**在不安全通道上建立金鑰的方法**（→ 第 13 講 Diffie-Hellman）。
- 如果 Oscar 拿到金鑰，他就能輕鬆解密（因為演算法是公開的）。所以**「安全傳訊」的問題被轉化成「安全傳金鑰 + 安全保存金鑰」的問題**。
- 這裡只談**機密性（confidentiality）**，也就是不讓別人看懂內容。密碼學還能做到**完整性（integrity）**（訊息沒被偷改）、**來源認證（authentication）**（訊息真的是 Alice 送的），後面才講。

## 4. 加密方法要公開嗎？Kerckhoffs 原則

### 4.1 【課堂討論】「價值 64,000 美元的問題」

`[00:24]` 教授問：**加密函數 $e$ 和解密函數 $d$，應該保密還是公開？**

| 學生立場 | 理由 |
|---|---|
| 公開 | （當時還沒講到金鑰，但有人已經想到「只要有金鑰就好」） |
| 保密 | 大家都知道怎麼解密，Oscar 也能解密，**公開很蠢** |
| 公開 | **只有公開，才能知道這些函數是不是真的安全** ← 教授要的答案 |

【口頭】歷史上：
- 密碼學很古老。約**西元前 2000 年**的埃及就有「加密的」象形文字。
- 從那時到 **1970 年代初**，人類都認為**把加解密函數保密比較安全**。
- **這是錯的。人類做錯了 4000 年。**

### 4.2 為什麼密碼學很特別：你不知道自己有沒有成功

`[00:28]`【口頭】教授拿一般工程做對比：

> 老闆叫你設計一台**只耗 3 公升油**的車。你造出來上路一測：2.9 公升 → 成功，老闆愛你；6 公升 → 失敗，你被開除。
> **一般工程裡，你很清楚自己有沒有達成目標。密碼學不是這樣。**

### 4.3 【口頭】思想實驗：48 小時、1 萬歐元

`[00:29]`
> 教授：「給你們 48 小時、沒有網路、只有紙筆。誰能設計出真正安全的密碼系統，我給他 10,000 歐元。」

會發生什麼事：
1. 週六會有 150 個人來敲門，每個人都帶著「牢不可破」的設計。
2. **大概三分之二到四分之三的人會真心相信自己的設計很安全**：「我做了這個矩陣，再做排列、交換……沒人能破。」
3. 結果：**150 個設計，每一個都很不安全。**

為什麼？
> 【口頭】「因為你不是有經驗的密碼設計者。我做這行 15 年了，**我也不設計加密演算法**。要做出真正安全的密碼系統非常難；但要做出**連自己都相信很安全**的東西，非常容易。」

**歷史例子：Enigma**
二戰時納粹德國**深信** Enigma 很安全，但波蘭、英國、美國一直在破解德軍的通訊。

### 4.4 唯一的出路：公開，讓別人來破

`[00:31]` 確認加解密函數強不強的**唯一方法**：

1. **公開它**：寫成論文、在研討會上發表。
2. 讓 cryptanalysis 的人（→ 回扣 §2.1 為什麼「破解」也是學問）**試著破解**。
3. 很聰明的人花了 1 年、3 年、甚至 10 年都破不了 → **我們才信任這個演算法**。

> 【口頭】「除了極少數情況，**沒有數學證明能保證一個加密演算法是安全的**。我們只能得到一種『溫暖模糊的感覺』（warm fuzzy feeling）：沒人破得了，所以它大概是（計算上）牢不可破的。」

### 4.5 ⚠️ 實務守則：不要自己發明加密法

`[00:32]`【口頭】
> 「**實務上，絕對不要用自製的加密演算法。**」

教授的親身經驗：
- 他跟業界合作過不少，有幾次廠商讓他看他們**自己做的加密**。
- **每一次都被破解了。**
- 「而且我不是什麼世界有名的破解高手。**要做出很爛的加密，實在太容易了。**」

結論：只用**標準化、公開過的演算法**（例如課本裡的那些）。

### 4.6 Kerckhoffs 原則（Kerckhoffs' Principle）

`[00:40]` Auguste Kerckhoffs，**1883 年**提出。

> ⚠️ 逐字稿缺字：原則的完整敘述在自動字幕中掉了，以下依課本 Definition 1.3.1 意譯。

> **Kerckhoffs 原則**：一個密碼系統，即使攻擊者（Oscar）知道系統的**所有細節**，只要不知道**秘密金鑰**，就仍然要是安全的。特別是：攻擊者知道加密與解密演算法時，系統仍須安全。

一句話：**唯一需要保密的，只有金鑰。**

【口頭】教授特別強調這一條的份量：
> 「如果你這個週末決定不念資訊安全，改念資工、機械或法國文學 —— **這是你一輩子應該帶走的一件事。**」
> 「這幾乎是整門課最重要的訊息。一旦知道了，它並不複雜。但人類做錯了 4000 年，而且之後又花了大約 90 年，大家才真正普遍接受。」

#### 為什麼它違反直覺

`[00:45]`【口頭】
- 一般人直覺是：把加解密藏起來，系統更安全。
- 這在**攻擊者不知道 $e$、$d$ 的時候**確實成立。
- 但現在所有東西都是大眾產品，**攻擊者遲早會拿到 $e$ 和 $d$**。一旦拿到，整個系統就垮了。

【課本補充】
- 「靠隱藏細節來求安全」這種做法叫 **security by obscurity（靠隱晦求安全）**。
- 經驗和軍事史一再證明：這種系統幾乎都很弱，一旦被**逆向工程（reverse engineering）** 或外洩，馬上被破。
- 例子：DVD 的版權保護 **CSS（Content Scrambling System）**，被逆向工程後很快就被破解了。

## 5. 替換密碼（Substitution Cipher）

### 5.1 背景：「歷史密碼」= 又老又笨的密碼

`[00:46]`【口頭】
> 「大家說 **historical cipher（歷史密碼）** 的時候，意思就是**又老又笨**的密碼。它們全都不安全，都能被或多或少輕鬆破解。叫它們『歷史密碼』只是比較客氣的說法。」

【口頭】直到約 30–40 年前，幾千年來的密碼都是**以字母為單位**加密文字。
現代的密碼沒有一個是逐字母加密的，全部都是**以 bit 或 byte 為單位**，處理數位資料。

### 5.2 規則

**把字母表中的每個字母，換成另一個字母。**（substitution = 替換、取代）

- 這個**替換表（substitution table）本身就是金鑰**。
- 慣例：**大寫 = 明文，小寫 = 密文**。
- 替換表要**完全隨機**挑選，攻擊者才猜不到。

### 5.3 例子：加密 ABBA

課本和影片用的替換表**不一樣**，兩邊都列出來：

| | 影片（黑板） | 課本 Example 1.1 |
|---|---|---|
| A → | **l** | **k** |
| B → | **d** | **d** |
| C → | **w** | **w** |
| `ABBA` 加密後 | `lddl` | `kddk` |

規則很直覺：每次看到 A 就換成同一個字母，每次看到 B 就換成同一個字母。

> 【口頭】「我為什麼要講這個？不只是給你們看一個笨的加密法。**真正有趣的是接下來 10 分鐘：怎麼破解它。**」

### 5.4 【課堂討論】這樣安全嗎？

`[00:51]` 教授要大家只能回答「是」或「否」。

> 教授（開玩笑）：「誰覺得這很安全、而且想被這間大學退學的，舉手？」

**答案：不安全。** 接下來看兩種攻擊。

## 6. 攻擊 1：暴力搜尋（Brute-force）

### 6.1 定義

`[00:52]` 又叫 **exhaustive key search（窮舉金鑰搜尋）**：**把所有可能的金鑰都試一遍。**

【口頭】「這幾乎是條件反射。看到一個密碼系統想破它，先看 key space：**能不能直接暴力搜尋？**」

【課本補充】課本的正式定義（Definition 1.2.1，意譯）：

> 設 $(x, y)$ 是一組明文和對應的密文，key space $\mathcal{K} = \{k_1, \ldots, k_\kappa\}$。
> 暴力攻擊就是對每一把 $k_i \in \mathcal{K}$ 檢查：
> $$d_{k_i}(y) \stackrel{?}{=} x$$
> 等號成立 → 可能找到正確金鑰；不成立 → 試下一把。

**Oscar 怎麼會有一小段明文 $x$？** 例如被加密檔案的**檔頭（header）** 通常是固定格式。

【口頭】實際上也可以不需要已知明文：每把金鑰解出一段明文，看看**它像不像有意義的文字**（例如 email 內容）。

- 暴力攻擊對對稱密碼**原則上永遠可行**。實際上可不可行，**完全看 key space 有多大**。
- 如果用很多台電腦試完所有金鑰要好幾十年 → 這個密碼對暴力攻擊是 **computationally secure（計算上安全）**。
- 【課本補充】實務上，錯的金鑰有時也會解出「看起來對」的結果（false positive），這在第 10 講（課本 §5.2）處理。

### 6.2 替換密碼的 key space 有多大

`[00:53]`【口頭】大部分現代對稱密碼很簡單：**金鑰有幾個 bit 就好。** 64 bit 金鑰 → $2^{64}$ 把金鑰，「討論結束」。

替換密碼比較麻煩：要算**有幾種不同的替換表**。

**一步一步數：**

| 字母 | 可以換成幾種 | 原因 |
|---|---|---|
| A | 26 | 26 個字母都可以 |
| B | 25 | 已經用掉 1 個 |
| C | 24 | 已經用掉 2 個 |
| … | … | … |
| Z | 1 | 只剩 1 個 |

全部乘起來：

$$|\mathcal{K}| = 26 \times 25 \times 24 \times \cdots \times 2 \times 1 = 26! \approx 4 \times 10^{26} \approx 2^{88}$$

> ⚠️ 逐字稿缺字：$26! \approx 2^{88}$ 這個換算在字幕中掉了，依課本補上。
> 自己驗算：$\log_2(26!) \approx 88.4$，所以 $26! \approx 2^{88}$。✔

#### 【口頭】$2^{88}$ 到底有多大？COPACOBANA 的例子

`[00:55]` 教授的研究團隊造了一台破解機 **COPACOBANA**（他說是全世界大學裡最強的破解機之一）。

| 搜尋量 | COPACOBANA 要花多久 |
|---|---|
| $2^{56}$ | **幾天**（而且這台機器很難造） |
| $2^{88}$ | 是 $2^{56}$ 的 $2^{88-56} = 2^{32}$ 倍難 |

$2^{32} \approx 4.3 \times 10^9$。【口頭】教授口頭說「大約十億倍」，意思就是：**如果 $2^{56}$ 要 1 天，$2^{88}$ 就要約 10 億天以上。**

> 【口頭】「$2^{88}$ 我們現在做不到。**沒有人做得到**，連 CIA、NSA 都不行。」

**結論**：key space 太大，**不能暴力搜尋**。（所以作業不用試暴力法 —— 「那樣出作業就太壞了」。）

> 看起來很安全？**錯。**還有更強的攻擊。

### 6.3 【課本補充】金鑰要多長才夠？

這一段課本有（§1.3.2），課堂上沒講。

#### 兩個常被誤會的重點

1. **金鑰長度只在「暴力法是最好的攻擊」時才有意義。** 如果有分析攻擊（像下一節的頻率分析），key space 再大都沒用。社交工程、實作攻擊也一樣。
2. **對稱和非對稱的金鑰長度不能直接比。** 例如 80 bit 對稱金鑰 ≈ 1024 bit RSA 金鑰的安全度。

#### 對稱密碼面對暴力攻擊的大致安全度（Table 1.2 整理）

| 金鑰長度 | 安全度估計 |
|---|---|
| **56–64 bit** | **短期**：幾小時到幾天就能破 |
| **112–128 bit** | **長期**：幾十年（前提：沒有量子電腦） |
| **256 bit** | **長期**：幾十年，**就算有**目前已知演算法的量子電腦也一樣 |

> 注意：key space 夠大是**必要條件**，但**不是充分條件**。密碼還必須能擋住分析攻擊。

#### Moore's Law 對破解成本的影響

**Moore's Law（摩爾定律）**：運算能力約每 **18 個月翻倍**，成本不變。

例子：今天破解某密碼要 **1 個月、價值 100 萬美元**的電腦。

| 時間 | 同樣 1 個月內破解的成本 |
|---|---|
| 今天 | \$1,000,000 |
| 18 個月後 | \$500,000 |
| 3 年後 | \$250,000 |
| 4.5 年後 | \$125,000 |
| 15 年後（翻倍 10 次） | $\$1{,}000{,}000 / 2^{10} \approx \$1{,}000$ |

換個角度：15 年後一樣花 100 萬美元，**約 45 分鐘**就能破解。
課本比喻：Moore's Law 就像**年利率 50% 的複利存款**，成長非常非常快。

## 7. 攻擊 2：字母頻率分析

### 7.1 核心弱點

`[00:57]` 替換密碼的問題：**替換表是固定的。**

> 每次明文出現 A，密文一定出現同一個字母（例如 l）。

所以**明文的統計特性，會原封不動地留在密文裡。**

### 7.2 英文字母不是平均分布的

`[00:58]` 如果 26 個字母平均出現，每個約 $1/26 \approx 3.8\%$。實際上差很多：

| 排名 | 字母 | 頻率 |
|---|---|---|
| 1 | **E** | **約 12.7%** |
| 2 | T | 約 9.1% |
| 3 | A | 約 8.2% |
| 4 | O | 約 7.5% |
| 5 | I | 約 7.0% |
| … | … | … |
| 倒數 | J、X | 約 0.15% |
| 倒數 | Q | 約 0.10% |
| 最少 | Z | 約 0.07% |

（數字依課本 Table 1.1。）

【口頭】
- 英文和德文的 **E 都是最常見**，頻率幾乎一樣。大約**每 7–8 個字母就有一個 E**。
- 英文第二名是 T，德文不一樣（教授說他腦中沒有德文表）。

### 7.3 怎麼攻擊

`[00:59]`【口頭】教授的例子：

1. 數密文中**每個字母出現幾次**。
2. 假設發現 **q** 佔了 13%。
3. Q 在英文裡是很少見的字母，不可能自己就這麼多 → **q 幾乎一定是 E**。
4. 把所有 q 換成 E，**一口氣就解出 13% 的字母**。

> 【口頭】「最容易猜到的字母，剛好也是最重要的字母，因為它們一直出現。」

【課本補充】三種技巧，實際上會**合併使用**：

| 技巧 | 做法 |
|---|---|
| **單字母頻率** | 數每個密文字母的頻率，對照語言的頻率表。就算密文很短，最常見的幾個字母通常也認得出來 |
| **字母組合** | 看兩個、三個、四個字母的組合。例如英文的 **Q 後面幾乎一定是 U** |
| **常見短字** | 如果能找到空格，就能抓常見短字如 **THE、AND**。認出一個字，整篇就知道好幾個字母 |

課本 Example 1.2 的密文用頻率分析解開後是：`WE WILL MEET IN THE MIDDLE OF THE LIBRARY AT NOON ALL ARRANGEMENTS ARE MADE`。

### 7.4 【口頭】教授的作業經驗

`[01:00]`
- 教授在美國麻州教了 7 年密碼學，一直**不敢**把「破解替換密碼」當作業。
- 2001 年到 Bochum 才第一次試。一開始很怕太難，給了很多提示。
- 結果第一週交作業：**150 個人全部解出來。**
- 之後每年越出越難，**每年學生都還是解得出來**。

> 結論：**頻率分析這種攻擊非常強。**

### 7.5 【Q&A】有特殊字元和數字怎麼辦？

`[01:01]`

**學生問**：如果明文有特殊字元和數字呢？

**教授答**：系統性的做法是**把兩邊的字母表都擴大**。明文不只 A–Z，還有 0–9；密文那一邊也一樣，不只 a–z，還加上 0、1、2、3……。

### 7.6 為什麼有效：一句話

`[01:02]`

> **同樣的明文符號，永遠對到同樣的密文符號**（identical mapping），所以明文的統計特性被保留下來。

### 7.7 這一節的教訓

【課本補充】
- **好的密碼應該藏住明文的統計特性**，密文要看起來像隨機的。
- **光有很大的 key space，不足以構成強的加密。**

## 8. 攻擊方式總覽

`[01:03]` 從替換密碼學到的更大教訓：

> 替換密碼：暴力法 → **失敗**（$2^{88}$ 太大）；頻率分析 → **成功**。
> **攻擊者只要有一種方法成功就夠了。**

所以教授最後要給大家一張「各種攻擊方式」的全景圖。

```
                Cryptanalysis（密碼分析 / 攻擊）
        ┌──────────────────┼──────────────────┐
  Classical            Social              Implementation
  Cryptanalysis        Engineering         Attacks
  （古典密碼分析）       （社交工程）          （實作攻擊）
   ├── Mathematical Analysis（數學 / 分析攻擊）
   └── Brute-Force Attacks（暴力攻擊）
```

### 8.1 古典密碼分析

`[01:07]` 從密文 $y$ 找回明文 $x$，或找回金鑰 $k$。

| 類型 | 怎麼看待密碼 | 本講例子 |
|---|---|---|
| **Brute-force** | 把密碼當**黑盒子**，只看輸入輸出，試所有金鑰 | §6 |
| **Analytical（分析攻擊）** | **看密碼內部怎麼運作**，找結構上的弱點 | §7 頻率分析（字母頻率被保留下來） |

【口頭】「Classical」是教授自己的叫法，「現在沒有一個好的詞」。他說**分析攻擊在實務上可能更重要**。

> 【口頭】「一般密碼學家會說：攻擊就這兩種，講完了。可惜在真實世界裡，如果你不只看演算法、而是看**實際的使用情境**，還有其他攻擊。」

### 8.2 社交工程

#### 【口頭】教授的例子：德國 Geldkarte

`[01:09]` **Geldkarte** 是德國銀行卡上的**電子錢包**功能：
- 在 ATM 把錢從支票帳戶存到卡上，**最多 €200**，然後可以近乎匿名地花。
- 教授自己用它**買郵票**。（全班只有約 10–15% 的人用過。）

誘惑：卡上的錢**只是記憶體裡的一些 bit**。如果能在家裡把對的 bit 翻轉，就多了 €200，卻不用從帳戶扣錢。
（教授拿出一張紙鈔對比：紙鈔是實體的；卡上的 20 歐元只是「某個 EEPROM 裡的一些電子」。）

要做到，就得**打敗卡上的密碼學**：

| 攻擊方式 | 可行嗎 |
|---|---|
| 暴力法 | 卡上跑的是 **Triple DES，約 112 bit** → $2^{112}$，**不可能** |
| 分析攻擊 | Triple DES 被研究了幾十年都破不了 → **不可能** |
| **社交工程** | 銀行裡某處一定有人知道金鑰…… |

#### 社交工程的做法

`[01:11]`【口頭】
- **收買**：找知道金鑰的銀行員工，「給你 100 歐元，你給我金鑰」。他們不會答應。但如果開價 1000、10 萬、100 萬，**到某個價格，有些人可能就會被收買。**
- **電話詐騙**（比較常見）：打給公司員工，「我是 IT 部門，要更新你的系統 / 你中毒了，**急需你的密碼**」。大公司員工通常不認識 IT 的人，**很多人就真的在電話上把密碼給了。**
- **釣魚（phishing）** 也是一種。

> 【口頭】「就算卡上的密碼學再強，如果你在電話上把密碼給了騙子，你就有麻煩了。」

【課本補充】社交工程包括：收買、勒索、欺騙、傳統間諜手段，甚至直接威脅某人交出金鑰。

### 8.3 實作攻擊（旁通道攻擊）

`[01:13]`【口頭】這是**最少人知道、但最新**的一類攻擊，也是**教授研究團隊的專長**。

#### 例子：用耗電量偷金鑰

Geldkarte 金色接點底下是：
- 一顆很小的 **8-bit 微處理器（8051 系列）**，在上面跑 Triple DES。
- 金鑰藏在很難讀出來的記憶體位置。

1990 年代中後期，大家發現：**把密碼當成跑在真實硬體上的東西，而不只是抽象的數學公式**，就有全新的攻擊方式。

步驟：
1. 在 eBay 花約 **€9** 買一台讀卡機。
2. 接上卡片的**電源腳位**。
3. 假裝自己是 ATM，叫卡片「開始加密」。
4. 同時**記錄耗電量曲線（power trace）**。
5. 結果：**微處理器的耗電量跟正在處理的金鑰有關** → 用訊號處理技術就能算出金鑰。

這叫 **power analysis（功率分析）**，屬於 **side-channel attack（旁通道攻擊）**。

> 【口頭】「對我們不幸的是，德國的銀行標準知道旁通道攻擊，**卡上有防護措施**（masking、隨機值等），所以這招沒用。但如果硬體**沒有防護**，抽出金鑰**簡單到難以置信**。」

#### 其他旁通道

`[01:16]`

| 旁通道 | 說明 |
|---|---|
| **耗電量** | 上面的例子 |
| **執行時間（timing）** | 不管在晶片卡還是筆電上，運算時間常常也跟金鑰 bit 有關，用訊號處理就能從時間曲線算出金鑰 |
| **電磁輻射** | 【課本補充】 |

【課本補充】
- 實作攻擊主要針對**攻擊者能實際摸到**的裝置，例如智慧卡。
- 透過網路攻擊遠端系統時，實作攻擊**通常不是重點**。
- 這份清單**不完整**：例如 buffer overflow、惡意程式也能從軟體中偷到金鑰。

### 8.4 攻擊者 vs 防守者：不對等的遊戲

`[01:04]` 和 `[01:16]` 教授兩次強調同一件事：

| 角色 | 處境 |
|---|---|
| **攻擊者** | **只要一種攻擊成功就夠了。**暴力法失敗不用沮喪，換頻率分析就好 |
| **設計者（防守者）** | 必須**擋住每一種攻擊**。只要有一種成功，整個系統就垮了 |

> 【口頭】「你設計了一個能擋暴力法的密碼，key space 有 $2^{88}$，你覺得很安全。**如果有另一種攻擊能成功，那一點用都沒有。**」
> 「而最難的可能是：**還有黑板上沒寫到的攻擊。**這真的很難。」

【課本補充】這一段課本的粗體重點（意譯）：

> **攻擊者永遠找你系統中最弱的一環。** 所以我們不只要選強的演算法，還要確保社交工程和實作攻擊都行不通。

課本也提到：你可能覺得社交工程、實作攻擊很「不公平」，但真實世界沒有公平可言 —— 想入侵你系統的人本來就已經在違法了。

## 9. 一頁速查表

### 9.1 名詞

| 名詞 | 意思 |
|---|---|
| **Cryptology** | 密碼學（最上層），= Cryptography + Cryptanalysis |
| **Cryptography** | 設計加密的科學，目的是隱藏訊息意思 |
| **Cryptanalysis** | 破解加密的科學 |
| **Symmetric** | 雙方共用同一把秘密金鑰；1976 年前唯一的密碼學 |
| **Asymmetric = Public-key** | 每人有公鑰 + 私鑰；1976 年 Diffie、Hellman、Merkle |
| **Hybrid scheme** | 對稱、非對稱、雜湊一起用 |
| **Security by obscurity** | 靠隱藏演算法求安全 → 不可靠 |
| **Computationally secure** | 用很多電腦暴力搜尋也要好幾十年 |
| **Side-channel attack** | 從耗電量、時間、電磁輻射等偷金鑰 |

### 9.2 符號

| 符號 | 意思 |
|---|---|
| $x$ | Plaintext 明文 |
| $y$ | Ciphertext 密文 |
| $k$ | Key 金鑰 |
| $y = e_k(x)$ | 加密 |
| $x = d_k(y)$ | 解密 |
| $\mathcal{K}$ | Key space（所有可能金鑰的集合） |
| Alice / Bob / Oscar | 傳送方 / 接收方 / 攻擊者 |

### 9.3 重要公式與數字

| 項目 | 數值 |
|---|---|
| 替換密碼 key space | $26! \approx 4 \times 10^{26} \approx 2^{88}$ |
| $n$ bit 金鑰的 key space | $2^n$ |
| COPACOBANA 搜 $2^{56}$ | 幾天 |
| $2^{88}$ 比 $2^{56}$ 難 | $2^{32} \approx 4.3 \times 10^9$ 倍 |
| 英文最常見字母 | E ≈ 12.7%、T ≈ 9.1%、A ≈ 8.2% |
| Moore's Law | 運算力每 18 個月翻倍；15 年 ≈ $2^{10} = 1024$ 倍 |

### 9.4 金鑰長度（對稱密碼，只看暴力法）

| 長度 | 安全度 |
|---|---|
| 56–64 bit | 短期（幾小時到幾天） |
| 112–128 bit | 長期（沒有量子電腦） |
| 256 bit | 長期（有量子電腦也行） |

### 9.5 攻擊分類

| 類別 | 子類 | 例子 |
|---|---|---|
| **古典密碼分析** | 暴力攻擊（黑盒子） | 試所有金鑰 |
| | 分析攻擊（看內部結構） | 字母頻率分析 |
| **社交工程** | — | 收買、假冒 IT 部門要密碼、釣魚 |
| **實作攻擊** | 旁通道 | 耗電量、執行時間、電磁輻射 |

### 9.6 三句一定要記住的話

1. **Kerckhoffs 原則**：系統要在攻擊者知道一切（除了金鑰）時仍然安全。**只有金鑰要保密。**
2. **不要自己發明加密演算法**，只用公開、經過長期分析、標準化的演算法。
3. **攻擊者只要成功一次；防守者要擋住全部。**

## 附：本講一句話總結

> **密碼學的安全只能寄託在金鑰上，而不是藏起來的演算法；就算金鑰空間大到暴力法完全不可行，只要有任何一種攻擊（分析、社交工程、實作）能成功，系統就破了。**
