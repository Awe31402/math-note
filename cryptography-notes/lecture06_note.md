## 1. 金鑰排程（Key Schedule）

### 1.1 目標

`[00:04]` 從原本的金鑰 $k$，**推導出 16 把子金鑰** $k_1, k_2, \ldots, k_{16}$，每把 **48 bit**，每輪用一把。

```
          k（64 bit）
              ↓
            PC-1
              ↓ 56
     ┌────────┴────────┐
    C₀（28）         D₀（28）
     ↓ LS₁             ↓ LS₁
    C₁               D₁    ──→ PC-2 ──→ k₁（48）
     ↓ LS₂             ↓ LS₂
    C₂               D₂    ──→ PC-2 ──→ k₂
     ⋮                 ⋮
     ↓ LS₁₆            ↓ LS₁₆
    C₁₆              D₁₆   ──→ PC-2 ──→ k₁₆
```

### 1.2 PC-1：64 bit 怎麼變 56 bit

`[00:07]`【口頭】「如果你很專心，圖的最上面應該讓你覺得**有矛盾**：金鑰寫的是 **64 bit**，但我一直說 DES 是 **56 bit**。」

**PC-1（Permuted Choice 1，置換選擇 1）**：
- 輸入 64 bit，**第 8、16、24、32、40、48、56、64 個 bit 被丟掉**（沒有接線過去）。
- 不管那些位置放什麼都**被忽略**。
- 剩下 $64 - 8 = 56$ bit，而且也被**置換（交叉接線）** 過。

**為什麼要這樣？**

`[00:10]`【口頭】
- 「**我其實不知道為什麼。**」
- 較舊的文獻說這 8 個 bit 是**同位元檢查位元（parity bits）**。但在加密標準裡放同位元檢查，**沒什麼道理**。
- 愛陰謀論的人說：NSA 放進去，是為了讓大家以為它是 64 bit 密碼，比 56 bit 安全。「我不知道。」

> **重點：永遠不要以為 DES 是 64 bit 密碼。它是 56 bit。**
> 【口頭】「這基本上是**歷史遺跡**，在密碼學上不重要。」

【課本補充】每第 8 個 bit 是前面 7 個 bit 的**奇同位檢查位元**。這 8 個 bit **不是金鑰 bit，也不增加金鑰空間**。

### 1.3 左旋 LS_i

`[00:11]` 56 bit 切成兩半：**$C_0$ 和 $D_0$，各 28 bit**。

**$LS_i$**（Left Shift）= **循環左移（left rotate）**：往左移，從左邊掉出去的 bit 從右邊補回來。

**每輪移幾位？**

| 輪 $i$ | 左旋幾位 |
|---|---|
| **1、2、9、16** | **1 位** |
| 其他 12 輪 | **2 位** |

- 旋轉**只在 $C$ 或 $D$ 內部**發生，$C$ 和 $D$ 之間**不會交換**任何 bit（「硬邊界」）。

### 1.4 一個好用的觀察：$C_{16} = C_0$

`[00:14]`【課堂討論】總共旋轉了幾位？

$$4 \times 1 + 12 \times 2 = 4 + 24 = \mathbf{28}$$

28 —— 剛好是 $C$、$D$ 的長度！旋轉 28 位等於**繞一整圈回到原點**：

$$\boxed{C_{16} = C_0, \qquad D_{16} = D_0}$$

【口頭】「現在只是個有趣的觀察，**講解密時會非常有用**。」

### 1.5 PC-2：56 bit 選出 48 bit

`[00:17]` 每輪把 $C_i$、$D_i$（共 56 bit）送進 **PC-2（Permuted Choice 2）**：
- **丟掉 8 個 bit**，剩 48 bit。
- 剩下的也被**置換**。
- 輸出就是那一輪的**子金鑰 $k_i$**。

### 1.6 重點：子金鑰只是原金鑰的「選擇」

`[00:19]`【口頭】「跟現代密碼比，這是**非常非常簡單**的子金鑰產生方式。」

> 「這 48 bit 和原本 56 bit 是什麼關係？我們**沒有做任何數學運算**：沒有 XOR、沒有 AND 閘、沒有拉普拉斯轉換、沒有矩陣、沒有解二次方程。**我們只是在玩電線。**」

- 旋轉也是一種置換；PC-2 又是一種置換。
- 所以 **每把子金鑰 $k_i$ 都只是從 56 bit 金鑰中「挑出 48 個 bit、換個順序」**。
- 聰明的地方：**每一輪挑的位置都經過特別設計**。

【課本補充】
- 金鑰排程本質上只是「**有系統地實現 16 個置換**」的方法，硬體上非常容易做。
- 每個金鑰 bit 大約會出現在 16 把子金鑰中的 **14 把**。

#### 【Q&A】旋轉和 PC-2 可以合併成一個置換嗎？

`[00:23]`

**學生問**：旋轉也是置換，後面又接一個置換，那不就可以把它們**合成一個置換**嗎？

**教授答**：可以，確實能合併成單一置換。

## 2. DES 解密

`[00:24]`【口頭】「**今天最重要的部分。**請醒來、請不要聊天。接下來 15 分鐘是亮點，之後你可以慢慢回去睡。」

### 2.1 基本想法：一輪一輪倒回去

`[00:26]`

```
  Alice（加密）                       Bob（解密）
     x                                  y
     ↓                                  ↓
    IP                                 IP      ← 抵銷加密端最後的 IP⁻¹
     ↓                                  ↓
  R1(e) ─────────────┐         ┌──── R1(d)   倒轉 R16(e)
  R2(e) ───────────┐ │         │ ┌── R2(d)   倒轉 R15(e)
     ⋮             │ │         │ │    ⋮
  R16(e) ─────┐    │ │         │ │  R16(d)   倒轉 R1(e)
     ↓        │    │ │         │ │    ↓
   IP⁻¹      (成對互相抵銷，像洋蔥一樣一層層剝回去)
     ↓                                  ↓
     y  ─────────── 網路 ────────→     IP⁻¹
                                        ↓
                                        x ✔
```

- 加密端最後做的是 IP⁻¹ → 解密端**第一件事做 IP**，兩者抵銷。
- 【口頭】`[00:30]` 很重要但很簡單的一句話：**解密第 1 輪倒轉加密第 16 輪，解密第 2 輪倒轉加密第 15 輪……解密第 16 輪倒轉加密第 1 輪。**
- 「往下走解密，就是往上走加密。」
- 最後再做 IP⁻¹ 抵銷加密端一開始的 IP → 拿回 $x$。

所以**唯一要證明的**：**怎麼倒轉一輪？** 因為 DES 每一輪結構都一樣，只是參數不同，證明了一輪就等於證明了全部。

### 2.2 解密 = 加密，只是金鑰順序反過來

`[00:33]`【口頭】「這看起來就是 DES，但它是 **DES 解密**。看起來**完全一樣**……我知道這很刺激。」

**唯一的差別：子金鑰順序反過來**，從 $k_{16}$ 用到 $k_1$。

直覺：加密第 16 輪用了 $k_{16}$，要倒轉它，解密第 1 輪大概也該用 $k_{16}$。

### 2.3 證明：解密第 1 輪倒轉加密第 16 輪

`[00:40]`【口頭】「請專心 3 分鐘。這段不簡單，如果你週日在家自己弄要花 90 分鐘。**專心 3 分鐘，省下 90 分鐘。**」

**符號**：加密端變數不加標記；解密端加上標 $d$。

#### 起點：解密的輸入

DES 加密最後一輪後，左右半會**再交換一次**，然後做 IP⁻¹。解密第一步做 IP 抵銷：

$$(L_0^d, R_0^d) = IP(y) = IP(IP^{-1}(R_{16}, L_{16})) = (R_{16}, L_{16})$$

所以：

$$L_0^d = R_{16}, \qquad R_0^d = L_{16} = R_{15}$$

（最後一步用了 Feistel 的 $L_{16} = R_{15}$。）

#### 目標

證明解密第 1 輪的輸出 $(L_1^d, R_1^d)$ = 加密第 16 輪的**輸入** $(R_{15}, L_{15})$ —— 注意左右是交換的。

#### 左半：很簡單

`[00:41]`【口頭】「用顏色證明 —— 數學家最討厭這種。但它是對的。」

$$L_1^d = R_0^d = L_{16} = R_{15} \;✔$$

$R_{15}$ 在加密第 16 輪**根本沒被加密**，只是一路被複製、交換、置換、再置換……原封不動到這裡。「沒有什麼神秘的。」

#### 右半：有趣的部分

`[00:42]` 被加密的是 $L_{15}$，所以這才是重點。

$$\begin{aligned}
R_1^d &= L_0^d \oplus f(R_0^d, k_?) && \text{（Feistel 公式）}\\
&= R_{16} \oplus f(R_{15}, k_?) && \text{（代入起點）}\\
&= \left[L_{15} \oplus f(R_{15}, k_{16})\right] \oplus f(R_{15}, k_?) && \text{（代入加密第 16 輪的 } R_{16}\text{）}
\end{aligned}$$

`[00:46]`【口頭】「**這是整整 90 分鐘裡真正有趣的那一分鐘。**」

我們想要 $R_1^d = L_{15}$。所以後面那兩個 $f$ **必須消失**。
- 什麼情況下 $a \oplus b = 0$？**$a = b$**（0⊕0 = 0，1⊕1 = 0）。
- $f$ 是確定性的函數，所以**兩個輸入要一樣**。
- 第一個輸入都是 $R_{15}$ ✔
- 第二個輸入：**必須選 $k_{16}$**。「不能選 $k_7$，那是不同的 bit 值。」

選 $k_? = k_{16}$：

$$R_1^d = L_{15} \oplus \underbrace{\left[f(R_{15}, k_{16}) \oplus f(R_{15}, k_{16})\right]}_{32 \text{ 個 } 0} = L_{15} \;✔$$

> **關鍵**：同一個 $f$ 輸出被 XOR 兩次，互相抵銷。（又是第 3 講的「翻兩次 = 原樣」！）

【口頭】「這是這門課**少數幾次比較乾淨的證明**之一。」

#### 推廣

同樣的論證一路做下去：

$$L_i^d = R_{16-i}, \qquad R_i^d = L_{16-i}, \qquad i = 0, 1, \ldots, 16$$

最後一輪後 $L_{16}^d = R_0$、$R_{16}^d = L_0$。再做 IP⁻¹（左右交換後）：

$$IP^{-1}(R_{16}^d, L_{16}^d) = IP^{-1}(L_0, R_0) = IP^{-1}(IP(x)) = x \;✔$$

【口頭】`[00:50]`「好，你們可以回去睡了。這是今天最難的部分，其實也沒那麼複雜。」

### 2.4 反向金鑰排程

【課本補充】課堂沒細講，但這是 §1.4 那個觀察派上用場的地方。

**問題**：解密第 1 輪就需要 $k_{16}$。難道要先把 16 把子金鑰全算完？

**不用。** 因為 $C_{16} = C_0$、$D_{16} = D_0$：

$$k_{16} = PC2(C_{16}, D_{16}) = PC2(C_0, D_0) = PC2(PC1(k))$$

**PC-1 之後直接就能算出 $k_{16}$。**

之後的子金鑰改成**循環右移（RS）**：

| 解密輪 | 右旋幾位 |
|---|---|
| 1 | **0**（不旋轉） |
| 2、9、16 | 1 位 |
| 其他 12 輪 | 2 位 |

例：$k_{15} = PC2(RS_2(C_0), RS_2(D_0))$

## 3. DES 的安全性

`[00:50]`【口頭】「這部分是**事實知識**，作業不太會考，考試偶爾有簡單題。但這是**一般素養**：知道現代 DES 的安全狀況。」

【課堂討論】數學上攻擊密碼演算法的兩種基本方法？學生答：**暴力攻擊**。另一種是**分析攻擊**。

### 3.1 分析攻擊

`[00:52]`

| 年份 | 攻擊 | 提出者 | 需要的資料 |
|---|---|---|---|
| **1990** | **差分密碼分析（Differential Cryptanalysis, DC）** | Eli Biham、Adi Shamir | $2^{47}$ 組**選擇明文** |
| **1993** | **線性密碼分析（Linear Cryptanalysis, LC）** | Mitsuru Matsui（松井充） | $2^{43}$ 組明文/密文 |

> ⚠️ 逐字稿把差分密碼分析的年份聽成「1999」，正確是 1990（課本與上一講皆為 1990）。

- 數學上 $2^{47}$ **比暴力的 $2^{56}$ 好**。
- **但實務上沒用**：
  - 攻擊者通常**只有密文**，沒有 $2^{47}$ 組明文。
  - 【口頭】算一下，這是**好幾 TB** 的明文，而且全部要在**同一把金鑰**下。好的協定會定期換金鑰 → 沒用。
  - 差分攻擊還要**選擇明文（chosen plaintext）**：攻擊者必須能**指定** $x$ 是什麼，不能用隨機的 $x$。
- 【課本補充】如果是隨機明文，差分攻擊需要 $2^{55}$ 組。而且就算成功，也**只拿到一把金鑰**（這也是為什麼要常換金鑰）。

> **結論**：數學上很漂亮、複雜度比暴力低，但**實務上不太相關**。不過差分和線性密碼分析**對其他區塊密碼非常強大**，是今天破解區塊密碼最強的一般方法之一。

### 3.2 暴力攻擊

`[00:55]` 攻擊者有一組明文/密文 $(x_0, y_0)$，只要**一個區塊 = 8 byte**（例如被加密檔案的檔頭）。

$$DES^{-1}_{k_i}(y_0) \stackrel{?}{=} x_0, \qquad i = 0, 1, \ldots, 2^{56} - 1$$

【口頭】「這個 $\stackrel{?}{=}$ 符號是我發明的，沒有別人用，但我覺得很傳神。」

【課本補充】有大約 $1/2^{16}$ 的機率找到**錯的金鑰**（剛好讓這一組對上、但其他組對不上）。要排除就再用第二組明文/密文驗證（→ 第 10 講）。

#### 暴力破解 DES 的歷史

`[00:57]`

| 年份 | 事件 | 成本 | 時間 |
|---|---|---|---|
| 1977 | Diffie & Hellman 估計造一台破解機 | 約 **2000 萬美元** | — |
| 1993 | Michael Wiener 提出設計（沒造）【課本補充】 | 約 100 萬美元 | 約 1.5 天 |
| **1998 夏** | **EFF 的 Deep Crack**（特製硬體） | 約 **25 萬美元** | 56 小時（平均 15 天） |
| **2006** | **COPACOBANA**（Bochum + Kiel 大學） | 約 **1 萬美元** | 平均不到 7 天 |
| 課堂當時 | 下一代 **RIVYERA** | — | 紀錄約 1.5 天 |

【口頭】
- 1980 年代估計 2000 萬美元：「對你太貴，對我這個德國教授也太貴」，但大家假設 NSA 等情報單位做得到。
- **Deep Crack**：「我認識那些人（例如 Paul Kocher），他們真的造出來了，**超酷**。」他們的訊息是：**別再用 DES 了**，花一筆錢就能破，**每家大公司都付得起 25 萬美元**。
  - 這是「**DES 的官方死亡**」，上了《紐約時報》頭條：美國資料加密標準不再安全。
  - 剛好跟 AES 的宣布同時，給美國政策更大的壓力淘汰 DES。
- **COPACOBANA**：「我們做的基本上一樣，只是玩具好多了。」只花約 1 萬美元。「不是我們比較聰明 —— 他們可能是更好的電腦工程師 —— 而是**技術進步了**：我們可以買現成的 **FPGA**（可重新程式化的硬體晶片）。」

【課本補充】Deep Crack 由 1800 顆晶片組成，每顆有 24 個金鑰測試單元。課本強調：這**不代表**大家用了 20 年的弱演算法 —— 是因為**數位硬體變便宜了**，在 1980 年代要造一台得花好幾百萬美元。

#### 【口頭】誰會想租 COPACOBANA？

`[01:00]`
- 「我們以為會收到很多可疑人士的請求，**結果沒有**。」
- 三年來只有一兩次，很明顯是想**破解汽車**或**入侵付款終端機**的人。「我們問『你的用途是什麼？』，就再也沒收到回信了。」
- 主要的正當用途：有些**舊標準用 DES 來雜湊密碼**，在**執法單位**有應用。

### 3.3 結論

`[01:02]`

> **單純的 DES 已經不安全了。不要再用。**
> 【口頭】「你們浪費了兩週。DES 是個蠢演算法。**你們為什麼還來上課？**」（開玩笑）

【課本補充】56 bit 太短，只適合**短期安全**（幾小時）或**價值很低**的資料。但 DES 的變形，特別是 **3DES，仍然安全**。而且因為 DES 是研究最透徹的演算法，**學它能幫助理解很多其他區塊密碼**。

## 4. DES 的替代品

`[01:03]`

### 4.1 AES（首選）

> 【口頭】「**這非常重要。**選區塊密碼時，**預設、標準的選擇應該是 AES**（Advanced Encryption Standard）。」

- 非常安全、非常快（尤其是軟體）、沒有專利問題……「**沒有什麼好理由不用 AES**。」
- 唯一可能的缺點：如果要**非常便宜的硬體**，AES 在硬體上**不算小**。
- 下兩週講。

【課本補充】AES 有三種金鑰長度 **128、192、256 bit**，對暴力攻擊可安全數十年，也沒有已知有實際成功機會的分析攻擊。

### 4.2 3DES

`[01:04]` 德國電子護照上沒有 AES，用的是 **3DES**：用 DES 加密**三次**，通常用**三把不同的金鑰**。「仍然非常安全。」

【課本補充】
$$y = DES_{k_3}(DES_{k_2}(DES_{k_1}(x)))$$

另一種版本（中間那次是**解密**）：

$$y = DES_{k_3}(DES^{-1}_{k_2}(DES_{k_1}(x)))$$

好處：當 $k_1 = k_2 = k_3$ 時，**等於單次 DES** → 方便需要相容舊系統的實作。3DES 在**金融應用**和**電子護照的生物特徵保護**上很流行；硬體上很有效率，軟體上不太快。

### 4.3 其他區塊密碼

`[01:05]`【口頭】
- 大概有 **200 個區塊密碼**被提出過。
- 教授有個博士生 Rand 想把它們分類（輸入輸出參數、內部函數），十年前做到**第 100 個就放棄了**。

**AES 的 4 個決賽落選者**（都很安全）：

| 密碼 | 說明 |
|---|---|
| **Mars** | |
| **RC6** | |
| **Serpent** | |
| **Twofish** | |

【口頭】AES 是公開競賽選出來的，最後一輪剩 5 個。另外 4 個**不是因為不安全才落選**，而是其他原因。據教授所知，它們都**沒有已知攻擊**。

【課本補充】Mars、Serpent、Twofish 可以**免權利金**使用。

### 4.4 【課本補充】DESX：金鑰白化

在 DES 前後各 XOR 一把 64 bit 金鑰：

$$y = DES_k(x \oplus k_1) \oplus k_2$$

這麼簡單的修改，就讓 DES **更能抵抗暴力搜尋**（→ 第 10 講「金鑰白化」）。

### 4.5 【課本補充】輕量級密碼 PRESENT

專為 **RFID 標籤**等極度受限的裝置設計（課本作者之一參與設計）。

| 項目 | 數值 |
|---|---|
| 結構 | **SP 網路**（Substitution-Permutation，不是 Feistel） |
| 區塊 / 金鑰 | 64 bit / 80 或 128 bit |
| 輪數 | 31 |
| 每輪 | XOR 輪金鑰 → **一個 4 bit S-box** 平行用 16 次 → bit 置換 |
| 硬體大小 | 約 1000～1600 個等效閘 |

用 **4 bit** 的 S-box 而不是 8 bit，正是為了硬體小。軟體上不快，但在小型微處理器上表現不錯。

## 5. 【課本補充】DES 的軟硬體實作

| | 軟體 | 硬體 |
|---|---|---|
| 置換（E、P、IP） | **慢**（要一個個 bit 搬） | **免費**（只是接線） |
| 6×4 S-box | 普通 | 約 100 個閘一個 |
| 效能 | 最佳化後 32 bit CPU 每區塊約 240 個時脈；2 GHz 約 533 Mbit/s；3DES 約 1/3 | 一輪少於 3000 閘；ASIC/FPGA 可達數百 Gbit/s；小到能放進 RFID |
| 加速技巧 | 預先算好的查表；**bit-slicing**（Biham 提出） | 管線化（pipelining） |

## 6. 一頁速查表

### 6.1 金鑰排程

| 步驟 | 輸入 → 輸出 | 說明 |
|---|---|---|
| PC-1 | 64 → 56 | 丟掉第 8、16、…、64 bit（同位元位元），並置換 |
| 切半 | 56 → $C_0$(28) + $D_0$(28) | |
| $LS_i$ | 28 → 28（各自） | 第 1、2、9、16 輪左旋 1 位；其他左旋 2 位 |
| PC-2 | 56 → 48 | 丟 8 bit、置換 → $k_i$ |

- 總旋轉 $4 \times 1 + 12 \times 2 = 28$ → **$C_{16} = C_0$，$D_{16} = D_0$**
- 子金鑰**只是原金鑰 bit 的選擇與重排**，沒有任何運算
- **DES 是 56 bit 密碼，不是 64 bit**

### 6.2 解密

| 項目 | 內容 |
|---|---|
| 結構 | **跟加密完全一樣** |
| 唯一差別 | 子金鑰順序反過來：$k_{16}, k_{15}, \ldots, k_1$ |
| 對應關係 | 解密第 $i$ 輪倒轉加密第 $17 - i$ 輪 |
| 關鍵等式 | $f(R_{15}, k_{16}) \oplus f(R_{15}, k_{16}) = 0$ |
| $k_{16}$ 怎麼來 | $k_{16} = PC2(PC1(k))$，之後改**右旋** |

$$L_i^d = R_{16-i}, \qquad R_i^d = L_{16-i}$$

### 6.3 安全性

| 攻擊 | 需求 | 實務上 |
|---|---|---|
| 差分密碼分析（1990） | $2^{47}$ 選擇明文 | 不實際 |
| 線性密碼分析（1993） | $2^{43}$ 已知明文 | 不實際 |
| **暴力搜尋** | 1 組明文/密文，$2^{56}$ 次 | **可行**：Deep Crack 25 萬美元、COPACOBANA 1 萬美元 |

### 6.4 替代品

| 選擇 | 說明 |
|---|---|
| **AES** | **預設首選** |
| 3DES | 仍安全；護照、金融 |
| Mars、RC6、Serpent、Twofish | AES 決賽者，都安全 |
| DESX | 金鑰白化 |
| PRESENT | 輕量級，RFID |
