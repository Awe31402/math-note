## 1. 再談碰撞與生日悖論

**碰撞**：找 $x_1 \ne x_2$ 使得 $h(x_1) = h(x_2)$。

```
   x₁ ──→ [ h ] ──→ h(x₁) ┐
                          ├── 兩個（例如 160 bit）輸出一樣 → 碰撞
   x₂ ──→ [ h ] ──→ h(x₂) ┘
```

上週的公式（輸出 $n$ bit，碰撞機率 $\lambda$）：

$$t \approx 2^{(n+1)/2}\sqrt{\ln\left(\frac{1}{1-\lambda}\right)}$$

【口頭】
- 「輸出 80 bit，你**以為**複雜度大概是 $2^{80}$ 或 $2^{81}$。**但這不對。**」
- 「**上週 90 分鐘無聊講課的最大結論**：指數裡**少了什麼**？」【課堂討論】→ **除以 2**（開根號）。「我們花了 90 分鐘在這上面……我誇張了，35 分鐘。」
- （⚠️ 語音辨識把這段辨識成「不是 $2^{n+1}$ 而是 $2^{n+1}$」，依上下文應為 $2^{(n+1)/2}$。）
- $\lambda$ 是機率：「你可能**運氣很差**，試了很多很多輸入還是沒碰撞。」

### 課本表 11.1 的教訓

| 輸出長度 | $\lambda = 0.5$ | $\lambda = 0.9$ |
|---|---|---|
| 160 bit | 約 $2^{81}$ 則訊息 | 約 $2^{82}$ 則訊息 |

【口頭】
- 160 bit 的雜湊函數，要有 50% 機率找到碰撞，大約要 $2^{81}$ 則訊息，**不是 $2^{160}$**。
- **有點反直覺**：要提高到 **90%** 機率，**不需要多很多**訊息（$2^{82}$）。所以 **$\lambda$ 其實沒那麼重要**。

### 安全等級要搭配

【口頭】很典型的情境：瀏覽器裡某個複雜協定用 **AES**。
- 【課堂討論】AES 最短金鑰長度？→ **128** → AES 的**安全等級（security level）**是 128。
- 協定裡也需要雜湊函數，當然應該有**一樣的安全等級**。
- 用很常見的 **160 bit** 雜湊函數 → **比 AES 還好破** → 雜湊函數變成**最弱的一環**。
- 【課堂討論】要 128 bit 強度，雜湊輸出要多長？→ **256**。「**完全正確。**」

> **雜湊輸出 $n$ bit → 抗碰撞強度約 $n/2$ bit。要配 AES-128，雜湊輸出要 256 bit。**

## 2. 雜湊函數怎麼建構

【口頭】「到目前為止都只談需求，在工程上不太具體。唯一討論的是**最短輸出長度**。**怎麼造這些寶貝（these babies）**，我們還完全沒講。」

### 2.1 兩大家族

```
                 雜湊函數
               /          \
   以區塊密碼為基礎        專用雜湊函數
   (block cipher-based)   (dedicated)
                               │
                          MD4 家族：MD5、SHA-1、SHA-2
                          SHA-3（新的）
                          其他……
```

| 類型 | 說明 |
|---|---|
| **以區塊密碼為基礎** | 拿區塊密碼來造雜湊函數。【口頭】「**課本裡有，我們這裡不講**。其實非常非常簡單，看書大概 **13 分鐘**就懂。」 |
| **專用雜湊函數（dedicated hash function）** | 【口頭】「**很花俏的名詞**（schicker Ausdruck），意思就是：**生來就是要當雜湊函數**的函數。」區塊密碼可以做很多事（特別是加密），也可以拿來做雜湊；但實務上**更常用**專門造來當雜湊的函數。過去約 20 年有**幾十個**提案 |

### 2.2 MD4 家族

【口頭】最重要的就是 **MD4 家族**：
- **MD4**：「**幾乎一出來就被破了**，沒有被廣泛使用。」
- **MD5**：被用過，**已被破**。
- **SHA-1**：「**搖搖欲墜（shaky）**。有攻擊在地平線上了，雖然找碰撞還是很難，但它**很快就會死**。」
- **SHA-2**：SHA-1 的延續，「**看起來非常安全**」。
- **SHA-3**：新的演算法，正在出現。「**之後會講**。」（→ 第 22 講）

#### 【口頭】Dobbertin 與 MD5

【口頭】MD5 被破，**Hans Dobbertin 教授**有**重大貢獻**，他是**波鴻大學第一位密碼學教授**，「**以破解 MD5 聞名全世界**」。
（⚠️ 語音辨識在這裡有重複、錯亂的句子，可能有提到他和教授同期來到波鴻的年份，無法確認，**待補**。）

【課本補充】⚠️ 課本的時間線更細：
- 1996 年 Dobbertin 對 MD5 提出**部分攻擊**，促使專家改推 SHA-1。
- 1995 年 Dobbertin 找到 **MD5 壓縮函數**的碰撞；也在 1995 年證明完整 MD4 的碰撞在一般 PC 上**不到一分鐘**就能做出來。
- **2004 年**由 **王小雲（Xiaoyun Wang）** 公布 **MD5 和 SHA-0** 的碰撞攻擊。

#### 課本表 11.2：MD4 家族

【口頭】「目前最重要的參數是**輸出長度**那一欄。」

| 演算法 | 輸出 [bit] | 輸入區塊 [bit] | 輪數 | 已找到碰撞？ |
|---|---|---|---|---|
| MD5 | 128 | 512 | 64 | **是** |
| SHA-1 | 160 | 512 | 80 | **還沒** |
| SHA-224（SHA-2） | 224 | 512 | 64 | 否 |
| SHA-256（SHA-2） | 256 | 512 | 64 | 否 |
| SHA-384（SHA-2） | 384 | 1024 | 80 | 否 |
| SHA-512（SHA-2） | 512 | 1024 | 80 | 否 |

【口頭】
- **MD5**：128 bit，**已找到碰撞**，「意思是碰撞已經在那裡了，**不要用**」。
- **SHA-1**：160 bit，正常應該有 $2^{80}$ 的抗碰撞性。**問題是**：「這是很新的東西，**大約三年前**，有人找到**數學方法**更有效率地找碰撞，大約 **$2^{63}$**。」
- 全世界在找：由**奧地利格拉茲科技大學（TU Graz）**協調，「**還沒找到**」。「想貢獻的話可以登入、下載軟體，幫他們找碰撞。很大的事。**大概未來兩年內會發生**。」
  （這是錄影當時的狀況。）
- **SHA-2**：一整組演算法，輸出 224、256、384、512 bit，**都有標準化**。很多新產品正**用 SHA-2 取代 SHA-1**，「**這很好**」。

#### 為什麼還要學一個「半死」的演算法？

【口頭】
- 「**有點好笑**：我們要討論一個**半死**的演算法。為什麼？」
- 「因為它**超級廣泛使用**（全世界的瀏覽器都用 SHA-1）—— 這**也許不是很好的理由**。」
- 「**真正好的理由**：**SHA-2 長得跟 SHA-1 很像**。下週二晚上你寫作業時搞懂 SHA-1，SHA-2 就很好懂，**只是稍微推廣一下**。」

【課本補充】
- MD4 是 **Ronald Rivest** 設計的，特點是**特別適合高效率軟體實作**：用 32 bit 變數，所有運算都是**位元布林運算**（AND、OR、XOR、NOT）。之後的 MD4 家族都沿用這個原則。
- **MD5**：1991 年 Rivest 提出，128 bit 輸出 → 抗碰撞約 $2^{64}$。
- **SHA（現稱 SHA-0）**：1993 年 NIST 發布；**1995 年**改成 **SHA-1**，**差別在壓縮函數的排程**（為了提升安全性）。兩者都 160 bit。
- **SHA-2**：2001 年 NIST 推出 SHA-256、SHA-384、SHA-512；2004 年加上 SHA-224（為了配 3DES 的安全等級）。
- **RIPEMD-160**：MD4 家族中**唯一不是 NIST/NSA 設計**的，由歐洲研究者設計。
- **重要提醒**：找到碰撞**不代表在所有情況都不安全**。例如**金鑰衍生**或**儲存密碼**只需要原像和第二原像抗性，這種用途 MD5 仍然夠用。

### 2.3 【課本補充】用區塊密碼做雜湊函數

課堂沒講（教授說看書 13 分鐘就懂），依課本 §11.3.2 整理。

訊息切成區塊 $x_i$，用區塊大小 $b$ 的區塊密碼 $e$ 處理。$g$ 是把 $b$ bit 映射到 $m$ bit 金鑰的函數（例如 AES-128 時 $b = m$，$g$ 可以是恆等映射）。

| 名稱 | 公式 |
|---|---|
| **Matyas–Meyer–Oseas** | $H_i = e_{g(H_{i-1})}(x_i) \oplus x_i$ |
| **Davies–Meyer** | $H_i = H_{i-1} \oplus e_{x_i}(H_{i-1})$ |
| **Miyaguchi–Preneel** | $H_i = H_{i-1} \oplus x_i \oplus e_{g(H_{i-1})}(x_i)$ |

- 都需要初始值 $H_0$（可以公開，例如全 0）。
- **雜湊輸出長度 = 區塊寬度**。AES 只有 128 bit → 生日攻擊只要 $2^{64}$，**抗碰撞不夠**（只需要原像/第二原像抗性時就夠）。
- 解法：用區塊寬 192 或 256 bit 的 **Rijndael**（安全等級 96、128 bit），或用輸出**兩倍區塊寬**的構造，例如 **Hirose 構造**（金鑰長度是區塊寬兩倍，例如 AES-256 → 256 bit 輸出）。
- 輕量的 **PRESENT** 也可以拿來做很小的硬體雜湊（128 bit 輸出，但抗生日攻擊只是勉強）。
- 這幾種構造（把區塊密碼當黑盒子時）都**可證明安全**。

## 3. SHA-1 概觀

### 3.1 從衛星看：Merkle–Damgård 結構

【口頭】「從**衛星照片**看 SHA-1，看不到細節，只看到：」

```
   任意長度的 x ──→ [ SHA-1 ] ──→ 160 bit
```

$x$ 可以是一句話、一個信用卡號、3 MB 的 PDF，甚至整顆硬碟。**輸出 160 bit 是關鍵參數。**

#### 內部：Merkle–Damgård 結構

【口頭】「記得區塊密碼有各種造法，其中一種是 **Feistel 網路**。雜湊函數也一樣，有一種**很特定、很流行**的造法：」

**Merkle–Damgård 結構**：
- 【口頭】**Ralph Merkle**：「我們總說是 **Diffie 和 Hellman**（Whitfield Diffie 和 Martin Hellman）發明了公鑰密碼。**這不完全對**，其實是 **Diffie、Hellman 和 Ralph Merkle**。他也在雜湊函數上做了重要的工作。」
- 【口頭】**Damgård**：「你的**丹麥文**怎樣？德文有**帶點的怪字母**，丹麥文也一樣，**A 上面有個小圈圈**（å）。**不會考，別擔心。**」

```
   x ──→ [填充] ──→ x₁, x₂, …, x_n

          x₁          x₂          x₃                x_n
          │           │           │                 │
   H₀ ──→[壓縮]──→ H₁ ──→[壓縮]──→ H₂ ──→[壓縮]──→ … ──→[壓縮]──→ H_n = h(x)
```

- 先**填充（padding）**。【口頭】「填充是**很實務的細節**，我不講，不複雜，**看書**。看看真實世界的填充怎麼做，**可能很有啟發**。」
- 然後是演算法的主體：**壓縮函數（compression function）**。
- 【口頭】「**接下來 15 秒要看黑板**。13、14、15，時間到。」
  - $x_1$ 丟進壓縮函數，得到一個輸出。
  - 把這個輸出**回饋**，連同 $x_2$ 一起再壓縮一次。
  - 再回饋，跟 $x_3$ 一起……「不複雜。」
  - 最後的輸出就是 $h(x)$。
- 【口頭】「書和講義裡**我不太一致，抱歉**。今天用**大寫 $H$**（groß H）表示輸出。」

#### 匯流排寬度

【課堂討論】這些線代表**匯流排（bus）**。我們知道哪些寬度？
- **輸出**：「很好」→ **160 bit**。所以回饋的線也是 160 bit。
- 你們還不知道的：**訊息區塊 $x_i$ 是 512 bit** = **64 個字元（64 byte）**。「你一次餵**相當大塊**的訊息進去。」

【課堂討論】接下來 55 分鐘要花在什麼？→ **壓縮函數**。

【口頭】
- 「這個結構裡**有很多智慧**，可以證明某些性質。但從**工程實作**的角度，問題是：**壓縮函數怎麼運作？**」
- （教授先秀出課本的完整圖）「**它看起來很複雜。我要嚇你們。你們害怕嗎？我希望是。**」
- 「為了**消除焦慮**，先別看了，拿掉。我要**牽著你們的手**，看這張瘋狂的圖**怎麼建立在我們以前學過的東西上**。」

### 3.2 壓縮函數像一個區塊密碼

【口頭】先回想**六個月前**學的**區塊密碼**（「十一月，差不多正好六、七個月前」）：

```
   區塊密碼（例如 AES、DES，抽象層次）：

   key ──→ [金鑰排程] ──→ k₀,  k₁,  …,  k_{s-1}
                           │    │          │
   m  ──→ [第0輪] ──→ [第1輪] ──→ … ──→ [第s-1輪] ──→ 輸出
```

- 區塊密碼也是**迭代**的，由**輪**組成。
- 每輪的輸入是訊息（或上一輪的輸出），**旁邊進來的是金鑰** → 其實是**子金鑰**，由**金鑰排程（key schedule）**導出。
- 【口頭】「德文叫 **Schlüsselfahrplan**，不太好聽的字……**是個好字，但不太合理**，德文不會叫它 Fahrplan（時刻表），是**爛翻譯**。」

**SHA-1 的壓縮函數，抽象上很像**：

```
   x_i (512 bit) ──→ [訊息排程] ──→ W₀,  W₁,  …,  W₇₉   （各 32 bit）
                                     │    │          │
   H_{i-1} (160) ──→ [第0輪] ──→ [第1輪] ──→ … ──→ [第79輪] ──→ ⊞ ──→ H_i
        │                                                         ↑
        └──────────────────── 前饋（feed-forward）──────────────────┘
```

| 區塊密碼 | SHA-1 壓縮函數 |
|---|---|
| 輸入：訊息 | 輸入：**上一個雜湊值 $H_{i-1}$**（【課堂討論】索引是 $i$ 還是 $i-1$？→ **$i-1$**） |
| 旁邊進來：**金鑰** | 旁邊進來：**訊息區塊 $x_i$** |
| 金鑰排程 → 子金鑰 $k_j$ | **訊息排程（message schedule）** → 「子訊息」$W_j$ |
| AES-128：**10 輪**（【課堂討論】） | **80 輪**（第 0 到 79 輪） |
| 最後一輪輸出就是結果 | 還要**前饋**：把輸入 $H_{i-1}$ 加到輸出上 |

**角色互換的原因**：
- 【口頭】「這是思考上**很大的不同**，某種**角色互換**。」
- 進去的是 **512 bit**（「我說了 512 byte 嗎？」⚠️ 口誤，應為 512 bit = 64 字元），出來只要 **20 個字元**（160 bit）→ 要**壓縮**。
- 如果照常把 512 bit 的訊息從主輸入餵進去，出來也是 512 bit，**沒有壓縮**。
- 所以把**長訊息**當成像**金鑰排程**那樣從旁邊餵進去。

**前饋加法**：
- 【口頭】「這純粹是**為了安全性**。」把原本的輸入 $H_{i-1}$ **前饋**到輸出，再加上去。
- 這個加法 ⊞ 是「**不進位的整數加法**」（詳見下面）。

【課本補充】課本也這樣詮釋：SHA-1 的壓縮函數**像一個區塊密碼**，輸入是上一個雜湊值 $H_{i-1}$、**金鑰是訊息區塊 $x_i$**；而 SHA-1 的輪其實**很像 Feistel 區塊密碼**。

### 3.3 四個階段，80 輪

課本圖 11.11 的更精確版本：

```
                        H_{i-1}（160 bit）
                             │
   x_i ──→ [訊息排程]     A  B  C  D  E
             │              │
        W₀…W₁₉  ─────→  第 1 階段（20 輪）：f₁, K₁
        W₂₀…W₃₉ ─────→  第 2 階段（20 輪）：f₂, K₂
        W₄₀…W₅₉ ─────→  第 3 階段（20 輪）：f₃, K₃
        W₆₀…W₇₉ ─────→  第 4 階段（20 輪）：f₄, K₄
                             │
                     逐字加法 mod 2³²（加上 H_{i-1}）
                             │
                           H_i（160 bit）
```

**160 bit 分成 5 個字（word）**：
- 【課堂討論】心算（Kopfrechnen）：160 ÷ 5 = ？→ **32**。（⚠️ 語音辨識寫成「除以四」，但後面列出 A、B、C、D、E 五個字。）
- 所以所有線都是 **32 bit**，叫**字（word）**，「這大概就是 $W$ 這個名字的由來」。
- $W_j$ 也是 32 bit。

**加法 mod $2^{32}$**：
- 不是 160 bit 加 160 bit，而是**逐字**加（32 bit + 32 bit）。
- 一般整數加法會有**進位（Übertrag）**，結果可能是 33 bit。
- **丟掉最高位（MSB，第 33 位）**（fallengelassen）→ 數學上就是**加法 mod $2^{32}$**。

**四個階段**：

| 階段 $t$ | 輪 $j$ |
|---|---|
| 1 | 0 – 19 |
| 2 | 20 – 39 |
| 3 | 40 – 59 |
| 4 | 60 – 79 |

（4 × 20 = 80，「可以用計算機檢查」。）

每一輪 $j$ 的輸入：**5 個字 A、B、C、D、E**，加上一個字 **$W_j$**。

【口頭】「**『階段（stage）』這個詞是我發明的**。每 20 輪分一組**是真的**，不是我發明的；但我不知道別人怎麼叫它。我寫書時想找個好名詞，就叫它 stage（Stufe、Phase，隨你叫）。」

#### 還剩兩個問題

【課堂討論】要用 Java（C、C++……「**Visual Basic？那是侮辱**」）實作，還缺什麼？
1. → 學生答：**輪裡面發生什麼？**
2. → 學生答：**訊息排程怎麼運作？**「很好。」

## 4. SHA-1 細節

### 4.1 輪函數

【口頭】
- 「需要 **20 個小方格**（Kästchen）、大約 10 公分來畫。」
- 「你**不用抄**，書裡有。你們大概注意到我**不太愛用 PowerPoint 或 PDF**，我通常用黑板……**你們生命的最後一年**有注意到嗎？我喜歡畫。如果你討厭畫，就別畫，書裡有。但為了解釋，我覺得畫出來有幫助。」

#### 從 Feistel 網路出發

【課堂討論】哪個密碼是基於 **Feistel 網路**？「我們**正好**介紹過一個。」→ **DES**。

Feistel 網路：分成**左右兩半**；右半送進函數 $f$，用 $f$ 的輸出（XOR）去「加密」左半。

**SHA-1 的輪**也類似：
- 分成**五塊** A、B、C、D、E。
- 用 **A、B、C、D** 去「加密」**E**，粗略地說。
- 不用 XOR，而用 **mod $2^{32}$ 加法**。

**「加密」E 用了哪些東西**：

| 加進 E 的東西 | 說明 |
|---|---|
| $f_t(B, C, D)$ | 階段相關的函數 |
| $A \lll 5$ | A 不進 $f$，而是**循環左移 5 位**（32 bit 中有 5 個 bit 掉出去，再從另一邊放回來 → **位元旋轉**） |
| $W_j$ | 【課堂討論】Feistel 裡 $f$ 的另一個輸入？→ **子金鑰**。這裡不放進 $f$，而是**更直接**地加上去。「不是真的金鑰，是訊息排程的字 $W_j$。」 |
| $K_t$ | **輪常數**，每個階段一個：$K_1, K_2, K_3, K_4$ |

【口頭】**不平衡 Feistel 網路**：
- 「它**不是**，但**很像**所謂的**不平衡 Feistel 網路（unbalanced Feistel network）**。」
- 一般 Feistel 叫**平衡的**，因為從中間切開。
- 這裡**不平衡**：只有 **1/5（20%）**被加密，另外 **4/5（80%）**沒被加密或幾乎沒被加密。

#### 為什麼要換位置

【口頭】「**別抄。我故意做錯一件事**，為了教學。」
- 如果把結果直接當**新的 E**，有什麼問題？
- 下一輪，E 又被很好地加密，再一次、再一次……**A、B、C、D 卻沒什麼變化**。
- 「Feistel 網路裡我們這樣做嗎？**不，我們會交換**。」

**SHA-1 的交換方式**：

| 新的 | 來自 |
|---|---|
| **A** | $E + f_t(B,C,D) + (A \lll 5) + W_j + K_t$（剛才「加密」的結果） |
| **B** | 舊的 **A**（右移一格） |
| **C** | 舊的 **B** $\lll 30$ ←「**唯一不規律**的」 |
| **D** | 舊的 **C** |
| **E** | 舊的 **D** |

【口頭】B **循環左移 30 位**，「等於**右移 2 位**」。

$$\boxed{A, B, C, D, E \;=\; \big(E + f_t(B,C,D) + (A)_{\lll 5} + W_j + K_t\big),\; A,\; (B)_{\lll 30},\; C,\; D}$$

```
     A       B       C       D       E
     │       │       │       │       │
     │       ├──→[  f_t(B,C,D)  ]───→⊞
     ├─⋘5────────────────────────→⊞
     │       │                       ⊞ ←── W_j
     │       │                       ⊞ ←── K_t
     │      ⋘30      │       │       │
     ↓       ↓       ↓       ↓       │
   新B     新C     新D     新E      新A（從最右繞到最左）
```

#### 每個階段的 $f_t$ 不一樣

【口頭】
- $f_t$ 對 SHA-1 **非常重要**。**四個不同的函數**：$f_1, f_2, f_3, f_4$，依階段而定。
- 換成區塊密碼的話：好比 DES 第 1–4 輪用一個 $f$，第 5–8 輪用另一個。**AES、DES 都沒這樣做**。
- 有些區塊密碼有：「我想到的是 **Serpent**（我們沒講過）。我想是前 8 輪用某組 S-box，接下來 8 輪用另一組……共四組。」⚠️ 教授自己說「**別引用我（don't quote me）**」，這段細節未經課本確認。
- 輪常數也一樣，4 個：$K_1, \ldots, K_4$。

【口頭】「（我把門關起來。）」

#### 課本表 11.3：輪函數與輪常數

| 階段 $t$ | 輪 $j$ | 常數 $K_t$ | 函數 $f_t(B,C,D)$ |
|---|---|---|---|
| 1 | 0…19 | `5A827999` | $(B \wedge C) \vee (\bar{B} \wedge D)$ |
| 2 | 20…39 | `6ED9EBA1` | $B \oplus C \oplus D$ |
| 3 | 40…59 | `8F1BBCDC` | $(B \wedge C) \vee (B \wedge D) \vee (C \wedge D)$ |
| 4 | 60…79 | `CA62C1D6` | $B \oplus C \oplus D$ |

【口頭】
- **常數**：每個 32 bit（8 個十六進位字元，每個 4 bit）。「**寫死在石頭上**，你不能選。」
- **$f$ 函數**：「都**非常簡單**，比 **DES 的 $f$ 函數**或 AES 的任何一層都簡單得多。」
- 符號：$\wedge$ = **AND**（位元 AND，32 bit）、$\vee$ = **OR**、$\bar{B}$（B 上面一條**線**，「Strich」）= **反相**（每個 bit 翻轉）、$\oplus$ = **XOR**。
- （⚠️ 語音辨識把 $f_2$、$f_3$ 的描述弄得有點亂；以課本表格為準：$f_2$ 和 $f_4$ 是 XOR，$f_3$ 是 AND/OR。）

### 4.2 訊息排程

【口頭】「**幸好，這個很好解釋。**」
問題：輸入 512 bit，怎麼得到 80 個 32 bit 的字 $W_0, \ldots, W_{79}$？

**步驟 1：切成 16 個字**
$$x_i = \big(x_i^{(0)}, x_i^{(1)}, \ldots, x_i^{(15)}\big)$$
【課堂討論】心算：512 bit 裡能放幾個 32 bit 字？→ 學生先說 15，教授：「是 **16**。16 × 32。最後一個索引是 15，因為從 0 開始數。」

**步驟 2：前 16 個直接複製**
$$W_j = x_i^{(j)}, \qquad 0 \le j \le 15$$
「**甚至不用算**，直接抄過來。」

**步驟 3：後 64 個用遞迴公式**（$16 \le j \le 79$）
- 往回 **16** 格、**14** 格、**8** 格、**3** 格，把這四個字 XOR 起來。
- 例：$W_{16}$ 用 $W_0, W_2, W_8, W_{13}$。
- 算 $W_{17}$ 時，全部**往右移一格**。

【課本補充】完整公式（課本 §11.4.2）：

$$W_j = \begin{cases} x_i^{(j)} & 0 \le j \le 15 \\[4pt] \big(W_{j-16} \oplus W_{j-14} \oplus W_{j-8} \oplus W_{j-3}\big)_{\lll 1} & 16 \le j \le 79 \end{cases}$$

⚠️ **課堂與課本不同**：教授在課堂上只講了四個字的 XOR，**沒有提到最後還要循環左移 1 位**（$\lll 1$）；課本的公式有。以課本為準。
（課本另外提到 SHA-0 和 SHA-1 的差別就在壓縮函數的「排程」。）

【口頭】「這也**很快**：舊的 $W$ 存著，算一個新 $W$ 只要 **3 次 XOR**。」

### 4.3 【課本補充】前處理：填充與初始值

課堂沒講（教授說看書），依課本 §11.4.1 整理。

**填充**：訊息 $x$ 長 $l$ bit，要補到 512 的倍數：
1. 接一個 **「1」**
2. 接 **$k$ 個「0」**，$k \equiv 448 - (l + 1) \pmod{512}$
3. 接 **64 bit 的 $l$**（訊息長度的二進位表示）

```
   ┌─────── l bits ───────┬── k+1 bits ──┬── 64 bits ──┐
   │      訊息 x          │  1 0 0 … 0   │      l      │
   └──────────────────────┴──────────────┴─────────────┘
              總長是 512 的倍數
```

**例 11.1**：訊息 `"abc"`，3 個 8 bit ASCII 字元，$l = 24$。
- $k = 448 - 25 = 423$
- 填充後：`01100001 01100010 01100011` + `1` + 423 個 `0` + 64 bit 的 `...011000`（= 24）
- 總長：$24 + 1 + 423 + 64 = 512$ ✔

（第 25 講提到：**含長度資訊的填充**能擋住 secret-prefix MAC 的附加攻擊。）

SHA-1 能處理的訊息最長 $2^{64}$ bit（因為長度欄位 64 bit）。

**初始值 $H_0$**（五個 32 bit 字，固定）：

| 字 | 十六進位 |
|---|---|
| $A = H_0^{(0)}$ | `67452301` |
| $B = H_0^{(1)}$ | `EFCDAB89` |
| $C = H_0^{(2)}$ | `98BADCFE` |
| $D = H_0^{(3)}$ | `10325476` |
| $E = H_0^{(4)}$ | `C3D2E1F0` |

### 4.4 實作效率

【口頭】
- 80 輪**看起來不利於吞吐量**：AES 10 輪，這是 80 輪。
- 但**每輪做的事非常簡單**：4 次加法、旋轉不複雜；$f$ 函數只要大約 **3–4 個組合語言指令**。
- 「整個一輪大概 **10 個機器週期**，**非常非常快**。」
- 「**這不是巧合**，這個密碼**主要就是為了快速軟體**設計的。」

【課本補充】
- 高度最佳化的組合語言，在 64 bit 處理器上可達 **1 Gbit/s** 以上，一般實作可能慢很多。
- MD4 家族的缺點：**很難平行化**。
- **硬體**：FPGA 可達幾 Gbit/s，比預期大，因為 $f_t$ 隨階段變化，而且要很多暫存器存 512 bit 中間結果。所以硬體上 **AES 通常更小更快**，有時會偏好**以區塊密碼為基礎**的雜湊。

## 5. 一頁速查表

### 5.1 生日攻擊與安全等級

| 項目 | 內容 |
|---|---|
| 找碰撞需要 | $t \approx 2^{(n+1)/2}\sqrt{\ln\frac{1}{1-\lambda}}$ |
| 160 bit 輸出 | 約 $2^{81}$（50%）、$2^{82}$（90%） |
| 安全等級 | 約 $n/2$ bit |
| 配 AES-128 | 雜湊輸出要 **256 bit** |

### 5.2 雜湊函數分類

| 類型 | 例子 |
|---|---|
| 專用 | **MD4 家族**：MD4（破）、MD5（破）、SHA-1（搖搖欲墜，$2^{63}$ 攻擊）、SHA-2（安全）；SHA-3（新） |
| 以區塊密碼為基礎 | Matyas–Meyer–Oseas、Davies–Meyer、Miyaguchi–Preneel、Hirose |

### 5.3 SHA-1 參數

| 項目 | 值 |
|---|---|
| 結構 | **Merkle–Damgård** |
| 輸出 | **160 bit** = 5 個 32 bit 字 A–E |
| 訊息區塊 | **512 bit** = 16 個 32 bit 字 |
| 輪數 | **80** = 4 階段 × 20 輪 |
| 每階段 | 自己的 $f_t$ 和 $K_t$ |
| 加法 | mod $2^{32}$（丟掉進位） |
| 最後 | 前饋：$H_i = H_{i-1} \boxplus (\text{80 輪的輸出})$（逐字 mod $2^{32}$） |

### 5.4 SHA-1 三個公式

**輪函數**：
$$A, B, C, D, E = \big(E + f_t(B,C,D) + A_{\lll 5} + W_j + K_t\big),\; A,\; B_{\lll 30},\; C,\; D$$

**訊息排程**：
$$W_j = x_i^{(j)}\ (0 \le j \le 15), \qquad W_j = (W_{j-16} \oplus W_{j-14} \oplus W_{j-8} \oplus W_{j-3})_{\lll 1}\ (16 \le j \le 79)$$

**填充**：訊息 + `1` + $k$ 個 `0` + 64 bit 長度，$k \equiv 448 - (l+1) \bmod 512$

### 5.5 壓縮函數 vs 區塊密碼

| 區塊密碼 | SHA-1 壓縮函數 |
|---|---|
| 明文從主輸入進去 | **$H_{i-1}$** 從主輸入進去 |
| 金鑰從旁邊進去 | **訊息 $x_i$** 從旁邊進去 |
| 金鑰排程 | **訊息排程** |
| Feistel（DES）：平衡 | **不平衡**（只「加密」1/5） |

## 附：本講一句話總結

> **雜湊輸出 $n$ bit 只有約 $n/2$ bit 的抗碰撞強度，所以配 AES-128 要用 256 bit 的雜湊；實務上最常見的雜湊函數屬於 MD4 家族，用 Merkle–Damgård 結構把長訊息切成 512 bit 區塊逐塊壓縮，而 SHA-1 的壓縮函數可以看成一個「把訊息當金鑰」的 80 輪不平衡 Feistel 密碼：每輪用 A、B、C、D 去更新 E 再換位置，最後把輸入前饋加回輸出。**
