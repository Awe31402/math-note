## 0. 這堂課要做什麼

> ⚠️ 逐字稿開頭直接進入定義，沒有一般的開場介紹。

`[00:00]` **雜湊函數**是一種**輔助函數**（德文 Hilfsfunktion）。

【口頭】
- 「它不像區塊密碼那樣拿來加密。雜湊函數**幾乎總是跟其他密碼機制一起用**，但它**超級重要**。」
- 用途（`[00:01]`）：**數位簽章**、**MAC**（訊息鑑別碼，兩週後）、**金鑰建立**（課程最後）、**亂數產生器**（【課堂討論】RNG 是什麼？→ 第三、四週講過的亂數產生器）……
- 「基本上，只要是**真實世界的密碼實作**，你**很有可能**會用到雜湊函數。」

【課本補充】
- 雜湊函數算出訊息的**摘要（digest）**：一個短的、固定長度的 bit 字串，可以看成訊息的**指紋（fingerprint）**。
- **跟之前所有密碼演算法不同：雜湊函數沒有金鑰。**
- 其他用途：**儲存密碼的雜湊值**、**金鑰推導**。

【口頭】`[00:02]`「我（以及其他一些書）用**數位簽章**來引出雜湊函數。我覺得這是很好的方式，也許也是它**歷史上主要的用途**。」

## 1. 動機：怎麼簽很長的訊息

### 1.1 問題：RSA 一次只能簽 256 byte

`[00:02]` 回顧上兩週的簽章協定：Bob 發公鑰；用私鑰簽 $x$ 得到 $s$；送 $(x, s)$；Alice 驗證。

用 RSA：$s = x^d \bmod n$，一次指數運算。

【課堂討論】`[00:04]`「你想用 email 附件寄一個 **PDF** 給我，用這種方式簽。真實世界的問題是什麼？我們有 90 分鐘，慢慢想。」
→ 學生答：每個區塊都要做一個簽章。

【口頭】
- $n$ 多長？大概 **2048 bit = 256 byte**。「這**很短**，大部分 PDF 都比這長。」
- 這個公式**一次只能簽大約 256 byte**。

【課本補充】RSA 模數實務上 1024～3072 bit，也就是只有 **128～384 byte**。大部分 email 都比這長。

### 1.2 天真做法：切塊各自簽 —— 很糟

`[00:05]` 大部分人的直覺（就像區塊密碼，AES 一次只加密 128 bit，所以切塊）：

```
x₁        x₂        x₃        …    x_n
 ↓         ↓         ↓              ↓
sig       sig       sig            sig
 ↓         ↓         ↓              ↓
s₁        s₂        s₃        …    s_n
```

【口頭】`[00:06]`「**看課本這張圖的標題**：『**簽長訊息的不安全做法**』。**這很糟。**課本列了三個理由，不看書的話有人想得到嗎？」

| 問題 | 說明 |
|---|---|
| **1. 不安全**（最嚴重） | 【課堂討論】學生答：可以**換掉一個區塊**。「非常好，其實這是**最嚴重**的。」 |
| **2. 太慢** | 【課堂討論】學生答：工作量很大 |
| **3. 訊息膨脹** | 【口頭】「我不想細講。」 |

#### 不安全

`[00:07]`【口頭】
- 假設 $x$ 是一份**很長的合約**，最後有**附件（Anhang）**。附件有時很重要，例如公司或房子的估價、其他財務細節。
- 攻擊者可以**丟掉最後的 $(x_n, s_n)$**，不轉發出去。→ 簽章**只涵蓋部分訊息**。
- 也可以從中間抽掉某個簽章、或**重新排序**（例如把 $(x_2, s_2)$ 和 $(x_3, s_3)$ 對調）。
- 「這跟**上學期對 ECB 模式的攻擊**很像（第 9 講）。簽章是有效的（完整性、不可否認性……），但**只在區塊層級**，沒把訊息當成一整個。」

【課本補充】攻擊者不能改單一區塊**內部**，但整則訊息**沒有保護**：可以移除、重排、從之前訊息的碎片**拼湊**出新訊息和簽章。

#### 太慢

`[00:09]`【口頭】
- RSA 指數運算本來就很貴。
- 256 MB 的檔案（「現在不算大」），一次只能簽 256 byte → 要做 **100 萬次 RSA 指數運算**才完成一個簽章。
- 「等於要把**整則訊息都丟進非對稱演算法**，**非常非常慢**。」

【課本補充】
- **驗證者也一樣慢**。
- **訊息膨脹**：簽章跟訊息一樣長 → 1 MB 的檔案要附 1 MB 的 RSA 簽章，總共傳 2 MB。

> 【口頭】「**不安全、又很慢。所以忘了它。**」

### 1.3 解法：先雜湊、再簽

`[00:10]`【口頭】「**簽之前先把訊息 $x$ 變小。**」

```
x₁  x₂  x₃  …  x_n     （很長的訊息，例如 256 MB 的 PDF）
 └───┴───┴──┬──┘
            ↓
         [  h  ]        雜湊函數
            ↓
            z           （短、固定長度）
            ↓
   k_pr → [ sig ]       （很慢，但只做一次、而且輸入很短）
            ↓
            s
```

【口頭】`[00:11]`「**這張圖非常重要**，對今天、對下週，**如果你留在 IT 安全，可能對你一輩子都是**。」

【口頭】`[00:12]`「今天這堂課**很有建設性**。有時候我進來給你們一個演算法，再討論它怎麼運作。今天**很有系統**：只看這張圖，**推導出需求**，不談 bit 移位之類的細節。」

#### 有雜湊的簽章協定

`[00:13]`

```
   Alice                                Bob
              ←────── k_pub,B ──────
                                     z = h(x)
                                     s = sig_{k_pr,B}(z)
              ←────── (x, s) ───────
   z' = h(x)
   ver_{k_pub,B}(s, z') = true / false
```

- Bob 不直接簽 $x$（256 MB），而是先算 $z = h(x)$（「壓縮」，加引號），**簽 $z$**。
- 【課堂討論】`[00:15]` 驗證函數的輸入？→ $s$，以及**另一個**？→ **$z'$**！
- 【課堂討論】Alice 怎麼知道 $z'$？→ **她也有雜湊函數**。「她去書店買我的書查 $h$ 怎麼算，或去維基百科。」

> 【口頭】`[00:16]`「**很重要**：不管簽章端還是驗證端，**訊息本身都不直接參與了**。」
> 「這就是為什麼今天這堂課不只 15 分鐘：**簽章和驗證都不再直接用訊息**，這**可能是攻擊的缺口**，而它**確實是**。」

**名詞**（`[00:17]`）：雜湊值 $z$ 也叫
- **訊息摘要（message digest）**
- **指紋（fingerprint）**。【口頭】「德文我想不到好詞。Fingerprint 很好。」

## 2. 雜湊函數的需求

`[00:18]`【口頭】「我們**很少**這樣做：列一張**待辦清單**，『演算法要有什麼才好』。平常是反過來，我給你演算法再討論。**現在我們做需求工程（requirement engineering）。**」

### 2.1 三個實用需求

`[00:19]`

| # | 需求 | 理由 |
|---|---|---|
| 1 | **任意長度的輸入** | 【口頭】「我們會陷入這個麻煩，就是因為**長訊息不能簽**。」不要做一個 256 MB 能用、260 MB 就不能用的函數。從 10 byte 的短 email 到 **50 GB 的硬碟**，都要**同一個函數** |
| 2 | **固定長度的輸出** | 【口頭】標準簽章演算法能好好簽的只有**幾百 bit** |
| 3 | **有效率（快）** | 【口頭】「要雜湊 50 GB 的硬碟，要把約 50 兆個 bit 全部丟進去。**你不會想等一週。**」軟體、硬體都要快 |

【課本補充】實務上的雜湊函數輸出長度在 **128～512 bit** 之間。

### 2.2 對輸入很敏感

`[00:23]`【口頭】課本有一張很好的圖：
- 一段《愛麗絲夢遊仙境》開頭的長文字 → 固定長度的輸出（例子裡是 8 個十六進位字元 = 32 bit）
- 不同的輸入 → 還是同樣長度的輸出
- 「**I am not a crook**」和「**I am not a cook**」—— 看起來、聽起來幾乎一樣 → **輸出應該完全不同**

> **翻一個 bit，輸出就要變得完全不一樣。**（跟區塊密碼的雪崩效應很像，第 5 講。）

【口頭】「前三個需求和這一點**有一點點**安全意味。接下來三個才是**真正的安全需求**，這是今天**最好玩的部分**，我們會談比平常**多很多**的攻擊。」

【課本補充】
- 雜湊函數**沒有金鑰**，那它們對安全性有什麼影響？它們不加密、也沒有金鑰……
- 但密碼學常常很狡猾，**有些攻擊專門利用雜湊函數的弱點**。
- 三個核心安全性質：**原像抵抗、第二原像抵抗、碰撞抵抗**。

### 2.3 安全需求 1：原像抵抗（單向性）

`[00:25]`

> **原像抵抗（preimage resistance）/ 單向性（one-wayness）**：給一個雜湊輸出 $z$，**算不出**任何輸入 $x$ 使 $h(x) = z$。

```
       x  ←── ✘ 不可能 ───  z
       x  ──── h ─────→     z   （容易）
```

【口頭】
- 「這是一個**單向函數**。」
- 「pre-image（原像）這個詞我很討厭，**太複雜了**。它的意思就是**輸入**。不是什麼前一張圖，就是**輸入的那張圖**。」
- 「對數位簽章**可能沒那麼超級重要**，但對**很多其他應用**，例如**金鑰推導**，就**非常非常重要**。」課本有個例子。

【課本補充】課本的例子：
- 假想一個協定，Bob **加密訊息但不加密簽章**，送出 $(e_k(x), \text{sig}_{k_{pr}}(z))$。$e_k$ 是 AES 之類，$k$ 是 Alice 和 Bob 共享的。
- 用 RSA 簽章 $s = z^d \bmod n$。
- Oscar 用 Bob 的**公鑰**算 $s^e \equiv z$ → 拿到雜湊值 $z$。
- 如果 $h$ **不是單向的**，Oscar 能算 $h^{-1}(z) = x$ → **AES 加密被簽章繞過了，明文洩漏**。

### 2.4 安全需求 2：第二原像抵抗（弱碰撞抵抗）

`[00:26]`

> **第二原像抵抗（second preimage resistance）**：**給定** $x_1$（以及 $h(x_1)$），**找不到**另一個 $x_2 \ne x_1$ 使 $h(x_1) = h(x_2)$。
> 也叫**弱碰撞抵抗（weak collision resistance）**。

#### 為什麼重要：替換攻擊

`[00:27]`【口頭】例子：
- $x_1$ = 「轉 **10 歐元**到 Oscar 的帳戶」—— Bob 真的送出的訊息，數位簽章簽給銀行。
- 假設 Oscar 能找到 $x_2$ = 「轉 **10,000 歐元**到 Oscar 的帳戶」，而且 $h(x_1) = h(x_2)$。

```
   Alice（銀行）              Oscar                    Bob
                                                    z = h(x₁)
                                                    s = sig(z)
              ←── (x₂, s) ──  替換  ←── (x₁, s) ────
   z' = h(x₂) = h(x₁)
   ver(s, z') = true ✔ ← 被騙了！
```

- Oscar 在網路上攔截，把 $x_1$ 換成 $x_2$，**簽章 $s$ 不變**。
- 【口頭】「當然他不會用紅粉筆寫，訊息標頭還是寫『我來自 Bob』。」
- 銀行 Alice 不知道是假的，算 $h(x_2)$ —— **跟 $z$ 一樣** → **驗證通過**。

> 【口頭】`[00:30]`「你剛學到一件**非常非常重要**的事：**簽章和驗證都作用在 $z$ 上，不是作用在訊息上**。所以如果你能偷偷讓**不同的訊息對到同一個 $z$**，就可能成功。**這是玩雜湊函數要付的代價。**」

【口頭】`[00:31]`「另一個我很喜歡的名字：**弱碰撞抵抗**。為什麼叫碰撞？因為**兩個輸出撞在一起**，一模一樣。」

### 2.5 安全需求 3：碰撞抵抗（強碰撞抵抗）

`[00:32]`【口頭】「可能**最重要**的攻擊，也是今天後半堂的動機。」

> **碰撞抵抗（collision resistance）**：找不到**任何一對** $x_1 \ne x_2$ 使 $h(x_1) = h(x_2)$。
> 也叫**強碰撞抵抗（strong collision resistance）**。

```
  第二原像：  x₁（固定、已給）       x₂ = ?    →  h(x₁) = h(x₂)
  碰撞：      x₁ = ?                x₂ = ?    →  h(x₁) = h(x₂)
```

【課堂討論】「這個奇怪的寫法 —— 為什麼這裡有**兩個問號**？兩者差在哪？」
→ 學生答：左邊 **$x_1$ 是固定的**，右邊**兩個都是隨意的**。「**完全正確。**」

- 第二原像：$x_1$ 是**給定**的（例如 Bob 的銀行轉帳）。
- 碰撞：**Oscar 兩個都能選**。

#### 碰撞也能變成攻擊

`[00:33]`【口頭】「你可能覺得這完全沒用，因為攻擊需要的是第二原像那種情況。但我要示範它**也能變成攻擊**。」

**Oscar 準備兩則訊息**（他可以兩則都調整）：
- $x_1$：**善意的**「請轉 10 歐元到我帳戶」
- $x_2$：**惡意的**「請轉 10,000 歐元到我帳戶」
- 而且 $h(x_1) = h(x_2)$

```
   Alice（銀行）              Oscar                    Bob
                              ──── x₁ ────→
                                                    z = h(x₁)
                                                    s = sig(z)
              ←── (x₂, s) ──  替換  ←── (x₁, s) ────
   h(x₂) = h(x₁) → 驗證通過 ✔
```

**關鍵**：Oscar 要**騙 Bob 簽 $x_1$**。

【口頭】`[00:35]`「這看起來很牽強，怎麼可能發生？舉個例子：
- Bob 是你我這種一般人。Oscar 是一個**電商**，在網路上賣東西。
- $x_1$ 是**發票**：你買了 iPod 的耳機 10 歐元，Oscar 說『請付款、請簽這張發票（PDF）然後寄給你的銀行』。
- Bob 雜湊（PDF 有 50 KB）、簽章、送出 $(x_1, s)$。
- Oscar 攔截，把『耳機 10 歐元』換成『10,000 歐元』。銀行驗證通過。」

【口頭】`[00:37]`「我不是說這跟上一個攻擊一樣，Oscar 這邊**比較複雜**，他得騙 Bob 簽。但可以想像這種事會發生。」

【課本補充】課本的例子用 10 美元 vs 10,000 美元；Oscar 可以假扮成**無辜的一方**，例如網路電商，$x_1$ 是他產生的訂單。

### 2.6 碰撞一定存在：鴿籠原理

`[00:42]`【口頭】「兩種攻擊都很討厭，我們不想要。正常反應應該是：**能不能設計出沒有碰撞的雜湊函數？**」

**答案：不行。所有雜湊函數一定有碰撞。**【課堂討論】為什麼？

```
   輸入空間 X（無限大）            輸出空間 Z（2ⁿ 個值）
   ┌──────────────────┐           ┌────────┐
   │ • • • • • • • •  │  ── h ──→ │ • • •  │
   │ • • • • • • • •  │           │ • • •  │
   │ • • • • • • • •  │           └────────┘
   └──────────────────┘
```

- 輸入可以**任意長** → 無限多個（「我沒辦法把它畫成封閉的，但假裝一下」）。
- 輸出長度固定，例如 160 bit → 只有 $2^{160}$ 個值（「很大，但有限」）。
- 只要有 $2^{160} + 1$ 個輸入，就**至少有一個碰撞**。
- 【口頭】「這是**計數論證（counting argument）**，**超級簡單**，沒有深奧的數學。」

**兩個好玩的名字**（`[00:45]`，「我寫書時才學到的」）：

| 名字 | 比喻 |
|---|---|
| **Dirichlet 抽屜原理** | 10 雙襪子、9 個抽屜 → 一定有一個抽屜放兩雙 |
| **鴿籠原理（pigeonhole principle）**，德文 Taubenschlagprinzip | 20 隻鴿子、19 個鴿籠 → 至少一個籠子有兩隻。【口頭】「有人家裡養鴿子嗎？沒有？」 |

【課本補充】實務上，對隨機輸入，每個輸出值**機率差不多**，所以**每個輸出值都有弱碰撞**。

【口頭】`[00:47]`「這前 45 分鐘好像沒什麼意思，反正一定攻擊得到？**不對，別那麼快放棄。**」

> **結論**：碰撞一定存在，**但要讓它們非常難找到**。

【課本補充】
- 好的雜湊函數：給 $x_1$ 和 $h(x_1)$，**不可能用分析的方式構造** $x_2$。
- 但 Oscar 永遠可以**隨機亂試** $x_2$，算雜湊、比對 —— 就像對稱密碼的暴力搜尋。
- 對這種攻擊，以今天的電腦，**80 bit 輸出就夠了**。
- **但有更強的攻擊**，逼我們用更長的輸出 → 下一節。

## 3. 生日悖論與生日攻擊

`[00:38]`【口頭】「接下來是**第三部分：生日悖論**。聽起來很好玩，但**這是最難的部分**。如果到現在都在睡，不太好但還好 —— 看筆記和課本的圖，大概 20 分鐘就懂了。**接下來請專心**，包括第八排。這也很酷，有一點數學，事情沒那麼顯而易見。」

【課堂討論】`[00:39]` 誰聽過生日悖論？→ 大約 41%。

【口頭】`[00:40]`
> 「第二原像攻擊（$x_1$ 由 Bob 選、$x_2$ 由 Oscar 選）和碰撞攻擊（$x_1$、$x_2$ **都由 Oscar 選**）看起來差不多。**結果碰撞攻擊容易得多** —— 『多很多』是指**平方根**。」
> 「如果第二原像攻擊要 $n$ 步，碰撞攻擊只要 $\sqrt{n}$ 步。100 萬步 → 【課堂討論】$\sqrt{1{,}000{,}000} = $ **1000 步**。100 步 → 10 步。」

#### 【口頭】雜湊函數是很熱門的主題

`[00:41]`
- 【課堂討論】AES 什麼時候產生的？→ **大約 2000 年**，從 1997 年開始的三年過程。
- 「**同樣的事正在雜湊函數上發生**：他們正在產生**新的雜湊函數**，整個密碼學界都在做。這是**非常重要**的需求，不是 Paar 教授特別喜歡的冷門題目。我其實也沒那麼喜歡它，但**超級重要**。」（→ 第 22 講 SHA-3）

### 3.1 第二原像攻擊要多少步

`[00:48]` Oscar 有 $x_1$（「轉 10 歐元」，存在資料庫裡），想找碰撞的 $x_2$：
1. 構造「轉 10,000 歐元」，雜湊，比對 → 大概不一樣。
2. 再構造 $x_3$：
   - 可以改語意，例如「9,999 歐元」。
   - **更好**：**語意不變**，在 PDF 結尾**加一個空格（Leerzeichen）** —— 銀行看不出差別，但雜湊值**完全不同**。
   - 不行就再換一個……

【口頭】`[00:50]`「這很實際。通常你能在**看不見的位置**做變化：加 Tab、加定位點；或者用 **7 bit ASCII**，每個字元的**第 8 個 bit 沒用到**，每個字元都可以設 0 或 1。所以**同樣意思**的『轉 10,000 歐元』可以產生**非常非常多**版本。」

【課本補充】例如有 **64 個位置**可以改或不改，就有 $2^{64}$ 個語意相同、雜湊值不同的版本。

**複雜度**（`[00:51]`）：如果輸出是 80 bit，每個新輸入得到一個偽隨機的 80 bit 輸出，大約要試 **$2^{80}$ 次**才會碰到 $h(x_1)$。

### 3.2 生日問題

`[00:52]`【口頭】「這跟一個問題**密切相關**：開派對要邀請多少人，才會有兩個人**同一天生日**？聽起來很怪。」

#### 版本 1：跟**特定一天**撞

`[00:53]`【口頭】「我的生日是 **7 月 18 日**。要邀請多少人，才會有**另一個人**也是 7 月 18 日？這對應**第二原像**。」

【課堂討論】
- 「30 或 40？」→「不、不、不，**多得多**。」
- 「200？」→「200 很好。」
- 教授：「每個人進來都有 1/365 的機會撞到，所以**平均要 365 人**。很大的派對。運氣好第一個人就是 7 月 18 日；運氣差邀 1000 人都沒有。」

> ⚠️ 教授先說「大約 180」（365 的一半），又改口說「平均 365」。課本則說直覺上會以為「任兩人撞」需要約 183 人（一年天數的一半），但其實**遠少於此**。

#### 版本 2：**任兩個人**撞

`[00:55]`【口頭】「稍微改一下：不要求撞 7 月 18 日，**任何一天**都可以。我們做個**實驗**：我傳一張紙下去，寫你的生日（只寫日和月，不寫年）。**一有人撞到，就跳起來大叫。**」

**計算**（`[00:56]`）：

| 人數 | 沒有碰撞的機率 |
|---|---|
| 1 人（我） | 1 |
| 2 人 | $1 - \frac{1}{365}$（第二人只能撞我） |
| 3 人 | $\left(1 - \frac{1}{365}\right)\left(1 - \frac{2}{365}\right)$ |
| $t$ 人 | $\left(1 - \frac{1}{365}\right)\left(1 - \frac{2}{365}\right) \cdots \left(1 - \frac{t-1}{365}\right)$ |

> 【口頭】`[00:56]`「**醒來，這是整整 90 分鐘最重要的一句話：**第三個人進來時，他**有兩個選擇**可以撞 —— 可以撞我，**也可以撞已經在房間裡的第二個人**。」

【口頭】`[00:59]`「如果是攻擊者構造訊息：第三則訊息**可以跟前面所有訊息比對**。你可以感覺到，**需要比對的組合數成長得很快**。」

**結果**：

$$P(\text{至少一對碰撞}) = 1 - P(\text{沒碰撞}), \qquad t = 23 \;\Rightarrow\; \approx 50.7\%$$

> **只要 23 人，就有約 50% 的機會兩人同一天生日。**
> 【口頭】「不是 365，是 **23**。這就是**生日悖論**。算一下，大概就是 $\sqrt{365} \approx 19$ 的量級。」

【課本補充】40 人時機率約 **90%**。366 人時一定有碰撞（一年只有 365 天）。

**課堂實驗**（`[01:00]`、`[01:04]`）：
- 「有碰撞了嗎？」「**九個人**……」「應該大概 23 人。」
- 到下課時：「我撞了！」「沒有。」「**繼續傳**，同學會接著。」

> ⚠️ 實驗最後結果字幕沒有清楚記錄。

### 3.3 推廣到雜湊函數

`[01:00]`
- 生日有 **365** 種可能。
- 【課堂討論】雜湊輸出有幾種可能？→ **$2^n$**（$n$ = 輸出長度）。「**非常好。**」

$$P(\text{沒碰撞}) = \prod_{i=1}^{t-1}\left(1 - \frac{i}{2^n}\right)$$

【課本補充】推導概要：
1. 用近似 $e^{-x} \approx 1 - x$（$x \ll 1$ 時）：$P(\text{沒碰撞}) \approx \prod e^{-i/2^n} = e^{-(1 + 2 + \cdots + (t-1))/2^n}$
2. 等差級數 $1 + 2 + \cdots + (t-1) = t(t-1)/2$：$P(\text{沒碰撞}) \approx e^{-t(t-1)/2^{n+1}}$
3. 設碰撞機率 $\lambda = 1 - P(\text{沒碰撞})$，解出 $t$，並用 $t(t-1) \approx t^2$：

> **生日攻擊公式（課本 11.1）**：要有機率 $\lambda$ 找到碰撞，大約需要雜湊的訊息數為
> $$\boxed{t \approx 2^{(n+1)/2}\sqrt{\ln\left(\frac{1}{1 - \lambda}\right)}}$$

【口頭】`[01:02]`「**這是這堂課最重要的公式。**$t$ 是你要丟進雜湊函數的輸入個數。」

### 3.4 結論：輸出長度要是安全等級的兩倍

`[01:03]` **例**：80 bit 輸出，要 50% 機率找到碰撞：

$$t = 2^{81/2}\sqrt{\ln\frac{1}{1 - 0.5}} \approx 2^{40.2}$$

【口頭】`[01:04]`
> 「看起來 80 bit 輸出有 $2^{80}$ 的安全性（而 80 bit 對**第二原像**抵抗是夠的），**結果只要 $2^{40}$ 個值就能找到碰撞**。**開了平方根。**」
> 「所以要有 **80 bit 的安全性**，需要**兩倍**的長度：**160 bit 的輸出**。下週會講更多。」

【課本補充】
- $2^{40}$ 次雜湊加比對，**現在的筆電就做得到**。
- 碰撞所需的雜湊次數**大約是可能輸出數的平方根**：$\sqrt{2^n} = 2^{n/2}$。

> **要 $x$ bit 的安全等級，雜湊輸出要 $2x$ bit。**

- 所以所有雜湊函數輸出**至少 128 bit**，現代的長得多。

**不同輸出長度需要的雜湊次數**（課本 Table 11.1）：

| $\lambda$ \ 輸出長度 | 128 bit | 160 bit | 256 bit | 384 bit | 512 bit |
|---|---|---|---|---|---|
| 0.5 | $2^{65}$ | $2^{81}$ | $2^{129}$ | $2^{193}$ | $2^{257}$ |
| 0.9 | $2^{67}$ | $2^{82}$ | $2^{130}$ | $2^{194}$ | $2^{258}$ |

**有趣的地方**：想要的成功機率（50% 或 90%）**影響不大**。

**其他重點**：
- 生日攻擊是**通用攻擊**（generic），**對任何雜湊函數都適用**。但**不保證是最強的** —— 對 MD5、SHA-1 就有**比生日攻擊更快**的數學碰撞攻擊（第 21 講）。
- 很多應用（例如**儲存密碼**）**只需要原像抵抗**，那短一點的輸出（例如 80 bit）可能就夠，因為碰撞攻擊不構成威脅。

## 4. 一頁速查表

### 4.1 為什麼要雜湊

| 切塊各自簽 | 先雜湊再簽 |
|---|---|
| ✘ 能刪除、重排區塊（類似 ECB 攻擊） | ✔ 整則訊息一起保護 |
| ✘ 256 MB → 100 萬次 RSA | ✔ 只簽一次 |
| ✘ 簽章跟訊息一樣長 | ✔ 簽章很短 |

協定：$z = h(x)$，$s = \text{sig}(z)$；驗證時重算 $z' = h(x)$，$\text{ver}(s, z')$。
**簽章和驗證都不直接用訊息** → 雜湊函數的弱點就是攻擊的缺口。

### 4.2 六個性質

| # | 性質 | 類型 |
|---|---|---|
| 1 | 任意長度輸入 | 實用 |
| 2 | 固定長度輸出 | 實用 |
| 3 | 有效率 | 實用 |
| 4 | **原像抵抗**（單向）：給 $z$ 找不到 $x$ | 安全 |
| 5 | **第二原像抵抗**（弱碰撞）：給 $x_1$ 找不到 $x_2$ | 安全 |
| 6 | **碰撞抵抗**（強碰撞）：找不到任何 $x_1, x_2$ | 安全 |

（另外：對輸入很敏感，翻 1 bit 輸出完全不同。雜湊函數**沒有金鑰**。）

### 4.3 攻擊

| 攻擊 | Oscar 能選 | 攻擊 $n$ bit 輸出的複雜度 |
|---|---|---|
| 原像 | — | $2^n$ |
| 第二原像 | 只有 $x_2$ | $2^n$ |
| **碰撞（生日攻擊）** | $x_1$ 和 $x_2$ | $\approx 2^{n/2}$ |

$$t \approx 2^{(n+1)/2}\sqrt{\ln\frac{1}{1-\lambda}}$$

### 4.4 生日悖論

| 問題 | 人數 |
|---|---|
| 跟**特定一天**撞 | 很多（數百人） |
| **任兩人**撞，50% | **23** |
| 任兩人撞，90% | 40 |

### 4.5 重要結論

| 項目 | 內容 |
|---|---|
| 碰撞一定存在 | **鴿籠原理 / Dirichlet 抽屜原理** |
| 目標 | 讓碰撞**很難找到** |
| 安全等級 $x$ bit | 輸出要 **$2x$ bit** |
| 80 bit 安全性 | 160 bit 輸出 |
| 128 bit 安全性 | 256 bit 輸出 |
| 只要原像抵抗的應用 | 例如存密碼，短一點也行 |
