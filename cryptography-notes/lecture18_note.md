## 1. 數位簽章入門

`[00:07]` 目標：**一個像簽名一樣的函數**。教授先討論**真實世界（紙本）的簽名**怎麼運作，再看數位世界能不能照做。

### 1.1 紙本世界的簽名

`[00:08]`【口頭】例子：**學士文憑**
- 「你們還有四個半學期就會拿到學士文憑：IT 安全理學士，上面有你的名字和成績。」
- 「**用 Photoshop 做一張很誘人**，那就不用考我的試了，還是能找到好工作。」
- 為了防止這樣，系主任（或院長）會在**每一張文憑上簽名**。
- 假設：你也許能用 Photoshop 做出文件，**但做不出簽名**。

**簽名在抽象上的目的**（`[00:10]`）：**證明發送者（發行者）是真的** —— 例如真的是我們系、我們大學發的。

【口頭】`[00:11]`
- 「這在真實世界運作得**相當好**。你可以靠簽名**買一棟 100 萬歐元的房子**。有趣的是，簽名其實**沒那麼難偽造**：給你一小時和我的簽名，你大概能複製。」
- 「但有**社會、法律、刑事上的障礙**，讓偽造很難。」
- 「它在現代世界非常重要：用簽名註冊大學、買東西……」

**目標**：在網路、在數位世界，也要有**類似的功能**。例如在網路上買東西，提供一個簽名證明你真的買了。

### 1.2 在數位世界照做？很蠢

`[00:12]` 現在文件不是紙，是 **PDF、Word 檔**。用編輯器打開 PDF，看到的是**十六進位資料**，其實就是 0 和 1。

**天真的想法**：
- 紙本上，簽名是一條**獨特的、生物特徵般的**線。
- 那數位上，我也選一串**獨特的 0/1 組合**，例如 **1000 bit**，當作我的簽名。
- 每次寄 email 或 PDF，就把這 1000 bit 附在後面。

【課堂討論】`[00:14]`「為什麼這是我**在這堂課說過最蠢的話**？」→ 學生答：**可以複製**。

【口頭】「你們有注意到祖父母看電視用**錄影帶**而不是 DVD 嗎？—— 好吧，不是你們祖父母，是我。錄影帶是**類比**的。我們改用 DVD 和 CD 的原因之一，就是它們**很容易做出完美的複本**。」

→ 我寄一封簽了名的信給你，**第一次你就拿到我的簽名**，之後可以**完美複製**。**不行。**

### 1.3 用密碼學：簽章函數 + 驗證函數

`[00:15]`【口頭】「這門課不是教你做合約，是教**密碼學**。也許可以用密碼學。」
- 回想 Alice 和 Bob：Bob 有**正確的金鑰**，就能做到**別人做不到**的事（例如解密）。
- 所以：用**有金鑰的密碼學演算法**來產生簽名。**有金鑰的人能簽，沒金鑰的人不能偽造。**
- 「這當然跟紙本簽名有**根本上的巨大差別**。」

```
         訊息空間（所有可能的訊息）
              ┌─────────┐
              │   • x   │ ──→ [ sig_k ] ──→ y（簽章）
              └─────────┘
                                 ↓
              Alice ── (x, y) ──→ Bob
                                 ↓
                         [ ver_k (x, y) ] ──→ true / false
```

**簽章（signing）**：$y = \text{sig}_k(x)$
- 把訊息 $x$（文件、明文）和金鑰丟進**簽章演算法**。
- 【口頭】每一則訊息（例如這張文憑）都會算出**一個**簽章點。

**送出**：$(x, y)$ **兩個都要送**。

**驗證（verification）**（`[00:20]`）：
- 【口頭】「真實世界（至少在德國）大部分時候，雇主看到你的文憑上有 Bochum 大學的簽名，**就相信了**，**不會真的檢查**。」
- 「**這在數位世界不行。**你不能看著 $y$ 說『大概是對的吧，沒人會偽造』。」
- 所以需要**驗證函數** $\text{ver}_k(x, y)$，輸入**訊息、簽章、金鑰**。

#### 【口頭】一個真的會比對簽名的例子

`[00:20]`
- 教授一個大學同學娶了**西班牙**太太。他們需要她文憑的某種認證或翻譯，去了市政廳。
- 市政廳**有現任大學校長的簽名樣本**，但她的文憑比較舊，簽名是前任校長的 → 不給蓋章。
- 「他們真的有一份**原始簽名清單**，**真的拿來比對**文憑上的簽名。所以是可以這樣做的。但至少在德國，大部分人不會檢查。」

### 1.4 驗證只輸出 1 個 bit

`[00:22]`【課堂討論】驗證的結果有哪些可能？會得到幾個 bit 的資訊？→ **1 個 bit**：**通過或不通過（go / no go）**。

$$\text{ver}_k(x, y) = \begin{cases} \text{true} & \text{若 } y \text{ 有效} \\ \text{false} & \text{若 } y \text{ 無效} \end{cases}$$

【口頭】「為什麼要強調？之後用 RSA，可能要用 **2000 bit 做運算**、square-and-multiply 等大計算，但**最後只是一個『通過/不通過』**。不像加密，密文是整整 2048 bit。」

【口頭】`[00:24]`「這**不是全部的真相**，我在作弊。還缺一個**很重要的小細節**，10 分鐘後補上。我們大概對了 70%～90%。」（→ §2.6：要改用公鑰）

## 2. 安全服務（Security Services）

`[00:25]`【口頭】
- 「過去講了大概 10 個演算法，但我**有點作弊**，**沒怎麼告訴你們能用它們做什麼**。我的主要動機只有一個，可能是密碼學最簡單的事：**加密**。」
- 「現實中，除了加密還有**很多**事情能做。」

> **安全服務（security services，德文 Schutzziele）**：一個安全系統的**目標**。

【口頭】`[00:29]`「可以列出大概一打，實務上**重要性不一樣**。我介紹**最重要的四個**。」

### 2.1 機密性

> **機密性（Confidentiality）**：資訊只有授權的人看得到。

- 【口頭】「這是我一個半學期以來一直用來讓你們保持清醒的主要動機：透過不安全的通道傳東西，Oscar 想竊聽，所以要保密。」
- 主要用**對稱加密**，也可以用公鑰加密。

【課堂討論】`[00:33]` 這個簽章協定（§1.3 的圖）有提供機密性嗎？
→ **沒有**，$x$ 是明文。
→ 這是問題嗎？**不是**！「這個例子剛好相反：**你不想把成績保密**，你希望大家都看得到。我們要的是**發送者的證明**。」

【課本補充】如果需要機密性，可以把訊息和簽章**再用 AES 等加密**。

### 2.2 訊息鑑別

`[00:33]`【口頭】「接下來三個越來越有趣、越來越複雜。**醒來，接下來 10 分鐘是今天最重要的。**」

> **訊息鑑別（Message Authentication）**：訊息的發送者是真的。也叫**資料來源鑑別（data origin authentication）**。

【課堂討論】`[00:34]` Bob 收到 $(x, y)$，驗證說「有效」。Bob 知道訊息**真的來自 Alice** 嗎？
- 有學生說「**不知道，任何人都可能送**」→ 教授：「**錯**。」
- 【課堂討論】誰能產生有效的 $(x, y)$？需要什麼？→ **金鑰**。
- 假設 Alice 和 Bob 用 DH 之類建立了金鑰，**只有 Alice 有金鑰** → 只有 Alice 能產生 → **有訊息鑑別** ✔
- 「這基本上就是我的簽名在你文憑上做的事。」

### 2.3 完整性

`[00:36]`

> **完整性（Integrity）**：訊息在傳輸中**沒被竄改**。

【口頭】「不只達成了原本的目標，**還多得到更多**。」

**情境**：電子合約或電子轉帳。Oscar 在通道上把 $x$ 換成 $\tilde{x}$，例如**多加一個 0**：本來轉 1 歐元變 1000 歐元。

【課堂討論】Bob 用 $\tilde{x}$ 驗證會怎樣？→ **false**。為什麼？→ 因為這個 $y$ 和這把金鑰是屬於 $x$ 的，**不是** $\tilde{x}$。
【口頭】「之後用 RSA 時，就算只翻一個 bit，做指數運算後會**馬上擴散到整個字**，所以幾乎一定會失敗。」

#### 【口頭】紙本簽名沒有完整性

`[00:39]`
- 你的文憑上有總成績，例如 **68%**。「不太好，你想要那份工作。」
- 6 和 8 看起來沒差多少，你坐下來把 68 改成 **88**。
- 簽名在下面，**簽名能防止這個嗎？不能。**
- 「**傳統的類比紙本簽名不提供任何資料完整性。**」數位簽章**附贈**了完整性。

### 2.4 不可否認性：粉紅色福斯汽車

`[00:40]`【口頭】「**現在是這堂課最重要的 5 分鐘**：第四個服務，也是**最不直觀的**。需要一些討論才能解釋。」

> **不可否認性（Non-repudiation，德文 Nichtabstreitbarkeit / Verbindlichkeit）**：訊息的發送者**不能否認**他產生了這則訊息。更精確地說：**能向中立的第三方證明**。

#### 先看 Amazon

`[00:41]`【口頭】
- 你在 Amazon 買我的書（34 歐元左右）要送女友當聖誕禮物，大概 12 月 20 或 22 日買（「我都那時候買聖誕禮物」）。
- 結果**她跟你分手了**（或你男友跟你分手）。你又討厭密碼學，兩本書要幹嘛？
- 你想退款。Amazon 很友善：**寄回來就退錢，不問問題**。

#### 再看福斯汽車

`[00:42]` 情境：**在網路上買車**。
- 現在大部分車廠網站都有**車輛配置器**：選 Golf 的引擎、內裝顏色、導航……
- 你**品味很差**：課本例子是**粉紅色車子配橘色座椅**之類，「很醜」。
- 你用**數位簽章**簽了訂單送給福斯。你跟福斯用 DH 之類**協商了同一把金鑰**。
- 福斯驗證：「這是真的訂單，真的來自 Christof Paar，因為有數位簽章。」→ 開始生產。
- 三週後車子送到。

`[00:44]`
- 你又跟女友復合了。她看到車子說：「**你瘋了嗎？我要跟你分手。這車太醜了。**」
- 你想保住女友，想用 Amazon 那招：「我不要了。」
- **福斯不會退。**「他們不笨。這車醜到**永遠賣不出去**，他們剛損失了一兩萬歐元的生產成本。」
- 他們只能**告你**（德文 verklagen）。

#### 法庭上

`[00:45]`
- **福斯**：「Paar 教授訂了這輛車又不付錢。這是訂單（網頁表單、所有配置資料），這是**有效的簽章**，**只有 Christof Paar 有這把金鑰**，所以一定是他簽的。」
- **我（或我的律師）**：「我沒訂。」
- 【課堂討論】我能怎麼辯？→ 「**還有一方**能產生有效簽章：**福斯自己**！」
- 「而且他們**有很大的動機**這樣做 —— 這樣能賣更多車。」

> **法官無法判斷。** 事實是：我**可能**產生了簽章，但**福斯也可能**。
> 在密碼學裡，法官叫**中立的第三方（neutral third party）**。

【口頭】`[00:48]`「嚴格說這是**發送者不可否認性**。也有**接收者不可否認性**：例如作業截止時間，Marcus（助教）很嚴格，想證明你**真的在今早 8:30 前收到/寄出**作業。今天只講發送者的。」

【課本補充】課本的版本：車商是 Alice、顧客是 Bob，訂單用 AES 加密，車價 25,000 美元。「依大多數國家的法律，**Bob 大概能脫身**。」

### 2.5 為什麼對稱密碼做不到不可否認性

`[00:49]`【課堂討論】目前的協定有不可否認性嗎？→ **沒有**。接收者也有 $k$，**接收者也能產生有效簽章**。

【口頭】「怎麼辦？簡短回答：**只要待在對稱密碼學，就什麼都不能做。這是對稱演算法的固有性質。**」

【課堂討論】為什麼叫**對稱**密碼？對稱在哪？→ **同一把金鑰**。
→ Alice 能做的，Bob 也能做：都能簽、都能驗。**兩方的能力一樣。**

#### 攻擊者是誰？

`[00:51]`

| 服務 | 壞人是誰 |
|---|---|
| 機密性、鑑別、完整性 | **Oscar**（第三人） |
| **不可否認性** | **Alice 或 Bob 自己**（合法的通訊對象） |

> 【口頭】「這是網路**美麗新世界**發生的事：福斯想跟客戶安全通訊，但**客戶可能想作弊**。Alice 不是假冒的，不是 Oscar 說『我是 Alice』；**Alice 就是 Alice**，她想通訊，但之後可能想作弊。」
> 「**當 Alice 或 Bob 作弊時，對稱密碼學幫不上忙。**」

【口頭】`[00:52]`
- 「我多年來的聖經《**Handbook of Applied Cryptography**》說：**不可否認性是我們需要非對稱密碼學的主要原因**。」
- 「這有點簡化，公鑰還有其他擅長的事，例如**金鑰交換**。但這是**很大的一個理由**。」

### 2.6 改用公鑰：私鑰簽、公鑰驗

`[00:53]` 修改協定：一把金鑰變**私鑰**、另一把變**公鑰**。

【課堂討論】「如果答對，你今天早上花 60 分鐘在這裡就值得了：**私鑰用在簽章，還是驗證？**」→ **簽章**（請贊成的舉手）。

| 用途 | 金鑰 | 誰有 |
|---|---|---|
| **簽章** | **私鑰** | 只有 Alice → **只有 Alice 能簽** |
| **驗證** | **公鑰** | 任何人（包括福斯） |

【口頭】`[00:54]`
- 「這也很好：**公鑰容易分發**。我的公鑰**真的在我的網站上**：到我們研究團隊的網站，點 People，點 Christof Paar，就看得到我的 **PGP 公鑰**。」
- 「我們想讓**驗證**很容易：我透過 Blackboard 寄給你們一封數位簽章的信，你們就能驗證，只要從網站下載我的金鑰。」
- 「這很簡化，我沒處理很多討厭的攻擊，但**基本想法就是這樣**。」

**回到福斯**（`[00:55]`）：
- 你用**私鑰**簽了那張粉紅橘色的訂單。福斯生產、送車、你說「我沒訂」。
- 福斯把你拖上法庭：「這是訂單，這是數位簽章，我**用 Christof Paar 的公鑰**驗證過了。」
- 「**這下我卡住了。**我不能說『福斯簽的』，因為那是**我的私鑰**，只有我有。」「（也許埋在我的新德國身分證晶片裡，你可以用新身分證做這種事。）」
- 「**接收者能驗證，但不能自己產生簽章。**這是很酷的設定。」

【口頭】「你可以回去睡了，**今天的重點就是這個**。」

#### 一般化的數位簽章協定

`[00:57]`

```
   Alice（簽章者）                         Bob（驗證者）
   產生 k_pr, k_pub
              ────── k_pub ──────→
   s = sig_{k_pr}(x)
              ────── (x, s) ─────→
                                     ver_{k_pub}(x, s) = true / false
```

【口頭】課本從這裡開始把簽章叫 **$s$**（不叫 $y$）。

**附帶一提**（`[00:59]`）：如果把公私鑰換回**對稱金鑰**（兩邊都是 $k$），這個圖**也有名字**：**訊息鑑別碼（MAC，Message Authentication Code）**。「三四週後會講。**瀏覽器建立安全連線時大量使用 MAC**，但那是另一個故事。」

【課本補充】
- **數位簽章本身沒有用，除非跟訊息一起**。沒有訊息的簽章，就像一張紙條上只有簽名、沒有合約或支票。
- 數位簽章本身只是一個（很大的）整數，例如 2048 bit。
- 有效的簽章能**明確追溯到它的產生者**，這種證明甚至有**法律效力**，例如美國的 **ESIGN** 法、德國的**簽章法（Signaturgesetz）**。
- 三大公鑰家族（整數分解、離散對數、橢圓曲線）**都能做數位簽章**。

### 2.7 【課本補充】其他安全服務

**四個核心服務**整理：

| 服務 | 意思 | 用什麼達成 |
|---|---|---|
| 1. **機密性** | 只有授權者能看 | 主要是**對稱加密**，較少用非對稱加密 |
| 2. **完整性** | 訊息沒被改 | **數位簽章**、**MAC** |
| 3. **訊息鑑別** | 發送者是真的 | **數位簽章**、**MAC** |
| 4. **不可否認性** | 發送者不能否認 | **數位簽章** |

注意：**訊息鑑別一定隱含完整性**，反過來不一定。

**不同應用要不同組合**：
- 私人 email：前三個
- 公司 email：可能還要不可否認性
- 手機軟體更新：主要是**完整性**和**訊息鑑別**（廠商只想確保載入的是原廠更新）

**其他六個服務**：

| 服務 | 意思 |
|---|---|
| 5. **識別 / 實體鑑別** | 確認某個實體（人、電腦、信用卡）的身分 |
| 6. **存取控制** | 只讓有權限的實體使用資源 |
| 7. **可用性** | 系統可靠地可用（常用**備援**，不是密碼學） |
| 8. **稽核** | 留下安全相關活動的證據（例如日誌） |
| 9. **實體安全** | 防止實體竄改，或對竄改有反應 |
| 10. **匿名性** | 防止身分被發現和濫用 |

**例**：email 系統要匿名性沒道理（寄件人應該清楚）；但**車對車通訊**防碰撞系統很需要匿名性，**避免車子和駕駛被追蹤**。

## 3. RSA 數位簽章

`[01:00]`【口頭】「以前我介紹一個密碼系統，要花兩週（例如橢圓曲線），**很難**。**現在不是了**，因為所有密碼系統我們都做過了。例如 RSA 數位簽章**超級簡單**，這有點令人意外。」

【課本補充】
- 安全性依賴**分解兩個大質數乘積的困難度**。
- 1978 年首次描述，**實務上用得最廣的數位簽章方案**。

### 3.1 協定

`[01:02]`

**建立**：跟 RSA 加密**完全一樣**的金鑰產生（「$\Phi$ 函數、兩個隨機質數……不再做一次了，第一次考試就做過了」）：
- 私鑰 $k_{pr} = d$
- 公鑰 $k_{pub} = (n, e)$

```
   Alice（簽章者）                              Bob（驗證者）
   k_pr = d, k_pub = (n, e)
              ────── (n, e) ──────→
   s = sig_{k_pr}(x) ≡ x^d mod n
              ────── (x, s) ──────→
                                       x' ≡ s^e mod n
                                       x' ≡ x  →  有效
                                       x' ≢ x  →  無效
```

#### 【口頭】教授故意寫錯

`[01:04]` 教授先在黑板上寫了 $s = x^e$，然後問：「**有人知道我為什麼寫錯成 $e$ 嗎？**」
- RSA **加密**時用 $x^e$ —— **公開指數**。記得信箱的比喻：**任何人都能加密**，所以用公鑰。
- **RSA 簽章**要把**秘密放在指數裡** → **$x^d$**。因為產生簽章需要私鑰。

> **RSA 簽章 = 用私鑰「加密」，用公鑰「解密」。**
> 公私鑰的角色跟 RSA 加密**互換**。

**送什麼**：$(x, s)$。【口頭】「**很重要：不要只送簽章**，只有簽章沒有意義。」

**驗證**（`[01:06]`）：
- Bob 算 $x' \equiv s^e \bmod n$（用**公鑰** $e$）。
- 這只是一個 2048 bit 的數。【課堂討論】怎麼變成「有效/無效」？→「不是 XOR」→ **比較 $x'$ 和 $x$ 是否相同**。

### 3.2 正確性

`[01:08]`

$$s^e = (x^d)^e = x^{de} \equiv x \ (\mathrm{mod}\ n)$$

【課堂討論】$x^{de}$ 等於什麼？→ RSA 那時證明過（Euler phi 函數在指數裡……）：因為 $de \equiv 1 \ (\mathrm{mod}\ \Phi(n))$，所以得到 $x$。「**加密時成立的，這裡一樣成立。**」

### 3.3 達到哪些安全服務

`[01:10]`

| 服務 | 有嗎 | 理由 |
|---|---|---|
| **完整性** | ✔ | 【課堂討論】Oscar 翻了電子轉帳的最高位（「後果很嚴重」）→ Bob 算出的 $x'$ 等於**原本的** $x$，但他手上的是被改過的 → **不相等** → 無效 |
| **訊息鑑別** | ✔ | 驗證通過 → 只有 Alice 有正確的私鑰 |
| **不可否認性** | ✔ | 有爭議（上法庭）時，Bob 能證明**一定是 Alice** 產生了簽章 |
| 機密性 | ✘ | $x$ 是明文。需要的話再用 AES 加密 |

### 3.4 【課本補充】數字例子

用第 12 講同一組 RSA 參數：$p = 3, q = 11, n = 33, \Phi(n) = 20, e = 3, d = 7$。Bob 簽 $x = 4$：

| 誰 | 計算 |
|---|---|
| 簽章者 | $s = 4^7 \bmod 33 = 16384 \bmod 33 = 16$ |
| 送出 | $(x, s) = (4, 16)$ |
| 驗證者 | $x' = 16^3 \bmod 33 = 4096 \bmod 33 = 4$ |
| 比較 | $x' = 4 = x$ → **有效** ✔ |

（驗算：$33 \times 496 = 16368$，$16384 - 16368 = 16$ ✔；$33 \times 124 = 4092$，$4096 - 4092 = 4$ ✔）

## 4. 計算面

`[01:12]`

**簽章**：要算 $x^d \bmod n$，$d$ 是**完整長度**（例如 2048 bit）→ square-and-multiply → **很貴**。

【口頭】**經驗法則**：公鑰運算大約比 AES **慢 1000 倍**。「AES 加密一次要 1 毫秒的話，這要 1 秒。」「很粗略，有時是 100 倍。**很慢，不好玩。**」

**驗證**：要算 $s^e \bmod n$。
- 指數運算**沒有捷徑**。
- 但可以選**特別的 $e$**（第 12 講）。實務上 2048 bit 的 RSA，$e$ **不選 2048 bit**，而是：
  - $e = 3$（「很短」）
  - $e = 2^{16} + 1$【課堂討論】有幾個 bit？→ **17 bit**

【口頭】`[01:15]`「square-and-multiply 不用掃 2000 bit，**只要掃 17 bit**。**這超級實用**，很多瀏覽器和各種裝置都這樣做。」

> **RSA 的特點：驗證超快（接近對稱密碼的速度），簽章很慢。**

【口頭】「這有點奇怪，**橢圓曲線就沒有**這種不對稱：簽章和驗證速度差不多。ECC 簽章可能快 10 倍，但驗證可能慢 10 倍左右。**這是 RSA 特有的。**」

【課本補充】
- **為什麼快速驗證很有用**：很多情況下，一則訊息**只簽一次**但**驗證很多次**。例如 **PKI 的憑證**：憑證簽一次，但每次使用者用他的非對稱金鑰時都要驗證（第 27 講）。
- 簽章長度跟 $n$ 一樣，**1024～3072 bit**。網路上通常沒問題，但在**頻寬或能量受限**的系統（例如手機）可能不理想。
- 第 12 講的 RSA 加速技巧（短 $e$、CRT）在簽章時都適用。

## 5. 【課本補充】RSA 簽章的安全性

課堂沒講到，依課本 §10.2.3 整理。

### 5.1 公鑰真實性

- 跟所有非對稱方案一樣，要確保驗證者拿到的**真的是簽章者的公鑰**。
- 如果攻擊者能讓驗證者用一把**錯的公鑰**（他自己的），他就能簽訊息。
- → 用**憑證**（第 27 講）。

### 5.2 分解攻擊

- 最一般的攻擊：**分解 $n$** 得到 $p, q$，再從 $e$ 算出 $d$。
- → $n$ 要夠大，實務上建議 **1024 bit 以上**（見第 12 講）。

### 5.3 存在性偽造

**教科書版 RSA 簽章**有一個攻擊，讓攻擊者能為**某個隨機訊息**產生有效簽章：

| 步驟 | Oscar 做的事 |
|---|---|
| 1 | **先隨便選一個簽章** $s \in \mathbb{Z}_n$ |
| 2 | **算出對應的訊息** $x \equiv s^e \bmod n$（只需要公鑰） |
| 3 | 假冒 Bob，把 $(x, s)$ 送給 Alice |
| 驗證 | Alice 算 $s^e \equiv x$ → 跟收到的 $x$ 一樣 → **有效！** |

**為什麼「有點奇怪」**：Oscar **先選簽章、再算訊息**，所以他**不能控制訊息的意思**。例如他沒辦法產生「轉 1000 美元到 Oscar 的帳戶」這樣的訊息 —— 得到的 $x$ 只是一堆亂碼。

**但**：自動化驗證程式**認不出這是偽造的**，這當然不是好性質。所以教科書版 RSA 簽章**實務上很少用**，要加 **padding**。

### 5.4 解法：Padding（RSA-PSS）

**簡單的想法**：只允許**特定格式**的訊息。例如規定所有訊息的**最後 100 bit 都是 0**（或某個固定圖樣）。
- Oscar 選 $s$ 再算 $x = s^e$，$x$ 剛好符合這個格式的機率只有 $2^{-100}$。
- 「比中任何樂透都低得多。」

**實務上的標準：RSA-PSS（Probabilistic Signature Scheme，機率性簽章方案）**
- 實務上幾乎**不直接簽訊息本身**，而是簽它的**雜湊值**（固定長度的「數位指紋」，例如 160 或 256 bit；第 20 講）。
- 編碼方式叫 **EMSA-PSS**，大致做法：
  1. 產生一個隨機值 **salt（鹽）**
  2. 把固定 padding、訊息雜湊 $h(M)$、salt 串起來，再雜湊得到 $H$
  3. 用一個**遮罩產生函數 MGF**（實務上常用雜湊函數如 SHA-1）產生遮罩，跟含 salt 的資料區塊 XOR
  4. 組成編碼後的訊息 $EM$
- 然後簽 $s \equiv EM^d \bmod n$。
- 驗證時：取回 salt，檢查 EMSA-PSS 編碼是否正確。
- **因為有隨機的 salt**，編碼變成**機率性**的：**同一則訊息簽兩次，會得到不同的簽章**（這是好性質，回想第 9 講、第 15 講）。

## 6. 一頁速查表

### 6.1 數位簽章

| 項目 | 內容 |
|---|---|
| 簽章 | $s = \text{sig}_{k_{pr}}(x)$ —— **私鑰** |
| 送出 | $(x, s)$ —— **一定要附訊息** |
| 驗證 | $\text{ver}_{k_{pub}}(x, s) \in \{\text{true}, \text{false}\}$ —— **公鑰** |
| 驗證輸出 | **1 bit** |
| 為什麼要公鑰 | 對稱式**兩方能力一樣** → 沒有不可否認性 |
| 對稱版本 | 叫 **MAC**（第 25 講） |

### 6.2 四大安全服務

| 服務 | 壞人 | 對稱式（MAC） | 數位簽章 |
|---|---|---|---|
| 機密性 | Oscar | （加密） | ✘ |
| 完整性 | Oscar | ✔ | ✔ |
| 訊息鑑別 | Oscar | ✔ | ✔ |
| **不可否認性** | **Alice / Bob 自己** | **✘** | **✔** |

### 6.3 紙本簽名 vs 數位簽章

| | 紙本簽名 | 數位簽章 |
|---|---|---|
| 鑑別 | ✔ | ✔ |
| 完整性 | **✘**（68% → 88%） | ✔ |
| 不可否認性 | ✔（靠法律） | ✔ |
| 會被檢查嗎 | 通常不會 | **一定要驗證** |
| 能複製嗎 | 難 | 簽章本身能複製，但**綁定訊息** |

### 6.4 RSA 簽章

| | RSA 加密 | **RSA 簽章** |
|---|---|---|
| 用私鑰 | 解密 $y^d$ | **簽章 $x^d$** |
| 用公鑰 | 加密 $x^e$ | **驗證 $s^e$** |
| 驗證 | — | $s^e \bmod n \stackrel{?}{=} x$ |

例：$n = 33, e = 3, d = 7$，$x = 4$ → $s = 16$ → $16^3 \equiv 4$ ✔

### 6.5 效能

| 運算 | 速度 |
|---|---|
| RSA 簽章（$d$ 完整長度） | **慢**（約 AES 的 1000 倍） |
| RSA 驗證（$e = 3$ 或 $2^{16}+1$） | **很快** |
| ECC 簽章 vs 驗證 | 差不多 |

### 6.6 攻擊

| 攻擊 | 防禦 |
|---|---|
| 假公鑰 | 憑證 |
| 分解 $n$ | $n \ge 1024$ bit |
| 存在性偽造（先選 $s$ 再算 $x$） | **Padding（RSA-PSS）**、簽雜湊值 |

## 附：本講一句話總結

> **數位簽章要做到紙本簽名做不到的事：不只證明是誰簽的（鑑別）、證明內容沒被改（完整性），還要能向法官證明「只有他簽得出來」（不可否認性）—— 而這最後一點對稱密碼永遠做不到，因為兩方有同一把金鑰；RSA 簽章就是把加密反過來用：私鑰算 $s = x^d$、公鑰驗 $s^e \stackrel{?}{=} x$。**
