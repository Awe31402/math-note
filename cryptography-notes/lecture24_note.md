## 1. Merkle 簽章方案的原理

### 1.1 背景

`[00:02]`

| 項目 | 內容 |
|---|---|
| 名稱 | **Merkle 簽章方案（MSS）** |
| 別名 | **Merkle 樹**、**雜湊樹（hash trees）** |
| 發明 | **Ralph Merkle**，教授說是 **1989 年**，「公鑰密碼學發明後約 12 年」 |

【口頭】「多一點動機，免得你們睡著：**雜湊樹的應用遠超過這個特定的後量子簽章**，是很一般的構造，用在密碼學很多地方。IT 安全的同學在進階課程**大概還會碰到**。」

【課堂討論】`[00:04]` 誰聽過 Ralph Merkle？在什麼脈絡？
- 「質數？」→「好猜測。」
- 有人說在**加密貨幣**相關的地方看到 Merkle 樹 →「對，加密貨幣**確實**用 Merkle 樹。」
- 教授：「**他其實是公鑰密碼學的共同發明人之一。**大家通常把公鑰歸功於 Diffie 和 Hellman，但其中一人說應該叫 **Diffie-Hellman-Merkle**。他也是獨立做出來的。**他是那種沒得到應有功勞的人。很棒的人。**」

> ⚠️ 教授說「我想是 Whitfield Diffie 說的」；第 15 講引用的課本 §8.6 寫的是 **Hellman** 在 2003 年提議改名為「Diffie–Hellman–Merkle 金鑰交換」。

### 1.2 目標：很多一次性金鑰 → 一把公鑰

`[00:05]`

```
  ┌──────────────── MSS ─────────────────┐
  │  (k_pr,0 , k_pub,0)                  │
  │  (k_pr,1 , k_pub,1)      2^T 組      │      ──→   一把 K_pub
  │       ⋮                  WOTS 金鑰對  │
  │  (k_pr,2^T−1 , k_pub,2^T−1)          │
  └──────────────────────────────────────┘
```

- 裡面是 $2^T$ 組 **Winternitz 一次性金鑰對**（「就是你們昨晚做的作業、最後一張習題」）。
- **產生它們不是問題**（`[00:08]`）：
  - 【課堂討論】WOTS 算公鑰的主要運算是什麼？→ **重複套用雜湊函數**。
  - 「雜湊函數設計得很快。算一把沒什麼，**算 100 萬把也沒什麼**，實務上大概幾秒，而且幾年才做一次。」
- **真正的問題是**：要把 **100 萬把公鑰推出去**（而且每把都要被認證）。

> **今天的大步：從 $2^T$ 把一次性公鑰，變成一把公鑰。**

#### 例：$T$ 要多大？

`[00:09]`
- 假設實務上要簽大約 **50 萬**個簽章。
- 【課堂討論】$T$ 要多少？→ **20**。「$2^{20}$ 大約是 1 mega，約 100 萬。1 kilo 約 1000。」
- 【口頭】「**$T$ 很適中，這很好**：之後的計算複雜度跟 $T$ 成正比。跟 100 萬成正比會很痛，**跟 20 成正比就沒什麼**。」

【口頭】`[00:10]`「如果你還醒著，那已經很好了。」

### 1.3 最簡單的例子：$T = 1$

`[00:11]`【口頭】「先從一個**很小、很不刺激的玩具**開始：$T = 1$。」

$2^1 = 2$ → **兩組** WOTS 金鑰對：$(X_0, Y_0)$、$(X_1, Y_1)$
（課本用**大寫** $X, Y$；$X$ 是私鑰、$Y$ 是公鑰。）

**建樹**（`[00:13]`）：「這棵樹**簡單到可笑**，你幾乎不知道 Christof 在說什麼。」

```
                K_pub = H(A₀ ‖ A₁)
                   ┌────┴────┐
                  A₀         A₁
                  │          │
              A₀ = H(Y₀)  A₁ = H(Y₁)
                  │          │
                 Y₀         Y₁       ← WOTS 公鑰
                 X₀         X₁       ← WOTS 私鑰
```

1. **永遠從底部開始**。先**雜湊**每把 WOTS 公鑰：$A_0 = H(Y_0)$、$A_1 = H(Y_1)$。
   - 「計算上難嗎？**不難**，雜湊函數超快。它們設計來雜湊 1 GB 的硬碟，這裡只有幾百 bit，**閃電般快**。」
2. 把兩個值**串接（concatenate, ‖）**再雜湊：
   $$K_{pub} = H(A_0 \,\|\, A_1)$$
   - 【課堂討論】‖ 是什麼意思？→ **串接**（Verkettung），「就是放在旁邊」。
3. 「**奇蹟般地（wunderbarer Weise）**，這就是公鑰。」

【口頭】「這不太像一棵樹。」

#### 【課堂討論】能簽幾則訊息？

`[00:16]` → **2 則**。「我很高興你問了，因為我做了筆記所以很清楚，你們不一定。」

### 1.4 簽第一則訊息

`[00:17]` Alice 送出 $K_{pub}$（「可以繼續睡，但不會太久了」）。

**簽 $M_0$**：
- 【課堂討論】用公鑰還是私鑰簽？→「答錯的人會被踢出去。」→ **私鑰**。
- 【課堂討論】用 $X_0$ 還是 $X_1$？→「這是玩笑題吧。」→ **$X_0$**，「這裡一切都是 0」。

$$S_0 = \text{WOTS-sign}(X_0, M_0)$$

【口頭】「**我第五次說了**：這就是 Winternitz，上週的東西，**很無聊**。我們今天不談實際怎麼簽。」

**送什麼？**（`[00:19]`）
- $M_0$、$S_0$
- 【課堂討論】用 Winternitz 還要送什麼？→「**檢查碼**？」→「**完全正確**，但那是 Winternitz 特有的，我們這裡跳過。」
- → 要送 **WOTS 公鑰 $Y_0$**。

【口頭】「（我要破壞我漂亮的教學小技巧了）這樣**還不行**，之後要**再加東西**。留三格空間。」

#### Bob 怎麼確認 $Y_0$ 是真的？

`[00:20]`

> **問題**：$Y_0$ 是**真的**（authentic）嗎？真的是 Alice 的公鑰嗎？

- 【口頭】上週你們問了兩次：「如果 Oscar 換掉公鑰呢？」→「**那在攻擊者模型之外。**現在假設金鑰**正確分發**。拿掉這個假設，整個東西就不安全了。這學期最後一講會談。」
- 「**醒來，停止滑 Instagram。**」
- Bob **知道 $K_{pub}$ 真的來自 Alice**。他要知道的是：**$Y_0$ 是不是來自 Alice**。

【課堂討論】`[00:22]` Bob 能拿 $Y_0$ 做什麼？→ **雜湊它** → 得到 $A_0$。「**很好**，他走到這裡了。」
- 這樣夠算出 $K_{pub}$ 嗎？→ **不夠**。缺什麼？→ **$A_1$**。

【課堂討論】那 Alice 直接送 $Y_1$ 呢？「**別抄，抄了會死。**」
- 學生答：那 Oscar 會看到 $Y_1$……「他會把**公鑰送出去**，那不是大問題，**但我們不想這樣做**。」

**解法**（`[00:23]`）：**直接送 $A_1$**。

$$\text{送出：}(M_0,\; S_0,\; Y_0,\; \textcolor{red}{(A_1)})$$

【口頭】「$T = 1$ 不太刺激，所以我用**紅色括號**。之後這個紅色部分會**變長**。」

**這是安全問題嗎？**（`[00:24]`）
- Oscar 看到 $A_1$，但**他回不去**，算不出 $Y_1$（雜湊是單向的）。
- 「$Y_1$ 對他也沒太大幫助，但這樣還是比較好。」

#### Bob 的驗證

`[00:24]`【口頭】「**大家醒著嗎？**如果你答得出這個，今天就懂了 50%。不複雜，不是傅立葉轉換之類的瘋狂東西。」

1. 重算 $A_0 = H(Y_0)$（用 SHA-3 之類的，「有各種公開的實作」）
2. 用免費拿到的 $A_1$ 算 $H(A_0 \,\|\, A_1)$
3. 檢查：$H(A_0 \,\|\, A_1) \stackrel{?}{=} K_{pub}$
   - $K_{pub}$「在課程最後會用某種神奇方式（憑證）認證」
4. **如果相等** → $A_0$、$A_1$ 都對 → **$Y_0$ 一定對**
   - 【口頭】「這就是雜湊函數瘋狂的地方：**就算差一個 bit，$A_0$ 的輸出也會看起來完全隨機**。所以等式成立是**很強的保證**。」
5. 現在 Bob 知道他有**正確的 WOTS 公鑰**，就做 **Winternitz 驗證**：$\text{WOTS-verify}(Y_0, S_0, M_0) = $ **true / false**

【口頭】`[00:28]`「回到老朋友數位簽章：**有效或無效**。小投票：誰覺得懂了 80%？……**80% 的人懂了 80%**。不，幾乎 100%。你們很棒。我們時間很充裕。」

### 1.5 簽第二則訊息

`[00:31]`【口頭】「這次換一個人收，比較有意思：**Charlie**。（第一次教，犯菜鳥錯誤。）」

- Charlie 也知道 $K_{pub}$。
- Alice 簽 $M_1$：$S_1 = \text{WOTS-sign}(X_1, M_1)$，送出 $Y_1$。
- 【課堂討論】Charlie 要把 $Y_1$ 跟 $K_{pub}$ 連起來，從 $Y_1$ 能算什麼？→ **$A_1$**。缺什麼？→ **$A_0$**。

$$\text{送出：}(M_1,\; S_1,\; Y_1,\; \textcolor{red}{(A_0)})$$

**Charlie 驗證**：$A_1 = H(Y_1)$ → $H(A_0 \,\|\, A_1) \stackrel{?}{=} K_{pub}$ → WOTS-verify$(Y_1, S_1, M_1)$

> ⚠️ 逐字稿中教授一度說「用 $Y_0$」驗證 $M_1$，應為口誤，是 $Y_1$。

#### 實務上怎麼做

`[00:35]`
- Alice 先把第一則簽好的訊息送給 Bob（「因為她比較喜歡 Bob 之類的」）。
- 之後她要**打個勾**，表示「我用掉了這個」—— 因為是一次性的。
- 再用下一個。

#### 【Q&A】Alice 要不要也送索引？

`[00:35]`

**學生問**：Alice 也要送索引（這裡的 0 和 1）嗎？

**教授答**：「**絕對要。**索引會扮演很重要的角色。好問題。這裡因為二元樹是對稱的所以看不太出來，但**10 分鐘後你的問題就有意義了**。」

### 1.6 【Q&A】這不也是在送公鑰嗎？

`[00:28]`

**學生問**：Alice 還是在送公鑰（$Y_0$）給 Bob 啊，那跟沒有 Merkle 樹有什麼差別？

**教授答**：「**超級好的問題。**」
- 如果**沒有** Merkle 方案，天真地用 Winternitz：你在某個時間點要把公鑰送出去，頻寬上差不多。
- 「**但它們全部都要被認證。祝你好運。**」
- 【課堂討論】誰聽過網路上的憑證？→ 每個人。「**憑證很麻煩**，很複雜，有各種計算上的缺點。**只做一次**就好。」
- 而且：誰會拿到這些公鑰？**每個想跟你通訊的人**。「所以不只是你有 100 萬（$2^{20}$）把金鑰要認證，**所有人**都要拿到它們。」
- 有了 Merkle 樹：**每個人只拿一把公鑰**（反正本來就要做），每次簽章附上的 WOTS 公鑰**靠 Merkle 樹認證**，不用憑證。
- 「好像差不多，但**在腦中實際跑一遍（durchspielen）**，就會發現那樣**非常亂**。」

## 2. 三層的 Merkle 樹（$T = 3$）

`[00:36]`【口頭】「這是**半個戰場（halbe Miete）**。」
- 「你們學了很多例子，**大部分書不這樣做**。用索引一般化會**非常亂**。真的不太難，比橢圓曲線簡單多了。但用樹會變得很亂。」
- 「我跟 **Tim Güneysu**（新版書的共同作者）**大吵了一架**，討論怎麼教比較好，最後決定用 $T = 3$。」

$T = 3$ → $2^3 = 8$ 個簽章。「$T = 1$ 看起來不像樹，只是兩個值合在一起。幾分鐘後你會知道為什麼叫樹。」

### 2.1 建樹

`[00:38]`【口頭】「**大圖**：至少要三分之一頁，留半頁會比較漂亮。如果本子快寫完了，翻新的一頁。」

**第 0 步：8 組 WOTS 金鑰對**（放在**最底下**）

$(X_0, Y_0), (X_1, Y_1), \ldots, (X_7, Y_7)$
「從真亂數產生器來，然後雜湊 8 次或 256 次之類的。」

【口頭】`[00:40]`「這些都在書裡，不用抄。但**自己畫圖會比較懂**。記得 AES 那張圖嗎？大家說『為什麼不發給學生』—— 我發了，在書裡（你們免費拿到）。但**你自己畫，會懂得更多**。」

**第 1 步：雜湊每把 WOTS 公鑰**（同 $T = 1$）

$$A_j = H(Y_j), \quad j = 0, \ldots, 7$$

**第 2 步：兩兩串接、雜湊，一層一層往上**（`[00:42]`）

「這是**二元樹**。也可以做三個一組的樹，我們不做。二元最自然。」

$$B_0 = H(A_0 \| A_1), \quad B_1 = H(A_2 \| A_3), \quad B_2 = H(A_4 \| A_5), \quad B_3 = H(A_6 \| A_7)$$

【課堂討論】$B_0$ 是什麼雜湊在一起？→ **$A_0$ 串接 $A_1$**。「這不是火箭科學。」「給你們 45 秒填剩下的。」

$$C_0 = H(B_0 \| B_1), \quad C_1 = H(B_2 \| B_3)$$

$$D = H(C_0 \| C_1) = K_{pub}$$

```
 level 3（根）                         D = K_pub
                              ┌──────────┴──────────┐
 level 2                     C₀                     C₁
                        ┌─────┴─────┐          ┌─────┴─────┐
 level 1               B₀          B₁         B₂          B₃
                     ┌──┴──┐     ┌──┴──┐    ┌──┴──┐     ┌──┴──┐
 level 0（葉）       A₀    A₁    A₂    A₃   A₄    A₅    A₆    A₇
                     │     │     │     │    │     │     │     │
 WOTS 公鑰          Y₀    Y₁    Y₂    Y₃   Y₄    Y₅    Y₆    Y₇
 WOTS 私鑰          X₀    X₁    X₂    X₃   X₄    X₅    X₆    X₇
```

【口頭】

### 2.4 認證路徑

`[00:56]`

> 紅色那組值 $(A_2, B_0, C_1)$ 有一個很炫的名字：**認證路徑（authentication path，德文 Authentisierungspfad）**。
> 這是 Merkle 簽章方案**非常基本、非常重要**的部分。

**每一層剛好一個值**：它是從葉往根的路上，每個節點的**兄弟節點（sibling）**。

```
 level 3                               D ✔（比對 K_pub）
                              ┌──────────┴──────────┐
 level 2                    [C₀]                  (C₁) ← 送
                        ┌─────┴─────┐
 level 1              (B₀) ← 送    [B₁]
                                 ┌──┴──┐
 level 0                       (A₂)   [A₃]
                               ← 送     │
                                       Y₃ ← 送

 ( ) = 認證路徑（Alice 送的）     [ ] = Bob 自己算的
```

**Bob 的驗證**（`[00:57]`）：「**現在很簡單了**。**永遠從底部開始**。」（綠色圈圈 = Bob 算的）

1. $A_3 = H(Y_3)$
2. $B_1 = H(A_2 \| A_3)$
3. $C_0 = H(B_0 \| B_1)$
4. $D' = H(C_0 \| C_1)$
5. **決定性的檢查**：$D' \stackrel{?}{=} K_{pub}$
6. 相等 → $Y_3$ 是真的 → $\text{WOTS-verify}(Y_3, S_3, M_3) = $ **true / false**

【口頭】`[00:59]`「**其實沒那麼難吧？**誰懂了 80%？……**幾乎全部**。很好，是我講太慢。」
「我有個**世界有名的密碼學家**同事，我跟他說『我在教雜湊鏈』，他說『**真的？這很難解釋耶**』。**他比我聰明得多。**」

## 3. 一般化的 MSS

`[01:03]`【口頭】「一般情況**完全一樣，沒有別的事發生**。所以你們**都懂了**很好（除非在騙我）。但一旦拿掉 A B C D，**改用一般變數，索引會要你的命**。這大概就是我那位同事說很難教的原因。」

### 3.1 節點的通用命名

`[01:05]`【口頭】「我們需要一個演算法，不想一直畫這種蠢圖，粉筆和紙都會用完。」

這棵樹是**二維結構**。每個**節點（node，德文 Knoten）** 記作：

$$v_{i,j}$$

| 索引 | 意思 |
|---|---|
| $i$ | **層（level）**，從 0（葉）到 $T$（根）。【口頭】「我一開始說反了，**這是列（row）**。我做這個 35 年了，從學士生開始。」 |
| $j$ | 這一層裡**從左到右**的位置。「加引號的『行』，因為這不是矩陣」 |

- 很亂的地方：level 0 有 $2^T$ 個（$j = 0..7$），level 1 有 4 個、level 2 有 2 個、level 3 有 1 個。「**金字塔結構**。」

**對照 $T = 3$**：

| 舊名 | 新名 |
|---|---|
| $A_0, \ldots, A_7$ | $v_{0,0}, \ldots, v_{0,7}$ |
| $B_0, \ldots, B_3$ | $v_{1,0}, \ldots, v_{1,3}$ |
| $C_0, C_1$ | $v_{2,0}, v_{2,1}$ |
| $D$ | $v_{3,0}$ |

【口頭】`[01:08]`「新版書 Figure 12.6。」「**Tim Güneysu** 教授 —— 誰跟他合作過？他很棒 —— 問我『**你真的要叫它 A B C 嗎？**』我說對，我要。**一開始就用比較系統化的方式，反而比較難懂。**」

### 3.2 建樹演算法

`[01:09]`【口頭】「我想省事，結果得用投影。第一次教，**下次不這樣了**。」

**1. WOTS 金鑰產生**（葉的**下面**一層，「不算樹的一部分」）

$$(X_j, Y_j) = (k_{pr,j},\; k_{pub,j}), \qquad j = 0, \ldots, 2^T - 1$$

「怎麼做取決於你的一次性簽章方案，實務上常常就是 Winternitz。」

**2. 葉的計算**（`[01:13]`）

$$v_{0,j} = H(Y_j), \qquad j = 0, \ldots, 2^T - 1$$

**3. 其他節點的計算**（`[01:14]`）

【口頭】「建構原則**很簡單**：永遠拿**前一層的兩個節點**雜湊在一起。公式看起來有點亂，但想清楚就不意外。」

【課堂討論】在第 $i$ 層，需要第幾層的節點？→ **$i - 1$**。

$$\boxed{v_{i,j} = H\left(v_{i-1,\,2j} \;\|\; v_{i-1,\,2j+1}\right)}, \qquad i = 1, \ldots, T, \quad j = 0, \ldots, 2^{T-i} - 1$$

【口頭】「$i$ 從 1 到 $T$ 往上走，$j$ 的範圍**越來越小**，因為是樹。」
「要玩一下演算法才能體會，我不做了。我覺得重要的是你們**懂了**。**你們很聰明。**」
「另一種教法是從這個公式開始、填 $i$ 和 $j$ 的數字。**我覺得那很亂**，所以我才說叫它 A B C D，大家都懂。」

**驗算**：$v_{1,0} = H(v_{0,0} \| v_{0,1}) = H(A_0 \| A_1) = B_0$ ✔；$v_{3,0} = H(v_{2,0} \| v_{2,1}) = H(C_0 \| C_1) = D$ ✔

### 3.3 算認證路徑的演算法

`[01:18]`【口頭】「這也不太複雜。**我只給你演算法。**它很系統化。」（新版書裡有，「你們都有 PDF，有些人有紙本」。）

**輸入**：
- Merkle 樹的所有節點 $v_{i,j}$
- **索引 $c$**：要簽第幾個（$0 \le c \le 2^T - 1$）。「剛剛有人問過索引，**現在它真的很重要**。」

**輸出**：認證路徑 $(a_0, a_1, \ldots, a_{T-1})$ —— **每一層一個值**

```
FOR i = 0 TO T − 1:
    q = ⌊ c / 2^i ⌋              ← 輔助值（floor：無條件捨去）
    IF q 是偶數:  r = q + 1      ← 兄弟節點在右邊
    ELSE:         r = q − 1      ← 兄弟節點在左邊
    a_i = v_{i, r}               ← 第 i 層的認證節點
RETURN (a_0, …, a_{T−1})
```

【口頭】
- 「$\lfloor \cdot \rfloor$ 叫 **floor 函數**（無條件捨去，abrunden）。因為 $c / 2^i$ 通常不是整數，例如得到 5.37 而不是 5。」「另外還有 **ceiling 函數** $\lceil \cdot \rceil$（無條件進位，aufrunden）。」
- 「$q$ 是你在第 $i$ 層的位置，**兄弟節點**就在它旁邊。」

> ⚠️ 投影片上的偽碼細節字幕沒抓到，上面依教授口述（「算 $q = \lfloor c/2^i \rfloor$、找兄弟節點、當作這一層的認證節點」）整理成可執行的形式。

**驗算：$c = 3$、$T = 3$**（`[01:22]`）

| $i$ | $q = \lfloor 3 / 2^i \rfloor$ | 兄弟 $r$ | $a_i$ | 舊名 |
|---|---|---|---|---|
| 0 | 3（奇） | 2 | $v_{0,2}$ | $A_2$ ✔ |
| 1 | 1（奇） | 0 | $v_{1,0}$ | $B_0$ ✔ |
| 2 | 0（偶） | 1 | $v_{2,1}$ | $C_1$ ✔ |

【口頭】「跑這個演算法，就得到 $v_{0,2}$、$v_{1,0}$、$v_{2,1}$，**正好就是紅色那些**。你們看得到嗎？」
「我們不多講這個，你們會不會很沮喪？能接受嗎？……我們看看。」
「**$T = 20$ 也一樣**：100 萬片葉，不是 3 步而是 0～19 共 **20 步**，永遠給你認證路徑需要的正確節點。」

## 4. 幾點說明

`[01:24]`【口頭】「最後一點說明。**你可以睡了**。接下來對考試不重要，但**如果你要留在資安，對人生很重要**。」

### 4.1 MSS 是有狀態的

`[01:25]`

> **MSS 是有狀態的（stateful，德文 zustandsbehaftet）。**

- 意思是：**你必須記錄東西**。特別是那些**打勾** —— Alice 要記得她**已經用過哪些** WOTS 金鑰。
- 【口頭】「**這不太好。**例如有某種資料庫或記憶體，如果 Oscar 設法**刪掉一個打勾**，Alice 就開始**重複使用** → 變弱。」
- 「這不是我們想要的，但**可以處理**。」

### 4.2 雜湊函數用在三個地方

`[01:26]` 實務上常常是 **SHA-3**。【口頭】「寫書時我覺得這很有趣：這是一個**分層系統**。」

| 層 | 雜湊函數做什麼 | 哪一講 |
|---|---|---|
| **1. 訊息雜湊** | 【課堂討論】當初為什麼用雜湊函數？→ **簽章**！RSA 只能簽約 2000 bit（約 128 個字元），太蠢。要簽 1 MB（800 萬 bit）的 PDF，**先雜湊**。所以 $M$ 其實是雜湊值 | 第 20 講 |
| **2. Winternitz 雜湊鏈** | 雜湊 $2^w - 1$ 次算公鑰；簽章 $S_i$ 也是雜湊鏈上的值 | 第 23 講（「兩週前，因為上週是國定假日」） |
| **3. Merkle 樹** | 把 WOTS 公鑰雜湊成葉，再一層層雜湊到根 | **今天** |

【口頭】「**教訓：雜湊函數在密碼學裡很重要。**」

## 5. 一頁速查表

### 5.1 MSS 基本想法

| 項目 | 內容 |
|---|---|
| 問題 | WOTS 金鑰**只能用一次**；要分發、認證 100 萬把公鑰很痛苦 |
| 解法 | 把 $2^T$ 把 WOTS 公鑰用**二元雜湊樹**濃縮成**一把公鑰**（樹根） |
| $T$ 的大小 | $T = 20$ → 約 100 萬個簽章；複雜度跟 $T$ 成正比 |
| 發明 | Ralph Merkle（公鑰密碼學的共同發明人之一） |

### 5.2 建樹

$$v_{0,j} = H(Y_j) \qquad v_{i,j} = H(v_{i-1,2j} \,\|\, v_{i-1,2j+1}) \qquad K_{pub} = v_{T,0}$$

| 名詞 | 位置 |
|---|---|
| 葉 | level 0（**最底下**） |
| 根 | level $T$（**最上面**）= $K_{pub}$ |
| ⚠️ | 「根在上、葉在下，Paar 教授覺得很蠢」 |

### 5.3 簽章

簽第 $c$ 則訊息，送出：

$$\left(c,\; M_c,\; S_c = \text{WOTS-sign}(X_c, M_c),\; Y_c,\; \underbrace{a_0, \ldots, a_{T-1}}_{\text{認證路徑}}\right)$$

### 5.4 驗證

1. $h = H(Y_c)$
2. 對 $i = 0..T-1$：依位置把 $h$ 跟 $a_i$ 串接（左或右）再雜湊
3. 檢查 $h \stackrel{?}{=} K_{pub}$
4. 相等 → $\text{WOTS-verify}(Y_c, S_c, M_c)$

### 5.5 認證路徑

- 從葉往根，**每一層取兄弟節點**，共 $T$ 個值
- $q = \lfloor c / 2^i \rfloor$；$q$ 偶 → 取 $q+1$，$q$ 奇 → 取 $q-1$
- 例（$T = 3, c = 3$）：$(A_2, B_0, C_1) = (v_{0,2}, v_{1,0}, v_{2,1})$

### 5.6 例子（$T = 3$）

```
                D
          C₀          C₁
       B₀    B₁    B₂    B₃
      A₀ A₁ A₂ A₃ A₄ A₅ A₆ A₇
      Y₀ Y₁ Y₂ Y₃ Y₄ Y₅ Y₆ Y₇
```

| 簽 | 認證路徑 |
|---|---|
| $T = 1$，第 0 則 | $(A_1)$ |
| $T = 1$，第 1 則 | $(A_0)$ |
| $T = 3$，第 3 則 | $(A_2, B_0, C_1)$ |

### 5.7 重點

| 項目 | 內容 |
|---|---|
| 兩種公鑰 | 本地 WOTS 公鑰 $Y_j$；MSS 公鑰 $K_{pub}$ |
| $K_{pub}$ | 仍然要靠**憑證**認證（只要一次） |
| **有狀態** | 必須記住用過哪些金鑰；被竄改會導致重用 |
| 雜湊的三個用途 | 訊息雜湊、WOTS 雜湊鏈、Merkle 樹 |
| 為什麼現在換 | **Store now, decrypt later** |

## 附：本講一句話總結

> **Merkle 簽章方案把 $2^T$ 把只能用一次的 Winternitz 公鑰當作樹葉，一層層兩兩雜湊成一個樹根當作唯一的公鑰；簽第 $c$ 則訊息時，附上那把 WOTS 公鑰和「每層一個兄弟節點」的認證路徑，驗證者自己往上雜湊回樹根比對，就知道這把一次性公鑰是真的 —— 代價是簽章者必須記住用過哪些金鑰（有狀態）。而之所以現在就要換成這類後量子方案，是因為情報單位正在「現在儲存、以後解密」。**
