## 12.1 MAC 協定與簽章協定的接收方

**題目摘要**：發送方做：
- 協定 A：$y = e_{k_1}[x \,\|\, h(k_2 \| x)]$（$k_1, k_2$ 是雙方共享的秘密金鑰）
- 協定 B：$y = e_k[x \,\|\, \text{sig}_{k_{pr}}(h(x))]$

列出接收方收到 $y$ 後的步驟。

### 協定 A（對稱：加密 + 以雜湊做的 MAC）

1. **解密**：$x \,\|\, m = e^{-1}_{k_1}(y)$，把結果拆成訊息 $x$ 和附加的檢查碼 $m$（雜湊的輸出長度固定，所以知道從哪裡切）。
2. **重算 MAC**：$m' = h(k_2 \,\|\, x)$（用共享的 $k_2$）。
3. **比較**：$m' \stackrel{?}{=} m$
   - 相等 → 接受 $x$（來自擁有 $k_2$ 的一方，而且沒被改）
   - 不等 → 丟掉

```
   y ──→ [ e⁻¹_{k1} ] ──→ x ‖ m
                          │    │
              k2 ──→ [ h(k2 ‖ x) ] → m'
                                   │
                          m' =? m ←┘
```

### 協定 B（加密 + 數位簽章）

1. **解密**：$x \,\|\, s = e^{-1}_k(y)$，拆成訊息 $x$ 和簽章 $s$。
2. **雜湊**：算 $h(x)$。
3. **驗證簽章**：用**發送方的公鑰** $k_{pub}$：$\text{ver}_{k_{pub}}(h(x), s) \stackrel{?}{=} \text{true}$
   - 成立 → 接受（而且有不可否認性：只有發送方有 $k_{pr}$）
   - 不成立 → 丟掉

**主要差別**：協定 A 驗證時用的是**同一把秘密金鑰** $k_2$（接收方也能產生同樣的檢查碼，所以沒有不可否認性）；協定 B 驗證用**公鑰**，只有發送方能簽（有不可否認性）。另外協定 A 用的是 secret prefix 形式 $h(k_2 \| x)$，課本與課堂指出它有附加攻擊的疑慮，但這裡外面還有一層加密。

**出處**：📖 §12.1（MAC 的原理）、§12.2（secret prefix MAC）、§10.1.2（簽章與驗證）；📝 L25 §1.3（MAC 的基本協定）、§1.5（安全服務：沒有不可否認性）、§2.2（secret prefix 的弱點）、L18 §1.3

## 12.2 為什麼 MAC 80 bit 就夠

**題目摘要**：雜湊函數需要約 160 bit 輸出才能擋生日攻擊。為什麼 MAC 用 80 bit 就夠？假設 $(x, \text{MAC}_k(x))$ 以明文傳送，說明 Oscar 要做什麼才能攻擊。

### 關鍵：Oscar **算不出** MAC

- 雜湊函數是公開的，任何人都能自己算 $h(x)$。所以 Oscar 可以**離線**算 $2^{n/2}$ 個雜湊值找碰撞（生日攻擊）→ 安全等級只有 $n/2$。
- MAC 需要**秘密金鑰** $k$。Oscar 沒有 $k$，**自己算不出任何 MAC 值**，也就沒辦法離線做生日攻擊。

### Oscar 能做的攻擊

| 攻擊 | 做法 | 難度（80 bit MAC，金鑰夠長） |
|---|---|---|
| **猜 MAC** | 改一則訊息 $x'$，**隨便猜**一個 80 bit 的 MAC 值送出 | 每次成功機率 $2^{-80}$；而且每次猜都要真的送出去讓接收方驗證（**線上**），失敗的嘗試會被發現 |
| **暴力找金鑰** | 用截到的 $(x, m)$ 試所有金鑰 | 取決於**金鑰長度**（例如 128 bit），跟 MAC 長度無關 |
| **生日攻擊找碰撞** | 需要 $2^{40}$ 個**由合法方算出的** MAC 值 | 必須讓 Alice 幫他算約 $2^{40}$ 次 MAC，實務上不可能（見 12.5） |

> 所以 80 bit 的 MAC 提供約 **80 bit** 的偽造抵抗力，而 80 bit 的雜湊只有約 **40 bit** 的碰撞抵抗力。

**出處**：📖 §12.1、§11.2.3（生日攻擊）；📝 L25 §1.4（MAC 的性質）、§1.5、L20 §3.4

## 12.3 加密加雜湊 vs 加密加 MAC

**題目摘要**：(1) $c = e_k(x \| h(x))$，$e$ 是串流密碼，攻擊者知道整個明文 $x$。說明他怎麼把 $x$ 換成任意的 $x'$（同長度），算出能通過驗證的 $c'$。用 OTP 加密也行得通嗎？(2) 改用 $c = e_{k_1}(x \| \text{MAC}_{k_2}(x))$ 呢？

### (1) 用一般雜湊：攻擊成功

串流密碼：$c = (x \| h(x)) \oplus s$（$s$ 是金鑰串流）。

**攻擊**：
1. 攻擊者知道 $x$，自己算出 $h(x)$（雜湊是公開的）。
2. 求出這段金鑰串流：$s = c \oplus (x \,\|\, h(x))$
3. 選想要的 $x'$，算 $h(x')$。
4. 造新密文：$c' = (x' \,\|\, h(x')) \oplus s$
   （等價寫法：$c' = c \oplus (x \| h(x)) \oplus (x' \| h(x'))$，連 $s$ 都不用明確算出。）
5. 接收方解密得到 $x' \| h(x')$，重算 $h(x')$ 一致 → **驗證通過**。

**用 OTP 也一樣**：攻擊完全沒有用到金鑰串流是怎麼產生的，只用到「加密 = XOR」和「知道明文」。OTP 的無條件安全只保護**機密性**，不保護**完整性**（10.2 題）。

### (2) 用 MAC：攻擊失敗

- 攻擊者可以照樣把 $x$ 那段換成 $x'$（因為知道 $x$）。
- 但他需要附上 $\text{MAC}_{k_2}(x')$，而這需要秘密金鑰 $k_2$，**算不出來**。
- 他也不知道原本的 $\text{MAC}_{k_2}(x)$（被加密了），只能亂翻 MAC 那段的 bit，但無法讓它變成 $x'$ 的正確 MAC。
- 接收方重算 $\text{MAC}_{k_2}(x')$ 會跟收到的不符 → 拒絕。

> **教訓**：完整性保護要用**有金鑰的**檢查碼（MAC 或簽章），單純的雜湊不行。

**出處**：📖 §12.1（MAC 提供完整性）、§2.1.2（串流密碼的 XOR）、§11.1（雜湊沒有金鑰）；📝 L25 §1.5（完整性）、L03 §2（串流密碼）、§4（OTP）

## 12.4 一個很弱的 MAC

**題目摘要**：訊息 $X = x_1 \| \cdots \| x_z$，每塊 8 bit。壓縮函數 $c_i = c_{i-1} \oplus x_i$，最後 $\text{MAC}_k(X) = c_z + k \bmod 2^8$，$k$ 是 64 bit 共享金鑰。(1) 只用一則已知訊息，怎麼算出（有效部分的）$k$？(2) $X$ = HELLO ALICE!，$c_0 = 11111111_2$，$\text{MAC} = 10011101_2$，求 $k$。(3) $k$ 的有效長度？(4) 弱點來自設計的哪個性質？

### (1) 方法

$c_z$ 只跟訊息和 $c_0$ 有關，**不用金鑰**，攻擊者自己能算：
$$c_z = c_0 \oplus x_1 \oplus x_2 \oplus \cdots \oplus x_z$$
然後：
$$k \bmod 2^8 = \text{MAC}_k(X) - c_z \bmod 2^8$$

### (2) 計算

**ASCII**：

| 字元 | H | E | L | L | O | (空白) | A | L | I | C | E | ! |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 十六進位 | 48 | 45 | 4C | 4C | 4F | 20 | 41 | 4C | 49 | 43 | 45 | 21 |

**逐步 XOR**：

| 步驟 | 運算 | 結果 |
|---|---|---|
| 1 | 48 ⊕ 45 | 0D |
| 2 | ⊕ 4C | 41 |
| 3 | ⊕ 4C | 0D |
| 4 | ⊕ 4F | 42 |
| 5 | ⊕ 20 | 62 |
| 6 | ⊕ 41 | 23 |
| 7 | ⊕ 4C | 6F |
| 8 | ⊕ 49 | 26 |
| 9 | ⊕ 43 | 65 |
| 10 | ⊕ 45 | 20 |
| 11 | ⊕ 21 | **01** |

（觀察：兩個 4C 互相抵消、E 出現兩次也抵消，其實就是剩下的字元 XOR。）

$$c_z = c_0 \oplus 01 = \text{FF} \oplus 01 = \text{FE} = 254$$

$$k \bmod 256 = \text{MAC} - c_z = 157 - 254 = -97 \equiv \mathbf{159} = \text{9F} = \mathbf{10011111_2}$$

驗算：$254 + 159 = 413 = 256 + 157$ → MAC = 157 = $10011101_2$ ✔

### (3) 有效金鑰長度

只有 $k \bmod 2^8$ 會影響 MAC → **有效長度只有 8 bit**（64 bit 金鑰中其他 56 bit 完全沒用）。

### (4) 弱點的來源

- **線性**：壓縮函數只用 XOR，金鑰只在最後用一個加法混進去。整個 MAC 是「訊息的線性函數 + 金鑰」，攻擊者可以把金鑰的影響直接**解出來**（就像 LFSR 被解線性方程組一樣，參考 2.9 題）。
- 而且金鑰只在**最後**加一次、只用到 8 bit，訊息的處理完全不依賴金鑰 → 攻擊者能自己算出所有中間值。
- 很容易找碰撞：任何兩則 XOR 總和相同的訊息（例如把兩個字元對調）MAC 都一樣。

> **設計原則**：密碼學元件需要**非線性**（混淆），而且金鑰要**充分混入**整個運算過程。這對區塊密碼（S-box）、雜湊函數、MAC 都一樣。

**出處**：📖 §12.1（MAC 的性質）、§3.3.2（S-box 的非線性，「Without a nonlinear building block, an attacker could express … a system of linear equations」）、§2.3.2（LFSR 的線性攻擊）；📝 L25 §1.4、L05 §3.1（混淆）、L04 §3

## 12.5 MAC 的碰撞

**題目摘要**：(1) 假設 Oscar 找到 $\text{MAC}_k(x_1) = \text{MAC}_k(x_2)$，給一個基於碰撞的攻擊協定。(2) 為什麼實務上對 MAC 做碰撞比對雜湊函數難得多？80 bit 的 MAC 跟 80 bit 的雜湊各提供多少安全性？

### (1) 攻擊

Oscar 準備兩則訊息：無害的 $x_1$（例如「轉 10 元給 Oscar」）和有利於他的 $x_2$（「轉 10,000 元給 Oscar」），而且 $\text{MAC}_k(x_1) = \text{MAC}_k(x_2) = m$。

```
   Alice                       Oscar                         Bob
   m = MAC_k(x₁)
          ──── (x₁, m) ────→   攔截，換成 x₂
                                      ──── (x₂, m) ────→
                                                         m' = MAC_k(x₂) = m ✔
                                                         接受 x₂
```

（Oscar 需要讓 Alice 願意對 $x_1$ 算 MAC，例如 $x_1$ 看起來是一則正常的交易。）

### (2) 為什麼 MAC 的碰撞難得多

- 雜湊碰撞：Oscar 可以**自己離線**算 $2^{n/2}$ 個雜湊值。
- MAC 碰撞：每個 MAC 值都需要秘密金鑰 $k$。Oscar 必須讓**擁有金鑰的一方**（Alice 或 Bob）幫他算約 $2^{n/2}$ 個 MAC（例如 $2^{40}$ 次），而且要是他選的訊息 —— 實務上做不到，也會被發現。
- 另外，就算對一把金鑰找到碰撞，換一把金鑰就沒用了。

| | 80 bit 雜湊 | 80 bit MAC |
|---|---|---|
| 碰撞 | 約 $2^{40}$ 次**離線**計算 → **約 40 bit** 安全性 | 需要約 $2^{40}$ 次**合法方**的 MAC 計算，實務上不可行 |
| 偽造（猜 MAC） | — | 每次 $2^{-80}$ → **約 80 bit** 安全性 |

> 所以 80 bit 的 MAC 實務上提供約 **80 bit** 的安全性，而 80 bit 的雜湊只有約 **40 bit**（碰撞）。

**出處**：📖 §12.1、§11.2.3（生日攻擊）；📝 L25 §2.3（secret suffix 的碰撞攻擊，教授也提到生日攻擊 $2^{80} < 2^{128}$）、L20 §3
