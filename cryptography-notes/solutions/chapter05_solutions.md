## 5.1 資料庫加密用哪個模式

**題目摘要**：大型資料庫用 AES 加密，每筆記錄 16 位元組，記錄之間互不相關。哪個模式最適合？為什麼？

### 解答

**每筆記錄剛好一個 AES 區塊（16 位元組 = 128 bit），而且互相獨立** → 最直接的選擇是 **ECB**：
- 每筆記錄可以**單獨**加解密，**隨機存取**很方便（讀第 1000 筆不用先處理前 999 筆）。
- 不需要串鏈，也不需要存 IV。
- 一筆記錄出錯不會影響其他記錄。

**但要注意 ECB 的缺點**：它是**確定性**的 —— 兩筆內容相同的記錄會有相同的密文，攻擊者能看出「哪些記錄一樣」，也可能做**替換攻擊**（把一筆記錄的密文搬到另一筆的位置）。

**更好的做法**（依課本對各模式的描述）：用 **CTR 模式**，把**記錄編號**放進 IV/計數器。這樣：
- 仍然可以隨機存取、平行處理；
- 相同內容的記錄在不同位置會有不同密文。
- 但要確保同一個 (IV‖CTR) 值永遠不會被重複使用（例如記錄被更新時）。

**出處**：📖 §5.1.1（ECB 的優缺點、替換攻擊）、§5.1.5（CTR）；📝 L09 §3（ECB）、§3.2（替換攻擊）、§4（確定性 vs 機率性加密）、§7（CTR）

## 5.2 ECB 和 CBC 的暴力搜尋

**題目摘要**：已知明文攻擊，金鑰 $k$ bit，區塊 $n$ bit，$n > k$。(1) ECB 要幾組明文/密文？最壞幾步？(2) CBC 且 IV 已知呢？描述攻擊。(3) IV 未知呢？(4) 攻擊 CBC 比 ECB 難很多嗎？

### (1) ECB

- 錯誤金鑰期望數 $2^{k - tn}$。因為 $n > k$，$t = 1$ 時 $2^{k-n} < 1$ → **1 組**明文/密文就夠。
- 最壞要試 **$2^k$** 把金鑰。

### (2) CBC，IV 已知

CBC 的第一個區塊：$y_1 = e_k(x_1 \oplus IV)$。

**攻擊**：IV 已知，所以 $x_1 \oplus IV$ 已知，等於一組「ECB 的明文/密文」$(x_1 \oplus IV, y_1)$。
對每把金鑰 $k_i$ 檢查 $e_{k_i}(x_1 \oplus IV) \stackrel{?}{=} y_1$。

> **1 組**（$x_1$、$y_1$），最壞 **$2^k$** 步。

### (3) CBC，IV 未知

改用**第二個區塊**：$y_2 = e_k(x_2 \oplus y_1)$。$y_1$ 是密文（看得到），$x_2$ 是已知明文。
對每把金鑰檢查 $e_{k_i}(x_2 \oplus y_1) \stackrel{?}{=} y_2$。

> 需要**兩個連續的密文區塊** $y_1, y_2$ 和對應 $y_2$ 的**一個明文區塊** $x_2$。（找到金鑰後，$IV = e_k^{-1}(y_1) \oplus x_1$ 也能算出來，如果知道 $x_1$。）

### (4) 難很多嗎？

**不會。**步驟數一樣是 $2^k$，只是需要的資料稍微多一點（多一個密文區塊）。CBC 的好處在於**隱藏明文模式**，不是增加暴力搜尋的難度。

**出處**：📖 §5.1.1–5.1.2（ECB、CBC 的定義）、§5.2（定理 5.2.1）；📝 L09 §5（CBC）、L10 §4（暴力搜尋再探）

## 5.3 用已知檔案找出 CBC 的 IV

**題目摘要**：公司用 AES-128 CBC 加密檔案，金鑰固定，IV 每天換一次，每個檔案開頭都用當天的 IV。你偷到了金鑰，但不知道今天的 IV。今天截到兩個檔案：一個內容未知，一個是自動產生的暫存檔，內容全是 0xFF。怎麼找出 IV 和未知檔案的內容？

### 步驟 1：用暫存檔求 IV

暫存檔第一個區塊：$x_1 = $ FF…FF（16 個 FF，已知），截到 $y_1$。

$$y_1 = AES_k(x_1 \oplus IV) \;\Rightarrow\; AES_k^{-1}(y_1) = x_1 \oplus IV$$

$$\boxed{IV = AES_k^{-1}(y_1) \oplus \text{FF…FF}}$$

（金鑰已知，所以能做 AES 解密。）

### 步驟 2：解密未知檔案

兩個檔案是**同一天**的，用**同一個 IV**：
$$x'_1 = AES_k^{-1}(y'_1) \oplus IV, \qquad x'_i = AES_k^{-1}(y'_i) \oplus y'_{i-1}\;(i \ge 2)$$

（其實只有第一個區塊需要 IV；有了金鑰，第 2 塊以後本來就能解密。IV 是用來救回第一個區塊。）

**出處**：📖 §5.1.2（CBC 加解密、IV）；📝 L09 §5.2–5.4（CBC 的加密、解密、IV）

## 5.4 OFB 的 IV 保密沒有用

**題目摘要**：OFB 模式下，IV 保密並不會讓暴力搜尋變難。說明 IV 未知時怎麼暴力搜尋，以及對明文/密文的要求。

### 攻擊

OFB：$s_1 = e_k(IV)$，$s_i = e_k(s_{i-1})$，$y_i = s_i \oplus x_i$。

**關鍵**：只要知道**兩個連續**的金鑰串流區塊 $s_i, s_{i+1}$，就有 $s_{i+1} = e_k(s_i)$ —— 這就是一組「明文 $s_i$ / 密文 $s_{i+1}$」，**完全不需要 IV**。

1. 取兩個**連續**的已知明文區塊 $x_i, x_{i+1}$ 和對應的密文 $y_i, y_{i+1}$。
2. 算出 $s_i = x_i \oplus y_i$、$s_{i+1} = x_{i+1} \oplus y_{i+1}$。
3. 對每把金鑰 $k_j$ 檢查 $e_{k_j}(s_i) \stackrel{?}{=} s_{i+1}$。
4. 找到金鑰後，可以往後產生所有 $s$；如果需要 IV，$IV = e_k^{-1}(s_1)$。

### 要求

- 至少**兩個連續**的已知明文區塊（及對應密文）。
- 如果金鑰比區塊長（$\kappa > n$），要再多幾組連續區塊來排除錯誤金鑰（定理 5.2.1）。
- 步驟數一樣是 $2^\kappa$，跟 IV 公開時相同。

**出處**：📖 §5.1.3（OFB 的定義 5.1.3）、§5.2；📝 L09 §6（OFB 模式）、L10 §4.4（定理）

## 5.5 OFB 重複使用 IV

**題目摘要**：如果每次加密都用同一個 IV，OFB 怎麼被攻擊？

### 解答

OFB 的金鑰串流 $s_1, s_2, \ldots$ **只跟金鑰和 IV 有關**，跟明文無關。同一把金鑰 + 同一個 IV → **完全相同的金鑰串流**。

兩則訊息 $x$、$x'$：
$$y_i = s_i \oplus x_i, \qquad y'_i = s_i \oplus x'_i \;\Rightarrow\; y_i \oplus y'_i = x_i \oplus x'_i$$

- **已知明文**：只要知道其中一則訊息的某段明文，就能算出那段金鑰串流 $s_i = x_i \oplus y_i$，再拿去解**其他所有訊息**的同一段：$x'_i = y'_i \oplus s_i$。
- **只有密文**：$y \oplus y'$ 消掉了金鑰，剩下兩段明文的 XOR，可以用統計方法拆開（同 2.3 題）。

> 這跟串流密碼重複使用金鑰串流是同一個問題（課本 §2.3.3 也說明了為什麼需要 IV）。

**出處**：📖 §5.1.3（OFB、IV 應為 nonce）、§2.3.3（IV 的目的）；📝 L09 §6、L03 §4（OTP 只能用一次）

## 5.6 一次加密一個位元組的 OFB

**題目摘要**：設計用 AES 的 OFB 方案，一次加密一個位元組（例如遠端鍵盤的按鍵），每個新的明文位元組做一次 AES。畫方塊圖，標明位元寬度。

### 設計

保持 OFB 的原則：**AES 的完整 128 bit 輸出回授當下一次輸入**，但每次只拿其中 **8 bit** 當金鑰串流。

```
           IV (128)
             │
             ↓
      ┌─────────────┐
      │  暫存器 128  │←──────────────────┐
      └──────┬──────┘                    │
             │ 128                       │ 128（完整回授）
             ↓                           │
      ┌─────────────┐                    │
 k ──→│  AES  e_k   │                    │
      └──────┬──────┘                    │
             │ 128 ──────────────────────┘
             │
        取 8 bit（例如最高 8 位）
             │ 8 = s_i
             ↓
   x_i ──8──→ ⊕ ──8──→ y_i
```

| 線 | 寬度 |
|---|---|
| 暫存器、AES 輸入、AES 輸出、回授 | 128 bit |
| 金鑰串流 $s_i$（AES 輸出的其中 8 bit） | 8 bit |
| 明文 $x_i$、密文 $y_i$ | 8 bit |

- 第 $i$ 個位元組：$O_i = e_k(O_{i-1})$（$O_0 = IV$），$s_i = $ $O_i$ 的最高 8 bit，$y_i = x_i \oplus s_i$。
- 解密完全一樣（$x_i = y_i \oplus s_i$），只用到 AES 的**加密**方向。

（另一種也可以：像課本 §5.1.4 的位元組 CFB 一樣用移位暫存器，每次左移 8 位並填入那 8 bit 金鑰串流。重點是**暫存器要維持 128 bit 的狀態**，不能像 5.7 題那樣只剩 8 bit。）

**出處**：📖 §5.1.3（OFB）、§5.1.4 末段（位元組模式）；📝 L09 §6–7

## 5.7 只回授 8 bit 的 OFB 變形

**題目摘要**：OFB 變形：只把 AES 輸出最高的 8 bit 回授，另外 120 bit 輸入補 0。(1) 畫方塊圖；(2) 為什麼加密中等大小的資料（例如 100 KB）時很弱？攻擊者最多需要多少已知明文？(3) 如果把回授位元組 FB 複製 16 次當 AES 輸入，會變強嗎？

### (1) 方塊圖

```
   FB (8) ──→ [ FB ‖ 0…0 ] (128) ──→ AES e_k ──→ 輸出 s_i (128)
     ↑                                              │
     └──────────── 取最高 8 bit ────────────────────┤
                                                    ↓
                                  x_i (128) ──→ ⊕ ──→ y_i (128)
```

（假設金鑰串流用的是 AES 完整的 128 bit 輸出，一次加密 128 bit 明文區塊。）

### (2) 為什麼弱

- AES 的輸入只有 **8 bit 是變的** → 只有 $2^8 = 256$ 種可能的輸入 → 只有 **256 種**可能的金鑰串流區塊。
- 下一個狀態只由這 8 bit 決定，所以金鑰串流**最多 256 個區塊就會開始重複**（週期 ≤ 256 個區塊 = 256 × 16 = **4 KB**）。
- 100 KB 遠大於 4 KB → 金鑰串流會**重複很多次**，就像 OTP 重複使用（2.3 題）。

**最多需要多少已知明文**：一整個週期，也就是**最多 256 個區塊（4 KB）**的連續已知明文。拿到之後就知道週期內所有金鑰串流區塊，所有密文都能解開。
（如果攻擊者能從已知的金鑰串流讀出 FB，甚至可以直接預測下一個 FB，進一步縮短需要的資料。）

### (3) 把 FB 複製 16 次

**不會變強。**AES 的輸入雖然變成 128 bit（FB, FB, …, FB），但它**仍然只由 8 bit 的 FB 決定** → 還是只有 256 種可能的輸入、256 種金鑰串流區塊，週期還是 ≤ 256。

> **教訓**：OFB 的安全性靠的是**大的內部狀態**。狀態只有 8 bit，就跟 8 bit 的密碼一樣弱。

**出處**：📖 §5.1.3（OFB）；📝 L09 §6；比較 2.3、2.6 題（週期太短的串流密碼）

## 5.8 位元組 CFB 的方塊圖

**題目摘要**：畫課本提到的位元組 CFB（用 AES），標出每條線的寬度。

依課本 §5.1.4 末段：前一次的區塊密碼輸入**左移 8 位**，空出來的 8 個最低位**填入密文位元組**。

```
     IV (128)
       │
       ↓
  ┌──────────────────────────────┐
  │   移位暫存器 128 bit          │ ←── 左移 8 位，
  │  [ 120 bit 舊值 | 8 bit 新 ]  │     最低 8 位填入 y_i
  └──────────────┬───────────────┘            ↑
                 │ 128                         │ 8
                 ↓                             │
          ┌─────────────┐                      │
     k ──→│  AES  e_k   │                      │
          └──────┬──────┘                      │
                 │ 128                         │
           取 8 bit（例如最高 8 位）            │
                 │ 8                           │
                 ↓                             │
     x_i ──8───→ ⊕ ──────8──────→ y_i ─────────┘
```

| 線 | 寬度 |
|---|---|
| 移位暫存器 / AES 輸入 | 128 bit |
| AES 輸出 | 128 bit |
| 選出的金鑰串流 | 8 bit |
| 明文 $x_i$、密文 $y_i$ | 8 bit |
| 回授（密文進暫存器） | 8 bit |

**解密**：同一個結構，只是回授進暫存器的是**收到的**密文 $y_i$，輸出 $x_i = y_i \oplus s_i$。

**出處**：📖 §5.1.4（CFB、位元組變形）；📝 L09 §7（【課本補充】CFB）

## 5.9 CTR 模式加密 1 TB 硬碟

**題目摘要**：用 AES 的 CTR 模式加密 1 TB 硬碟，IV 最長可以多長？

### 解答

CTR 的區塊輸入是 $(IV \,\|\, CTR)$，共 128 bit。計數器部分要能數完整顆硬碟的所有區塊。

- 1 TB ≈ $2^{40}$ 位元組（若用 $10^{12}$ 位元組，結果一樣，見下）
- AES 區塊 = 16 位元組 = $2^4$ 位元組
- 區塊數：$2^{40} / 2^4 = 2^{36}$ → 計數器需要 **36 bit**

$$|IV|_{\max} = 128 - 36 = \mathbf{92 \text{ bit}}$$

（用 $10^{12}$ 位元組：$10^{12} / 16 = 6.25 \times 10^{10}$ 個區塊，$\log_2(6.25 \times 10^{10}) \approx 35.9$ → 還是要 36 bit。）

⚠️ 課本 §5.1.5 的例子寫「每個區塊 8 位元組」，但 AES 區塊是 16 位元組；這裡用 16 位元組計算。

**出處**：📖 §5.1.5（CTR、IV‖CTR 的構造）；📝 L09 §7（【課本補充】CTR）

## 5.10 錯誤傳播

**題目摘要**：分析各模式下的位元錯誤傳播。

### (1) ECB，傳輸中 $y_i$ 出錯

只有 **$x_i$** 受影響（解出來是亂碼）。ECB 每個區塊獨立。

### (2) CBC，傳輸中 $y_i$ 出錯

CBC 解密：$x_i = e^{-1}_k(y_i) \oplus y_{i-1}$。
- **$x_i$**：$y_i$ 錯了 → $e^{-1}_k(y_i)$ 整塊變亂碼 → $x_i$ **整塊錯**。
- **$x_{i+1}$** $= e^{-1}_k(y_{i+1}) \oplus y_i$：只有 XOR 的 $y_i$ 錯了 → $x_{i+1}$ **只有對應的那幾個 bit 翻轉**。
- $x_{i+2}$ 以後：用到 $y_{i+1}, y_{i+2}$，都是對的 → **正確**。

> 受影響：$x_i$（全錯）和 $x_{i+1}$（相同位置的 bit 錯）。

### (3) CBC，Alice 這邊的明文 $x_i$ 本身就錯了

- Alice 用錯的 $x_i$ 加密，之後的 $y_i, y_{i+1}, \ldots$ 都會跟原本不同（因為串鏈）。
- 但 Bob 解密時用的就是這些密文，**解出來的就是 Alice 輸入的東西**。

> Bob 那邊只有 **$x_i$** 是錯的（而且錯得跟 Alice 輸入的一模一樣），其他區塊都正確。

### (4) 8 bit CFB，一個密文位元組有 1 bit 錯

（以 AES 為例，區塊 128 bit = 16 位元組；若是 DES 則是 8 位元組。）

- **當下這個位元組** $x_i = y_i \oplus s_i$：$s_i$ 是用之前（正確的）暫存器算的 → $x_i$ **只有同一個 bit 錯**。
- 錯誤的 $y_i$ 接著被移進暫存器，會在暫存器裡停留 **128 / 8 = 16 步**。這 16 步裡 AES 的輸入都錯 → 金鑰串流變亂碼 → **後面 16 個位元組全部亂碼**。
- 16 步後錯誤的位元組被移出暫存器 → 恢復正常。

> 錯誤傳播：1 個位元組（1 bit 錯）+ 後面 16 個位元組（亂碼），共影響 17 個位元組。

### (5) 總整理

「**特定位元錯誤**」= 明文中**同一個位置**的 bit 翻轉（攻擊者可以**刻意**翻轉想要的 bit）；「**隨機錯誤**」= 整塊變成無法預測的亂碼。

| 模式 | $y_i$ 錯誤時的影響 | 會傳播嗎 |
|---|---|---|
| **ECB** | $x_i$：整塊隨機 | 否 |
| **CBC** | $x_i$：整塊隨機；$x_{i+1}$：**特定**位元翻轉 | 一個區塊 |
| **CFB**（完整區塊） | $x_i$：**特定**位元翻轉；$x_{i+1}$：整塊隨機 | 一個區塊 |
| **CFB**（8 bit） | 該位元組：特定位元；後面 $b/8$ 個位元組：隨機 | $b/8$ 個位元組 |
| **OFB** | $x_i$：**特定**位元翻轉 | 否 |
| **CTR** | $x_i$：**特定**位元翻轉 | 否 |

> 注意：OFB、CTR 不傳播錯誤，但攻擊者可以**有目標地**翻轉明文的某些 bit（例如把金額改掉），所以需要另外的完整性保護（MAC、GCM）。

**出處**：📖 §5.1.1–5.1.5（各模式的定義、課本提到 CBC 和 OFB/CTR 都需要完整性保護）；📝 L09 §3、§5、§6、§7

## 5.11 1 bit CFB 的自動同步

**題目摘要**：插入或刪除一個 bit 通常會讓之後全部解錯。證明回授寬度 1 bit 的 CFB，在 $\kappa + 1$ 步之後會**自動恢復同步**（$\kappa$ = 區塊大小）。

### 解答

**1 bit CFB 的結構**：$\kappa$ bit 的移位暫存器裡，放的永遠是**最近 $\kappa$ 個密文 bit**。每一步：
- 金鑰串流 bit $s_j$ = $e_k(\text{暫存器})$ 的某一個 bit
- $x_j = y_j \oplus s_j$
- 暫存器左移 1 位，填入 $y_j$

**關鍵**：接收方的暫存器內容**只由收到的密文決定**，跟過去的狀態無關（不像 OFB 有內部狀態）。

**插入或刪除一個 bit 之後**：
1. 發生錯誤的那一步，接收方的暫存器開始跟發送方不同（裡面有「多出來的」或「缺少的」bit）。
2. 之後每一步，接收方把**收到的**密文 bit 移進暫存器。錯誤之後收到的密文 bit 都是正確的（只是整體位置錯開了一位，但接收方本來就只是逐 bit 地處理串流）。
3. 經過 $\kappa$ 步，暫存器裡的 $\kappa$ 個 bit **全部**是錯誤之後收到的正確密文 bit → 跟發送方產生這些密文時的暫存器內容**完全一樣**。
4. 所以下一步（第 $\kappa + 1$ 步）算出的金鑰串流 bit 是對的，解密恢復正常。

> 錯誤那一步 + $\kappa$ 步把錯誤移出暫存器 = **$\kappa + 1$ 步**後自動同步。（AES：129 步；DES：65 步。）

這種「自我同步」是**非同步串流密碼**的特性（課本 §2.1.1：CFB 是非同步串流密碼的例子）。

**出處**：📖 §5.1.4（CFB）、§2.1.1（同步 / 非同步串流密碼、圖 2.3）；📝 L09 §7、L03 §1

## 5.12 破解 2DES 的成本

**題目摘要**：$2DES(x) = DES_{K_2}(DES_{K_1}(x))$。ASIC 每秒 $10^7$ 把，每顆 5 美元，建造額外成本 50%。(1) 不用記憶體，搜尋全部 $(K_1, K_2)$，一週內（最壞情況）破解要多少錢？(2) 中間相遇攻擊：要存幾筆？每筆幾位元組？一週破解要多少錢？（硬碟 8 美元 / 10 GB，1 GB = $10^9$ 位元組）(3) 依摩爾定律，什麼時候成本會低於 100 萬美元？

**一顆 ASIC 一週能試**：$10^7 \times 604{,}800 = 6.05 \times 10^{12}$ 把
**每顆 ASIC 實際成本**：$5 \times 1.5 = 7.5$ 美元

### (1) 純暴力搜尋

最壞要試 $2^{112}$ 組金鑰。$\log_{10} 2^{112} = 112 \times 0.30103 = 33.72$ → $2^{112} \approx 5.19 \times 10^{33}$

$$\text{ASIC 數} = \frac{5.19 \times 10^{33}}{6.05 \times 10^{12}} \approx 8.6 \times 10^{20}$$

$$\text{成本} \approx 8.6 \times 10^{20} \times 7.5 \approx \mathbf{6.4 \times 10^{21} \text{ 美元}}$$

### (2) 中間相遇攻擊

**要存幾筆**：每個 $K_1$ 一筆 → $2^{56} \approx 7.2 \times 10^{16}$ 筆

**每筆幾位元組**：中間值 $z$（64 bit）+ 金鑰 $K_1$（56 bit）= 120 bit = **15 位元組**

**儲存成本**：
- 總量：$7.2 \times 10^{16} \times 15 \approx 1.08 \times 10^{18}$ 位元組 = $1.08 \times 10^9$ GB
- 價格：8 美元 / 10 GB = 0.8 美元 / GB
- $1.08 \times 10^9 \times 0.8 \approx \mathbf{8.6 \times 10^8 \text{ 美元}}$（約 8.65 億）

**計算成本**：第一階段 $2^{56}$ 次加密，第二階段最多 $2^{56}$ 次解密，都要在一週內完成 → $2^{57} \approx 1.44 \times 10^{17}$ 次
$$\text{ASIC 數} = \frac{1.44 \times 10^{17}}{6.05 \times 10^{12}} \approx 23{,}800, \quad \text{成本} \approx 23{,}800 \times 7.5 \approx 1.8 \times 10^5 \text{ 美元}$$

> **總成本 ≈ 8.65 億美元**，幾乎全部是硬碟。比純暴力搜尋便宜約 $10^{13}$ 倍。

### (3) 什麼時候低於 100 萬美元

假設摩爾定律也適用於儲存成本（每 18 個月成本減半）：

**中間相遇攻擊**：要降低 $8.65 \times 10^8 / 10^6 \approx 865$ 倍
$$\log_2 865 \approx 9.76 \text{ 次減半} \times 1.5 \approx \mathbf{15 \text{ 年}}$$

（純暴力搜尋：$6.4 \times 10^{21} / 10^6 = 6.4 \times 10^{15}$ 倍，$\log_2 \approx 52.5$ 次 → 約 79 年。）

**出處**：📖 §5.3.1（雙重加密與中間相遇攻擊、表格條目寬 $n + \kappa$ bit、複雜度 $2^{\kappa+1}$ 與 $2^\kappa$ 儲存）；📝 L10 §2（雙重加密與中間相遇攻擊）、§2.6（複雜度與結論）

## 5.13 外星人的 AES 破解機

**題目摘要**：外星人的電腦能在幾天內搜完 128、192、256 bit 的金鑰。他們需要幾組明文–密文才能以合理的機率排除錯誤金鑰？

用定理 5.2.1：錯誤金鑰期望數 $2^{\kappa - tn}$，AES 的 $n = 128$。

| 金鑰長度 $\kappa$ | $t = 1$ | $t = 2$ | $t = 3$ | 建議 |
|---|---|---|---|---|
| 128 | $2^0 = 1$ | $2^{-128}$ | — | **2 組** |
| 192 | $2^{64}$ | $2^{-64}$ | — | **2 組** |
| 256 | $2^{128}$ | $2^{0} = 1$ | $2^{-128}$ | **3 組** |

- AES-128 只用 1 組：期望有 1 把錯誤金鑰跟正確金鑰混在一起，分不出來 → 要 2 組。
- AES-256 用 2 組：還是期望有 1 把錯誤金鑰 → 要 3 組。

> 一般原則：$t > \kappa / n$，再多一組讓錯誤機率變得極小。

**出處**：📖 §5.2（定理 5.2.1）；📝 L10 §4.3（多一組明文/密文）、§4.4（定理）

## 5.14 多重加密需要幾組明文–密文

**題目摘要**：(1) 三重 AES-192（$n = 128$，$\kappa = 192$），要幾組才能讓錯誤金鑰的機率降到 $2^{-20}$？(2) 雙重加密（$l = 2$）、區塊 $n = 80$，錯誤機率最多 $2^{-10}$，能攻擊的最大金鑰長度？(3) 雙重 AES-256，只有 4 組，成功機率？

用定理 5.3.1：$2^{l\kappa - tn}$。

### (1) 三重 AES-192

$l\kappa = 3 \times 192 = 576$。要 $2^{576 - 128t} \le 2^{-20}$：
$$128t \ge 596 \Rightarrow t \ge 4.66 \Rightarrow \mathbf{t = 5}$$
（$t = 5$：$2^{576 - 640} = 2^{-64}$，遠小於 $2^{-20}$；$t = 4$：$2^{576 - 512} = 2^{64}$，太多。）

### (2) 雙重加密、$n = 80$

要 $2^{2\kappa - 80t} \le 2^{-10}$：
$$2\kappa \le 80t - 10 \Rightarrow \kappa \le 40t - 5$$

⚠️ 題目沒說有幾組明文–密文。依 $t$ 而定：

| $t$ | 最大 $\kappa$ |
|---|---|
| 1 | **35 bit** |
| 2 | 75 bit |
| 3 | 115 bit |

如果只有 **1 組**明文–密文（最自然的解讀），最大金鑰長度是 **35 bit**。

### (3) 雙重 AES-256、4 組

$$2^{2 \times 256 - 4 \times 128} = 2^{512 - 512} = 2^0 = 1$$

**期望有 1 把錯誤金鑰**同樣符合全部 4 組。攻擊者找到的候選裡，平均有正確的那把加上大約 1 把錯誤的，無法分辨。

> **成功機率約 1/2**（從兩個候選中猜一個）。要可靠地成功，需要 5 組（$2^{-128}$）。

（題目也提醒：$2^{128}$ 以上的金鑰空間實際上不可能暴力搜尋，這只是理論題。）

**出處**：📖 §5.3.1（定理 5.3.1、例 5.3）；📝 L10 §4.4（定理：錯誤金鑰的期望個數）

## 5.15 攻擊三把金鑰的 3DES

**題目摘要**：三把不同金鑰的 3DES 可以用大約 $2^{2k}$ 次加密和 $2^k$ 個記憶體位置破解（$k = 56$）。設計這個攻擊。需要幾組 $(x, y)$ 才能讓找到錯誤金鑰三元組的機率夠低？

### 攻擊（中間相遇）

$y = e_{k_3}(e_{k_2}(e_{k_1}(x)))$。把「中間」放在第一次加密之後：

**第一階段（建表）**：對所有 $2^{56}$ 個 $k_1$，算 $z = e_{k_1}(x_1)$，存 $(z, k_1)$，依 $z$ 排序。
→ $2^{56}$ 次加密、$2^{56}$ 個記憶體位置。

**第二階段（從另一邊找碰撞）**：對所有 $2^{112}$ 組 $(k_2, k_3)$，算 $z' = e^{-1}_{k_2}(e^{-1}_{k_3}(y_1))$，在表中查 $z'$。
→ 約 $2 \times 2^{112}$ 次解密（量級 $2^{112} = 2^{2k}$）。

**驗證**：每個碰撞給出候選 $(k_1, k_2, k_3)$，用其他明文–密文對檢查。

> 總計：約 $2^{112}$ 次運算、$2^{56}$ 個記憶體位置。所以三重 DES 的有效安全性約 **112 bit**。

### 需要幾組

$l = 3$，$\kappa = 56$，$n = 64$：$2^{168 - 64t}$

| $t$ | 錯誤金鑰期望數 |
|---|---|
| 2 | $2^{40}$ |
| 3 | $2^{-24}$ |
| 4 | $2^{-88}$ |

> **3 組**時錯誤機率約 $2^{-24}$（約一千六百萬分之一），已經相當低；要非常保險可以用 **4 組**。

**出處**：📖 §5.3.2（三重加密、圖 5.11 的中間相遇攻擊）、定理 5.3.1；📝 L10 §3.1（中間相遇攻擊還能用嗎？）、§3.2（有效金鑰長度 112 bit）

## 5.16 DESA：錯誤的金鑰白化

**題目摘要**：$DESA_{k, k_1}(x) = DES_k(x) \oplus k_1$。證明破解它大約跟暴力破解單一 DES 一樣難（給你幾組明文–密文）。

### 攻擊

拿兩組明文–密文 $(x_1, y_1)$、$(x_2, y_2)$：
$$y_1 = DES_k(x_1) \oplus k_1, \qquad y_2 = DES_k(x_2) \oplus k_1$$

兩式 XOR，**$k_1$ 消掉了**：
$$y_1 \oplus y_2 = DES_k(x_1) \oplus DES_k(x_2)$$

1. 對所有 $2^{56}$ 把 $k$，檢查 $DES_k(x_1) \oplus DES_k(x_2) \stackrel{?}{=} y_1 \oplus y_2$。
2. 找到 $k$ 之後，直接算出 $k_1 = y_1 \oplus DES_k(x_1)$。
3. 用第三組明文–密文驗證（排除錯誤的 $k$；期望錯誤數約 $2^{56 - 64} < 1$）。

**成本**：每把 $k$ 做 2 次 DES → 總共約 $2 \times 2^{56} = 2^{57}$ 次 DES，跟單一 DES 的暴力搜尋（$2^{56}$）只差 2 倍。

> **為什麼正常的金鑰白化不會這樣**：正規的白化是 $DES_k(x \oplus k_1) \oplus k_2$，白化金鑰 $k_1$ **進入 DES 的輸入**，XOR 兩組時消不掉，攻擊者必須同時猜 $k$ 和 $k_1$。DESA 只在輸出端 XOR 一把金鑰，一個線性的 XOR 就把它消掉了。

**出處**：📖 §5.3.3（金鑰白化）、§3.7.2（DESX）；📝 L10 §5（【課本補充】金鑰白化）
