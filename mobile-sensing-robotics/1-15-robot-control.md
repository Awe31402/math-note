## 0. 這堂課要做什麼

前面幾集都在講「估計」（我在哪）。這集開始講「行動」：怎麼讓機器人照我們要的方式動。三個層次：

| 層次 | 例子 | 本集方法 |
|---|---|---|
| 馬達 | 讓馬達以每秒 50 轉轉動 | PWM、回饋、P 控制 |
| 位置 | 開到某個點停下 | PID |
| 軌跡 | 沿一條路徑平順地走 | 縱向 PID ＋ 橫向依運動學 |

最後概覽幾種進階方法：最佳控制、LQR、MPC、強健控制、自適應控制、故障安全控制、學習式控制。

## 1. 控制在整個系統裡的位置

[▶ 01:15](https://youtu.be/pEVsedl2KO4?t=75)

一個自主機器人的大致架構：

- **思考／表示**（灰色框）：前面幾集的東西。用感測器建地圖、用地圖定位。
- **致動器**（actuator）：和世界互動的方式。移動機器人就是接在輪子上的馬達。
- **感測器**：知道自己實際怎麼動。例如輪子編碼器、GPS、雷射掃描儀。

文獻裡有時叫 **think–act–sense**（思考—行動—感測）架構 [▶ 04:45](https://youtu.be/pEVsedl2KO4?t=285)。本集講的是「行動」這一側的三層控制。例子都用都市裡的自駕車，但無人機、人形機器人的結構一樣。

## 2. 最底層：馬達控制

### 2.1 直流馬達

[▶ 05:07](https://youtu.be/pEVsedl2KO4?t=307)

- 兩塊磁鐵（N、S 極）產生磁場。
- 通電的導線在磁場中會受力。
- 電刷連到線圈，線圈在磁場裡；接上電池，電流流過線圈。磁場和電流方向垂直 → 軸受力轉 180°。
- 把電能轉成旋轉的機械能，可以把馬達看成一種**換能器**（transducer）。
- 講者的用意：設計控制器時，常常要懂到致動器本身怎麼運作。

### 2.2 脈寬調變 PWM

[▶ 06:57](https://youtu.be/pEVsedl2KO4?t=417)

- 直流馬達：給越多電，轉越快。線圈受的力和電流成正比。
- **脈寬調變**（pulse width modulation, PWM）：送一串脈衝，0 V 是關、5 V 是開。
  - 整個週期都開 → 最高轉速。
  - 想要 1/4 的速度 → 每個週期只開 1/4 的時間。
- **工作週期**（duty cycle）= 開的時間 ÷ 週期，和轉速成正比。
- 市面上有現成晶片做這件事（投影片上的晶片可以同時控制 4 個馬達）。業餘和多數專業機器人都有這種板子。

### 2.3 開迴路 vs. 回饋控制

[▶ 08:58](https://youtu.be/pEVsedl2KO4?t=538)

- 如果馬達完全照指令做，到這裡就結束了。
- 實際上：要求每秒 50 轉，可能只有 48 或 52 轉（沒校正好、電流和轉速的關係不完美）。
- **開迴路控制**（open-loop control）：下指令、控制器執行，**不知道結果怎樣**。
- **回饋控制**（feedback control）[▶ 09:47](https://youtu.be/pEVsedl2KO4?t=587)：
  1. 給控制器**期望值**（例如 50 轉）。
  2. 控制器產生電力，系統動起來。
  3. 用**感測器**（馬達軸上的編碼器）量實際轉了幾圈，例如 48。
  4. **誤差** = 期望 − 實際 = 2。
  5. 控制器根據誤差多給一點電力補上。

【口頭】**洗澡的例子** [▶ 11:22](https://youtu.be/pEVsedl2KO4?t=682)：

| 控制概念 | 洗澡 |
|---|---|
| 期望狀態 | 想要 35°C |
| 目前狀態 | 水現在 30°C |
| 控制 | 轉水龍頭把手（加冷水或熱水） |
| 感測器 | 你的皮膚 |
| 回饋 | 「現在大概 32°C，還不到 35，再往熱水那邊轉一點」 |

我們每天早上都在解這個控制問題。

## 3. 回饋控制的數學架構

[▶ 12:57](https://youtu.be/pEVsedl2KO4?t=777)

**誤差訊號**：

$$
e_t = x_{\text{des}} - z_t
$$

$x_{\text{des}}$ = 期望狀態，$z_t$ = 量到的值。

- 注意：量到的不一定是**完整狀態**。例如 2D 機器人狀態是 $(x, y, \theta)$，但 GPS 只給位置、不給朝向 → 朝向**不可觀測**。本集例子假設能觀測全部狀態，但實務上要記得這件事 [▶ 13:24](https://youtu.be/pEVsedl2KO4?t=804)。

**控制器**：給定誤差，產生控制 $u_t$（馬達轉多快、到哪個位置……）。這是本集要設計的東西。

**系統模型**（最簡單的線性形式）：

$$
x_t = x_{t-1} + u_t
$$

- 洗澡：現在的水溫 = 之前的水溫 + 新加的熱水造成的變化。
- 很多移動機器人需要更複雜（非線性）的模型。
- 模型只是我們的**假設**，是簡化過的，本身就會造成誤差 [▶ 15:16](https://youtu.be/pEVsedl2KO4?t=916)。

## 4. 比例控制（P）

[▶ 15:50](https://youtu.be/pEVsedl2KO4?t=950)

最簡單的控制器：

$$
u_t = K_p\, e_t
$$

- 誤差大 → 控制大；誤差小 → 控制小。
- $K_p$ 決定用多少比例：$K_p = 1$ 是整個誤差都拿來當控制；$K_p = 0.1$ 是只用 10%。

下面都用洗澡例子。圖的上半是水溫（紅線 = 真實溫度，藍線 = 量到的溫度），下半是控制。控制的單位是「溫度的度數」：例如把手轉一半 = 加熱 5°C，轉到底 = 10°C。

**注意**：真實溫度在現實中不知道，只能估計；圖上畫出來只是為了比較 [▶ 18:29](https://youtu.be/pEVsedl2KO4?t=1109)。

### 4.1 理想情況

[▶ 16:49](https://youtu.be/pEVsedl2KO4?t=1009)

- $K_p = 1$，起始 25°C，目標 35°C。
- 誤差 10 → 控制 10 → 一秒後就到 35°C。
- 沒雜訊，一次就到。但你的洗澡經驗告訴你，**現實從來不是這樣**。

**兩種誤差** [▶ 19:44](https://youtu.be/pEVsedl2KO4?t=1184)：

- **系統誤差**：模型不準（例如冷熱水混合有雜訊、轉把手和水溫變化之間有延遲）。
- **量測誤差**：感測器不準，或比較晚才感覺到。

### 4.2 有雜訊：調低增益

[▶ 20:00](https://youtu.be/pEVsedl2KO4?t=1200)

- 量測有雜訊時（藍線抖動），即使 $K_p = 1$，也永遠到不了 35：每一步都因雜訊而稍微偏上或偏下，每一步都在修正。
- 結果：**一直在轉把手**。洗澡時沒人想要這樣。
- 解法：**調低增益**。例如 $K_p = 0.15$：
  - 每次只修正誤差的 15%，雜訊造成的變化也小 15 倍左右 → 溫度平順得多。
  - 代價：要約 25 秒才到目標溫度，而不是一兩秒。
- **取捨**：反應速度 vs. 對雜訊的敏感度。看應用：洗澡等 20 秒可以接受；有些應用需要很快到達。

以下**不是逐字稿內容**，是依系統模型 $x_t = x_{t-1} + u_t$ 推論的，用來說明為什麼低增益比較平順：

- 沒有雜訊時，$e_t = x_{\text{des}} - x_t = x_{\text{des}} - x_{t-1} - K_p e_{t-1} = (1 - K_p)\, e_{t-1}$，所以 $e_t = (1 - K_p)^t e_0$。
- $K_p = 1$：一步歸零。$0 < K_p < 1$：誤差每步乘上 $1 - K_p$，單調變小，$K_p$ 越小越慢。
- 量測雜訊 $n_t$ 進來時，每一步的狀態會被推動 $K_p n_t$：$K_p$ 越小，雜訊對狀態的影響越小。

### 4.3 增益太大、符號相反、飽和

**增益大於 1** [▶ 22:58](https://youtu.be/pEVsedl2KO4?t=1378)：會**放大**誤差。例如量測誤差 5°C，每次乘 2，系統可能**不穩定**，「水會燒到 100°C」。建議：特別是有雜訊的系統，**不要用大於 1 的增益**。

（以下**不是逐字稿內容**，是依上面的 $e_t = (1 - K_p)\, e_{t-1}$ 推論的：在這個簡單模型裡，$1 < K_p < 2$ 時 $|1 - K_p| < 1$，誤差會正負交替地震盪但仍收斂；$K_p > 2$ 時 $|1 - K_p| > 1$，誤差越震越大、發散。講者的建議比這個界線保守，因為他考慮的是有雜訊的情況。）

**符號相反** [▶ 23:45](https://youtu.be/pEVsedl2KO4?t=1425)：【口頭】以前的程式作業有人把誤差的正負號弄反。在 25°C 想到 35°C，結果修正 −10 → 越來越遠。最後會碰到**物理極限**（例如不能低於絕對零度 −273°C 左右）。

`⚠️ 逐字稿缺字`：[▶ 24:30](https://youtu.be/pEVsedl2KO4?t=1470) 講者說「minus 272」，絕對零度約為 −273.15°C，應是口誤。

**飽和**（saturation）[▶ 25:01](https://youtu.be/pEVsedl2KO4?t=1501)：

- 系統本身有物理極限，控制也有極限：把手不能轉無限快、無限熱。
- 例如熱水器每秒最多只能加熱 5°C，那從 25°C 到 35°C 至少要 2 秒，不可能立刻到。
- 實務上常常因為「力氣不夠」而碰到飽和。

### 4.4 延遲與 Smith 預測器

**延遲** [▶ 25:57](https://youtu.be/pEVsedl2KO4?t=1557)：

- 例子：延遲在**量測**上。水已經 25°C，過幾秒才量到 25°C。（延遲也可能在系統上，例如冷熱水混合需要時間。）
- 真實溫度已經到 35°C 時，量到的還是 25°C → 控制器以為還要加熱 10°C → 繼續加熱。
- 結果：**過衝**（overshoot，超過 35°C），而且一直在目標附近**震盪**，因為永遠落後真實狀態。

**死區時間**（dead time）[▶ 27:58](https://youtu.be/pEVsedl2KO4?t=1678)：

- 延遲可能來自系統或感測器。
- 對控制器來說**分不出來**：它只看到誤差訊號，而這個訊號是延遲的。
- 例：系統延遲 1 秒＋感測器延遲 0.5 秒 → 控制器看到的是 1.5 秒前的狀態。

**Smith 預測器**（Smith predictor）[▶ 28:55](https://youtu.be/pEVsedl2KO4?t=1735)，處理延遲的經典方法：

1. 除了真實系統，還有一個**虛擬系統**（系統模型，只存在你腦中）。
2. 控制 $u_t$ 同時送給真實系統和虛擬模型。
3. 最簡單的想法：虛擬模型沒有延遲，直接用它的輸出回饋給控制器，完全不看真實世界。
   - 問題：要做出精確、沒有延遲的模型很難（例如熱水器怎麼混水）。
4. 實際做法：
   - 仍然用真實系統的量測 $z_t$（有延遲）。
   - 虛擬模型的輸出再經過一個**延遲模型**。最簡單的延遲模型：一個陣列，存過去約 5 秒的值。
   - 用經驗分析估出平均延遲（例如 2 秒），從陣列取 2 秒前的值。
   - 把真實量測和「延遲過的虛擬量測」結合起來回饋給控制器。
5. 需要好的系統模型和好的延遲模型；延遲模型很差的話，預測就不會比較好。

**延遲估得準不準** [▶ 31:50](https://youtu.be/pEVsedl2KO4?t=1910)：

| 情況 | 結果 |
|---|---|
| 延遲估得剛好（1.5 秒） | 完美追蹤 |
| **高估**延遲（實際 1.5 秒，估 2 秒） | **震盪**：施加了比需要更多的控制 |
| **低估**延遲 | 比較慢到達，但**不震盪** |

**建議**：寧可**低估**延遲。很多系統「穩定、不震盪」比「快一點到」重要。

（講者在 [▶ 33:13](https://youtu.be/pEVsedl2KO4?t=1993) 說高估時「實際上不是落後，而是跑在真實狀態前面」，前後描述不完全一致；結論是高估會震盪、低估比較安全。）

## 5. 中層：位置控制與 PID

[▶ 34:15](https://youtu.be/pEVsedl2KO4?t=2055)

上面的想法用在馬達轉速控制上完全一樣（雜訊、延遲的處理都適用）。現在往上一層：**位置控制**。例子：讓自駕車開到某個目標點**停下來**。

**簡化的運動學**：把車子看成一個**質點**（低速時夠用）：

$$
x_t = x_{t-1} + v\, \Delta t
$$

不考慮加速度。圖中取 $\Delta t = 1$。一維例子：從 $x = 0$ 到 $x = 1$。不給控制（速度 0），就永遠停在原地。

### 5.1 只用 P 會來回震盪

[▶ 37:08](https://youtu.be/pEVsedl2KO4?t=2228)

- 圖：紅線 = 位置；藍線 = **速度**（這次藍線不是量測，是速度，因為位置和速度兩個量描述車的運動）。
- 綠線 = P 控制：$K_p \times (1 - \text{目前位置})$。
- 現象：車子到了 1，但到達時**速度不是 0**（一路在加速度），停不下來 → **過衝** → 發現跑過頭，誤差反向 → 往回開 → 又過頭……**來回震盪**。
- 原因：P 控制只知道現在在哪、想去哪，**不知道現在速度多快**。

（以下**不是逐字稿內容**，是依講者描述的現象推論的：如果 $u$ 直接設定速度、而且 $x_t = x_{t-1} + u\,\Delta t$，P 控制在 $K_p \Delta t < 1$ 時不會過衝。講者描述的「到達時速度不為零、停不下來」表示這裡的控制量實際上是在**改變速度**（類似加速度），狀態有位置和速度兩個量。這種「控制作用在二階導數」的系統只用 P 控制就會震盪。）

### 5.2 PD 控制

[▶ 39:17](https://youtu.be/pEVsedl2KO4?t=2357)

加一個**微分項**（derivative），在這個例子裡就是**速度**的誤差：

$$
u_t = K_p\,(x_{\text{des}} - x_t) + K_d\,(\dot x_{\text{des}} - \dot x_t)
$$

- 第一項：位置誤差。
- 第二項：速度誤差。這裡想在位置 1 **停下來**，所以期望速度 $\dot x_{\text{des}} = 0$；一般情況可以是任何期望速度。
- 叫 **PD 控制**（proportional–derivative）。
- 結果 [▶ 40:17](https://youtu.be/pEVsedl2KO4?t=2417)：接近 1 時速度也降下來，**平順地**以速度 0 到達。
- 控制有兩個分量：紅色（位置誤差）、淺藍色（速度誤差）；實際送給車的是綠色（兩者之和）。
- 這是把物體移到某個狀態最常見的控制器之一。

**增益太大或太小** [▶ 41:23](https://youtu.be/pEVsedl2KO4?t=2483)：

- 太大（例如 $K_p$ 太大）：移動太快、停不住 → 超過目標。設計控制系統時要減少**過衝**和**震盪**。
- 太小：太慢到達。
- 取捨：能接受多少過衝 vs. 多快要到。調 $K_p$、$K_d$ 得到想要的表現。

### 5.3 PID：用積分項消除系統偏差

[▶ 42:47](https://youtu.be/pEVsedl2KO4?t=2567)

**系統性偏差**（systematic bias）：

- 例：輪式機器人兩個輪子大小不一（打氣不同），或重量分配不均 → 總是偏左或偏右。運動學和速度模型沒有涵蓋這個誤差。
- 結果：到不了目標，**停在一個固定偏移的地方**（穩態誤差，steady-state error）。
- 來源：校正誤差、建模誤差、各種假設的誤差。

**加上積分項** [▶ 44:00](https://youtu.be/pEVsedl2KO4?t=2640)：

$$
u_t = K_p\, e_t + K_i \int_0^t e(\tau)\, d\tau + K_d\, \dot e_t
$$

其中 $e_t = x_{\text{des}} - x_t$，$\dot e_t = \dot x_{\text{des}} - \dot x_t$。

- 積分項：把「期望狀態和目前狀態的差」**一路加起來**，也就是兩條曲線之間的面積。
- 即使 P 和 D 項都沒有貢獻，積分項仍然產生控制，把系統留在期望狀態。
- 直覺：到達目標、速度也對了，但系統偏差讓機器人每一刻都想偏離 → 一偏離，積分就開始累積 → 產生控制把它推回來。

| 項 | 負責 |
|---|---|
| P | 到達位置 |
| D | 以正確的速度到達（減少過衝） |
| I | 消除系統偏差（穩態誤差） |

### 5.4 積分飽和（wind-up）

[▶ 46:12](https://youtu.be/pEVsedl2KO4?t=2772)

積分項在接近穩態時很好用，但有**積分飽和**（wind-up）的危險：

- 例：機器人**卡在坑裡**。一直給控制，輪子在轉，編碼器說輪子在動，以為已經到了別處；但實際上位置沒變。
- 「以為的位置」和「實際位置」差很多 → 積分一直累積，變得很大。
- 某一刻突然脫困 → 巨大的積分項造成巨大的速度 → 機器人**暴衝**。

**對策**：

- 不要從頭積分到現在，只積分**最近一小段時間**（例如最近 5 秒）→ 積分項有上限，不會大到出事。
- 另一種情況：要求的控制超過致動器能做到的 → 要求和實際之間的差也會累積，導致到不了期望位置。

### 5.5 示範影片

[▶ 48:34](https://youtu.be/pEVsedl2KO4?t=2914)

把指針裝在馬達上，目標是讓指針停在刻度中央。

| 設定 | 現象 |
|---|---|
| 只有 P，$K_p = 200$ | 過衝（到了還有速度，衝過頭） |
| 更大的 $K_p$ | 過衝更多、震盪更多。只加大 $K_p$ 沒用 |
| 加上 D | 很接近目標，但還有一點**穩態誤差** |
| 加上 I（PID） | 原本以為會立刻成功，但出現 **wind-up**：馬達跟不上要求的控制 |
| PID ＋ **抗積分飽和**（anti-windup）程式 | 限制馬達的最大動作 → 很接近中央 |

**小結** [▶ 50:56](https://youtu.be/pEVsedl2KO4?t=3056)：

- 想快 → 調高 $K_p$。
- 不想過衝太多 → 加重 D。
- 有系統偏差 → 用 I。
- 找到正確的增益要花工夫，常常是**試誤法**；也有方法能給出合理的近似值。

## 6. 高層：軌跡控制

[▶ 51:55](https://youtu.be/pEVsedl2KO4?t=3115)

- 不只是到某點停下，而是**沿一條軌跡平順地移動**。
- 可以想成進階的位置控制：不是每個點都停，而是**以某個速度**通過每個點再繼續。
- 路徑從規劃演算法來（例如 A*，見 1-18）。這裡假設路徑已知，問題是怎麼產生控制 $u$ 去追蹤它。

### 6.1 架構：縱向與橫向

[▶ 53:00](https://youtu.be/pEVsedl2KO4?t=3180)

自駕車常見的架構（其他系統也可以改用）：

1. **感知**：用感測器建地圖、找出可行駛區域。
2. **運動規劃**：產生一條路徑，而且路徑上**每一點都有一個速度**，這樣才不會走走停停。
3. **控制**（本節）：拆成兩個控制器。
   - **縱向控制**（longitudinal）：沿著行進方向 → 控制車的**線速度**。
   - **橫向控制**（lateral）：控制和路徑的**垂直距離**，不要離路徑太遠。
4. **致動**：
   - 縱向 → 油門、煞車。
   - 橫向 → 方向盤。

**拆開的理由** [▶ 54:30](https://youtu.be/pEVsedl2KO4?t=3270)：嚴格說兩者不獨立：改變線速度也會影響和路徑的垂直距離。但為了簡化，實務上常拆成兩個比較好設計的控制器。雖然「沒那麼正確」，只要控制得**夠快**，就行得通。

### 6.2 產生軌跡

[▶ 56:03](https://youtu.be/pEVsedl2KO4?t=3363)

規劃器給一條紅線，要從上面取點：

| 方法 | 做法 | 適用 |
|---|---|---|
| 均勻取樣 | 例如每 5 公尺一個點 | 很多情況夠用 |
| 依**曲率**取樣 | 曲率大的地方多取點 | 速度較快時；轉彎處要轉更多方向盤，點多比較平順 |

講者說還有其他方法，但這兩個基本方法對中等速度的控制效果已經很好。

### 6.3 Ackermann 的限制

[▶ 57:19](https://youtu.be/pEVsedl2KO4?t=3439)

複習 1-06 的 Ackermann 轉向：

- $\delta$ 是虛擬前輪（腳踏車模型）的轉向角。
- 所有輪子的軸線都要通過同一個 ICC → 所有輪子純滾動、不打滑。滾動時摩擦小，也比較能估計系統怎麼演變。
- 設計控制器時要確保滿足這個條件。

**狀態與控制** [▶ 58:49](https://youtu.be/pEVsedl2KO4?t=3529)：

| | 內容 |
|---|---|
| 狀態 | $(x, y, \theta, \delta)$：位置、朝向、**轉向角** |
| 縱向控制 | 前進速度 $v$ |
| 橫向控制 | 轉向角的**變化率** $\dot\delta$（方向盤轉多快） |
| 運動學限制 | $\delta = \arctan(D/R)$（1-06 第 6.3 節，$D$ = 軸距），保證只有一個旋轉中心 |
| 控制限制 | 最大速度（油門只能踩這麼多）、最大轉向角 |

控制器產生的 $(v, \dot\delta)$ 要落在合法範圍內，並遵守運動學。

`⚠️ 逐字稿缺字`：[▶ 59:27](https://youtu.be/pEVsedl2KO4?t=3567) Whisper 寫 “tan inverse t by r”，依 1-06 應為 $\arctan(D/R)$（軸距 / 半徑）。

### 6.4 縱向控制：PID

[▶ 1:00:18](https://youtu.be/pEVsedl2KO4?t=3618)

- 運動規劃給出隨時間變化的參考速度 $v_{\text{ref}}(t)$。
- 和前面的 PID 問題一樣，只是**參考值隨時間變**（之前是常數）。每一刻都對當下的參考點算誤差：$e_t = v_{\text{ref}}(t) - v_t$。

### 6.5 橫向控制：照運動學走圓弧

**簡單但不夠好的做法** [▶ 1:01:22](https://youtu.be/pEVsedl2KO4?t=3682)：

- 找路徑上最近的點，算車頭方向和路徑切線的夾角，用 PID 讓這個夾角歸零（永遠沿切線走）。
- 問題：完全**沒考慮**運動學限制（轉向角的條件），不滿足的話就會**打滑**。

**實務做法** [▶ 1:02:29](https://youtu.be/pEVsedl2KO4?t=3749)：利用車的運動學。

- 轉向角設成某個值的反正切（公式在投影片上，逐字稿沒有唸出）。
- 效果：車子沿一段**圓弧**走，在前方距離 $l_d$ 處和期望路徑相交。$l_d$ 叫**前視距離**（look-ahead distance）。
- 不是馬上硬切回路徑，而是走一條平順的圓弧過去。
- 這樣就遵守了 ICC 的限制（永遠繞某一點滾動）。
- 講者把推導留作**習題**，提示：用幾何關係加上**正弦定理**（law of sines）。

以下**不是逐字稿內容**，是依講者的提示（圓弧、前視距離、正弦定理）和 1-06 的腳踏車模型推出的。這個方法一般稱為 **pure pursuit**（名稱是筆記補的，講者沒說）。

設：後輪中點在 $P$，路徑上前方距離 $l_d$ 的目標點是 $G$，車頭方向和 $PG$ 的夾角是 $\alpha$，軸距 $D$。

1. 要找一個圓：過 $P$、在 $P$ 和車頭方向相切（車子從 $P$ 出發沿圓弧走）、而且通過 $G$。圓心 $C$ 在 $P$ 的垂直方向上，半徑 $R$。
2. 三角形 $CPG$：$CP = CG = R$（等腰）。$CP$ 垂直於車頭方向，所以 $\angle CPG = 90° - \alpha$；同理 $\angle CGP = 90° - \alpha$；頂角 $\angle PCG = 2\alpha$。
3. 正弦定理：

$$
\frac{l_d}{\sin 2\alpha} = \frac{R}{\sin(90° - \alpha)}
\quad\Rightarrow\quad
\frac{l_d}{2\sin\alpha\cos\alpha} = \frac{R}{\cos\alpha}
\quad\Rightarrow\quad
R = \frac{l_d}{2\sin\alpha}
$$

4. 腳踏車模型（1-06）：$\tan\delta = D/R$，代入：

$$
\delta = \arctan\!\left( \frac{2D\sin\alpha}{l_d} \right)
$$

**示範影片** [▶ 1:04:02](https://youtu.be/pEVsedl2KO4?t=3842)：MIT 學生在小型遙控車上實作，追蹤地圖上的白色路徑。震盪蠻大的（PID 增益還要再調），但整體速度快，也追得上路徑。縱向控制速度、橫向控制和路徑的距離。

## 7. 串級控制

[▶ 1:04:56](https://youtu.be/pEVsedl2KO4?t=3896)

**串級控制**（cascaded control）：三層控制以**不同頻率**執行。

| 層 | 頻率（講者舉的例子） |
|---|---|
| 馬達 | 約 1000 Hz（每秒 1000 次） |
| 位置 | 每秒 10 次 |
| 軌跡 | 每 10 秒算一條新軌跡 |

**好處** [▶ 1:06:01](https://youtu.be/pEVsedl2KO4?t=3961)：

- 下層每秒設定馬達速度 1000 次 → 從位置控制的角度看，在它的一個控制週期內，速度幾乎是**恆定**的，好像下面沒有控制器一樣。
- 每往上一層，都可以安全地假設：因為下層控制頻率高，系統會到達預期的狀態。
- 這讓假設變簡單，也讓整個架構行得通。

## 8. 設計目標

[▶ 1:06:51](https://youtu.be/pEVsedl2KO4?t=4011)

設計控制器時，講者說最先要想到的五件事：

| 目標 | 意思 |
|---|---|
| 準確（accuracy） | 貼近追蹤的訊號，不要過衝太多 |
| 安全（safety） | 不產生傷害機器人或環境的控制，限制最大控制量 |
| 對雜訊強健（robustness） | 系統預測或量測有雜訊時，控制仍然合理 |
| 反應時間（response time） | 多快到達期望狀態 |
| 好維護（maintenance） | 多年來不同的人管理系統時，容易調參數；換新機器人時容易移植 |

還有其他和應用相關的目標。

## 9. 進階控制方法

[▶ 1:08:38](https://youtu.be/pEVsedl2KO4?t=4118)

講者只給概念，鼓勵自己去查文獻。

### 9.1 最佳控制與 LQR

[▶ 1:09:05](https://youtu.be/pEVsedl2KO4?t=4145)

- **最佳控制**（optimal control）：把控制問題寫成**最佳化問題**。定義一個目標函數（衡量表現），最佳化的解就是要施加的控制。
- 「好表現」可以是：誤差最小（離期望訊號最近）、控制量最小（方向盤／把手不要動太多），或兩者的各種組合。

**線性二次調節器**（linear quadratic regulator, LQR）[▶ 1:12:24](https://youtu.be/pEVsedl2KO4?t=4344)：

- 條件：系統是**線性**的，目標函數是**二次**的。
- 這時有**封閉形式**的最佳解，不可能更好。
- 目標函數兩部分：

$$
J = \sum_k \Bigl( x_k^{\mathsf T} Q\, x_k + u_k^{\mathsf T} R\, u_k \Bigr)
$$

  - $x_k$：目前狀態和期望狀態的**差**，用矩陣 $Q$ 加權。
  - $u_k$：控制量，用矩陣 $R$ 加權。
- 調 $Q$、$R$ 的相對大小：要**準確**（貼近期望訊號）還是要**省資源**（少用控制）。
- 也可以對狀態的各分量分別加權：例如 2D 機器人 $(x, y, \theta)$，位置權重高、朝向權重低 → 更重視到達位置。

（目標函數的形式依講者口述整理，投影片上的確切寫法逐字稿看不到。注意：這裡的 $Q$、$R$ 是**代價權重**，和 1-10 Kalman 濾波裡的雜訊共變異數 $Q$、$R$ 是完全不同的東西，只是剛好同名。）

**非線性系統** [▶ 1:14:37](https://youtu.be/pEVsedl2KO4?t=4477)：車輛、無人機都非常非線性。一種做法是**線性化**後用 LQR；這是近似，解不是真的最佳，但非線性不大時效果不錯。

### 9.2 模型預測控制 MPC

[▶ 1:15:16](https://youtu.be/pEVsedl2KO4?t=4516)

- **MPC**（model predictive control）：**保留非線性**，但不解整個問題，只在一個**短時間窗**（例如 5 秒）裡，用大量數值計算找非線性目標函數的最小值。
- 能做到是因為：短時間窗裡的可能性有限，加上現在電腦很快。
- 影片：車子做非常動態的動作：快速繞圈、再畫 H 形。明顯不是純滾動，打滑很多，很難寫出動力學；人來做也很難。用非線性方法可以做到。
- 詳見 1-16、1-17。

### 9.3 自適應控制

[▶ 1:16:58](https://youtu.be/pEVsedl2KO4?t=4618)

- 系統會**隨時間改變**，除了算控制律，還要估計這些變化。
- 經典例子：**飛機**。飛行中消耗燃料 → 重量變輕 → 在空中的動力學改變。
- 自適應控制方法會估計這些變化，或至少讓控制適應這些變化。

### 9.4 強健控制

[▶ 1:17:58](https://youtu.be/pEVsedl2KO4?t=4678)

- 現實中我們通常知道「雜訊**最大**會到多少」。例如給車的速度可能有 ±10% 的誤差。
- 利用這個知識設計控制，**保證**表現：「只要感測器雜訊小於某個門檻，誤差就不會超過例如 2 公尺。」
- 和自適應控制的差別：強健控制通常不考慮系統參數會變，重點是應付雜訊。同一個問題可以兩者都用。

### 9.5 學習式控制

[▶ 1:19:21](https://youtu.be/pEVsedl2KO4?t=4761)

- 通常需要系統模型；但像車子在停車場甩尾，很難建模。
- 想法：不建模，改從**很多例子**學。
  - 學**系統**：例如在車前放相機看很多甩尾的例子，學系統怎麼演變。
  - 學**控制器**：例如看人類操作員示範 100 次，從示範學出控制器。
- **四軸飛行器例子** [▶ 1:20:35](https://youtu.be/pEVsedl2KO4?t=4835)：上面有標記，能知道自己實際怎麼飛。要繞一條軌跡，一開始飛得不好；它用上一次的飛行結果回饋改進控制器，越飛越接近目標軌跡（也試了更複雜的 S 形）。打開**電風扇**造成外部干擾：一開始不知道，觀察自己的運動後發現有外力，學會補償。這是從**自己過去的經驗**學。
- **倒車路邊停車例子** [▶ 1:21:56](https://youtu.be/pEVsedl2KO4?t=4916)：邊倒車邊路邊停車，動力學很難建模。做法：直線段用物理模型（簡單）；困難的部分用**模擬器**產生的例子；兩者結合，在真車上做出漂亮的倒車轉彎。

### 9.6 故障安全控制

[▶ 1:10:32](https://youtu.be/pEVsedl2KO4?t=4232)、[▶ 1:23:06](https://youtu.be/pEVsedl2KO4?t=4986)

- **故障安全控制**（fail-safe control）：最壞情況下，系統要**平順地降級**，而不是撞牆或從天上掉下來。例如飛機失去一具引擎時仍有一些控制能力。
- 影片：無人機起飛後，故意讓一個螺旋槳脫落。它辨識出有一個螺旋槳壞了，**平順地降下來**，而不是直接摔下。

## 10. 總結

[▶ 1:24:02](https://youtu.be/pEVsedl2KO4?t=5042)

- 底層：馬達怎麼運作（直流馬達、PWM）。
- 回饋控制：用感測器量測把系統推向期望訊號（洗澡例子）。
- PID：用在位置控制。
- 軌跡追蹤：讓機器人沿路徑走（自主導航的常見任務）。
- 進階方法：有雜訊、參數會變、需要更好表現時用；也可以從過去經驗學控制器。
- 講者說部分投影片材料來自其他來源（投影片上列出），推薦去看不同的講法。

## 11. 一頁速查表

### 11.1 控制律

| 名稱 | 公式 | 用途 |
|---|---|---|
| 誤差 | $e_t = x_{\text{des}} - z_t$ | 所有回饋控制的輸入 |
| P | $u_t = K_p e_t$ | 最簡單；有雜訊時調低 $K_p$ |
| PD | $u_t = K_p e_t + K_d \dot e_t$ | 到達時速度也對，減少過衝 |
| PID | $u_t = K_p e_t + K_i \int_0^t e\, d\tau + K_d \dot e_t$ | 加上消除系統偏差 |
| 積分飽和對策 | 只積分最近一段時間窗；限制最大輸出（anti-windup） | 卡住後脫困不暴衝 |
| LQR 代價 | $J = \sum_k (x_k^{\mathsf T} Q x_k + u_k^{\mathsf T} R u_k)$ | 線性系統有封閉形式最佳解 |

### 11.2 P 控制在 $x_t = x_{t-1} + u_t$ 下（推論）

| 關鍵一步 | 結果 |
|---|---|
| $e_t = (1 - K_p)e_{t-1}$ | $0 < K_p \le 1$：單調收斂；$1 < K_p < 2$：震盪收斂；$K_p \ge 2$：不收斂 |

### 11.3 三種增益的效果

| 增益 | 太大 | 太小 |
|---|---|---|
| $K_p$ | 過衝、震盪 | 太慢 |
| $K_d$ | （本集沒談） | 過衝 |
| $K_i$ | 積分飽和、暴衝 | 穩態誤差消不掉 |

### 11.4 實際問題

| 問題 | 現象 | 對策 |
|---|---|---|
| 量測雜訊 | 一直在修正 | 降低增益 |
| 飽和 | 到不了那麼快 | 接受；anti-windup |
| 延遲（死區時間） | 過衝、震盪 | Smith 預測器；寧可**低估**延遲 |
| 系統偏差 | 穩態誤差 | 積分項 |
| 卡住 | 積分飽和 | 時間窗積分、限幅 |

### 11.5 軌跡控制（Ackermann）

| 部分 | 方法 |
|---|---|
| 軌跡取樣 | 均勻（每 5 m）或依曲率 |
| 縱向 | PID 追 $v_{\text{ref}}(t)$ |
| 橫向 | 沿圓弧在前視距離 $l_d$ 處切入路徑：$\delta = \arctan(2D\sin\alpha / l_d)$（推論） |
| 串級頻率 | 馬達 ~1000 Hz > 位置 ~10 Hz > 軌跡 ~0.1 Hz |

## 附：本集一句話總結

> **回饋控制用「期望 − 量測」的誤差產生控制。PID：P 負責到達、D 負責以正確速度到達（不過衝）、I 負責消除系統偏差（小心積分飽和）。軌跡控制拆成縱向（PID 追速度）和橫向（照 Ackermann 運動學走圓弧切入路徑），各層以不同頻率串接。**
