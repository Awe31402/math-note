## 0. 這堂課要做什麼

機器人怎麼決定從現在的位置走到目標？主角是 **A\***：結合「已經花了多少」和「估計還要多少」的有資訊搜尋演算法。最後講怎麼讓它在真實機器人上好用：保持安全距離、加速重新規劃、處理速度限制。

## 1. 運動規劃在解什麼

[▶ 00:00](https://youtu.be/HR1TNa8Lp7w?t=0)

- 機器人知道：自己在哪、要去哪、環境地圖、自己的形狀（知道「往前一公尺」不會撞到旁邊的牆）。
- **運動規劃**演算法產生一串運動指令（或一串要經過的狀態），讓機器人到達目標。
- 可以做到**最佳**：輸出的軌跡沒有更好的。最佳性永遠伴隨假設（能經過哪些狀態、空間怎麼離散化）。
- 例子：在羅馬地下墓穴裡導航的機器人；你車上的衛星導航。
- `⚠️ 逐字稿缺字`：[▶ 01:42](https://youtu.be/HR1TNa8Lp7w?t=102) Whisper 寫 “sub-nav system”，依上下文應為 **sat-nav**（衛星導航）。
- 現在的裝置可能用更進階、更最佳化的演算法，但底層的規劃問題可以用 A* 解。
- 【口頭】Latombe 在 1991 年說：運動規劃是機器人必備的能力，因為大部分（移動）機器人要做任何有用的事，都得從 A 移動到 B [▶ 02:27](https://youtu.be/HR1TNa8Lp7w?t=147)。

## 2. 傳統目標與動態環境

[▶ 03:08](https://youtu.be/HR1TNa8Lp7w?t=188)

**傳統目標**：

1. **不碰撞**：不撞牆、穿過門框時左右都不碰到。
2. 在所有不碰撞的軌跡中，找**最短**或**最快**的。

**最短 ≠ 最快** [▶ 04:00](https://youtu.be/HR1TNa8Lp7w?t=240)：【口頭】一條是高速公路（比較長）、一條是市區道路。高速公路比較長，但能開比較快，所以比較早到。有些應用要最快，有些要最短；兩者常常接近，但不一定一樣。

**靜態世界假設** [▶ 04:56](https://youtu.be/HR1TNa8Lp7w?t=296)：傳統問題假設世界不會變，沒有動態障礙物（沒有人在走動、沒有其他用路人）。這個假設很強，現實中通常不成立。

**動態環境** [▶ 05:16](https://youtu.be/HR1TNa8Lp7w?t=316)：

- 快速移動的障礙物（其他用路人），或建圖時不在的新物體。
- 仍要有效率地規劃，並在某些假設下保證不會撞到（如果物體比機器人快、一直追著它撞，那躲不掉）。對其他物體怎麼移動做假設，至少能給出**機率性**的保證。
- 常分成兩部分 [▶ 06:44](https://youtu.be/HR1TNa8Lp7w?t=404)：
  - **核心規劃**：規劃從 A 到 B 的一般路徑。
  - **局部避撞**（local collision avoidance）：跟著路徑走，但可以偏離以避開碰撞。
- 例子：**動態視窗法**（dynamic window approach）：考慮系統能做到的速度變化，產生一個「下一刻能到達的狀態」的局部視窗，選一個最能接近目標或沿路徑前進的速度。
- 還有很多其他方法：有的針對很狹窄的空間，有的針對能開很快、平順閃避的環境。

**A\* 和它的家族** [▶ 08:07](https://youtu.be/HR1TNa8Lp7w?t=487)：

- A* 是很受歡迎的**有資訊搜尋**演算法，不只用在機器人。它是為機器人發展出來的，是今天的「黃金標準」規劃方法。
- 變體：
  - **ARA\***：講者說是「anytime real-time A*」：很快先給一條初始軌跡讓機器人開始走，再利用剩下的計算資源一路改進（`⚠️ 待確認`：名稱展開）。
  - **D\* 家族**：需要頻繁**重新規劃**時（環境在變），更新效率高很多。
- **Markov 決策過程**：當**運動執行的不確定性**很重要時要用（1-19）。如果系統能照指令執行，A* 就夠了。

**主要挑戰** [▶ 09:57](https://youtu.be/HR1TNa8Lp7w?t=597)：

- 找**最佳**路徑：在給定的代價函數下最佳。代價可以是最短、最快、讓乘客最舒服（加速度小），或合法；【口頭】坐在自駕車上，晚兩三秒到無所謂，只要乘坐舒服。本集只看最短或最快。
- 要不要考慮**不確定性**：動作執行（叫它走 1 公尺，走了 95 公分）、感知系統不完美。
- 怎麼快速反應**沒預料到的障礙物**；其他用路人即使你停下來也可能撞上你。

## 3. 分層架構

[▶ 11:54](https://youtu.be/HR1TNa8Lp7w?t=714)

大多數機器人導航系統是**分層**的，各層以不同頻率執行：

| 層 | 做什麼 | 頻率（講者舉例） |
|---|---|---|
| **規劃**（planning） | 用地圖和自己的位置規劃到目標的路徑；給下一層一個**子目標**（例如前方 5 公尺） | 約每秒 1 次，或每 5 秒 1 次，或每秒 3 次 |
| **避撞**（collision avoidance，局部規劃器） | 檢查路徑附近有沒有障礙物、有沒有碰撞風險；有的話產生替代軌跡 | 感測器頻率：5～30 或 50 Hz |
| **控制**（control） | 把局部資訊變成實際的轉向和馬達指令；用里程計等做修正迴路 | 更高 |

本集主要講規劃層，也稍微講一個同時解規劃和避撞的系統（第 11 節）。控制在 1-15。

## 4. 標準運動規劃問題

[▶ 14:26](https://youtu.be/HR1TNa8Lp7w?t=866)

| 輸入 | |
|---|---|
| 起始組態 | 機器人現在的位姿；也可以是完整狀態（例如含速度） |
| 目標組態 | 例如到某位置、某速度；或「只要到某個 $(x, y)$，速度不管」；也可以是多個狀態 |
| 機器人描述 | 通常是幾何描述（大小），用來和環境結合判斷碰撞 |
| 環境描述 | 用來判斷哪裡是自由空間、哪裡被佔 |

| 輸出 | |
|---|---|
| 一條路徑 | 從起始組態到目標組態、**不碰撞**、在事先定義的代價函數下**代價最小** |

最佳的意思：可能有其他**一樣好**的路徑，但沒有**更好**的 [▶ 16:21](https://youtu.be/HR1TNa8Lp7w?t=981)。

## 5. 組態空間

[▶ 16:37](https://youtu.be/HR1TNa8Lp7w?t=997)

- 規劃問題發生在真實世界（物體在移動），但內部是在**組態空間**（configuration space，C-space）裡規劃。
- **組態**：系統可能處於的狀態，例如機器人的朝向也要算進去。重點：組態要能描述機器人整個形狀在世界中佔了哪些點。
- 【口頭】手臂的例子 [▶ 17:55](https://youtu.be/HR1TNa8Lp7w?t=1075)：只知道肩膀的位置，無法判斷會不會碰撞；手肘的關節角度也要知道。肩膀不動，手肘轉一下也可能撞到東西。
- 常常**離散化**：例如 1 公分的網格、1° 的朝向解析度。
- 簡化例子 [▶ 18:54](https://youtu.be/HR1TNa8Lp7w?t=1134)：一張格子很大的佔用網格地圖。假設機器人只能在格子中心，能移到相鄰格（例如全向輪），這是一個 2D 的離散組態空間。離散化本身是一種近似。

### 形式定義

[▶ 19:57](https://youtu.be/HR1TNa8Lp7w?t=1197)

| 記號 | 意思 |
|---|---|
| $W$ | 工作空間（workspace），例如 $\mathbb R^2$ 或 $\mathbb R^3$ |
| $O \subset W$ | 障礙物（圖上灰綠色） |
| $q$ | 一個組態（例如關節角度＋肩膀位置） |
| $A(q) \subset W$ | 機器人在組態 $q$ 時佔據的工作空間區域 |

**自由空間**（free space）：機器人和任何障礙物都不重疊的組態：

$$
C_{\text{free}} = \{\, q \in C \;\mid\; A(q) \cap O = \emptyset \,\}
$$

**被佔空間**：$C_{\text{obs}} = C \setminus C_{\text{free}}$。

**路徑**（solution）[▶ 22:07](https://youtu.be/HR1TNa8Lp7w?t=1327)：一個連續函數

$$
\tau : [0, 1] \to C_{\text{free}}, \qquad \tau(0) = q_{\text{init}}, \quad \tau(1) = q_{\text{goal}}
$$

只能映射到自由空間（映射到被佔空間就代表碰撞）。規劃就是在 C-space 裡移動一個點，從初始組態到目標組態。

### 兩種離散化

[▶ 23:28](https://youtu.be/HR1TNa8Lp7w?t=1408)

| | 組合式（combinatorial） | 取樣式（sampling-based） |
|---|---|---|
| 做法 | 把所有狀態切成小格（2D 像佔用網格，3D 像體素） | 在 $C_{\text{free}}$ 裡**取樣**可能的組態，一邊規劃一邊擴展 |
| 問題 | 格子數**隨維度指數成長** | 需要能在某個組態附近產生自由組態的方法 |
| 適用 | 低維（2D、3D） | 10、20、30 維；有好策略時只需取樣一小部分空間 |
| 本集 | **用這個** | — |

## 6. 搜尋演算法的評估標準

[▶ 26:09](https://youtu.be/HR1TNa8Lp7w?t=1569)

規劃可以用**搜尋**解：在組態空間中搜尋一串組態，從現在的組態到目標組態。

**兩類**：

- **無資訊搜尋**（uninformed）[▶ 27:26](https://youtu.be/HR1TNa8Lp7w?t=1646)：盲目搜尋。可能考慮已經走了幾步、每次展開最便宜的節點，但**不用**任何關於目標的額外資訊（例如上下界）。例：BFS、DFS、均勻代價搜尋。
- **有資訊搜尋**（informed）[▶ 29:15](https://youtu.be/HR1TNa8Lp7w?t=1755)：用額外資訊，叫**啟發函數**（heuristic）：從某組態到目標的代價**估計**。用它加快搜尋，但找到的解仍然要是最佳的。不是所有有資訊搜尋都是最佳的（例如貪婪搜尋不是），A* 是，但啟發函數要滿足一些條件。

**四個評估標準** [▶ 31:15](https://youtu.be/HR1TNa8Lp7w?t=1875)：

| 標準 | 意思 |
|---|---|
| **完備性**（completeness） | 如果解存在，一定找得到。（例：兩個房間之間沒有門，就沒有解；有門的話保證找到嗎？） |
| **最佳性**（optimality） | 找到的解在給定代價函數下是最佳的 |
| **時間複雜度** | 找到解要多久，用狀態數、轉移數的大 O 表示，不是幾秒 |
| **空間複雜度** | 要多少記憶體，同上 |

【口頭】講者提醒 [▶ 32:57](https://youtu.be/HR1TNa8Lp7w?t=1977)：說「最佳演算法」時，永遠是在**定義好的代價函數**和假設（離散化等）下的最佳，不代表它是任何導航問題的最好演算法。小心「最佳」這個詞。

## 7. 無資訊搜尋

### 7.1 BFS 與 DFS

[▶ 34:26](https://youtu.be/HR1TNa8Lp7w?t=2066)

- 展開節點時不考慮代價，可以想成每次展開代價都是 1，目標是找「經過狀態數最少」的路徑。
- 例子：一棵樹，1 是初始組態；1 的鄰居是 2、3、4；2 的鄰居是 5、6；5 的鄰居是 9、10……找到目標（例如 12）就停。

| | **廣度優先**（BFS） | **深度優先**（DFS） |
|---|---|---|
| 順序 | 一層一層：先 2、3、4，再 5、6、7、8，再 9、10…… | 先第一個鄰居、它的第一個鄰居……到底才回頭 |
| 最佳？ | **是**（各步代價相同時） | **否**：可能先沿深的一支找到目標，但其實有更短的路 |
| 完備？ | **是** | 有限空間是；**無限**空間不是（可能一直往一條無限長的走廊走，錯過旁邊很近的目標） |

- 第 $k$ 層的節點代價就是 $k$（走了 $k$ 步）。
- 複雜度取決於：每個節點有幾個鄰居、目標在第幾層、樹的最大深度。

### 7.2 均勻代價搜尋

[▶ 39:02](https://youtu.be/HR1TNa8Lp7w?t=2342)

- 通常不同轉移的代價不同 → **代價敏感搜尋**。仍然是無資訊的（只用代價函數，不用關於目標的資訊）。
- **名稱的意思**：節點被**一視同仁**地對待（不分在第幾層），但轉移有不同代價。**不是**「代價都一樣」，名稱容易誤會 [▶ 39:45](https://youtu.be/HR1TNa8Lp7w?t=2385)。
- **累積路徑代價** $g(n)$：從起點到節點 $n$ 已經花的代價。例：1→2 代價 2、2→5 代價 4，則 $g(5) = 2 + 4 = 6$；另一條 5 + 6 = 11。
- 規則：**永遠展開 $g$ 最小的節點**。
- 性質：**最佳**且**完備**。
- 為什麼第一次找到目標就是最佳 [▶ 41:53](https://youtu.be/HR1TNa8Lp7w?t=2513)：每次展開的都是目前最便宜的節點；第一次展開到目標時，所有更便宜的節點都已經展開過、都不是目標，所以沒有更便宜的路。
- **關係**：
  - 所有轉移代價都是 1 → 一層一層展開 → 退化成 **BFS**。BFS 是均勻代價搜尋的特例。
  - 從**目標**開始跑、展開整個空間、記下每個節點的 $g$ → 就是 **Dijkstra 演算法**（算出所有節點到一個節點的最短路徑）[▶ 42:39](https://youtu.be/HR1TNa8Lp7w?t=2559)。
- `⚠️ 逐字稿缺字`：Whisper 寫 “dextrose algorithm”，應為 **Dijkstra's algorithm**。

**無資訊搜尋的問題**：要很久才找到目標。能不能用更多資訊更快找到？

## 8. 有資訊搜尋

### 8.1 啟發函數

[▶ 44:11](https://youtu.be/HR1TNa8Lp7w?t=2651)

- **啟發函數** $h(n)$：從節點 $n$ 到目標的**代價估計**。不是真實代價，是一個提示。
- 估計越好，越快找到目標；完全隨機的啟發函數沒有幫助，甚至會誤導。
- 常常能給出**下界**：在歐氏世界裡，兩個組態之間不可能比**直線距離**更短 [▶ 45:02](https://youtu.be/HR1TNa8Lp7w?t=2702)。這非常有價值，可以引導搜尋優先展開比較可能快速到達目標的節點。

### 8.2 貪婪搜尋

[▶ 45:52](https://youtu.be/HR1TNa8Lp7w?t=2752)

- 最簡單的形式：**只看** $h(n)$，永遠展開「看起來離目標最近」的節點。
- 忽略累積代價 $g$（不管到這裡花了多少）。
- 啟發函數好時，通常**很快**找到目標。
- 但**不保證最佳**：結果快，品質可能差。

### 8.3 A*

[▶ 47:54](https://youtu.be/HR1TNa8Lp7w?t=2874)

**A\* = 均勻代價搜尋 ＋ 貪婪搜尋**：

$$
f(n) = g(n) + h(n)
$$

| 項 | 意思 | 來源 |
|---|---|---|
| $g(n)$ | 從起點到 $n$ 的**真實**累積代價 | 已經算出來的（同均勻代價搜尋） |
| $h(n)$ | 從 $n$ 到目標的**估計**代價 | 啟發函數（同貪婪搜尋） |
| $f(n)$ | 經過 $n$ 的解的估計總代價 | 「已知的＋估計剩下的」 |

**規則**：永遠展開 $f$ 最小的節點 [▶ 56:47](https://youtu.be/HR1TNa8Lp7w?t=3407)。

只要啟發函數選得好（第 8.4 節），A* 是**最佳**且**完備**的。

**歷史** [▶ 49:17](https://youtu.be/HR1TNa8Lp7w?t=2957)：

- 1960 年代末，Nils Nilsson 在史丹佛研究院（SRI）參與 **Shakey 機器人**計畫。Shakey 是最早能做導航和感知任務的機器人之一（當然是在簡化、受限的環境下），在當時的條件下很了不起。
- 今天機器人和 AI 裡的很多標準演算法都是那時在 SRI 發展的，包括 A*。
- A* 現在是 AI 有資訊搜尋的黃金標準，大部分規劃系統用 A* 或它的變體。【口頭】這是機器人社群想出的解法影響了其他領域的例子之一。
- `⚠️ 逐字稿缺字`：Whisper 寫 “Neil's Nielsen” 和 “shaky the robot”，應為 **Nils Nilsson**、**Shakey the robot**。

### 8.4 可容許的啟發函數

[▶ 57:14](https://youtu.be/HR1TNa8Lp7w?t=3434)

條件：

1. $h(\text{goal}) = 0$：在目標時剩下代價是 0（很容易滿足）。
2. **永遠不高估**：對所有節點，

$$
h(n) \le h^*(n)
$$

  $h^*(n)$ 是從 $n$ 到目標的**真實**最小代價（我們不知道它）。

- 滿足這個條件叫**可容許的啟發函數**（admissible heuristic），A* 就保證得到最佳解。
- 例：真實剩下 8 單位，啟發函數說 10 → **不允許**。
- 希望 $h$ 越接近 $h^*$ 越好。如果 $h = h^*$，規劃就很簡單：在代價函數上做梯度下降就好。
- **標準選擇**：歐氏空間裡用**直線距離**。只知道「在歐氏空間」、沒有其他資訊時，直線距離是很好的選擇 [▶ 59:05](https://youtu.be/HR1TNa8Lp7w?t=3545)。
- **最快路徑**問題 [▶ 52:50](https://youtu.be/HR1TNa8Lp7w?t=3170)：還是可以用直線距離：最快不可能比「以最高速沿直線開」更快，所以 $h = \text{直線距離} / v_{\max}$ 仍然不高估。
- 有朝向（非歐氏）時要另外處理。

以下**不是逐字稿內容**，是可容許啟發函數保證最佳的簡短論證（樹搜尋版本）。講者只說「可容許就會得到最佳解」：

- 設最佳解代價 $C^*$。假設 A* 先展開到一個非最佳的目標 $G_2$，$g(G_2) > C^*$。
- 那時，最佳路徑上一定還有某個節點 $n$ 在待展開清單裡（最佳路徑還沒被完整展開）。
- 對這個 $n$：$f(n) = g(n) + h(n) \le g(n) + h^*(n) = C^*$（第二步用可容許性；$n$ 在最佳路徑上，所以 $g(n) + h^*(n) = C^*$）。
- 而 $f(G_2) = g(G_2) + 0 > C^*$。
- 所以 $f(n) < f(G_2)$，A* 應該先展開 $n$ 而不是 $G_2$，矛盾。

### 8.5 高估的啟發函數

[▶ 59:35](https://youtu.be/HR1TNa8Lp7w?t=3575)

- 若 $h > h^*$（不可容許），就**失去最佳性**。
- 但如果知道高估多少，可以給出界限：例如啟發函數最多是最佳值的 2 倍，那找到的解最多比最佳解差 2 倍。
- 一些 anytime 演算法（例如 ARA*）利用這一點：先用高估的啟發函數很快算出一條不一定最佳的路徑，再隨著計算資源增加而改進。
- **經驗法則** [▶ 1:00:30](https://youtu.be/HR1TNa8Lp7w?t=3630)：

| | 效果 |
|---|---|
| $h$ 越大 | 搜尋越快 |
| $h \le h^*$ | 保證最佳 |

  所以希望 $h$ 盡量大但不超過 $h^*$。如果應用允許路徑稍微貴一點、換來只用一小部分時間，也可以選擇高估。

（以下**不是逐字稿內容**：講者說的「2 倍」是一般性質的特例：若 $h \le \varepsilon\, h^*$，$\varepsilon \ge 1$，則找到的解代價不超過 $\varepsilon\, C^*$。）

### 8.6 A* 的流程

[▶ 1:01:15](https://youtu.be/HR1TNa8Lp7w?t=3675)

實作需要：

- **優先佇列**（priority queue）：放進節點，永遠能拿出最便宜的。
- 因為組態空間是**圖**（一個節點可以從不同路徑到達），找到更便宜的路時要能**更新**節點。

講者用一張流程圖（出自 Choset 的書，`⚠️ 待確認`）說明 [▶ 1:02:18](https://youtu.be/HR1TNa8Lp7w?t=3738)：

| 集合 | 意思 |
|---|---|
| $O$（open） | 正在考慮的節點，用優先佇列實作 |
| $C$（closed） | 已經處理完的節點，代價不會再變 |

```
Algorithm A*(start, goal):
  O = {start}; C = ∅
  loop:
    if O is empty: return failure              // 整個空間都探索完了
    n_best = 從 O 取出 f 最小的節點
    將 n_best 從 O 移到 C
    if n_best == goal: return path               // 找到了
    for each neighbor x of n_best not in C:
      if x not in O:
        將 x 加入 O（記下 g(x) 和來源 n_best）
      else if g(n_best) + c(n_best, x) < g(x):
        更新 g(x) 和來源為 n_best               // 找到更便宜的路
```

- 一開始 $O$ 裡放初始組態，不是空的。
- 已經在 $C$ 的節點代價不會再變；還在 $O$ 的節點可能因為找到更便宜的路而更新。
- 有現成的優先佇列，一兩頁程式碼就能寫完。
- 使用者只要定義**路徑代價**和**可容許的啟發函數**。

## 9. 用在機器人：2D 網格

[▶ 50:31](https://youtu.be/HR1TNa8Lp7w?t=3031)、[▶ 1:07:41](https://youtu.be/HR1TNa8Lp7w?t=4061)

- 假設已知位姿和地圖（通常是佔用網格，也可以是多邊形等其他離散化），有一個能用的定位系統。
- 輸出：機器人要依序經過的組態，沿著走就是最佳路徑。
- 通常用 **8 鄰域**：網格上可以往周圍 8 格移動；機器人可以原地轉、再移到相鄰組態。
- 動畫 [▶ 53:29](https://youtu.be/HR1TNa8Lp7w?t=3209)：
  - 灰色節點：代價已知。邊界節點：還沒探索完所有鄰居。黃色：目前正在展開的節點。
  - 搜尋被**引導**往目標方向；離目標越來越遠的節點（例如上方）不會被探索，因為啟發函數說那裡不太可能是好路徑。
  - 仍然不確定哪條最短（例如那邊會不會有一扇門），所以兩種可能都會展開，直到找到最佳解。

## 10. 違反假設時怎麼辦

[▶ 1:08:40](https://youtu.be/HR1TNa8Lp7w?t=4120)

A* 底下的假設：

| 假設 | 現實 |
|---|---|
| 機器人知道自己的位置 | 定位精度可能只有 20 公分；如果路徑只離障礙物 1 公分，就不夠 |
| 地圖正確 | 有人走來走去 |
| 運動執行正確 | 叫它往前 1 公尺，可能偏左 1°；貼牆走時就會撞上 |

A* 算出的是「不碰撞」的路徑，但現實中沒人能保證。要回頭檢視假設，**改寫問題**讓解對小偏差不那麼敏感。

**兩個實際問題** [▶ 1:11:38](https://youtu.be/HR1TNa8Lp7w?t=4298)：

1. 路徑常常**緊貼障礙物**：為了最短，從牆邊 1 毫米擦過也算「不碰撞」。只有能精確到毫米地執行才行，現實做不到。
2. 網格只有 **45° 的朝向離散化**：走廊方向沒對齊網格時，可能產生奇怪的次佳軌跡。

### 10.1 卷積網格地圖：和障礙物保持距離

[▶ 1:13:48](https://youtu.be/HR1TNa8Lp7w?t=4428)

**最簡單**：把所有障礙物加厚 10 公分再規劃。原本 1 毫米的距離變成 10 公分＋1 毫米。

- 問題 [▶ 1:14:37](https://youtu.be/HR1TNa8Lp7w?t=4477)：狹窄通道。門框 80 公分、機器人 70 公分，加厚 10 公分就**過不去**了。
- 想要的是：**能的話**保持距離，不能的話也要過得去。

**技巧：對網格地圖做卷積** [▶ 1:15:04](https://youtu.be/HR1TNa8Lp7w?t=4504)：

- 像影像處理的**高斯模糊**（Photoshop 那種）：每格取鄰近格的加權平均。
- 被佔格的高機率「分一點」給旁邊的空格 → 空格的佔用機率稍微升高。
- 如果代價和佔用機率相關，就等於把障礙物的（無限大）代價**抹一點**到附近的自由空間。
- 結果：
  - 有足夠空間時，機器人走離障礙物遠的地方（比較便宜）。
  - 沒有別的路時，還是會穿過門框，而且會走**門框正中央**（離兩邊牆最遠）。機器人甚至可以用這個資訊在那裡減速、更精確地走。

**一維例子** [▶ 1:17:22](https://youtu.be/HR1TNa8Lp7w?t=4642)：

- **二項式核**（binomial kernel）：中間格取 1/2，左右各 1/4。對所有列、所有行各做一次，近似高斯模糊。
- 做兩次卷積後，被佔格的值稍微變低、旁邊空格的值稍微變高。
- 再和原地圖取**最大值**：確定被佔的格子仍然是 1（永遠不能走）。

以下**不是逐字稿內容**，是筆記自己算的數值例子（講者的格子數值在投影片上）：

| 格子 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 原地圖 | 0 | 0 | 1 | 1 | 0 | 0 |
| 卷積一次 $[\tfrac14, \tfrac12, \tfrac14]$ | 0 | 0.25 | 0.75 | 0.75 | 0.25 | 0 |
| 卷積兩次 | 0.0625 | 0.3125 | 0.625 | 0.625 | 0.3125 | 0.0625 |
| 和原圖取 max | 0.0625 | 0.3125 | **1** | **1** | 0.3125 | 0.0625 |

（例：第 2 格第一次 $= \tfrac14 \cdot 0 + \tfrac12 \cdot 0 + \tfrac14 \cdot 1 = 0.25$；第二次 $= \tfrac14 \cdot 0 + \tfrac12 \cdot 0.25 + \tfrac14 \cdot 0.75 = 0.3125$。）

- 這叫「**在卷積網格地圖上做 A\***」，是今天多數規劃系統的標準做法。
- 路徑只比最佳的稍長（如果有的話），但執行可靠得多，因為不太會因為定位偏差或執行誤差撞上障礙物。
- 真的要正確處理不確定的動作執行，要用 **MDP**（1-19）。卷積是計算量小很多的「快速修補」，效果類似 [▶ 1:20:04](https://youtu.be/HR1TNa8Lp7w?t=4804)。

### 10.2 用 Dijkstra 算出最佳啟發函數

[▶ 1:20:30](https://youtu.be/HR1TNa8Lp7w?t=4830)

- 啟發函數要低估真實代價。能不能直接算**真實**代價？可以：**Dijkstra** 從目標開始展開整個空間，就得到每一格到目標的真實代價 = **最佳啟發函數**。
- 但這比 A*（甚至無資訊搜尋）還貴。所以：
  - **只規劃一次** → 用 A* 加歐氏啟發函數。
  - **經常重新規劃到同一個目標**（例如每秒重新規劃一次，機器人移動了一點，或地圖加了看到的行人）→ 值得先跑一次 Dijkstra，再用這個最佳啟發函數規劃 [▶ 1:21:27](https://youtu.be/HR1TNa8Lp7w?t=4887)。
- 有了最佳啟發函數，如果環境不變，A* 幾乎退化成在代價地圖上的**梯度下降**（講者隨即修正：不完全是梯度下降，但非常快）。
- 有新障礙物（行人）時，某些格子代價變高。這不影響啟發函數的可容許性（它只會變得更低估），A* 照跑：遇到障礙物時繞過去，多花一點計算，然後繼續用最佳啟發函數 [▶ 1:23:02](https://youtu.be/HR1TNa8Lp7w?t=4982)。

## 11. 高維：5D 規劃

[▶ 1:23:35](https://youtu.be/HR1TNa8Lp7w?t=5015)

**想法**：不只在 $(x, y)$ 規劃，而是在

$$
(x,\; y,\; \theta,\; v,\; \omega)
$$

五維空間規劃（位置、朝向、平移速度、旋轉速度）。

- 好處：
  - 鄰近狀態由目前組態和速度**自動**決定。
  - 能正確考慮轉彎（2D 網格沒有），產生更好的最快軌跡。
  - 能加入速度限制、**加速度上限**（平順地起步和停止）；某些區域開慢、某些開快。
  - 不再有 45° 的折線。
- 計算鄰居更複雜：要考慮平台的物理限制（平移、旋轉的加速度限制，多快能停下）[▶ 1:26:02](https://youtu.be/HR1TNa8Lp7w?t=5162)。
- **問題**：狀態數隨維度指數成長，五維空間太大。如果沒有底層的避撞系統，這個規劃器要高頻率執行：室內 5 Hz；比走路快一點就要 10 Hz；戶外道路要 30～40 Hz。在完整的 5D 空間做不到。

**階層式規劃** [▶ 1:27:38](https://youtu.be/HR1TNa8Lp7w?t=5258)：

1. **地圖**：靜態佔用網格（不變）＋動態地圖（只放目前看到的障礙物，例如雷射以 10 Hz 更新）。規劃用的地圖 = 兩者取最大值，再做卷積。
2. **2D A\***：在 2D 網格上規劃，用 Dijkstra 算的最佳啟發函數，加上前面的所有技巧。
   - 每秒執行約 5 次，所以值得先花約半秒算最佳啟發函數；之後規劃快 10～30 倍，「快得驚人」[▶ 1:30:48](https://youtu.be/HR1TNa8Lp7w?t=5448)。
3. **假設**：2D 路徑和 5D 路徑在 $(x, y)$ 上不會差太多（可能因為加速度或彎道稍微偏離，但不會大改）。
4. **建一條通道**：只在 2D 路徑周圍的一條窄**通道**裡建立 5D 組態空間，而且只到前方一個**子目標**（例如 5 或 10 公尺）。反正每秒重新規劃 5 次，200 毫秒內也開不到 10 公尺外。
5. **在通道裡做 5D A\***：啟發函數考慮速度、到子目標的距離，以及 2D Dijkstra 的代價（Dijkstra／價值迭代只在 2D 做，5D 做太貴）[▶ 1:32:52](https://youtu.be/HR1TNa8Lp7w?t=5572)。

**假設什麼時候會出問題** [▶ 1:31:09](https://youtu.be/HR1TNa8Lp7w?t=5469)：最短路徑和最快路徑在 $(x, y)$ 上相差很遠時。例如一條短但要頻繁停下轉彎，另一條稍長但是很順的直線或弧線：2D 會選短的那條，5D 通道裡就找不到快的那條。講者說現實中很少發生。

**例子** [▶ 1:33:26](https://youtu.be/HR1TNa8Lp7w?t=5606)：

- 模擬：白色虛線是每一刻算出的軌跡；實際執行的軌跡沒有 45° 折角，很平順，考慮了運動學限制。
- 真實機器人：未知障礙物（垃圾桶）出現、有人走進來擋路 → 規劃器繞過去，還能穿過窄門，平順地避開障礙物。

**通道大小的影響** [▶ 1:35:20](https://youtu.be/HR1TNa8Lp7w?t=5720)：

| 通道（寬 × 長） | 和最佳解（完整 5D，只能離線算）的差距 |
|---|---|
| 0.7 m × 1.5 m | 約差 10% |
| 0.9 m × 2.5 m，或超過 1 m × 5 m | 多數室內環境**沒有差別** |

只展開狀態空間的一小部分，就得到最佳或接近最佳的軌跡。當時（約 18 年前）的硬體就能每秒跑好幾次，現代系統更輕鬆。

## 12. 總結

[▶ 1:36:29](https://youtu.be/HR1TNa8Lp7w?t=5789)

- 規劃：從起點到目標找最佳或接近最佳的軌跡。
- 搜尋技術：無資訊和有資訊。機器人學實務上幾乎都用有資訊搜尋。
- **A\*** 是路徑規劃的黃金標準。可以調整地圖（卷積）、預先計算啟發函數（Dijkstra）來加速、方便重新規劃。
- 約 1969 年由 Nils Nilsson 為 Shakey 開發，至今是 AI 有資訊搜尋的關鍵工具。
- AI 領域有尋找甚至**學習**啟發函數的研究；機器人通常在歐氏世界，很容易定義好的啟發函數。
- 可以在 2D 網格上做，也可以加一些近似擴展到高維（考慮運動學限制）。
- 如果運動執行有**嚴重的不確定性**，要用別的方法（1-19 MDP）；系統行為合理的話，本集的方法就是正解。

## 13. 一頁速查表

### 13.1 搜尋演算法比較

| 演算法 | 展開哪個節點 | 最佳？ | 完備？ |
|---|---|---|---|
| BFS | 層數最小 | 是（等代價） | 是 |
| DFS | 最深 | 否 | 有限空間是 |
| 均勻代價 | $g(n)$ 最小 | 是 | 是 |
| 貪婪 | $h(n)$ 最小 | 否 | — |
| **A\*** | $f(n) = g(n) + h(n)$ 最小 | **是**（$h$ 可容許） | 是 |

關係：等代價時 均勻代價 = BFS；從目標跑完整個空間的均勻代價 = Dijkstra。

### 13.2 A* 的條件

| 條件 | 公式 | 關鍵一步 |
|---|---|---|
| 目標 | $h(\text{goal}) = 0$ | — |
| 可容許 | $h(n) \le h^*(n)$ | $f(n) \le C^* < f(G_2)$，最佳路徑上的節點先被展開 |
| 最短路徑 | $h = $ 直線距離 | 歐氏距離是下界 |
| 最快路徑 | $h = $ 直線距離 $/ v_{\max}$ | 不可能更快 |
| 高估 | $h \le \varepsilon h^* \Rightarrow$ 代價 $\le \varepsilon C^*$ | 換取速度 |
| 最佳啟發 | 從目標跑 Dijkstra 得 $h^*$ | 重新規劃到同一目標時值得 |

### 13.3 組態空間

$$
C_{\text{free}} = \{ q \mid A(q) \cap O = \emptyset \}, \qquad \tau: [0, 1] \to C_{\text{free}},\ \tau(0) = q_{\text{init}},\ \tau(1) = q_{\text{goal}}
$$

### 13.4 實務技巧

| 問題 | 技巧 |
|---|---|
| 路徑緊貼障礙物 | 卷積網格地圖（二項式核 $[\tfrac14, \tfrac12, \tfrac14]$，兩次），再和原圖取 max |
| 經常重新規劃 | 先跑 Dijkstra 當最佳啟發函數 |
| 速度限制、平順軌跡 | 5D $(x, y, \theta, v, \omega)$ A*，只在 2D 路徑周圍的通道裡、到子目標為止 |
| 動作執行不確定 | 改用 MDP（1-19） |

## 附：本集一句話總結

> **A\* 每次展開 $f = g + h$ 最小的節點：$g$ 是已知的累積代價、$h$ 是到目標的估計。只要 $h$ 永不高估（例如直線距離），結果就是最佳的。實務上在卷積過的網格地圖上規劃以保持安全距離，用 Dijkstra 預先算最佳啟發函數加速重新規劃，再在 2D 路徑周圍的窄通道裡做 5D 規劃以考慮速度限制。**
